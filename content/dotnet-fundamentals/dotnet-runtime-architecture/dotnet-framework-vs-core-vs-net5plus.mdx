<SimpleDefinition>

.NET Framework was Microsoft's original, Windows-only runtime (1.0 in 2002); .NET Core was a ground-up, open-source, cross-platform rewrite (2016) built to fix Framework's platform lock-in and slow release cycle; .NET 5 (2020) onward dropped the word "Core" and unified everything — Framework, Core, Xamarin, Mono — into one platform released yearly.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Interview me "`.NET Framework` aur `.NET Core` me kya fark hai" bahut common opening question hai, especially freshers/SDE-1 ke liye — kyunki bahut sa production code (banking, insurance, legacy enterprise apps) aaj bhi `.NET Framework` pe chal raha hai India me, aur nayi cheez `.NET 8`/`.NET 9` pe likhi jaa rahi hai. Teeno ka relationship samajhna, na ki sirf naam yaad rakhna, yahi asli test hai.

### .NET Framework (2002) — jahan se sab shuru hua

Microsoft ne `.NET Framework 1.0` ko 2002 me launch kiya — Windows-only, tightly coupled Windows APIs (registry, IIS, Windows-specific file system assumptions) ke saath. Ye monolithic tha — ek single installation jisme CLR, BCL (Base Class Library), ASP.NET, WinForms, WPF sab kuch bundled tha. Iski problems:

- **Windows-only** — Linux/Mac pe deploy karna practically impossible tha.
- **Slow release cycle** — naya version aane me saalon lagte the, aur ek machine pe sirf ek `.NET Framework` version cleanly install ho sakta tha (side-by-side versioning weak tha).
- **Closed-source** (2014 tak) — community contribute nahi kar sakti thi.
- `.NET Framework 4.8` (2019) iski final version hai — ab sirf security patches milte hain, koi naya feature nahi aata.

### .NET Core (2016) — ground-up rewrite, cross-platform-first

Cloud aur containers (Docker/Kubernetes) ka era aane par, Windows-only hona ek real business problem ban gaya — companies Linux containers pe deploy karna chahti thi, cost aur flexibility dono ke liye. Microsoft ne `.NET Core 1.0` (2016) ko literally **scratch se rewrite** kiya, in goals ke saath:

- **Cross-platform** — Windows, Linux, macOS, sab pe same code chalta hai.
- **Open-source** (GitHub par, `dotnet/runtime`) — community contributions accept hote hain.
- **Modular** — `csproj`/NuGet ke through sirf zaroori packages reference karo, poora framework bundle nahi hota.
- **Fast, yearly-ish release cycle** — `.NET Core 1.0` → `2.0` → `2.1` (LTS) → `3.0` → `3.1` (LTS), roughly saal-saal bhar me.
- Performance bhi genuinely better tha — `.NET Core` ka JIT aur GC redesigned the, kai benchmarks me `.NET Framework` se significantly fast.

Trade-off: `.NET Core` ke early versions (1.x, 2.x) me `.NET Framework` ki har API available nahi thi — WinForms/WPF `.NET Core 3.0` tak nahi aaye the, kuch legacy libraries (jo Windows-specific COM interop use karti thi) migrate hi nahi ho sakti thi.

### .NET 5+ (2020) — "Core" naam hata diya, ek hi platform

`.NET Core 3.1` ke baad agla version `.NET Core 4.0` nahi, balki seedha **`.NET 5`** (2020) aaya — jaan-boojhkar version-number jump kiya taaki `.NET Framework 4.x` se confuse na ho. Isi release se Microsoft ne officially declare kiya: ab sirf **ek `.NET`** hai, going forward. "Core" naam permanently drop ho gaya kyunki ab koi "non-Core .NET" bana hi nahi rahi thi.

`.NET 5` ne `.NET Core` ki cross-platform/open-source foundation ko `Mono` (Xamarin/mobile runtime) aur `.NET Framework` ke remaining relevant pieces ke saath unify kiya — ek hi BCL, ek hi runtime team, ek hi release train. Har naya version November me aata hai:

- Odd-numbered (`.NET 5`, `7`, `9`) = Current release, 18 months support
- Even-numbered (`.NET 6`, `8`, `10`) = **LTS (Long Term Support)**, 3 saal support — production ke liye usually LTS choose kiya jaata hai

`.NET 8` (Nov 2023) is site ke examples ki baseline hai — current LTS.

### Kyun ye timeline interview me matter karti hai

Recruiters/interviewers ye check karte hain ki candidate ko pata hai ki `.NET Framework` "purana" nahi, balki genuinely **discontinued-for-new-features** hai (sirf maintenance mode), aur `.NET Core` ek transitional naam tha jo `.NET 5` se merge ho gaya — "`.NET Core` vs `.NET 5` alag runtimes hain" jaisi galatfehmi ek common trap hai. Practically: naya project kabhi `.NET Framework` pe start nahi hota (except very specific legacy-interop cases), aur `.NET Core` naam ab sirf history/legacy `.csproj` files me dikhta hai.

</Hinglish>

<Callout type="trap">

".NET Core aur .NET 5 do alag runtimes hain" — galat. `.NET 5` `.NET Core 3.1` ka hi seedha successor hai, sirf naam se "Core" hataya gaya taaki ye clear ho ki ab yahi **the** `.NET` hai, `.NET Framework` ka replacement nahi ek parallel option.

</Callout>

## Real World Example

<RealWorld company="Microsoft">

Microsoft khud is unification story ka sabse bada proof hai — `.NET 8`/`.NET 9` par Azure, Visual Studio backend services, aur bahut se internal Microsoft products chalte hain, jabki dus saal pehle sab kuch `.NET Framework` pe tha. Migration overnight nahi hui — `.NET Framework` se `.NET Core`/`.NET 5+` tak jaana ek multi-year, incremental effort tha kai bade Microsoft products ke liye bhi.

</RealWorld>

<RealWorld company="An Indian Bank's Core Banking Modernization">

Ek typical Indian BFSI setup me, core banking engine aaj bhi `.NET Framework 4.8` pe chal sakta hai (decades purana, heavily tested, migrate karna risky) — jabki naye customer-facing microservices (mobile banking APIs, notification services) `.NET 8` pe likhe jaate hain. Dono coexist karte hain, alag deployment models ke saath, jab tak legacy system ka poora rewrite justify na ho.

</RealWorld>

## Numbers That Matter

<Numbers>

- `.NET Framework 1.0` — 2002, Windows-only, closed-source (2014 tak)
- `.NET Framework 4.8` (2019) — final version, maintenance-only ab
- `.NET Core 1.0` — 2016, cross-platform, open-source ground-up rewrite
- `.NET 5` — Nov 2020, "Core" naam drop, unification ka start
- LTS releases har 2 versions me ek — `.NET 6`, `.NET 8` (current baseline), `.NET 10` — 3 saal support
- Non-LTS (Current) releases — 18 mahine support, production ke liye usually avoid kiye jaate hain

</Numbers>

## Interview Angle

<InterviewAngle>

"`.NET Framework`, `.NET Core`, aur `.NET 5+` me kya fark hai?" ka strong answer teen-part timeline ke roop me dena chahiye: "`.NET Framework` (2002) Windows-only, monolithic, closed-source tha; `.NET Core` (2016) ek ground-up rewrite tha jo cross-platform aur open-source bana, taaki cloud/container deployments possible ho; `.NET 5` (2020) se Microsoft ne `.NET Core` ki foundation ko `.NET Framework`'s remaining relevance aur Mono/Xamarin ke saath unify kar diya aur 'Core' naam hata diya kyunki ab yahi ek `.NET` hai jo aage badhega. Production me naya kaam `.NET 8`/`.NET 9` jaisi current/LTS release pe hota hai, `.NET Framework` sirf legacy maintenance ke liye reh gaya hai."

</InterviewAngle>

## Common Mistakes

<Mistake>

`.NET Core` aur `.NET 5+` ko alag runtimes samajhna — ye ek hi continuous evolution hai, naam sirf marketing/clarity ke liye badla gaya.

</Mistake>

<Mistake>

Ye maan lena ki `.NET Framework` "deprecated" hai isliye kal hi hat jaayega — reality me ye still-supported (security patches ke liye) hai, sirf feature-frozen hai, aur bahut sa production code decades tak isi pe chalega.

</Mistake>

<Mistake>

Har naya `.NET` version (odd-numbered, Current) production ke liye grab kar lena bina LTS check kiye — sirf even-numbered (`6`, `8`, `10`) LTS hain, jo production stability ke liye usually preferred hote hain.

</Mistake>

<Mistake>

Ye sochna ki `.NET Core` se `.NET Framework` ka har feature/library available thi from day one — early `.NET Core` (1.x/2.x) me WinForms/WPF jaisi cheezein missing thi, ye `.NET Core 3.0` tak nahi aayi.

</Mistake>

## Quick Revision

<QuickRevision>

- `.NET Framework` (2002) — Windows-only, monolithic, closed-source until 2014, now maintenance-only at `4.8`
- `.NET Core` (2016) — ground-up rewrite, cross-platform, open-source, modular
- `.NET 5` (2020) — unification, "Core" dropped, single platform going forward
- Yearly November releases — odd = Current (18 months support), even = LTS (3 years support)
- `.NET 8` is this site's baseline — current LTS
- Interview trap: `.NET Core` and `.NET 5+` are NOT different runtimes — same lineage, renamed

</QuickRevision>
