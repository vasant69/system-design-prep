<SimpleDefinition>

The .NET BCL ships a set of built-in exception types for the most common failure conditions — `NullReferenceException`, `InvalidCastException`, `IndexOutOfRangeException`, `DivideByZeroException`, `InvalidOperationException`, `ArgumentNullException`, and `FormatException` among them — and recognizing exactly what triggers each one, and how they differ from their near-lookalikes, is a routine early-interview screening question.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Ye ek "rapid-fire" style topic hai — interviewer aksar 3-4 exceptions ek ke baad ek poochta hai, expect karta hai ki tum turant bata do "ye kab throw hota hai." Depth kam chahiye, **precision** zyada chahiye — exact trigger condition, aur similar-lagne-wale exceptions ke beech fark.

### `NullReferenceException` (NRE)

Sabse common runtime exception. Tab aata hai jab ek `null` reference (koi bhi reference type — `string`, `class` object) ko dereference kiya jaaye — uski property/method access ki jaaye jaise wo valid object ho.

```csharp
string name = null;
Console.WriteLine(name.Length); // NullReferenceException
```

### `InvalidCastException`

Ek direct cast fail hota hai jab source object actually target type nahi hai.

```csharp
object obj = "hello";
int number = (int)obj; // InvalidCastException — string ko int me cast nahi kar sakte directly
```

Ye `as` operator se alag hai — `as` fail hone par `null` return karta hai (reference types ke liye), throw nahi karta. Direct cast (`(int)obj`) throw karta hai.

### `IndexOutOfRangeException`

Array (ya string index) ko uski valid range se bahar access karna.

```csharp
int[] arr = { 1, 2, 3 };
Console.WriteLine(arr[5]); // IndexOutOfRangeException — valid indices sirf 0,1,2
```

Note: `List<T>` bhi similar situation me `ArgumentOutOfRangeException` throw karta hai (`IndexOutOfRangeException` nahi) — ye ek subtle difference hai jo confuse karta hai, kyunki `List<T>` internally array use karta hai lekin apna wrapper exception deta hai.

### `DivideByZeroException`

Integer division by zero par throw hota hai — lekin **sirf integer types ke liye**.

```csharp
int a = 10, b = 0;
Console.WriteLine(a / b); // DivideByZeroException

double x = 10.0, y = 0.0;
Console.WriteLine(x / y); // NO exception — result is Infinity (double follows IEEE 754)
```

Ye interview ka classic trap hai: `double`/`float` division by zero exception nahi deta, `Infinity`/`NaN` deta hai (IEEE 754 floating-point standard follow karta hai). Sirf integer (`int`, `long`, waghera) division exception throw karta hai.

### `InvalidOperationException`

Ek generic "object apni current state me ye operation support nahi karta" exception. Bahut broad use case — jaise ek empty `Enumerable.First()` call, ya ek already-disposed object pe operation, ya `Dictionary` ko enumerate karte hue usme modify karna.

```csharp
var list = new List<int>();
var first = list.First(); // InvalidOperationException — "Sequence contains no elements"
```

### `ArgumentNullException`

Ek method parameter jo `null` nahi hona chahiye tha, `null` aaya.

```csharp
void Process(string input)
{
    if (input is null)
        throw new ArgumentNullException(nameof(input));
    // ...
}
```

`ArgumentNullException` `ArgumentException` se derive hoti hai — dono me `nameof(parameter)` pass karna convention hai taaki exception message me exact parameter name ho, hardcoded string se refactor-safe rahe.

### `FormatException`

Ek string ko expected format me parse karne ki koshish fail ho jaaye.

```csharp
int number = int.Parse("abc"); // FormatException — "abc" is not a valid integer
```

`int.TryParse` isi problem ka exception-free alternative hai — `bool` return karta hai, `out` parameter me value deta hai, `FormatException` throw nahi karta. Jahan parse failure ek **expected**, common case ho (jaise user input validate karna), `TryParse` prefer karo — exceptions ko control flow ke liye use karna anti-pattern hai.

### Quick lookup table

| Exception | Trigger |
|---|---|
| `NullReferenceException` | `null` reference ko dereference karna |
| `InvalidCastException` | Direct cast fail (`(T)obj`) |
| `IndexOutOfRangeException` | Array index range se bahar |
| `ArgumentOutOfRangeException` | `List<T>`/collection index range se bahar |
| `DivideByZeroException` | Integer division by zero (double/float nahi) |
| `InvalidOperationException` | Object apni current state me operation support nahi karta |
| `ArgumentNullException` | Required parameter `null` aaya |
| `FormatException` | String parse fail (e.g. `int.Parse` invalid input pe) |

</Hinglish>

## Real World Example

<RealWorld company="Microsoft">

.NET BCL design guidelines specifically distinguish `IndexOutOfRangeException` (array-specific, framework-internal, generally not meant to be caught/thrown by app code) se `ArgumentOutOfRangeException` (public API-facing, jab tumhara khud ka method ek invalid index parameter reject karta hai) — ye distinction library authors ke liye explicitly documented hai taaki consistent exception types across the BCL mile.

</RealWorld>

<RealWorld company="An Indian E-commerce Checkout API">

Ek checkout API me `int.Parse(request.PincodeString)` directly use ho raha tha bina validation ke. Jab kisi user ne pincode field khaali ya alphanumeric bhej diya, `FormatException` production me unhandled crash kar gaya, poora request 500 fail hua. Fix: `int.TryParse` use karke graceful `400 Bad Request` return karna, exception ko sirf genuinely unexpected cases ke liye reserve karna.

</RealWorld>

## Numbers That Matter

<Numbers>

- `NullReferenceException` decades se .NET codebases ki sabse commonly-reported runtime exception rahi hai
- Integer division by zero → `DivideByZeroException`; floating-point (`double`/`float`) division by zero → `Infinity`/`NaN`, NO exception (IEEE 754)
- Array out-of-range → `IndexOutOfRangeException`; `List<T>`/collection out-of-range → `ArgumentOutOfRangeException` (different type despite similar cause)
- `ArgumentNullException` derives from `ArgumentException`, which derives from `SystemException`
- `int.TryParse`/`int.Parse` — same underlying parse logic, but `TryParse` never throws `FormatException`, returns `bool` instead

</Numbers>

## Interview Angle

<InterviewAngle>

"Kuch common built-in exceptions bata sakte ho, aur unke exact triggers?" ka strong answer: ek crisp list dena hai exact trigger condition ke saath, bina padhe-likhe jaisa sunne diye — "`NullReferenceException` jab null reference dereference ho, `InvalidCastException` jab direct cast fail ho, `IndexOutOfRangeException` array ke bounds ke bahar access pe, `DivideByZeroException` sirf integer division by zero pe — double division by zero exception nahi deta, `Infinity` deta hai, jo ek common trap hai. `InvalidOperationException` ek broader 'object apni state me ye operation support nahi karta' case ke liye hai, jaise empty sequence pe `.First()`." Almost certain follow-up: "`ArgumentOutOfRangeException` aur `IndexOutOfRangeException` me kya fark hai?" — answer: dono conceptually similar hain (out-of-range access), lekin `IndexOutOfRangeException` array-specific/CLR-thrown hai, `ArgumentOutOfRangeException` collections/APIs apne parameter validation ke liye use karte hain — `List<T>` indexer isi wajah se `ArgumentOutOfRangeException` deta hai, `IndexOutOfRangeException` nahi.

</InterviewAngle>

## Common Mistakes

<Mistake>

Ye maan lena ki `double`/`float` division by zero bhi `DivideByZeroException` deta hai — nahi deta, `Infinity`/`NaN` deta hai. Sirf integer types exception throw karte hain.

</Mistake>

<Mistake>

`IndexOutOfRangeException` aur `ArgumentOutOfRangeException` ko same samajhna — array direct access `IndexOutOfRangeException` deta hai, `List<T>` ka indexer `ArgumentOutOfRangeException` deta hai, alag types hain.

</Mistake>

<Mistake>

User input parse karne ke liye `int.Parse` use karna jab failure genuinely expected ho (form input, external data) — `int.TryParse` use karo jahan invalid input ek normal, expected case hai.

</Mistake>

<Mistake>

`ArgumentNullException` throw karte waqt hardcoded string parameter name dena instead of `nameof(parameter)` — refactor karne par naam mismatch ho jaata hai, `nameof` compile-time safe hai.

</Mistake>

<Mistake>

`InvalidCastException` aur `as` operator ke failure behavior ko confuse karna — direct cast throw karta hai, `as` `null` return karta hai (reference types ke liye), koi exception nahi.

</Mistake>

## Quick Revision

<QuickRevision>

- `NullReferenceException` — dereferencing a null reference
- `InvalidCastException` — a direct cast (`(T)obj`) fails
- `IndexOutOfRangeException` — array index out of bounds
- `ArgumentOutOfRangeException` — collection (e.g. `List<T>`) index out of bounds — a different type from the array case
- `DivideByZeroException` — integer division by zero ONLY; `double`/`float` give `Infinity`/`NaN`, no exception
- `InvalidOperationException` — object's current state doesn't support the requested operation (e.g. `.First()` on empty sequence)
- `ArgumentNullException` — a required parameter came in null; use `nameof(parameter)` in the constructor call
- `FormatException` — string parse failure; prefer `TryParse` over `Parse` when invalid input is an expected case

</QuickRevision>
