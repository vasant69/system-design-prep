<SimpleDefinition>

`List<T>` is a dynamic, growable array with `O(1)` amortized append and `O(n)` search/insert-in-middle; `Dictionary<TKey,TValue>` is a hash-table-backed key-value store with `O(1)` average lookup by key; `HashSet<T>` is a hash-table-backed collection guaranteeing uniqueness with `O(1)` average `Contains` — these three are the most-reached-for collections in everyday C# code.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Roz-marra ke C# code me sabse zyada teen collections use hote hain — `List<T>`, `Dictionary<TKey,TValue>`, `HashSet<T>`. Interview me inka internal mechanism poocha jaata hai, sirf "kya karte hain" nahi — "kaise itni fast hain" bhi.

### `List<T>` — dynamic array

Array ki tarah hi hai, lekin resize khud-ba-khud ho jaata hai. Internally ek plain array (`T[]`) wrap karta hai — jab wo array full ho jaata hai aur naya element add hota hai, `List<T>` internally ek NAYA, bada array allocate karta hai (typically double size) aur purane elements copy kar deta hai.

```csharp
List<int> numbers = new List<int>();
numbers.Add(1);   // internal array grows as needed
numbers.Add(2);
numbers.Insert(0, 0);  // O(n) — sab elements ek position shift karne padte hain
numbers.RemoveAt(1);   // O(n) — same reason

int x = numbers[0];    // O(1) — direct index, jaise array
bool has = numbers.Contains(5); // O(n) — linear scan, no shortcuts
```

**`Add` amortized O(1)** kyun kehte hain: zyaadatar `Add` calls me jagah already hoti hai (`O(1)`), lekin kabhi-kabhar jab array full ho jaata hai, ek `O(n)` resize-and-copy hota hai. Averaged out over many operations, ye still `O(1)` per-add kehlata hai — "amortized" ka yahi matlab hai.

### `Dictionary<TKey,TValue>` — hashing-based key-value store

Key ko ek **hash function** se ek bucket-index me convert karta hai, aur us bucket me value store karta hai. Lookup karte waqt same hash function se seedha sahi bucket pe pahunch jaata hai — koi linear scan nahi.

```csharp
var ages = new Dictionary<string, int>();
ages["Alice"] = 30;
ages["Bob"] = 25;

int aliceAge = ages["Alice"];       // O(1) average — hash se direct bucket
bool exists = ages.ContainsKey("Bob"); // O(1) average

if (ages.TryGetValue("Charlie", out int age))
{
    Console.WriteLine(age);
}
else
{
    Console.WriteLine("Not found — no exception thrown");  // TryGetValue safe hai
}
```

`ages["Charlie"]` (indexer, `TryGetValue` nahi) agar key exist nahi karti to `KeyNotFoundException` throw karega — `TryGetValue` safer hai jab key ka exist karna guaranteed nahi ho.

**O(1) "average" kyun, "worst case" nahi:** agar bahut saari keys same bucket me collide kar jaayein (bad hash function, ya adversarial input), worst case `O(n)` tak degrade ho sakta hai. `GetHashCode()`/`Equals()` ka sahi implementation is risk ko minimize karta hai.

### `HashSet<T>` — uniqueness, fast membership check

`Dictionary` jaisa hi internal mechanism (hashing), lekin sirf keys store karta hai, koi value nahi — pure "is this item present?" ke liye.

```csharp
var seen = new HashSet<string>();
seen.Add("apple");
seen.Add("banana");
seen.Add("apple");  // Duplicate — silently ignored, Add returns false

Console.WriteLine(seen.Count);           // 2, not 3
Console.WriteLine(seen.Contains("apple")); // O(1) average — true
```

Real use case: duplicates hataana ek list se, ya fast "already processed?" checks (jaise ek visited-nodes set graph traversal me).

### Teeno ka comparison — jab kab use karein

- **`List<T>`** — ordered sequence chahiye, index se access karna hai, ya duplicates allowed hain. Search/insert-in-middle slow (`O(n)`).
- **`Dictionary<TKey,TValue>`** — key se fast lookup chahiye, ek value associate karni hai har key ke saath.
- **`HashSet<T>`** — sirf uniqueness/membership chahiye, koi associated value nahi, ordering matter nahi karti.

Ek common mistake: `List<T>.Contains()` ko `HashSet<T>.Contains()` jaisa fast samajh lena — List ka `Contains` `O(n)` hai (linear scan), HashSet ka `O(1)` average hai (hash lookup). Bade datasets me repeated membership checks ke liye ye difference bahut matter karta hai.

</Hinglish>

## Real World Example

<RealWorld company="Microsoft">

ASP.NET Core ke andar `Dictionary<string, StringValues>` route-values aur query-string parsing me heavily use hota hai — request processing ke path pe key-based lookup performance-critical hai, aur `Dictionary` ka O(1) average lookup exactly wahi guarantee deta hai jo per-request overhead ko minimal rakhta hai high-throughput servers me.

</RealWorld>

<RealWorld company="An Indian E-commerce Order System">

Ek order-processing service me duplicate order-IDs ko reject karna tha ek incoming batch me. Pehle `List<string>.Contains()` se check kiya jaata tha — chhoti batches me theek chala, lekin jaise batch size 50,000+ tak gaya, processing time linearly badh gaya (O(n) per check, O(n^2) overall). `HashSet<string>` me switch karne se — same logic, sirf collection type badla — processing time seconds se milliseconds tak aa gaya, kyunki har `Contains` ab O(1) average tha.

</RealWorld>

## Numbers That Matter

<Numbers>

- `List<T>.Add()` — amortized `O(1)`, occasional `O(n)` resize-and-copy
- `List<T>.Contains()`/`IndexOf()`/`Insert(middle)`/`Remove(middle)` — all `O(n)`
- `Dictionary<TKey,TValue>` — `O(1)` average for `Add`/`ContainsKey`/`TryGetValue`/indexer read
- `HashSet<T>` — `O(1)` average for `Add`/`Contains`/`Remove`
- `Dictionary`/`HashSet` worst case degrades to `O(n)` under heavy hash collisions
- Indexer access on a missing `Dictionary` key throws `KeyNotFoundException`; `TryGetValue` never throws

</Numbers>

## Common Mistakes

<Mistake>

`List<T>.Contains()` ko `Dictionary`/`HashSet` jitna fast samajhna — List ka Contains linear scan hai (`O(n)`), hashing-based collections O(1) average dete hain. Bade datasets me repeated lookups ke liye ye difference significant hai.

</Mistake>

<Mistake>

`Dictionary` indexer (`dict[key]`) use karna bina pehle key exist karne ka confirm kiye — missing key par `KeyNotFoundException` throw hoga. `TryGetValue` ya `ContainsKey` check safer hai.

</Mistake>

<Mistake>

`HashSet<T>` ya `Dictionary<TKey,TValue>` se koi specific ordering expect karna — technically insertion order internally kabhi-kabhi stable dikh sakti hai, lekin ye ek guaranteed contract nahi hai. Ordering guaranteed chahiye to `SortedDictionary`/`SortedSet` ya explicit sorting use karo.

</Mistake>

<Mistake>

`List<T>.Insert(0, item)` ko baar-baar loop me call karna — har `Insert` `O(n)` hai (sab existing elements shift karne padte hain). Agar frequent front-insertion chahiye, `LinkedList<T>` ya `Queue<T>` better fit ho sakta hai.

</Mistake>

<Mistake>

Custom class ko `Dictionary` ki key ya `HashSet` ka element banate waqt `GetHashCode()`/`Equals()` override na karna — default reference-equality-based hashing use hoga, jisse "same logical value" wale do objects alag treat honge, hashing collections me unexpected behavior degi.

</Mistake>

## Quick Revision

<QuickRevision>

- `List<T>` — dynamic array, `O(1)` amortized `Add`, `O(n)` search/insert-in-middle, allows duplicates, ordered
- `Dictionary<TKey,TValue>` — hash-table key-value store, `O(1)` average lookup by key
- `HashSet<T>` — hash-table uniqueness set, `O(1)` average `Contains`, no associated value
- `List<T>.Contains()` is `O(n)`; `HashSet<T>.Contains()` is `O(1)` average — never confuse the two for large data
- Missing `Dictionary` key via indexer throws `KeyNotFoundException`; use `TryGetValue` to avoid it
- Neither `Dictionary` nor `HashSet` guarantees ordering as a contract
- Override `GetHashCode()`/`Equals()` together on custom types used as Dictionary keys or HashSet elements

</QuickRevision>
