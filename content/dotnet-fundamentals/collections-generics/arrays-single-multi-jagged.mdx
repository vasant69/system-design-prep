<SimpleDefinition>

A C# array is a fixed-size, zero-indexed collection of a single type, allocated as one contiguous block on the heap; it comes in three shapes — single-dimensional (`int[]`), rectangular multi-dimensional (`int[,]`), and jagged (`int[][]`, an array of arrays) — each with different memory layout and different appropriate use cases.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Array C# ka sabse basic collection type hai, aur interview me isse zyada "obvious" lagne wale sawaal me hi log confuse ho jaate hain — especially jab multi-dimensional aur jagged arrays ka fark poocha jaaye. Chalo teeno shapes ko clearly samjhte hain.

### Single-dimensional array — sabse basic shape

Ek fixed-size, same-type elements ka linear collection. Size declare karte hi fix ho jaata hai — resize nahi ho sakta (agar zyada elements chahiye, naya array banana padta hai).

```csharp
int[] scores = new int[5];        // 5 ints, sab default 0
int[] marks = { 90, 85, 78, 92 }; // collection initializer, size auto-inferred = 4

scores[0] = 100;
Console.WriteLine(scores.Length); // 5 — Length property, not Count
```

Array heap pe ek **single contiguous memory block** ke roop me allocate hota hai — isi wajah se index-based access `O(1)` hai (address = base + index * element-size, direct calculation, koi traversal nahi).

### Multi-dimensional (rectangular) array — `int[,]`

Ek genuine grid — har row ka same number of columns hota hai, isliye "rectangular" naam hai. Memory me bhi ye ek hi contiguous block hota hai, jisme row-major order me elements store hote hain.

```csharp
int[,] grid = new int[3, 4]; // 3 rows, 4 columns — fixed rectangle
grid[0, 0] = 1;
grid[2, 3] = 99;

Console.WriteLine(grid.GetLength(0)); // 3 — rows
Console.WriteLine(grid.GetLength(1)); // 4 — columns

int[,] matrix = { { 1, 2 }, { 3, 4 }, { 5, 6 } }; // 3x2 rectangular initializer
```

Real use case: kisi cheez ka genuinely fixed grid shape ho — jaise ek chessboard (8x8), ek fixed-resolution image buffer, ya matrix math. Har row same length honi chahiye — agar rows ka length vary karna ho, rectangular array galat tool hai.

### Jagged array — `int[][]`, "array of arrays"

Jagged array ek array hai jiska har element khud ek alag, independently-sized array hai. Ye **contiguous single block nahi** hai — outer array me har slot ek reference hota hai apne alag heap-allocated inner array ki taraf.

```csharp
int[][] jagged = new int[3][]; // outer array of 3 array-references, sab abhi null
jagged[0] = new int[] { 1, 2, 3 };       // row 0: 3 elements
jagged[1] = new int[] { 4, 5 };          // row 1: 2 elements — different length, valid!
jagged[2] = new int[] { 6, 7, 8, 9 };    // row 2: 4 elements

Console.WriteLine(jagged[1].Length); // 2
Console.WriteLine(jagged[1][0]);     // 4 — double index, but each [] is a separate array access
```

Real use case: variable-length rows — jaise ek employee-department mapping jahan har department me alag number of employees hain, ya triangular data structures (Pascal's triangle jaisa kuch), ya ek adjacency list for a graph (har node ke alag number of neighbours).

### Kab kaun sa shape use karein — decision

- **Single-dimensional** — default choice, linear data, fixed count.
- **Rectangular (`int[,]`)** — genuinely fixed grid, har row same length, matrix-style access, thoda better cache locality (ek hi contiguous block) aur slightly less memory overhead (no extra array-of-references indirection).
- **Jagged (`int[][]`)** — variable-length rows, ya jab rows independently allocate/replace karne hon. Thoda zyada memory overhead (har inner array apna khud ka object hai, apna `Length`, apna heap header) lekin flexibility zyada.

Performance angle: jagged arrays technically thodi si extra indirection lagate hain (pehle outer array se reference nikaalna, phir inner array me index) — rectangular arrays single calculation se access hote hain. Practically ye difference tab hi matter karta hai jab tight numeric loops me millions of accesses ho rahe hon; typical business-app code me ignorable hai.

</Hinglish>

## Real World Example

<RealWorld company="Microsoft">

.NET ke `System.Array` class rectangular aur jagged dono ko support karta hai, lekin BCL (Base Class Library) ke andar khud performance-critical code (jaise image-processing ya numeric libraries) mostly single-dimensional arrays ya jagged arrays use karta hai rectangular arrays ke bajaye — kyunki `int[,]` ka JIT-level optimization historically `int[]`/`int[][]` jitna tight nahi raha; `for` loops over `int[]` aksar fastest measured hote hain.

</RealWorld>

<RealWorld company="An Indian EdTech Attendance System">

Ek college attendance system me, "kaun se students kis class me present the" ko model karne ke liye team ne pehle `bool[,]` (students x classes rectangular grid) try kiya — lekin har class ka student count alag tha (electives me kam students). Isse switch karke `bool[][]` (jagged — har class ka apna present-students array) use kiya gaya, jisse memory waste (empty/unused grid cells) khatam ho gaya aur code bhi natural map ho gaya real-world data shape se.

</RealWorld>

## Numbers That Matter

<Numbers>

- Array access: `O(1)` — direct address calculation, index-based
- Array resize: not possible — fixed size at creation; `Array.Resize()` actually allocates a NEW array and copies elements, `O(n)`
- Rectangular array (`int[,]`): one contiguous memory block, one heap allocation
- Jagged array (`int[][]`): `n + 1` heap allocations for `n` rows (outer array + each inner array separately)
- `arr.Length` on a jagged outer array gives row count; `arr[i].Length` gives that specific row's length
- Default values on array creation: `0` for numeric types, `false` for bool, `null` for reference types — same rules as `default(T)`

</Numbers>

## Interview Angle

<InterviewAngle>

"Rectangular aur jagged array me kya fark hai?" ka strong answer: "Rectangular array (`int[,]`) ek single contiguous memory block hai jisme har row ka length same hota hai — genuinely fixed-grid data ke liye best fit, jaise matrix ya chessboard. Jagged array (`int[][]`) 'array of arrays' hai — outer array sirf references store karta hai, har inner array independently-sized aur independently-allocated hota hai, isliye variable-length rows ke liye better fit hai, jaise ek graph ki adjacency list jahan har node ke alag number of neighbours hote hain." Follow-up jo aksar aata hai: "kaunsa faster hai?" — answer: rectangular thoda faster access deta hai (single calculation, no extra indirection) lekin practical business code me ye difference rarely noticeable hota hai; choice mostly data-shape-driven honi chahiye, performance-driven nahi.

</InterviewAngle>

## Common Mistakes

<Mistake>

`int[,]` aur `int[][]` ko same syntax/concept samajhna — dono ka declaration, initialization, aur memory layout genuinely alag hai. `new int[3,4]` ek single 2D array banata hai; `new int[3][]` ek outer array banata hai jiske andar abhi sab `null` hai, har row alag se assign karni padti hai.

</Mistake>

<Mistake>

Jagged array banake har inner row ko explicitly initialize karna bhool jaana — `int[][] jagged = new int[3][];` ke baad `jagged[0]` abhi `null` hai, agar directly `jagged[0][0] = 1;` try karo bina `jagged[0] = new int[...]` kiye, `NullReferenceException` aayega.

</Mistake>

<Mistake>

`array.Length` ko `Count` samajhna — arrays me `Length` property hai, `Count` nahi (jo `List<T>` jaisi collections me hota hai). `.Count` array pe compile error dega (`IEnumerable` extension method `Count()` ke through kaam kar sakta hai, lekin wo LINQ hai, property nahi).

</Mistake>

<Mistake>

Ek fixed-size array ko baar-baar "resize" karne ki koshish karna loop me — `Array.Resize()` internally poora naya array allocate karke copy karta hai, `O(n)` har baar. Agar dynamic growth chahiye, `List<T>` sahi tool hai, array nahi.

</Mistake>

<Mistake>

Rectangular array ko force karna jab data genuinely uneven ho (jaise "employees per department" jahan department sizes vary karte hain) — isse bahut saari unused/wasted grid cells ban jaati hain. Aise cases me jagged array natural aur memory-efficient fit hai.

</Mistake>

## Quick Revision

<QuickRevision>

- Arrays are fixed-size, zero-indexed, single-type, contiguous-heap-allocated — `O(1)` access
- `int[]` — single-dimensional, the default choice
- `int[,]` — rectangular multi-dimensional, all rows same length, one contiguous block, genuinely fixed grids
- `int[][]` — jagged, array of arrays, independently-sized rows, extra indirection but flexible
- `arr.Length` for arrays (not `.Count`); `arr.GetLength(0)`/`GetLength(1)` for rectangular array dimensions
- Jagged rows must be individually initialized (`new int[]`) before use — default is `null`, not an empty array
- `Array.Resize()` allocates a whole new array under the hood — it is not a true in-place resize
- Choose rectangular for uniform grids, jagged for irregular/variable-length row data

</QuickRevision>
