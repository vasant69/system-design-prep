<SimpleDefinition>

C# provides standard arithmetic, logical, and bitwise operators, plus a small family of null-handling operators — the null-conditional operator (`?.` and `?[]`) that short-circuits to `null` instead of throwing when the left side is `null`, and the null-coalescing operators (`??` and `??=`) that supply a fallback value or assign one only when the target is currently `null`.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Operators to sabko pata hote hain — `+`, `-`, `&&`, `||`, `&`, `|` — inme kuch naya nahi hai. Interview me asli test hota hai null-handling operators pe: `?.`, `?[]`, `??`, `??=`. Ye four operators mil kar nested null-check `if` chains ko drastically chhota kar dete hain, aur inka exact behavior (kab short-circuit hota hai, kya return hota hai) precisely samajhna zaroori hai.

### Quick recap — arithmetic, logical, bitwise

`+ - * / %` arithmetic; `== != < > <= >=` comparison; `&& ||` logical (short-circuit — `&&` ka right side tabhi evaluate hota hai jab left `true` ho); `& | ^ ~ << >>` bitwise (integer types pe bit-level operations, ya non-short-circuiting boolean AND/OR). Interview me `&&` vs `&` ka difference kabhi kabhi poocha jaata hai — `&&` short-circuits, `&` dono sides hamesha evaluate karta hai (yahi wajah hai `&` ko rarely boolean logic ke liye use karte hain, sirf bitwise ke liye).

### `?.` — Null-Conditional Operator (C# 6)

Ek member access ya method call ko safe banata hai jab left-side `null` ho sakta hai:

```csharp
Customer? customer = GetCustomer();

// Purana style — verbose nested checks
string city;
if (customer != null && customer.Address != null)
{
    city = customer.Address.City;
}
else
{
    city = null;
}

// Modern — ek line
string? city2 = customer?.Address?.City;
```

Agar `customer` `null` hai, poori chain `customer?.Address?.City` turant `null` return karti hai — `Address` ko access karne ki koshish bhi nahi hoti. Ye **short-circuit evaluation** hai, `&&` ki tarah — pehla `null` milte hi baaki chain skip ho jaati hai, koi `NullReferenceException` nahi aata.

`?[]` wahi cheez indexers ke liye karta hai:

```csharp
int[]? numbers = GetNumbers();
int? first = numbers?[0]; // numbers null hai to null, warna numbers[0]
```

**Method calls ke saath bhi chalta hai:**

```csharp
customer?.SendWelcomeEmail(); // customer null hai to call hi nahi hota, silently skip
```

Ye ek genuinely useful pattern hai — agar `customer` `null` hai, `SendWelcomeEmail()` call hi nahi hoga, koi exception nahi aayega, code bas aage badh jaayega.

### `??` — Null-Coalescing Operator

"Agar left side null hai, right side use karo" — ek fallback value dene ka sabse concise tarika:

```csharp
string displayName = customer?.Name ?? "Guest";
int count = GetCount() ?? 0;
```

Chain bhi kar sakte ho:

```csharp
string result = primary ?? secondary ?? "default";
// primary null nahi to primary; primary null but secondary nahi to secondary; dono null to "default"
```

### `??=` — Null-Coalescing Assignment (C# 8)

"Agar variable currently `null` hai, tabhi assign karo" — ek common **lazy-initialization** pattern ko ek line me:

```csharp
// Purana style
if (cache == null)
{
    cache = new Dictionary<string, object>();
}

// Modern
cache ??= new Dictionary<string, object>();
```

`??=` ka right side sirf tabhi evaluate hota hai jab left side `null` ho — agar `cache` already non-null hai, `new Dictionary<...>()` call hi nahi hota (koi wasted allocation nahi). Ye behavior interview me trap ki tarah poocha jaata hai — kuch candidates sochte hain right side hamesha evaluate hoti hai, jo galat hai.

### Chaining sabko saath

Real code me ye chaaron combine hote hain:

```csharp
public string GetCityOrDefault(Customer? customer)
{
    return customer?.Address?.City ?? "Unknown City";
}
```

Ek line me: null-safe navigation (`?.`) + fallback (`??`). Ye pattern har layered/DTO-heavy codebase me baar baar dikhta hai — interview me isko likh kar dikhana ek strong signal hai ki candidate modern C# idioms se comfortable hai, purane verbose null-check style se nahi chipka hua.

</Hinglish>

## Real World Example

<RealWorld company="Microsoft">

ASP.NET Core ke apne source me `?.`/`??` heavily use hote hain configuration aur options binding code me — jaise `options?.Value ?? defaultValue` pattern jab ek optional configuration section missing ho sakta hai. Ye .NET team ki khud ki coding guidelines ka hissa hai jab kabhi bhi ek reference genuinely optional ho.

</RealWorld>

<RealWorld company="An Indian E-commerce Backend">

Ek typical order-processing API me, `order?.ShippingAddress?.Pincode ?? "000000"` jaisa pattern common hai jab shipping address optional ho sakta hai (e.g. digital-only orders). Bina in operators ke, ye 3-4 line ka nested null-check ban jaata, jo har jagah repeat hota — `?.`/`??` isse ek predictable, reviewable one-liner bana dete hain.

</RealWorld>

## Interview Angle

<InterviewAngle>

"`??` aur `??=` me kya fark hai?" ka strong answer: "`??` ek expression operator hai — `a ?? b` evaluate hoke ek value return karta hai, `a` ya `b` chahe jo bhi non-null ho. `??=` ek assignment operator hai — `a ??= b` sirf tabhi `b` ko `a` me assign karta hai jab `a` currently `null` ho; agar `a` already non-null hai, `b` evaluate hi nahi hota, `a` unchanged rehta hai. Common use case `??=` ka lazy initialization hai — jaise `cache ??= new Dictionary<...>()`, jahan hum expensive allocation sirf first-time chahte hain." Follow-up jo aksar aata hai: "`?.` short-circuit kaise karta hai chain me?" — answer: pehla `null` milte hi poori remaining chain skip ho jaati hai, koi further member access attempt nahi hota.

</InterviewAngle>

## Common Mistakes

<Mistake>

`?.` ko method call ke return value pe rely karke bina check kiye aage use karna — `customer?.GetOrders()` agar `customer` null hai to poora expression `null` return karta hai, `List<Order>` nahi — ise aage `.Count` jaisa access karne se pehle phir se `?.` ya `??` lagana zaroori hai.

</Mistake>

<Mistake>

`??=` ke right side me ek side-effect wali expression daalna aur assume karna ki wo hamesha run hogi — jaise `count ??= LogAndReturnDefault()`. Agar `count` already non-null hai, `LogAndReturnDefault()` kabhi call hi nahi hoga, jo silent logic bug ban sakta hai agar logging side-effect expected thi.

</Mistake>

<Mistake>

`&` aur `&&` (ya `|` aur `||`) ko interchangeable samajhna — `&`/`|` short-circuit nahi karte, dono operands hamesha evaluate hote hain, jo performance aur (agar right side me null-check hai) correctness dono ko affect kar sakta hai.

</Mistake>

<Mistake>

Bahut deep `?.` chains (4+ levels) likhna jab actually ek genuine null case ek explicit exception deserve karta ho — over-using null-conditional operators silently har failure ko "just return null/default" bana deta hai, jo debugging mushkil kar sakta hai.

</Mistake>

## Quick Revision

<QuickRevision>

- `?.`/`?[]` (C# 6) — null-safe member/index access, short-circuits chain to `null` on first null
- `??` (C# 2) — fallback value expression: `a ?? b`
- `??=` (C# 8) — assign only if currently null, right side lazily evaluated
- `&&`/`||` short-circuit; `&`/`|` always evaluate both sides
- Classic combo: `x?.Y?.Z ?? default` replaces multi-line nested null-check `if` blocks
- Don't overuse `?.` where a genuine null deserves a loud exception instead of a silent default

</QuickRevision>
