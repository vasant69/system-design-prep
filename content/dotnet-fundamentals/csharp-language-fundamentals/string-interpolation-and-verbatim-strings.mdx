<SimpleDefinition>

String interpolation (`$"Hello {name}"`) embeds expressions directly inside a string literal for readability, verbatim strings (`@"C:\path"`) disable escape-sequence processing so backslashes are literal, and raw string literals (C# 11, triple-quote) handle strings containing quotes or mixed content without escaping gymnastics.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

String banane ke teen tareeke — concatenation, interpolation, verbatim/raw — har ek apni jagah sahi hai, aur inka evolution readability + real edge-cases handle karne ke around hai.

### String Interpolation (C# 6.0) — `$"..."`

```csharp
string name = "Amit";
int age = 30;

// Purana style — concatenation
string message1 = "Name: " + name + ", Age: " + age;

// Interpolation — modern
string message2 = $"Name: {name}, Age: {age}";
```

`{expression}` ke andar koi bhi valid C# expression ja sakta hai — sirf variables nahi, method calls, property access, arithmetic bhi:

```csharp
string summary = $"{items.Count} items, total: {items.Sum(i => i.Price):C}";
```

`:C` yahan ek **format specifier** hai — currency format apply karta hai. Format specifiers (`:C` currency, `:N2` 2-decimal number, `:yyyy-MM-dd` date format) interpolation ke andar directly use ho sakte hain, jo `ToString(format)` calls ko avoid karta hai.

**Perf note:** Interpolation compile-time pe `string.Format()` (ya kuch simple cases me `string.Concat()`) me translate hota hai — koi magic runtime overhead nahi hai, ye readability ke liye syntactic sugar hai jo purane `string.Format("Name: {0}, Age: {1}", name, age)` ka hi cleaner version hai.

### Verbatim Strings — `@"..."`

```csharp
string path1 = "C:\\Users\\Amit\\Documents"; // regular string — backslash escape karna padta hai
string path2 = @"C:\Users\Amit\Documents";   // verbatim — backslash literal hai, no escaping

string multiline = @"Line 1
Line 2
Line 3"; // verbatim strings multi-line bhi ho sakte hain, literally
```

`@` prefix escape-sequence processing ko disable karta hai — `\n`, `\t`, `\\` sab literal characters ban jaate hain, koi special meaning nahi. Ye Windows file paths (jahan `\` common hai) aur regex patterns (jahan `\` bahut use hota hai) ke liye especially useful hai — bina `@`, har `\` ko `\\` likhna padta, jo readability kharab karta hai.

**Verbatim string me ek literal double-quote chahiye ho to `""` (double double-quote) use karo:**

```csharp
string quoted = @"She said ""Hello"" to me.";
```

### Verbatim + Interpolation combined — `$@"..."` ya `@$"..."`

```csharp
string path = $@"C:\Users\{userName}\Documents";
```

Dono prefix combine ho sakte hain (order matter nahi karta, C# 8+ dono order allow karta hai) — verbatim ka no-escaping behavior AUR interpolation ka `{expression}` embedding, ek saath.

### Raw String Literals (C# 11.0) — triple-quote `"""..."""`

```csharp
string json = """
{
  "name": "Amit",
  "path": "C:\Users\Amit"
}
""";
```

Raw strings triple (ya usse zyada) quotes se start/end hote hain — inke andar **na escape sequences process hote hain, na double-quotes ko escape karna padta hai** (jab tak literal content khud triple-quote na ho). Ye JSON, regex, ya kisi bhi content ke liye ideal hai jisme quotes aur backslashes dono mixed ho — verbatim strings me bhi double-quotes ko `""` karna padta tha, raw strings me wo bhi nahi karna padta.

</Hinglish>

<Callout type="tip">

Quick decision guide: readability ke liye variables embed karne hain — interpolation (`$""`). Windows paths ya regex jinme bahut saare backslashes hain — verbatim (`@""`). JSON/XML/multi-quote-heavy content — raw string literals (`"""..."""`, C# 11+). Sab combine ho sakte hain zarurat ke hisaab se.

</Callout>

## Real World Example

<RealWorld company="Microsoft">

.NET SDK ke apne tooling code (jaise `dotnet` CLI ke internal templates) me raw string literals (C# 11) heavily use hote hain jab embedded JSON/YAML config templates likhne hote hain — pehle in cases me verbatim strings ke saath bahut saara `""` escaping karna padta tha, raw strings ne is friction ko poori tarah eliminate kar diya.

</RealWorld>

<RealWorld company="An Indian Logistics File-Processing Service">

Ek batch file-import service me Windows network paths (`\\server\share\imports\`) verbatim strings me likhe jaate hain — `@"\\server\share\imports\"` — bina isse `\\\\server\\share\\imports\\\\` jaisa unreadable escape-heavy string banaye. Interpolation ke saath combine kar ke `$@"\\server\share\imports\{batchId}\"` jaisa dynamic path bhi clean rehta hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- String interpolation (`$""`) — C# 6.0 (2015)
- Verbatim strings (`@""`) — C# 1.0 se hi maujood
- Raw string literals (`"""..."""`) — C# 11.0 (2022)
- Interpolation compile-time pe `string.Format()`/`string.Concat()` me translate hoti hai — no runtime magic
- Combined prefix (`$@""` ya `@$""`) — dono order C# 8.0+ me valid syntax hain

</Numbers>

## Interview Angle

<InterviewAngle>

"String interpolation aur `string.Format()` me kya fark hai?" ka strong answer: "Functionally almost same hain — interpolation (`$\"Name: {name}\"`) compile-time pe `string.Format()`-jaisi call me hi translate hoti hai, koi runtime performance difference nahi hai. Interpolation ka fayda purely readability hai — placeholder aur actual value ek saath dikhte hain, `string.Format(\"Name: {0}\", name)` ki tarah alag-alag index-tracking nahi karni padti. Format specifiers (jaise `{price:C}`) dono me equally kaam karte hain." Follow-up: "verbatim string kab use karoge, raw string literal kab?" — verbatim jab sirf backslash-heavy content ho (paths, simple regex); raw string literal jab content me quotes bhi heavily mixed hon (JSON, multi-line structured text) — raw strings verbatim se superset capability deti hain.

</InterviewAngle>

## Common Mistakes

<Mistake>

Windows file paths me `@` prefix bhoolna aur backslashes ko manually double-escape karna (`"C:\\Users\\..."`) — ye readable-hone-ke-bajaye error-prone ban jaata hai, especially deeply nested paths me.

</Mistake>

<Mistake>

Verbatim string me literal double-quote ke liye `\"` use karne ki koshish karna — verbatim strings me escape sequences process hi nahi hote, isliye `\"` literally do characters (`\` aur `"`) ban jaate hain, poora string malformed ho jaata hai. Sahi tareeka `""` (double double-quote) hai.

</Mistake>

<Mistake>

Interpolation ke andar `{` ya `}` ko literal character ki tarah use karna bina double kiye — `$"{{literal braces}}"` chahiye agar literal `{`/`}` chahiye, single `{`/`}` ek expression start/end signal karta hai aur agar andar valid expression na ho to runtime error deta hai.

</Mistake>

<Mistake>

Har jagah raw string literals (C# 11) use karna chahe project ka target framework purana ho — raw strings sirf tab compile honge jab project C# 11+ language version target kar raha ho (typically .NET 7+ SDK ke saath), purane .NET Framework/.NET Core projects me syntax error dega.

</Mistake>

## Quick Revision

<QuickRevision>

- `$"..."` (C# 6) — embeds expressions directly, compiles to `string.Format()`-equivalent, no runtime cost beyond that
- `@"..."` (C# 1) — disables escape processing, backslashes literal, can span multiple lines, `""` for a literal quote
- `$@"..."`/`@$"..."` — combines both, C# 8+ allows either prefix order
- `"""..."""` raw string literals (C# 11) — no escaping needed for quotes or backslashes, ideal for JSON/regex/multi-line content
- Format specifiers (`{value:C}`, `{date:yyyy-MM-dd}`) work inside interpolation directly
- Windows paths and regex patterns are the classic verbatim/raw-string use cases

</QuickRevision>
