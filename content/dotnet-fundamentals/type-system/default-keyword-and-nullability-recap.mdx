<SimpleDefinition>

`default(T)` (or the inferred `default` literal) produces a type's default value — zero for numeric types, `false` for `bool`, `null` for reference types and nullable value types, and an all-fields-zeroed instance for a struct — and is especially useful in generic code where `T`'s actual type isn't known at the call site.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

### default value ka matlab type-category ke hisaab se alag hai

Har C# type ka ek well-defined "default value" hota hai — ye wahi value hai jo tumhe milti hai jab koi variable explicitly initialize nahi kiya jaata (jaise class ka field, ya array element):

```csharp
Console.WriteLine(default(int));     // 0
Console.WriteLine(default(bool));    // False
Console.WriteLine(default(double));  // 0
Console.WriteLine(default(char));    // '\0' (null character)
Console.WriteLine(default(string));  // null (string reference type hai)
Console.WriteLine(default(object));  // null
```

Rule simple hai: **numeric types ke liye zero, `bool` ke liye `false`, reference types ke liye `null`.**

### Struct ka default — sab fields zero/default

Ek struct ka default value ek instance hai jiske **saare fields apni-apni default value pe set hote hain**, recursively:

```csharp
struct Point { public int X, Y; }
Point p = default(Point);
Console.WriteLine($"{p.X}, {p.Y}"); // 0, 0 — dono fields int hain, unki default 0 hai
```

Agar struct ke andar koi reference-type field hai, wo field `null` hoga default instance me, chahe struct khud value type ho.

### default literal (C# 7.1+) — type inference ke saath shorthand

C# 7.1 se `default(T)` ki jagah sirf `default` likha ja sakta hai jab compiler context se type infer kar sake — verbosity kam karta hai:

```csharp
int x = default;        // compiler infers int, same as default(int)
Point p = default;      // compiler infers Point
void Method(int y = default) { } // default parameter value
```

### Generic code me sabse common use-case

`default(T)` (ya `default`) genuinely zaroori hota hai generic methods/classes me, jahan actual type `T` compile-time pe pata nahi hota us specific method likhte waqt — tumhe phir bhi "empty"/reset value chahiye ho sakta hai:

```csharp
T GetValueOrFallback<T>(T? value, T fallback = default!) // generic constraint ke bina, T? yahan illustrative
{
    return value is null ? fallback : value;
}

// Ek aur common pattern:
public T GetDefault<T>() => default(T);
// T = int ho to 0 milega, T = string ho to null, T = SomeStruct ho to zeroed struct
```

Bina `default(T)` ke, generic code me "type ka empty/reset value do" likhna possible hi nahi hota, kyunki compiler ko `T` ke liye specific literal (`0`, `null`, etc.) pata nahi hota — `default(T)` compiler ko batata hai "jo bhi `T` ho, uski default value do."

### Nullable types ka quick recap — is topic ka connecting point

`default(int?)` = `null` — kyunki `int?` (`Nullable<int>`) khud ek struct hai jiska default state `HasValue = false` hai, jo effectively `null` represent karta hai. Ye poore module ke shuru me cover kiye gaye nullable value/reference types topic ke saath directly connect karta hai:

- `default(int)` = `0` (plain value type)
- `default(int?)` = `null` (nullable value type — `HasValue` false ke saath ek valid struct instance)
- `default(string)` = `null` (reference type, nullable by nature unless NRT annotation `string` non-nullable declare kare)
- `default(string?)` = `null` (explicitly nullable reference type)

</Hinglish>

<Callout type="tip">

Yaad rakhne ka simplest tareeka: "default = jo bhi value tumhe milti agar tumne kuch initialize hi na kiya hota." Numeric zero, bool false, reference null, struct = saare fields ki apni default value.

</Callout>

## Real World Example

<RealWorld company="Microsoft">

.NET ke generic collections (`List<T>`, `Dictionary<TKey,TValue>`) internally `default(T)` heavily use karte hain — jaise `Dictionary.TryGetValue()` jab key nahi milti, `out` parameter ko `default(TValue)` se initialize kiya jaata hai (reference type ke liye `null`, value type ke liye `0`/zeroed struct), taaki caller ko hamesha ek predictable, safe value mile chahe lookup fail ho jaaye.

</RealWorld>

<RealWorld company="An Indian EdTech Backend">

Ek generic caching helper (`T GetOrDefault<T>(string key)`) likha gaya jo cache-miss hone par `default(T)` return karta tha. Team ne isko `int`-based scores ke liye use kiya, aur cache-miss ko silently `0` (default int) treat kar liya — jo galti se genuine "score is zero" se indistinguishable ho gaya, ek real business-logic bug. Fix: `int` ke bajaye `int?` return type use kiya gaya, taaki `default(int?)` genuinely `null` ("no data") ho, `0` se clearly alag.

</RealWorld>

## Numbers That Matter

<Numbers>

- Numeric types (int, double, decimal, etc.): default = `0`
- `bool`: default = `false`
- `char`: default = `'\0'` (null character, not a printable character)
- Reference types (class, string, array): default = `null`
- Struct: default = an instance with every field set to its own default (recursively)
- `default` literal (without explicit type) available since C# 7.1 — compiler infers from context

</Numbers>

## Common Mistakes

<Mistake>

`default(T)` (jaise cache-miss scenario me `int` ke liye) aur "genuinely zero/empty value" ko distinguish na karna — dono cases me same `0` milta hai, jo business logic me ambiguity create kar sakta hai. Fix: nullable type (`int?`) use karo jab "no data" aur "genuinely zero" alag distinguish karni ho.

</Mistake>

<Mistake>

Struct ka default assume karna ki wo `null` hoga — struct kabhi `null` nahi ho sakta (jab tak `Nullable<T>` wrap na ho), default struct ek valid, saare-fields-zero wala instance hai, `null` nahi.

</Mistake>

<Mistake>

`default` literal (bina explicit type ke) use karna aisi jagah jahan compiler type infer nahi kar sakta — compile error dega, `default(SpecificType)` explicitly likhna padega.

</Mistake>

## Quick Revision

<QuickRevision>

- `default(T)` / `default`: the value you'd get if a variable were never explicitly initialized
- Numeric types → `0`; `bool` → `false`; `char` → `'\0'`
- Reference types (class, string, array) → `null`
- Struct → every field set to its own default, recursively (never `null` itself)
- `int?` (`Nullable<T>`) → `null` (via `HasValue = false`, since `Nullable<T>` is itself a struct)
- `default` literal (no explicit type) works since C# 7.1 wherever the compiler can infer the type from context
- Essential in generic code (`default(T)`) where the actual type isn't known when the method is written

</QuickRevision>
