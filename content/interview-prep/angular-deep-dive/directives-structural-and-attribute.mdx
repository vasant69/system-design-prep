<SimpleDefinition>

Angular directives are classes that modify the DOM, split into structural directives that add or remove entire chunks of DOM (like ngIf and ngFor) and attribute directives that change the appearance or behavior of an existing element (like ngClass and ngStyle) without adding or removing it.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Directives Angular ka teesra major building block hain — components (template + class + selector) khud bhi technically ek directive hain (template ke saath), lekin "directive" term usually un cheezon ke liye use hota hai jo template nahi rakhte, sirf behavior add karte hain existing elements pe.

### Structural directives — DOM ka shape badalte hain

Structural directives ek `*` prefix ke saath aate hain (jaise `*ngIf`, `*ngFor`) aur ye poore DOM chunks ko **add ya remove** karte hain, sirf hide/show nahi karte.

```html
<div *ngIf="isLoggedIn">Welcome back!</div>

<ul>
  <li *ngFor="let product of products; let i = index" [class.featured]="product.isFeatured">
    {{ i + 1 }}. {{ product.name }}
  </li>
</ul>
```

`*ngIf` jab condition false hoti hai, element ko DOM se **completely remove** kar deta hai (CSS `display: none` nahi karta) — isse do implications hain: (1) removed element ke andar ke child components destroy ho jaate hain (`ngOnDestroy` fire hota hai), aur (2) heavy content ke liye ye `[hidden]` attribute se better performance deta hai kyunki DOM me wo nodes exist hi nahi karte.

`*ngFor` ek array pe iterate karke har item ke liye ek template instance banata hai. `trackBy` function use karna important hai bade lists ke liye:

```html
<li *ngFor="let product of products; trackBy: trackByProductId">
```

```typescript
trackByProductId(index: number, product: Product): number {
  return product.id;
}
```

Bina `trackBy` ke, Angular default me array ke har item ko reference se compare karta hai — agar poori list ek naye array reference se replace hoti hai (jaise API se fresh data aane pe), Angular saare DOM elements **destroy karke phir se banata hai**, chahe underlying data same ho. `trackBy` Angular ko batata hai ki items ko unique ID se identify karo, taaki sirf actually changed items re-render ho.

### `<ng-template>` desugaring — asal mechanism

`*ngIf` aur `*ngFor` asal me syntactic sugar hain. `*ngIf="condition"` internally is tarah expand hota hai:

```html
<ng-template [ngIf]="condition">
  <div>Welcome back!</div>
</ng-template>
```

`<ng-template>` ek **invisible container** hai — browser me kuch bhi render nahi karta jab tak koi directive explicitly usko instantiate na kare. `NgIf` directive is template ko ek `ViewContainerRef` ke through conditionally DOM me insert/remove karti hai. Yehi wajah hai ki ek element pe do structural directives ek saath nahi laga sakte (jaise `*ngIf` aur `*ngFor` same tag pe) — dono alag-alag `<ng-template>` wrap create karne ki koshish karenge jo conflict karta hai. Iska solution `<ng-container>` hai, jo apna koi DOM element add nahi karta lekin ek wrapper provide karta hai:

```html
<ng-container *ngIf="isLoggedIn">
  <li *ngFor="let item of menuItems">{{ item.label }}</li>
</ng-container>
```

`*ngSwitch` multiple conditions ke liye — `if-else if` chain ka replacement:

```html
<div [ngSwitch]="userRole">
  <p *ngSwitchCase="'admin'">Admin Panel</p>
  <p *ngSwitchCase="'editor'">Editor Tools</p>
  <p *ngSwitchDefault>Read-Only View</p>
</div>
```

### Attribute directives — behavior/appearance badalte hain, DOM shape nahi

Attribute directives element ko add/remove nahi karte, sirf uski property ya behavior modify karte hain.

`ngClass` — dynamically CSS classes toggle karta hai:

```html
<div [ngClass]="{ active: isActive, disabled: isDisabled }">Status</div>
```

`ngStyle` — dynamically inline styles set karta hai:

```html
<div [ngStyle]="{ color: statusColor, fontWeight: isBold ? 'bold' : 'normal' }">Text</div>
```

Note: simple, single-class/style cases me `[class.active]="isActive"` ya `[style.color]="statusColor"` (bina ngClass/ngStyle ke) zyada lightweight hain — `ngClass`/`ngStyle` tab use karo jab multiple conditions ek saath evaluate karni ho ek object ke through.

### Custom attribute directive banana

Ek simple custom directive — jaise input pe highlight-on-focus:

```typescript
import { Directive, ElementRef, HostListener } from "@angular/core";

@Directive({
  selector: "[appHighlight]",
})
export class HighlightDirective {
  constructor(private el: ElementRef) {}

  @HostListener("focus") onFocus() {
    this.el.nativeElement.style.backgroundColor = "#fff3cd";
  }

  @HostListener("blur") onBlur() {
    this.el.nativeElement.style.backgroundColor = "";
  }
}
```

```html
<input appHighlight type="text" />
```

`ElementRef` DOM element ka direct reference deta hai, `@HostListener` us element pe events sunta hai. Ye pattern reusable, cross-cutting UI behavior (tooltips, drag handles, auto-focus) ke liye ideal hai jo multiple components me repeat hota hai.

</Hinglish>

<Callout type="warning">

Ek hi element pe do structural directives (jaise `*ngIf` aur `*ngFor`) ek saath laga dena compile error deta hai. Fix: inner ya outer directive ko ek `<ng-container>` wrapper me move karo.

</Callout>

## Real World Example

<RealWorld company="Google">

Ek internal analytics dashboard me (jaisa Google Ads ka reporting UI) bade data tables `*ngFor` se render hote hain, aur `trackBy` mandatory convention hai team me — kyunki bina uske, real-time data refresh (har few seconds naya data aana) poori table ko destroy-recreate kar deta, jisse scroll position reset hoti aur UI flicker karta. `trackBy` add karne ke baad sirf actually changed rows update hoti hain.

</RealWorld>

## Numbers That Matter

<Numbers>

- `*ngFor` without `trackBy` re-creates every DOM node on any array reference change — O(n) DOM operations regardless of how many items actually changed
- `*ngIf` fully removes elements from the DOM tree, versus `[hidden]` which only toggles CSS display — a measurable difference on large subtrees (hundreds of nodes)
- Only one structural directive is allowed per host element — a compile-time restriction, not a style guideline
- `@HostListener` and `ElementRef` are the two most common building blocks for custom attribute directives

</Numbers>

## Interview Angle

<InterviewAngle>

"What's the difference between *ngIf and [hidden]" is a classic — the correct answer names both the DOM-removal-vs-CSS-toggle mechanism and its consequence: ngIf destroys child component state and re-runs lifecycle hooks, hidden does not. "Explain what `*ngFor` desugars to using ng-template" separates candidates who've only used the directive from those who understand Angular's structural directive mechanism — being able to write the `<ng-template>` form live is a strong signal. A practical scenario question is common too: "your list flickers on every data refresh" — the expected diagnosis is a missing `trackBy`, not a rendering bug elsewhere.

</InterviewAngle>

## Common Mistakes

<Mistake>

`*ngFor` me `trackBy` add na karna bade, frequently-updating lists ke liye — performance degrade hoti hai aur UI state (scroll position, focus, animations) reset ho jaata hai har data refresh pe.

</Mistake>

<Mistake>

Ek element pe `*ngIf` aur `*ngFor` dono ek saath lagane ki koshish karna — Angular ye allow nahi karta. `<ng-container>` wrapper use kiye bina ye common compile error deta hai.

</Mistake>

<Mistake>

`*ngIf` aur `[hidden]` ko interchangeable samajhna — `*ngIf` heavy, rarely-toggled content ke liye better hai (DOM se completely hat jaata hai), lekin frequently toggle hone waale elements ke liye `[hidden]` cheaper ho sakta hai kyunki repeatedly create/destroy nahi karta.

</Mistake>

<Mistake>

`ngClass`/`ngStyle` ko single, simple condition ke liye use karna jab lightweight `[class.name]` ya `[style.prop]` binding kaafi hota — extra unnecessary object creation aur change detection overhead add hota hai.

</Mistake>

## Quick Revision

<QuickRevision>

- Structural directives (`*ngIf`, `*ngFor`, `*ngSwitch`) add/remove whole DOM chunks; attribute directives (`ngClass`, `ngStyle`, custom ones) modify existing elements
- `*ngIf`/`*ngFor` desugar to `<ng-template>` wrapped by the directive — this is why only one structural directive per element is allowed
- `<ng-container>` is a non-rendering wrapper used to combine multiple structural directives
- Always add `trackBy` to `*ngFor` on lists that refresh — avoids full destroy/recreate of DOM nodes
- `*ngIf` removes elements from the DOM (destroys child state); `[hidden]` only toggles CSS display
- `[class.x]`/`[style.y]` are lighter-weight alternatives to `ngClass`/`ngStyle` for single conditions
- Custom attribute directives typically use `ElementRef` + `@HostListener` to add cross-cutting DOM behavior
- `*ngSwitch`/`*ngSwitchCase`/`*ngSwitchDefault` replace long `*ngIf`/`else` chains

</QuickRevision>
