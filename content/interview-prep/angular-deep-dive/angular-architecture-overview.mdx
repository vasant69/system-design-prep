<SimpleDefinition>

Angular is a component-based, TypeScript-first framework where an application is a tree of components, each pairing a template with a class, wired together by dependency-injected services and compiled ahead-of-time into deployable JavaScript.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Angular ek **opinionated, batteries-included framework** hai — React jaisi sirf ek library nahi, balki routing, forms, HTTP client, dependency injection, sab kuch built-in aata hai. Iska matlab hai team ke andar kam "kaunsa library use karein" wali bahas hoti hai, kyunki Angular already decide kar chuka hai.

### Building blocks — component, template, service

Har Angular app **components ka tree** hai. Ek component teen cheezon ka combination hai: ek **class** (TypeScript, business logic), ek **template** (HTML, UI), aur optional **styles** (CSS/SCSS, scoped to us component tak). `@Component` decorator class ko component banata hai — selector (custom HTML tag jaise `<app-header>`), templateUrl, aur styleUrls define karta hai.

```typescript
@Component({
  selector: "app-user-card",
  templateUrl: "./user-card.component.html",
  styleUrls: ["./user-card.component.scss"],
})
export class UserCardComponent {
  @Input() user!: User;
}
```

**Services** un jagah use hote hain jahan logic components ke beech share karna hai — API calls, state, business rules. Component ka kaam sirf UI dikhana aur user interaction handle karna hai; actual kaam (data fetch, validation) service me hota hai. Ye separation testing aasan banata hai — service ko component ke bina unit-test kar sakte ho.

### CLI aur workspace structure

`ng new` se jo project banta hai usme ek predictable structure hoti hai: `src/app/` me components/services/modules, `angular.json` build configuration, `package.json` dependencies. `ng generate component`, `ng generate service` jaise commands boilerplate khud bana dete hain — consistency ensure hoti hai poori team me.

### NgModules vs Standalone Components

Traditionally Angular me **NgModule** (`@NgModule`) components/directives/pipes ko group karta tha — `AppModule` root module hota, `declarations` array me components list hoti, `imports` me doosre modules. Angular 14+ ne **standalone components** introduce kiya — ab component khud apne dependencies (`imports: [CommonModule, FormsModule]`) declare kar sakta hai, NgModule wrapper ki zaroorat nahi. Angular 17+ me standalone hi default hai `ng new` se. Interview me ye distinction poochha jaata hai — purane codebase NgModule-based honge, naye standalone-first, aur dono ek hi app me co-exist kar sakte hain migration ke dauraan.

### Compilation — Ahead-of-Time (AOT)

Angular templates ko production build me **AOT compiler** HTML/TypeScript ko efficient JavaScript me pehle hi compile kar deta hai (build time pe, browser me nahi) — isse do fayde: (1) browser ko template compile nahi karna padta, faster startup, aur (2) template errors build time pe hi pakde jaate hain, runtime pe nahi. Development me default JIT (Just-in-Time) tha purane versions me, lekin modern Angular (9+) me AOT hi default hai dev aur prod dono me.

### Data flows one way, events flow the other

Angular ka mental model: **data neeche jaata hai (parent to child via `@Input`), events upar aate hain (child to parent via `@Output`)**. Ye unidirectional flow debugging aasan banata hai — agar UI me galat data dikh raha hai, to sirf upar se neeche trace karna hota hai, har direction check nahi karni padti. (Two-way binding `[(ngModel)]` iska ek syntactic-sugar exception hai, jo internally isi Input/Output pattern ko wrap karta hai.)

</Hinglish>

<Callout type="tip">

Naye project me hamesha standalone components se shuru karo (Angular 17+ default) — NgModules sirf legacy codebase maintain karte waqt seekhne padte hain, naya code likhte waqt nahi.

</Callout>

## Real World Example

<RealWorld company="Google">

Angular khud Google ke internal tools (AdWords/Google Ads ka bada hissa) power karta hai — yahi wajah hai ki framework enterprise-scale apps (bahut saare developers, bahut saare modules, long-term maintenance) ke liye design hua hai, chhoti landing pages ke liye nahi. Isliye Angular me strict typing (TypeScript mandatory), dependency injection, aur consistent CLI-driven structure jaise "enterprise" features built-in hain — ek 50-developer team ka codebase bina in guardrails ke maintain karna mushkil ho jaata.

</RealWorld>

## Numbers That Matter

<Numbers>

- Angular releases a major version every ~6 months (semantic versioning)
- Standalone components became the `ng new` default from Angular 17 (2023)
- AOT has been the default compilation mode since Angular 9 (2020), for both dev and prod
- A typical initial bundle for a mid-size Angular app: 150-300 KB gzipped before lazy-loaded routes

</Numbers>

## Interview Angle

<InterviewAngle>

"Angular vs React" is a near-guaranteed opener — the strong answer avoids "better/worse" and instead frames it as framework-vs-library: Angular ships routing/forms/HTTP/DI out of the box and enforces TypeScript, React is a rendering library you compose a stack around. "NgModules vs standalone components" tests whether the candidate has touched a modern (17+) codebase — naming the actual migration path (standalone components can import NgModule-based ones and vice versa) signals real experience over textbook knowledge. Expect a quick "what's AOT and why does it matter" — the answer should name both benefits (faster startup, earlier error detection), not just one.

</InterviewAngle>

## Common Mistakes

<Mistake>

Component class ke andar hi HTTP calls aur business logic likhna instead of a service — component untestable ho jaata hai aur logic reuse nahi ho paata across components.

</Mistake>

<Mistake>

"Angular is just like React with different syntax" bol dena — ignore karta hai ki Angular ek full framework hai (DI, routing, forms built-in) jabki React sirf UI library hai jiske upar aur cheezein add karni padti hain.

</Mistake>

<Mistake>

Naye project me bina wajah NgModules use karna kyunki purane tutorials me wahi dikha — Angular 17+ me standalone components hi recommended default hain.

</Mistake>

## Quick Revision

<QuickRevision>

- Angular = full framework (routing, forms, HTTP, DI built-in), TypeScript-first, component-tree architecture
- Component = class (logic) + template (HTML) + styles (scoped CSS), wired via `@Component` decorator
- Services hold shared/business logic; components stay thin and focused on UI + user interaction
- Standalone components (Angular 14+, default since 17) replace NgModules for new code — old and new can coexist
- AOT compiles templates to JS at build time — faster startup, template errors caught before runtime
- Data flows down via `@Input`, events flow up via `@Output` — unidirectional, easier to debug
- `ng generate` / Angular CLI enforces a consistent project structure across large teams

</QuickRevision>
