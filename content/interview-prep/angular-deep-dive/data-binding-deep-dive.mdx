<SimpleDefinition>

Angular offers four kinds of data binding between a component class and its template — interpolation, property binding, event binding, and two-way binding — each covering a different direction of data flow and syntax, and choosing the right one is central to writing idiomatic Angular templates.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Pichle topic me humne interpolation aur property binding ko surface level pe dekha. Ab in dono ko event binding aur two-way binding ke saath ek unified mental model me rakh ke dekhte hain — kyunki interview me "Angular ke saare binding types batao" ek near-guaranteed question hai.

### Four binding types — ek quick map

Angular me data do directions me flow karta hai: **class se template ki taraf** (output) aur **template se class ki taraf** (input, usually user actions se). Chaaron binding types isi do-direction model ke combinations hain:

1. **Interpolation** `{{ expr }}` — class se template, text output
2. **Property binding** `[prop]="expr"` — class se template, DOM property output
3. **Event binding** `(event)="handler()"` — template se class, user action input
4. **Two-way binding** `[(ngModel)]="value"` — dono directions, ek saath

### Interpolation aur property binding — recap plus nuance

```html
<h3>{{ user.name }}</h3>
<img [src]="user.avatarUrl" />
```

Interpolation internally property binding ka hi ek special case hai — Angular compiler `{{ expr }}` ko roughly `[textContent]`-jaisi binding me convert karta hai. Isliye jab interview me poochha jaaye "kya ye do alag mechanisms hain", sahi jawab hai: conceptually same underlying mechanism, bas syntax aur target (text vs any property) alag hai.

### Event binding — template se class ki taraf

Round brackets `( )` ek DOM event ko component method se bind karte hain:

```html
<button (click)="addToCart(product)">Add to Cart</button>
<input (keyup.enter)="onSearch(searchTerm)" />
```

`$event` ek special variable hai jo actual DOM event object ko handler tak pass karta hai:

```html
<input (input)="onInputChange($event)" />
```

```typescript
onInputChange(event: Event) {
  const value = (event.target as HTMLInputElement).value;
  console.log(value);
}
```

Event binding me **koi return value template me use nahi hoti** — ye pure side-effect trigger karne ke liye hai (method call), na ki koi value render karne ke liye.

### Two-way binding — `[(ngModel)]`

Two-way binding syntax dikhta hai `[(ngModel)]="searchTerm"` — ise "banana in a box" bhi kaha jaata hai (square brackets ke andar round brackets, jaise banana box me hota hai). Ye actually do bindings ka syntactic sugar hai:

```html
<input [(ngModel)]="searchTerm" />
```

Yehi expand hone pe:

```html
<input [ngModel]="searchTerm" (ngModelChange)="searchTerm = $event" />
```

Matlab: `ngModel` property binding value ko input me daalta hai, aur `ngModelChange` event input se naye value ko wapas class me le aata hai. `ngModel` use karne ke liye `FormsModule` import karna zaroori hai (ya standalone component me `imports: [FormsModule]`).

### Kab kaun sa use karein

- **Interpolation**: simple text/label display ke liye — headings, paragraph content.
- **Property binding**: DOM property set karni ho jo string na ho (boolean `disabled`, object `src`, array), ya jab dynamic attribute value chahiye.
- **Event binding**: koi bhi user interaction handle karna ho — click, input, keyboard, form submit.
- **Two-way binding**: sirf simple form inputs ke liye jahan value display bhi karni hai aur update bhi turant chahiye, jaise search box, filter toggle. Complex forms (validation, multiple fields, dynamic fields) ke liye **Reactive Forms** (`FormGroup`, `FormControl`) better hai — two-way binding scale nahi karta bade forms me kyunki template me hi state management fail jaata hai spread hone lagta hai.

Ek important gotcha: two-way binding sirf `ngModel` tak limited nahi hai — koi bhi custom component `[(x)]="y"` syntax use kar sakta hai agar wo `@Input() x` aur `@Output() xChange` dono define kare (naming convention: output ka naam input naam + `Change`). Ye Angular ke apne banana-box pattern ko developers khud bhi apne custom components pe apply kar sakte hain.

</Hinglish>

<Callout type="trap">

`[(ngModel)]` ke brackets ka order galat likhna (`([ngModel])` instead of `[(ngModel)]`) ek bahut common typo hai — Angular compiler isse parse error dega. Yaad rakhne ka trick: "banana in a box" — round () pehle andar, square [] bahar.

</Callout>

## Real World Example

<RealWorld company="Microsoft">

Ek internal admin dashboard (jaisa Microsoft ke internal enterprise tools) me search filters usually `[(ngModel)]` se banaye jaate hain — quick, minimal code, aur value turant filter list ko update kar deti hai. Lekin same dashboard ka "create new record" form Reactive Forms se banta hai, kyunki usme field-level validation, conditional fields, aur submit-time error handling chahiye jo template-driven two-way binding se maintain karna mushkil ho jaata.

</RealWorld>

## Numbers That Matter

<Numbers>

- Angular templates support four primary binding syntaxes: `{{ }}`, `[ ]`, `( )`, `[( )]`
- `[(ngModel)]` requires importing `FormsModule` — a very common first-time build error is forgetting this import
- The `$event` object is available in every event binding without any extra declaration
- Two-way binding is syntactic sugar for exactly two underlying bindings: one property, one event

</Numbers>

## Interview Angle

<InterviewAngle>

"What are the types of data binding in Angular" is asked in nearly every Angular interview — the strong answer lists all four AND explains the direction of data flow for each, not just names. A frequent trap question is "what does `[(ngModel)]` actually compile to" — candidates who can write out the desugared `[ngModel]`/`(ngModelChange)` form demonstrate they understand the mechanism, not just the syntax. Expect a practical follow-up: "would you build a 10-field registration form with ngModel or Reactive Forms" — the strong answer picks Reactive Forms and explains why (validation, scalability, testability), showing judgment beyond syntax recall.

</InterviewAngle>

## Common Mistakes

<Mistake>

`[(ngModel)]` use karna bina `FormsModule` import kiye — Angular runtime error dega ki `ngModel` ek known property nahi hai, jo beginners ke liye confusing hota hai kyunki syntax bilkul sahi dikhta hai.

</Mistake>

<Mistake>

Event binding me `(click)="doSomething()"` ki jagah `(click)="doSomething"` (bina parentheses) likh dena — ye method call nahi karta, sirf function reference assign karne ki koshish karta hai jo template expression me kaam nahi karta jaisa expect kiya jaata hai.

</Mistake>

<Mistake>

Bade, multi-field forms ko purely `[(ngModel)]` se banana — validation logic, conditional fields, aur error handling template ke andar hi mess ban jaate hain. Iske bajaye Reactive Forms use karna chahiye jab form complexity badhti hai.

</Mistake>

<Mistake>

Property binding aur attribute ko confuse karna — jaise `[colspan]="2"` likhna jab `colspan` ek attribute hai, DOM property nahi (kuch HTML attributes ka koi corresponding DOM property nahi hota). Aise cases me `attr.` prefix chahiye: `[attr.colspan]="2"`.

</Mistake>

## Quick Revision

<QuickRevision>

- Four binding types: interpolation `{{ }}`, property `[ ]`, event `( )`, two-way `[( )]`
- Interpolation is conceptually a special case of property binding, targeting text output
- Event binding runs a method as a side effect; `$event` gives access to the raw DOM event
- `[(ngModel)]` desugars to `[ngModel]="value" (ngModelChange)="value = $event"`
- `[(ngModel)]` needs `FormsModule` imported — a very common forgotten-import bug
- Use two-way binding for simple inputs; use Reactive Forms for anything with validation or multiple fields
- Custom components can support `[(x)]` by pairing `@Input() x` with `@Output() xChange`
- `[attr.name]` binds an HTML attribute directly when there's no matching DOM property

</QuickRevision>
