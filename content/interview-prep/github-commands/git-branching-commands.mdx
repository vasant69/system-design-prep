<SimpleDefinition>

git branch lists, creates, and deletes branches, while git checkout and the newer git switch move HEAD (Git's pointer to the current commit) between branches. Understanding HEAD as a movable pointer, rather than a fixed location, explains how branch switching, deletion, and creation all behave.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Branching Git ki sabse powerful feature hai — isse multiple developers parallel mein independent kaam kar sakte hain bina ek-doosre ke code ko disturb kiye. Lekin iske commands (`branch`, `checkout`, `switch`) aur `HEAD` ka concept beginners ke liye confusing hote hain, isliye interview mein deeply test kiya jaata hai.

### HEAD — ek movable pointer, fixed location nahi

Sabse pehle yeh samajhna zaroori hai: `HEAD` Git ka ek pointer hai jo batata hai "abhi tum kis commit/branch pe khade ho." Normally `HEAD` ek branch ki taraf point karta hai (jaise `main`), aur woh branch khud latest commit ki taraf point karti hai.

```
HEAD --> main --> C3 (latest commit)
```

Jab tum branch switch karte ho, `HEAD` bas apna target badal deta hai — koi files "move" nahi hoti, Git sirf working directory ko us naye target ke snapshot ke hisaab se update kar deta hai.

### git branch — list, create, delete

```bash
git branch                       # local branches ki list (current branch pe * dikhega)
git branch feature/login-page    # naya branch banao, lekin HEAD wahan move nahi hota
git branch -d feature/old-work   # branch delete karo (safe — sirf agar already merged hai)
git branch -D feature/experiment # force delete karo (chahe merged na ho — data loss possible)
```

Zaroori baat: `git branch <name>` sirf ek naya pointer banata hai current commit pe — yeh tumhe automatically us branch pe le nahi jaata. Us naye branch pe kaam karne ke liye alag se switch karna padta hai.

`-d` (lowercase) safe delete hai — Git check karta hai ki us branch ke commits kisi aur jagah (jaise `main`) merge ho chuke hain ya nahi, agar nahi to error de deta hai. `-D` (uppercase) force delete hai — bina check kiye delete kar deta hai, agar us branch mein unmerged commits the to woh permanently lost ho sakte hain.

### git checkout -b vs git switch -c — banao aur turant move ho jao

`git checkout -b` purana, multi-purpose command hai jo branch switching, file restoration, aur branch creation — sab ek hi command ke andar handle karta hai. Isi confusion ki wajah se Git 2.23+ mein do naye, focused commands aaye: `git switch` (branches ke liye) aur `git restore` (files ke liye).

```bash
# Purana style (sab kaam karta hai, isliye confusing)
git checkout -b feature/login-page     # naya branch banao AUR turant usme switch ho jao
git checkout main                      # existing branch pe switch karo

# Naya style (Git 2.23+), zyaada explicit aur safe
git switch -c feature/login-page       # naya branch banao AUR switch karo
git switch main                        # existing branch pe switch karo
```

`-c` (create) flag `switch` mein wahi kaam karta hai jo `-b` `checkout` mein karta hai. Naya `switch` command isliye better hai kyunki iska sirf ek hi purpose hai — branches ke beech move hona — jabki `checkout` overloaded hai (file restore karne ke liye bhi wahi command use hota hai, jisse galti se file discard hone ka risk badh jaata hai).

### Local branch delete vs remote branch delete

Local delete (`-d`/`-D`) sirf tumhare machine se branch hataata hai. Remote pe woh branch tab tak exist karega jab tak explicitly delete na karo:

```bash
git branch -d feature/login-page              # local se delete
git push origin --delete feature/login-page   # remote se bhi delete
```

Yeh do alag operations hain — bahut common mistake hai sirf local delete karke yeh assume kar lena ki remote pe bhi branch gayab ho gaya.

### Naming conventions

Real teams mein branch names ek consistent pattern follow karte hain, jisse purpose turant samajh aa jaaye:

```bash
feature/payment-retry-logic
bugfix/null-pointer-checkout
hotfix/prod-login-crash
release/v2.3.0
```

Prefix (`feature/`, `bugfix/`, `hotfix/`, `release/`) branch ka category batata hai, aur baaki descriptive naam kaam ko summarize karta hai. Yeh convention CI/CD pipelines mein bhi useful hota hai — kai teams `hotfix/*` branches ko auto-deploy pipeline se link karte hain.

### Ek real scenario

Maan lo ek developer ko payment retry logic pe kaam karna hai:

```bash
git switch main                           # pehle main pe aao, latest ho
git pull origin main                      # sync ho jao remote ke saath
git switch -c feature/payment-retry-logic # naya branch banao aur turant usme chale jao
# ... kaam karo, commit karo ...
git push -u origin feature/payment-retry-logic
```

Kaam complete hone aur PR merge hone ke baad:

```bash
git switch main
git pull origin main
git branch -d feature/payment-retry-logic          # local cleanup
git push origin --delete feature/payment-retry-logic  # remote cleanup
```

</Hinglish>

<Callout type="tip">

Naye Git users ko `git switch` aur `git restore` seekhna chahiye purane `git checkout` ke bajaye — yeh dono commands purpose mein narrow hain, isliye accidental mistakes (jaise file discard ho jaana jab tum branch switch karna chahte the) kam hote hain.

</Callout>

## Numbers That Matter

<Numbers>

<ul>
<li>git switch and git restore were introduced in Git 2.23 (released 2019) to split checkout's overloaded responsibilities</li>
<li>-d (safe delete) checks for 1 condition before allowing deletion: is the branch fully merged</li>
<li>-D (force delete) skips that check entirely, risking permanent loss of any unmerged commits</li>
<li>Deleting a branch locally and on the remote are 2 separate commands — one does not imply the other</li>
</ul>

</Numbers>

## Interview Angle

<InterviewAngle>

Ek classic interview question: "HEAD kya hota hai Git mein?" Model answer: `HEAD` ek pointer hai jo batata hai ki working directory currently kis commit ke snapshot ko reflect kar raha hai. Normally yeh ek branch ki taraf point karta hai (jaise `main`), aur woh branch khud latest commit ki taraf. Branch switch karna sirf `HEAD` ka target badalta hai — files working directory mein us naye target ke hisaab se update ho jaati hain. Advanced follow-up: "detached HEAD state kya hai?" — jab `HEAD` directly ek commit (branch ke bajaye) ki taraf point kare, jaise ek purani commit ko directly checkout karne se; is state mein naye commits kisi bhi branch se linked nahi hote, isliye branch switch karte hi lost ho sakte hain agar pehle ek naya branch na banaya jaaye.

</InterviewAngle>

## Common Mistakes

<Mistake>

`git branch -d` se error aane pe (branch fully merged nahi hai) turant `-D` use kar dena bina check kiye ki us branch mein kya unmerged, important commits hain — isse kaam permanently lost ho sakta hai.

</Mistake>

<Mistake>

Sirf local branch delete karke yeh assume karna ki remote pe bhi automatically delete ho gaya — remote branch delete karne ke liye alag command chahiye: `git push origin --delete branch-name`.

</Mistake>

<Mistake>

`git checkout -b` aur `git branch` mein confuse ho jaana — `git branch name` sirf branch banata hai, HEAD ko move nahi karta, jabki `git checkout -b name` banata bhi hai aur turant switch bhi kar deta hai.

</Mistake>

<Mistake>

Bina naming convention ke random branch names use karna (jaise `test`, `new-branch`, `fix2`) — bade teams mein isse branch list quickly unreadable ho jaati hai, purpose samajhna mushkil.

</Mistake>

## Quick Revision

<QuickRevision>

<ul>
<li>git branch: list local branches (current one marked with *)</li>
<li>git branch name: create a new branch, HEAD does NOT move to it</li>
<li>git switch -c name (or git checkout -b name): create AND switch to a new branch</li>
<li>git switch name (or git checkout name): switch to an existing branch</li>
<li>git branch -d name: safe delete, fails if branch is not fully merged</li>
<li>git branch -D name: force delete, deletes even unmerged commits</li>
<li>git push origin --delete name: delete the branch on the remote too</li>
<li>HEAD is a movable pointer to the current branch/commit, not a fixed location</li>
</ul>

</QuickRevision>
