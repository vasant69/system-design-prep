**Closures – Complete Summary**

Closure matlab ek function jo apne banne wale scope ke variables ko yaad rakhta hai — chahe wo outer function return karke khatam ho chuka ho. Jab tum ek function ke andar function banake use return karte ho (ya callback/event handler ke roop mein kahin store karte ho), to andar wala function apne saath ek "backpack" le jaata hai jisme outer scope ke variables ke references hote hain. Wo variables garbage-collect nahi hote jab tak inner function zinda hai. Isi se banta hai private state — bahar se koi seedha touch nahi kar sakta, sirf returned functions ke through. Har baar outer function call karne par naya, alag backpack milta hai.

## Visual

```text
   makeCounter()  is CALLED
   ┌───────────────────────────────┐
   │  let count = 0                 │   ◀── lives in makeCounter's scope
   │  return function () {          │
   │      count++                   │
   │      return count              │
   │  }                             │
   └───────────────┬───────────────┘
                   │ returns the inner function...
                   ▼
   makeCounter() has RETURNED — its stack frame is "gone"
   ...but the inner fn walked away with a BACKPACK:

        inc  ─────▶  [ backpack:  count ─▶ 0 ]     (a reference, NOT a copy)

   inc()  ▶ count becomes 1 ▶ returns 1
   inc()  ▶ count becomes 2 ▶ returns 2

   const inc2 = makeCounter()   ▶ a brand-new backpack:  [ count ─▶ 0 ]
   inc2()  ▶ 1      (completely independent of inc)
```

## Code

```js
function makeCounter() {
  let count = 0;                 // private — nothing outside can touch it

  return {
    inc() { count += 1; return count; },
    dec() { count -= 1; return count; },
    value() { return count; },
  };
}

const c1 = makeCounter();
console.log(c1.inc());   // 1  -> the returned fns still see `count`
console.log(c1.inc());   // 2  -> same `count`, updated in place
console.log(c1.value()); // 2

const c2 = makeCounter();
console.log(c2.inc());   // 1  -> c2 has its OWN `count` (separate backpack)
console.log(c1.value()); // 2  -> c1 untouched
// console.log(count);   -> ReferenceError -> `count` is not reachable directly
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Function + uske banne wale scope ke variables ka reference-bundle. Outer function return hone ke baad bhi wo variables zinda rehte hain. |
| Kab/kaise hota hai | Jab inner function outer ke variables use karta hai aur inner function outer se bahar chala jaata hai (return, callback, event handler, `setTimeout`). |
| Kyun useful hai | Private state (counter, balance), function factories, `once` / memoize, event handlers jo config yaad rakhein, purana module pattern. |
| Interview trap | Closure variable ka reference capture karta hai, snapshot nahi — `for (var i ...)` wale loop mein saare callbacks last `i` dekhte hain. `let` per-iteration binding se fix. |

## Wrong vs Right

```js
// Galat: har call par kaam dobara — kuch yaad nahi rakha jaata
function square(n) {
  // pretend this is expensive
  return n * n;
}
square(5); // computes
square(5); // computes AGAIN — no memory of the last call
```

```js
// Sahi: closure mein ek private cache rakho (memoize)
function makeSquarer() {
  const cache = new Map();          // private, persists across calls
  return function (n) {
    if (cache.has(n)) return cache.get(n);
    const result = n * n;           // pretend expensive
    cache.set(n, result);
    return result;
  };
}
const sq = makeSquarer();
sq(5); // computes, stores
sq(5); // instant — the closure kept `cache` alive
```

**Ek line mein:** Closure ek function hai jo apne lexical scope ke variables ke references saath le jaata hai, isliye wo outer ke return hone ke baad bhi us private state ko padh aur badal sakta hai.
