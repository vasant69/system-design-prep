**Primitive vs Reference Types – Complete Summary**

JS ki har value do mein se ek hai: primitive (string, number, boolean, `null`, `undefined`, symbol, bigint) ya reference type (object, array, function). Primitive seedha variable mein rehta hai aur copy karne par uski poori value duplicate ho jaati hai — do variable ab bilkul alag. Reference type heap mein rehta hai aur variable ke andar sirf uska address (pointer) hota hai; copy karne par address duplicate hota hai, object nahi — ab do variable EK hi object par point karte hain aur ek ka change doosre ko dikhta hai. `===` primitives ki value compare karta hai, par objects ka identity (same address hai ya nahi) — content nahi.

## Visual

```text
   let a = 10
   let b = a          // COPY OF THE VALUE
   b = 99

   STACK  (name + primitive value together)
   ┌──────────────┐
   │  a  │   10   │        a untouched
   │  b  │   99   │        b is its own separate 10, now 99
   └──────────────┘


   let x = { n: 1 }
   let y = x           // COPY OF THE POINTER (address), not the object
   y.n = 42

   STACK                       HEAP
   ┌───────────────┐           ┌────────────────┐
   │  x  │  ref#01 ├─────────▶ │   { n: 42 }    │
   │  y  │  ref#01 ├─────────▶ │  (one object)  │
   └───────────────┘           └────────────────┘
        both hold ref#01   ▶  reading x.n now also gives 42

   x === y                 ▶ true    (same address)
   { n: 42 } === { n: 42 } ▶ false   (two different addresses)
```

## Code

```js
// PRIMITIVE: copied by value
let score = 10;
let copy = score;      // copy gets its own 10
copy = 20;
console.log(score, copy);   // 10 20  -> fully independent

// REFERENCE: copied by pointer
const user = { name: "Asha" };
const alias = user;    // alias holds the SAME address
alias.name = "Bhavna";
console.log(user.name);     // "Bhavna"  -> one object, two names for it

// Equality
console.log(1 === 1);                        // true  -> value compare
console.log({} === {});                      // false -> different objects
console.log(user === alias);                 // true  -> same reference

// Function args: primitive in = a copy; object in = shared reference
function bump(obj, num) { obj.x++; num++; }
const box = { x: 0 };
let n = 0;
bump(box, n);
console.log(box.x, n);      // 1 0  -> obj was mutated, num was just a copy
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Primitive = value khud variable mein (immutable). Reference type = object heap mein, variable mein sirf uska pointer. |
| Kab/kaise hota hai | `=` par ya function argument par: primitive ki value copy hoti hai; object ka pointer copy hota hai (object shared rehta hai). |
| Kyun useful hai | Pata hota hai kab ek change doosri jagah dikhega — accidental mutation bugs se bachte ho, jaan-boojhkar copy (`{ ...obj }`) lete ho. |
| Interview trap | `const` object bhi mutate hota hai (binding lock, content nahi). Aur `{ a: 1 } === { a: 1 }` `false` deta hai — `===` content nahi, identity dekhta hai. |

## Wrong vs Right

```js
// Galat: "backup" bana ke original ko safe samajh liya
const original = { total: 100 };
const backup = original;        // ye copy NAHI hai, wahi object hai
backup.total = 0;
console.log(original.total);    // 0  -> original bhi badal gaya
```

```js
// Sahi: naya object banao (shallow copy), tabhi original bacha rehta hai
const original = { total: 100 };
const backup = { ...original }; // naya object, alag address
backup.total = 0;
console.log(original.total);    // 100  -> safe
```

**Ek line mein:** Primitive `=` par value copy hoti hai (do alag values), object `=` par sirf pointer copy hota hai (ek hi object, do naam) — isliye `===` objects ko identity se compare karta hai, content se nahi.
