**var, let & const – Complete Summary**

Teen tareeke variable banane ke, teen jagah farak: **scope**, **reassignment**, **hoisting**. `var` poore function mein leak karta hai aur declaration se pehle `undefined` deta hai (silent bug). `let`/`const` sirf apne `{ }` block mein zinda rehte hain aur declaration line tak "Temporal Dead Zone" (TDZ) mein — waha access `ReferenceError` deta hai (loud, helpful). `const` ka extra rule: binding dobara assign nahi kar sakte (par object ke andar mutate kar sakte ho). Modern rule: `const` default, `let` jab reassign chahiye, `var` kabhi nahi.

## Visual

```text
                     SCOPE
   ┌──────────────────────────────────────────┐
   │ function foo() {                          │
   │    ┌───────────────────────────────────┐  │
   │    │  { block }                        │  │
   │    │    let / const  ──▶ live ONLY here│  │
   │    └───────────────────────────────────┘  │
   │    var  ──▶ ignores block, whole function │
   │ }                                         │
   └──────────────────────────────────────────┘

   HOISTING TIMELINE   (top of scope ─────▶ your declaration line)

   var x :  [ x = undefined ] ───────▶ [ x = 10 ]    read before = undefined
   let y :  [   TDZ   ✗ read ] ──────▶ [ y = 20 ]    read before = ReferenceError
```

## Code

```js
// 1. SCOPE — var leaks out of the block, let/const do not
if (true) {
  var a = 1;
  let b = 2;
  const c = 3;
}
console.log(a); // 1  -> var is function/global scoped
// console.log(b); -> ReferenceError: b is not defined
// console.log(c); -> ReferenceError: c is not defined

// 2. REASSIGN — const locks the BINDING, not the value
const user = { name: "Vasant" };
user.name = "Raj"; // OK -> mutating the object the binding points to
// user = {};      -> TypeError: Assignment to constant variable

// 3. HOISTING — var reads as undefined, let sits in the TDZ
console.log(x); // undefined  (var was hoisted, initialised to undefined)
var x = 10;
// console.log(y); -> ReferenceError  (TDZ — hoisted but not initialised)
let y = 20;
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Variable declare karne ke 3 tareeke; farak sirf scope, reassignment aur hoisting mein. |
| Kab/kaise hota hai | `var` = function-scoped, hoist hoke `undefined`. `let`/`const` = block-scoped, declaration line tak TDZ. `const` = binding reassign nahi hota. |
| Kyun useful hai | `const` default rakho -> reader ko bina poori body padhe pata "ye value fix hai". Block scope se variable leak nahi karta, loop-closure bug nahi hota. |
| Interview trap | `const` value ko freeze nahi karta, sirf binding ko. `const arr = []; arr.push(1)` bilkul valid — array mutate hua, binding wahi raha. |

## Wrong vs Right

```js
// Galat: var loop mein — teeno callbacks EK hi i share karte hain
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// Output: 3 3 3   (loop khatam hone ke baad callbacks chalte hain, i === 3)
```

```js
// Sahi: let — har iteration ka apna fresh i binding
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// Output: 0 1 2
```

**Ek line mein:** `const` by default, `let` jab reassign karna ho, `var` kabhi nahi — kyunki `let`/`const` ka block scope aur TDZ silent bugs ko turant loud error bana dete hain.
