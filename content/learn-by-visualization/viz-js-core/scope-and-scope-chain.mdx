**Scope & the Scope Chain – Complete Summary**

Scope matlab code ka wo ilaka jahan ek naam dikhta hai. Teen level: global (poori file), function (har function ka apna), block (har `{ }`, sirf `let`/`const`/`class` ke liye). JS lexical hai — kaunsa scope kiske andar hai ye tabhi tay ho jaata hai jab tum code likhte ho (nesting se), call kahan se hui isse nahi. Jab koi variable padhna ho, engine current scope mein dhoondta hai; na mile to parent scope, phir uska parent... global tak. Global mein bhi na mile to `ReferenceError`. Inner scope apne naam se outer ka same naam dhak deta hai — ise shadowing kehte hain. Lookup hamesha bahar ki taraf chalta hai, andar ki taraf kabhi nahi.

## Visual

```text
   ┌─ GLOBAL scope ───────────────────────────────────────────┐
   │  const app = "bank"                                       │
   │                                                          │
   │  ┌─ outer()  function scope ────────────────────────────┐ │
   │  │  const user = "Vasant"                               │ │
   │  │                                                      │ │
   │  │  ┌─ block { }   (let / const only) ────────────────┐ │ │
   │  │  │  const rate = 7                                 │ │ │
   │  │  │                                                 │ │ │
   │  │  │  read rate  ─▶ found right here            ✓    │ │ │
   │  │  │  read user  ─▶ not here ─▶ found in outer() ✓   │ │ │
   │  │  │  read app   ─▶ not here ─▶ not outer ─▶ GLOBAL ✓ │ │ │
   │  │  │  read xyz   ─▶ not here ─▶ not outer ─▶ not      │ │ │
   │  │  │              global ─▶ ReferenceError       ✗    │ │ │
   │  │  └─────────────────────────────────────────────────┘ │ │
   │  └──────────────────────────────────────────────────────┘ │
   └──────────────────────────────────────────────────────────┘

   LOOKUP DIRECTION:  inner ─▶ parent ─▶ parent ─▶ global ─▶ ReferenceError
                      (never inward: GLOBAL cannot see inside outer())
```

## Code

```js
const tenant = "hdfc";          // global scope

function outer() {
  const region = "west";        // outer() scope

  function inner() {
    const branch = "pune-01";   // inner() scope

    // lookup walks OUTWARD, the nearest scope that has the name wins:
    console.log(branch);  // "pune-01" -> own scope
    console.log(region);  // "west"    -> found one level out, in outer()
    console.log(tenant);  // "hdfc"    -> found in global
    // console.log(city); -> ReferenceError: city is not defined
  }

  inner();
  // console.log(branch); -> ReferenceError -> outer() cannot see inner()'s vars
}

outer();
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Naam kahan-kahan visible hai uska ilaka. 3 tarah ke: global, function, block (block sirf `let`/`const`/`class` par). |
| Kab/kaise hota hai | Lexical — scope ki nesting likhne ke waqt fix ho jaati hai. Lookup current scope se shuru, na mile to parent, phir parent... global, phir `ReferenceError`. |
| Kyun useful hai | Har function apni state chhupa sakta hai (encapsulation), naam clash nahi hote, aur closures isi outward-lookup ki wajah se kaam karte hain. |
| Interview trap | Scope call-site se nahi, definition-site se decide hota hai. `var` block scope ko ignore karta hai. Bina declare kiye `x = 1` non-strict mode mein accidental global bana deta hai. |

## Wrong vs Right

```js
// Galat: maan liya ki jahan function CALL hua wahan ke variables dikhenge
function printLabel() {
  console.log(label);       // kaunsa `label`?
}
function run() {
  const label = "Raj";
  printLabel();             // yahan se call kiya
}
run();
// Output: ReferenceError: label is not defined
// printLabel lexically GLOBAL mein likha hai -> run() ka `label` usse dikhta hi nahi
```

```js
// Sahi: jo value chahiye wo argument se pass karo
function printLabel(label) {
  console.log(label);
}
function run() {
  const label = "Raj";
  printLabel(label);        // "Raj"
}
run();
```

**Ek line mein:** Scope lexical hota hai — naam ka lookup current `{ }` se shuru hoke bahar-bahar parent scopes se hote hue global tak jaata hai, aur kahin na mile to `ReferenceError`.
