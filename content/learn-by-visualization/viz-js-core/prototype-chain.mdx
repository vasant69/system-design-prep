**The Prototype Chain – Complete Summary**

Har object ke andar ek chhupa hua link hota hai — `[[Prototype]]` — jo kisi doosre object ki taraf point karta hai. Jab tum koi property padhte ho jo object ke apne paas nahi hai, engine is link ke sahare upar chadhta hai: object, phir uska prototype, phir uske prototype ka prototype... jab tak property mile ya `null` aa jaaye (`Object.prototype` ke aage `null` hota hai). Function ya `class` se bane instances ka prototype `Constructor.prototype` hota hai — isliye shared methods wahan ek baar rakhe jaate hain, har instance mein copy nahi. Writes hamesha khud object par hote hain (chain par nahi), isliye assign karne se prototype ki property "shadow" ho jaati hai. `class` bas isi mechanism ka clean syntax hai.

## Visual

```text
   const arr = [10, 20]

   arr ──[[Prototype]]──▶ Array.prototype ──▶ Object.prototype ──▶ null
   own: 0, 1, length      push, map, slice...   hasOwnProperty, toString...

   arr.map(fn)     ▶ not own ▶ found on Array.prototype             ✓
   arr.toString()  ▶ not own ▶ Array.prototype ✗ ▶ Object.prototype ✓
   arr.fly()       ▶ not own ▶ ... ▶ null ▶ undefined ▶ TypeError on call


   CONSTRUCTOR / class — shared methods live in ONE place

   function User(n) { this.name = n; }
   User.prototype.hi = function () { return "hi " + this.name; };
   const u = new User("Asha")

   u ──▶ User.prototype ──▶ Object.prototype ──▶ null
   own: name          shared: hi

   u.hi()   ▶ found on User.prototype  (one fn, every instance shares it)
   u.hi = 1 ▶ WRITE lands on u itself ▶ now SHADOWS User.prototype.hi
```

## Code

```js
function User(name) {
  this.name = name;                 // own property, one per instance
}
User.prototype.greet = function () {  // shared method — ONE copy total
  return `Hi, ${this.name}`;
};

const a = new User("Asha");
const b = new User("Bhanu");

console.log(a.greet());            // "Hi, Asha" -> found on User.prototype
console.log(a.greet === b.greet);  // true -> same function object, not copied

console.log(a.hasOwnProperty("name"));  // true  -> own
console.log(a.hasOwnProperty("greet")); // false -> inherited via the chain

// walking the chain explicitly:
console.log(Object.getPrototypeOf(a) === User.prototype);            // true
console.log(Object.getPrototypeOf(User.prototype) === Object.prototype); // true
console.log(Object.getPrototypeOf(Object.prototype));               // null

// shadowing: a write always lands on the instance
a.greet = () => "overridden";
console.log(a.greet(), b.greet()); // "overridden" "Hi, Bhanu"
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Har object ka ek `[[Prototype]]` link doosre object par. Property na mile to engine is link par upar chalta hai. |
| Kab/kaise hota hai | Property READ: own, phir prototype, phir uska prototype... `Object.prototype`, phir `null`, phir `undefined`. Property WRITE: hamesha khud object par. |
| Kyun useful hai | Shared methods `Constructor.prototype` par ek baar — har instance mein copy nahi, memory bachti hai. Inheritance isi delegation se banta hai. |
| Interview trap | `__proto__` (instance ka link) aur `prototype` (function ki property jo naye instances ka link banti hai) alag cheezein hain. Prototype par likhne se saare instances affect hote hain. |

## Wrong vs Right

```js
// Galat: method ko constructor ke andar rakha — har instance apni copy banata hai
function User(name) {
  this.name = name;
  this.greet = function () { return `Hi, ${this.name}`; }; // NEW fn per instance
}
const x = new User("A");
const y = new User("B");
console.log(x.greet === y.greet);   // false -> 1000 users = 1000 function objects
```

```js
// Sahi: method prototype par — ek hi copy, sab instances usko delegate karte hain
function User(name) { this.name = name; }
User.prototype.greet = function () { return `Hi, ${this.name}`; };
const x = new User("A");
const y = new User("B");
console.log(x.greet === y.greet);   // true -> one function, shared
```

**Ek line mein:** Har object apne `[[Prototype]]` link ke through doosre object ko delegate karta hai, aur property lookup is chain par `Object.prototype` se `null` tak upar chalta hai — `class` isi ka syntax sugar hai.
