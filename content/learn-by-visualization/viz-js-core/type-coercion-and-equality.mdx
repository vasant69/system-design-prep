**Type Coercion & == vs === – Complete Summary**

Coercion matlab JS ka apne aap ek type ko doosre mein badalna. `+` ke saath agar ek operand string hai to result string ban jaata hai (`1 + '2'` ka `'12'`); baaki arithmetic aur comparison number ki taraf le jaate hain (`'5' * 2` ka `10`). `==` compare karne se pehle dono sides ko ek common type mein convert karta hai — isliye `0 == ''`, `0 == '0'`, `1 == true` sab `true`. `===` koi conversion nahi karta: type alag to seedha `false`. Rule simple — hamesha `===` use karo aur type khud explicitly badlo (`Number(x)`, `String(x)`). `null == undefined` `true` hai, par `null === undefined` `false`.

## Visual

```text
   a === b   (STRICT — no conversion)
   ──────────────────────────────────────
   type(a) !== type(b) ?  ──▶ YES ──▶ false     (one step, done)
            │ NO
            ▼
   same value ?  ──▶ true / false     (NaN === NaN is ALWAYS false)


   a == b   (LOOSE — convert first, then compare)
   ──────────────────────────────────────────────
   same type                ──▶ behave like ===
   null vs undefined         ──▶ true
   number vs string          ──▶ string becomes Number, retry
   boolean on either side    ──▶ boolean becomes Number, retry
   object vs primitive       ──▶ object becomes primitive, retry
   anything else             ──▶ false

   FALLOUT (why == is avoided):
     0 == ""    ▶ true      0 == "0"  ▶ true      "" == "0" ▶ false
     1 == true  ▶ true      null == 0 ▶ false     [] == ![] ▶ true
```

## Code

```js
// === : check type first, then value. No surprises.
console.log(1 === "1");          // false -> number vs string, stop
console.log(null === undefined); // false -> different types

// == : convert, then compare
console.log(1 == "1");           // true  -> "1" becomes 1
console.log(0 == "");            // true  -> "" becomes 0
console.log("" == "0");          // false -> both already strings, not equal
console.log(null == undefined);  // true  -> special-cased in the spec
console.log(null == 0);          // false -> null loosely-equals only undefined

// NaN is not equal to anything, including itself
console.log(NaN === NaN);        // false
console.log(Number.isNaN(NaN));  // true  -> the correct NaN check

// Explicit conversion — do this instead of leaning on ==
console.log(Number("42") === 42); // true
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Coercion = automatic type-conversion. `==` compare se pehle convert karta hai, `===` bilkul nahi. |
| Kab/kaise hota hai | `==`: type alag ho to string/boolean/object ko number (ya primitive) banake retry. `+` string ki taraf, baaki operators number ki taraf coerce karte hain. |
| Kyun useful hai | `===` + explicit `Number()` / `String()` se code predictable rehta hai; `==` ke edge cases (`0 == ''`, `[] == ![]`) debug hi nahi karne padte. |
| Interview trap | `null == undefined` `true` par `null == 0` `false`. `NaN` kisi ke barabar nahi, khud ke bhi nahi. `"" == "0"` `false` jabki `0 == "0"` `true`. |

## Wrong vs Right

```js
// Galat: user input ko == se check kiya
const input = "";            // form field khaali
if (input == 0) {
  console.log("looks like zero");   // ye branch chal jaata hai! "" becomes 0
}
```

```js
// Sahi: === + explicit conversion aur clear intent
const input = "";
if (input === "") {
  console.log("field is empty");
}
const n = Number(input);           // "" -> 0, "abc" -> NaN
if (!Number.isNaN(n) && n === 0) {
  console.log("an actual zero was entered");
}
```

**Ek line mein:** `==` dono sides ko ek common type mein convert karke compare karta hai (isliye `0 == ''` `true`), `===` bina conversion type aur value dono match maangta hai — hamesha `===` use karo.
