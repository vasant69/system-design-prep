**The this Keyword – Complete Summary**

`this` ki value function kaise call hua isse tay hoti hai, kahan likha hai isse nahi. Priority order mein 4 rules: (1) `new Fn()` — `this` naya bana object. (2) `fn.call` / `fn.apply` / `fn.bind` — `this` wahi object jo tumne diya. (3) `obj.method()` — `this` dot ke left wala `obj` (implicit binding). (4) Kuch bhi nahi, plain `fn()` — strict mode mein `this` `undefined`, warna global object. Arrow function ka apna `this` hota hi nahi — wo enclosing scope se `this` uthata hai (lexical), aur `call` / `bind` use badal nahi sakte. Method ko variable mein nikaalkar call karne par implicit binding toot jaati hai aur `this` default ban jaata hai.

## Visual

```text
   How was the function CALLED?   (top to bottom, first match wins)

   new Fn()                ─▶  this = the brand-new object
   Fn.call(o) / .apply(o)  ─▶  this = o
   Fn.bind(o) ... ()       ─▶  this = o   (locked in permanently)
   obj.method()            ─▶  this = obj  (the thing left of the dot)
   plain  fn()             ─▶  this = undefined  (strict / ES module)
   callback passed away    ─▶  this = globalThis (sloppy mode)


   ARROW FUNCTION   () => this      (no own this)
   ─────────────────────────────────────────────
   looks OUTWARD to the scope it was written in
   call / apply / bind CANNOT change it

   const o = {
     regular() { return this; },   // this = o            ▶ o
     arrow:  () => this,           // this = outer scope  ▶ not o
   }
```

## Code

```js
"use strict";

const user = {
  name: "Meera",
  greet() { return `Hi, ${this.name}`; },
};

console.log(user.greet());          // "Hi, Meera" -> implicit: this = user

const g = user.greet;               // detached from user...
// g();                             // TypeError -> this is undefined (strict)

console.log(user.greet.call({ name: "Ravi" })); // "Hi, Ravi" -> explicit
const bound = user.greet.bind({ name: "Sara" });
console.log(bound());               // "Hi, Sara" -> bind locks it in for good

function Account(bal) { this.bal = bal; }
console.log(new Account(500).bal);  // 500 -> new: this = the fresh instance

// arrow: no own `this`, inherits from the enclosing scope
const obj = { hi: () => typeof this };
console.log(obj.hi());              // "undefined" -> not obj, lexical this
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Ek keyword jiski value call-time par tay hoti hai — "yeh function kis context mein chala". |
| Kab/kaise hota hai | Priority: `new`, phir `call` / `apply` / `bind`, phir `obj.method()` (dot ke left), phir plain call (strict mein `undefined`). Arrow apna `this` rakhta hi nahi. |
| Kyun useful hai | Ek hi method alag-alag objects par reuse hota hai; `bind` se callback ka context fix; arrow se `this` "kho jaane" wala bug khatam. |
| Interview trap | `const f = obj.method; f()` — implicit binding tooti, `this` ab `undefined` / global. Arrow ka `this` `call` / `bind` se badla hi nahi ja sakta. |

## Wrong vs Right

```js
// Galat: method ko callback ki tarah pass kiya — `this` kho gaya
const timer = {
  secs: 0,
  tick() { this.secs++; console.log(this.secs); },
};
setTimeout(timer.tick, 100);
// TypeError / NaN -> `tick` plain call hua, `this` ab `timer` nahi raha
```

```js
// Sahi: bind karo, ya arrow se wrap karke as `timer.tick()` call karo
const timer = {
  secs: 0,
  tick() { this.secs++; console.log(this.secs); },
};
setTimeout(timer.tick.bind(timer), 100);   // logs 1
setTimeout(() => timer.tick(), 100);       // arrow calls it as timer.tick()
```

**Ek line mein:** `this` function ke call karne ke tareeke se decide hota hai (`new`, phir `call`/`apply`/`bind`, phir object-before-dot, phir default), aur arrow functions apna `this` na rakhkar enclosing scope se lete hain.
