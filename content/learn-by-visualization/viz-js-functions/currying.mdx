**Currying & Partial Application – Complete Summary**

Currying: ek multi-arg function `f(a, b, c)` ko aisi chain mein todna jahan har call sirf EK arg le — `f(a)(b)(c)`. Har call apna arg closure mein pakadta hai aur agla function return karta hai; jab saare args mil jaate hain tab asli kaam hota hai. Partial application thoda dheela version hai: abhi kuch args fix karo (`bind` ya wrapper se), baaki baad mein do. Dono ka maqsad ek: general function se chhote, reusable, pre-configured functions banana (jaise `add5`, `logError`).

## Visual

```text
  NORMAL                        CURRIED
  add(a, b, c)                  curriedAdd(a)(b)(c)

  curriedAdd(1)   ─▶ returns  fn(b)  { closure holds a = 1 }
        │
        ▼
     ( ... )(2)   ─▶ returns  fn(c)  { closure holds a = 1, b = 2 }
        │
        ▼
     ( ... )(3)   ─▶ all 3 collected  ─▶  1 + 2 + 3 = 6

  each call PEELS one argument and remembers it in a closure layer:

  ┌ a=1 ─────────────────────────┐
  │  ┌ b=2 ────────────────────┐ │
  │  │  ┌ c=3 ──▶ compute 6 ─┐ │ │
  │  │  └────────────────────┘ │ │
  │  └────────────────────────┘ │
  └─────────────────────────────┘
```

## Code

```js
// Manual curry: one arg per call, closures stack up
const add = (a) => (b) => (c) => a + b + c;
add(1)(2)(3);          // 6
const add10 = add(10); // fixes a = 10, still waits for b, c
add10(5)(1);           // 16  -> reusable, pre-configured

// Partial application with bind: fix leading args now, rest later
function request(method, url) {
  return `${method} ${url}`;
}
const post = request.bind(null, "POST"); // method fixed
post("/orders"); // "POST /orders"

// Generic curry helper: collect args until the arity is met
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) return fn(...args);
    return (...more) => curried(...args, ...more);
  };
}
const vol = curry((l, w, h) => l * w * h);
vol(2)(3)(4); // 24
vol(2, 3)(4); // 24  -> mix and match
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Multi-arg function ko single-arg calls ki chain banana: `f(a)(b)(c)`. Partial = kuch args ab fix, baaki baad mein. |
| Kab/kaise hota hai | Har call arg ko closure mein rakh kar agla function return karta hai; last arg pe actual computation hota hai. |
| Kyun useful hai | Pre-configured reusable functions (`add5`, `post = request.bind(null, "POST")`), config-first APIs, point-free composition. |
| Interview trap | Currying strictly ek-arg-per-call hoti hai; `bind` se ya kai args ek saath fix karna partial application hai, pure currying nahi. |

## Wrong vs Right

```js
// Galat: har jagah discount rate baar-baar pass karna
function price(rate, amount) { return amount - amount * rate; }
price(0.1, 1000);
price(0.1, 250);
price(0.1, 80); // 0.1 repeat hota hai -> galti ki gunjaish
```

```js
// Sahi: rate ek baar fix karke ek specialised function banao
const withDiscount = (rate) => (amount) => amount - amount * rate;
const festive = withDiscount(0.1);
festive(1000); // 900
festive(250);  // 225
```

**Ek line mein:** Currying `f(a, b, c)` ko `f(a)(b)(c)` bana deti hai jahan har call closure mein ek arg fix karta hai, jisse ek general function se chhote pre-configured functions bante hain.
