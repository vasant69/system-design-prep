**Arrow vs Regular Functions – Complete Summary**

Dono function hain, par arrow sirf chhota syntax nahi hai — behaviour alag hai. Regular function ko apna `this` milta hai jo CALL time pe decide hota hai, apna `arguments` object milta hai, `new` se constructor ban sakta hai, aur declaration form hoist hota hai. Arrow function ke paas apna `this`/`arguments` hota hi nahi — wo lexically bahar wale scope se udhaar leta hai, `new` pe `TypeError` deta hai, aur expression hone ki wajah se hoist nahi hota. Rule: callback jisme outer `this` chahiye to arrow; object method, constructor, ya `arguments` chahiye to regular.

## Visual

```text
        REGULAR  function () {}          ARROW  () => {}
  ┌──────────────────────────────┐  ┌──────────────────────────────┐
  │ own this    ✓ (call-time)    │  │ own this    ✗ (lexical)      │
  │ arguments   ✓                │  │ arguments   ✗ (outer's)      │
  │ new-able    ✓ constructor    │  │ new-able    ✗ TypeError      │
  │ hoisted     ✓ (declaration)  │  │ hoisted     ✗ (expression)   │
  │ prototype   ✓                │  │ prototype   ✗                │
  └──────────────────────────────┘  └──────────────────────────────┘

  this BINDING inside a method's callback

  obj.method()
     │  this ──▶ obj
     ├─ setTimeout(function () { this ──▶ undefined / global })   ✗ lost
     └─ setTimeout(() =>       { this ──▶ obj (borrowed)     })   ✓ kept
```

## Code

```js
const timer = {
  label: "build",
  count: 0,
  start() {
    // timer.start() -> inside start(), `this` === timer (implicit binding)
    setInterval(() => {
      // arrow has NO own `this`: it borrows start()'s `this` = timer
      this.count++;
      console.log(this.label, this.count); // "build" 1, "build" 2, ...
    }, 1000);

    setInterval(function () {
      // plain function call by the timer -> `this` is NOT timer
      console.log(this === timer); // false
    }, 1000);
  },
};
timer.start();

function Person(name) {
  this.name = name; // regular fn works with `new`
}
new Person("Ravi"); // { name: "Ravi" }

const Bad = (name) => { this.name = name; };
// new Bad("x"); // TypeError: Bad is not a constructor
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Do function forms; arrow ke paas apna `this`, `arguments`, `prototype` nahi aur `new` support nahi. |
| Kab/kaise hota hai | Arrow ka `this` define hone ki jagah (lexical scope) se fix; regular ka `this` har call pe caller decide karta hai. |
| Kyun useful hai | Callback (setTimeout, map, event handler) mein arrow outer `this` bina `bind` ke rakh leta hai — cleaner code. |
| Interview trap | Object method arrow se mat likho: `this` object ko nahi, module/global ko point karega. Method regular rakho, uske andar ka callback arrow. |

## Wrong vs Right

```js
// Galat: object method as arrow -> `this` counter nahi hai
const counter = {
  n: 0,
  inc: () => {
    this.n++; // `this` = module scope, counter nahi
  },
};
counter.inc();
console.log(counter.n); // 0  (kabhi nahi badhta)
```

```js
// Sahi: method regular, andar ka callback arrow
const counter = {
  n: 0,
  inc() {
    [1].forEach(() => {
      this.n++; // arrow borrows inc()'s `this` = counter
    });
  },
};
counter.inc();
console.log(counter.n); // 1
```

**Ek line mein:** Arrow function `this`/`arguments` ko lexically bahar se leta hai aur `new` nahi hota — callbacks ke liye perfect, par object methods aur constructors regular function maangte hain.
