**async / await – Complete Summary**

`async`/`await` promises ke upar meethi syntax hai. `async` function hamesha ek promise return karta hai. `await` us function ko us line pe pause kar deta hai jab tak promise settle na ho — par thread block nahi hota, aur function baad mein wahin se settled value ke saath resume hota hai. Errors ke liye normal `try/catch` kaafi hai. Bada gotcha: jo kaam ek dusre pe depend nahi karte unhe alag-alag `await` mat karo — `Promise.all` se ek saath chalao.

## Visual

```text
await = async function ko PAUSE, thread ko nahi

async function load() {
  const u = await getUser();    ──┐ yahan pause, promise ka wait
  //                              │  (is beech main thread free — baaki code chalta hai)
  const c = await getCart(u);   ──┘ resume with value, phir agla pause
  return c.total;               ──▶ load() ka returned promise fulfil
}

SEQUENTIAL vs PARALLEL   (a, b, c independent, 300ms each)
  await a(); await b(); await c();      a───▶ b───▶ c───▶   total = a + b + c   ✗ slow
  await Promise.all([a(), b(), c()]);   a───▶
                                        b───▶   total = max(a, b, c)            ✓ fast
                                        c───▶
```

## Code

```js
// async fn hamesha promise deta hai; await settled value nikaalta hai
async function getTotal(userId) {
  try {
    const user = await getUser(userId); // pause -> resume with user
    // independent calls -> ek saath, sequential nahi
    const [cart, coupons] = await Promise.all([
      getCart(user.id),
      getCoupons(user.id),
    ]);
    return cart.total - coupons.discount;
  } catch (err) {
    // getUser / getCart / getCoupons mein se koi bhi reject -> yahan
    console.error("getTotal failed:", err.message);
    return 0; // fallback
  }
}

getTotal(1).then((t) => console.log("total:", t)); // total: 850
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Promises ke upar syntax — `async` fn promise return karta hai, `await` settle hone tak fn ko pause karta hai. |
| Kab/kaise hota hai | `await` ke baad ka code ek microtask ban jaata hai; thread free rehta hai, function baad mein resume hota hai. |
| Kyun useful hai | Async code sync jaisa top-to-bottom padha jaata hai; `try/catch`, loops, conditionals sab natural. |
| Interview trap | Independent kaam ko alag-alag `await` karna unhe serial bana deta hai — `Promise.all` use karo. |

## Wrong vs Right

```js
// Galat: independent calls ko ek-ek karke await -> total time add hota hai
const a = await getCart(id); // 300ms
const b = await getCoupons(id); // 300ms (a khatam hone ke baad shuru)
// total lagbhag 600ms — jabki dono independent hain
```

```js
// Sahi: dono ek saath fire, phir dono ka result
const [a, b] = await Promise.all([getCart(id), getCoupons(id)]);
// total lagbhag 300ms — max(300, 300)
```

**Ek line mein:** `async`/`await` promises ki padhne-mein-aasaan shakl hai jahan `await` function ko pause karta hai thread ko nahi, aur independent kaam `Promise.all` se parallel chalna chahiye.
