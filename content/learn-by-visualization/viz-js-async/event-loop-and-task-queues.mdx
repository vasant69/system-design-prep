**The Event Loop & Task Queues – Complete Summary**

Event loop hi wo cheez hai jisse single-thread JavaScript async kaam sambhaalta hai. Sync code call stack pe chalta hai. Ready hua async callback do queues mein se ek mein jaata hai: macrotask queue (`setTimeout`, DOM events, I/O) ya microtask queue (promise `.then`, `queueMicrotask`, `await` ke baad ka code). Loop ka rule: stack khaali ho to ek macrotask chalao, phir poori microtask queue drain karo, phir browser render kare, phir agla macrotask. Isi wajah se promise callbacks hamesha `setTimeout` se pehle chalte hain.

## Visual

```text
   ┌──────────── CALL STACK (1 thread) ────────────┐
   │  sync code yahan chalta hai — LIFO frames     │
   └───────────────────┬───────────────────────────┘
                       │  stack khaali?
                       ▼
              ┌──────────────────┐
              │    EVENT LOOP    │   har round:
              │  1 macrotask     │   1) ek macrotask chalao
              │  ALL microtasks  │   2) poori microtask queue drain karo
              │  then render     │   3) (maybe) browser paint
              └───┬──────────┬───┘
       pull 1 macro│         │pull ALL micro
   ┌───────────────▼──┐  ┌───▼─────────────────────┐
   │  MACROTASK QUEUE │  │   MICROTASK QUEUE       │
   │  setTimeout, I/O │  │  promise .then/.catch,  │
   │  DOM events      │  │  await cont., queueMicro│
   └──────────────────┘  └─────────────────────────┘

ORDERING EXAMPLE
  console.log("1");
  setTimeout(() => console.log("2"), 0);            // macrotask
  Promise.resolve().then(() => console.log("3"));   // microtask
  console.log("4");
  ── sync: 1, 4   ── drain micro: 3   ── next macro: 2
  OUTPUT:  1  4  3  2
```

## Code

```js
console.log("A"); // 1) sync

setTimeout(() => console.log("B"), 0); // macrotask -> sabse last

Promise.resolve()
  .then(() => console.log("C")) // microtask
  .then(() => console.log("D")); // D tab queue hoti hai jab C khatam ho

queueMicrotask(() => console.log("E")); // microtask, C ke baad queue hui

console.log("F"); // 2) sync

// sync pehle:      A, F
// microtasks next: C, E, D   (C aur E queue mein; C chalte hi D queue hui)
// macrotask last:  B
// OUTPUT: A F C E D B
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Loop jo stack khaali hone pe queues se callbacks uthaakar chalata hai — JS ka async engine. |
| Kab/kaise hota hai | Har ek macrotask ke baad poori microtask queue drain hoti hai, tab render, tab agla macrotask. |
| Kyun useful hai | Ye ordering samajh lo to `setTimeout(0)` vs `Promise.then` vs `await` ka output predict kar sakte ho. |
| Interview trap | `setTimeout(fn, 0)` "turant" nahi — minimum lagbhag 4ms clamp, aur saari pending microtasks usse pehle chalti hain. |

## Wrong vs Right

```js
// Galat: maan lena setTimeout(0) promise .then se pehle chalega
setTimeout(() => console.log("timeout"), 0);
Promise.resolve().then(() => console.log("promise"));
// Expectation: timeout, promise
// Actual:      promise, timeout   (microtask macrotask se pehle)
```

```js
// Sahi: microtask (promise) hamesha current macrotask ke turant baad,
// agle macrotask (setTimeout) se pehle
Promise.resolve().then(() => console.log("promise")); // 1
setTimeout(() => console.log("timeout"), 0); // 2
// Output: promise, timeout
```

**Ek line mein:** Event loop stack khaali hone pe ek macrotask chalata hai phir poori microtask queue drain karta hai — isi wajah se promise callbacks hamesha `setTimeout` se pehle chalte hain.
