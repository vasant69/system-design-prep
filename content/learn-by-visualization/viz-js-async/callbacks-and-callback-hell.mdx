**Callbacks & Callback Hell – Complete Summary**

Callback ek function hai jo tum doosre function ko de dete ho: "jab kaam ho jaaye tab ise chala dena". Async ke liye ye sabse purana mechanism hai, aur simple ek-baar ke kaam ke liye theek bhi hai. Dikkat tab hoti hai jab step B ko A ka result chahiye aur C ko B ka — har step agle callback ke andar ghusta jaata hai aur code pyramid ki tarah daayein badhta hai (pyramid of doom). Node ka convention: callback ka pehla argument `err` hota hai, use pehle check karo. Asli fix: named functions, aur usse behtar promises ya async-await jo nesting ko flat kar dete hain.

## Visual

```text
CALLBACK (basic)
  doAsync(input, function done(err, result) {   ◀── "jab ho jaaye, ye chalao"
     ...
  });

CALLBACK HELL   (har step pichle ke andar — pyramid banti hai)
  login(user, (err, u) => {
    getProfile(u, (err, p) => {
      getOrders(p, (err, o) => {
        getInvoice(o, (err, inv) => {
          render(inv);          ◀── 4 level deep, har level pe alag err check
        });
      });
    });
  });
        └────────┐  indentation ────▶ daayein badhti jaati hai

FLATTENED   (promise chain — sab ek hi level pe)
  login(user)
    .then(getProfile)
    .then(getOrders)
    .then(getInvoice)
    .then(render)
    .catch(handleError);   ◀── ek jagah saare errors
```

## Code

```js
// Error-first callback convention (Node style)
function getUser(id, callback) {
  setTimeout(() => {
    if (id <= 0) return callback(new Error("bad id")); // err pehle
    callback(null, { id, name: "Asha" }); // success: err = null
  }, 100);
}

getUser(1, (err, user) => {
  if (err) return console.error(err.message); // hamesha pehle check
  // agle step ko user chahiye -> yahin nest karna padta hai
  getUser(user.id + 1, (err2, next) => {
    if (err2) return console.error(err2.message);
    console.log(user.name, next.name); // "Asha" "Asha"
  });
});
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Ek function jo argument ki tarah pass hota hai aur "baad mein" call hota hai — async ka original mechanism. |
| Kab/kaise hota hai | Dependent async steps ko chain karne pe har step agle callback ke andar jaata hai, aur nesting deep hoti jaati hai. |
| Kyun useful hai | Simple ek-baar ke async (`setTimeout`, event listener, `fs.readFile`) ke liye callback bilkul theek hai. |
| Interview trap | `try/catch` async callback ke error ko nahi pakadta — error alag tick pe aata hai; isi wajah se error-first `err` argument. |

## Wrong vs Right

```js
// Galat: async error ko try/catch se pakadne ki koshish
try {
  getUser(-1, (err, user) => {
    if (err) throw err; // ye throw alag tick pe — bahar wala catch miss karega
  });
} catch (e) {
  console.log("caught?", e.message); // kabhi nahi chalta
}
```

```js
// Sahi: err ko callback ke andar hi handle karo, ya promise + catch
const getUserP = (id) =>
  new Promise((res, rej) =>
    getUser(id, (err, u) => (err ? rej(err) : res(u)))
  );

getUserP(-1).catch((e) => console.log("caught:", e.message)); // caught: bad id
```

**Ek line mein:** Callback "jab ho jaaye tab chalao" wala function hai; dependent steps ko nest karne se pyramid banti hai, jise error-first convention aur promises/async-await flatten karte hain.
