**Promises – Complete Summary**

Promise ek object hai jo kisi future value ka abhi-ka placeholder hai. Teen states: `pending` (chal raha hai), `fulfilled` (value mil gayi), `rejected` (error) — aur settle sirf ek baar hota hai, uske baad immutable. `.then`, `.catch`, `.finally` handlers attach karte hain. `.then` se plain value return karo to wo agle `.then` ko milti hai; promise return karo to chain uske settle hone ka wait karti hai — isi se nesting flat hoti hai. Kahin bhi reject ya throw ho to control seedha neeche wale `.catch` pe jaata hai.

## Visual

```text
STATE MACHINE   (settle sirf ek baar, phir lock)
                     ┌─────────────┐
      new Promise ──▶│   pending   │
                     └──────┬──────┘
              resolve(v)    │    reject(e)
              ┌─────────────┴─────────────┐
              ▼                           ▼
        ┌───────────┐               ┌───────────┐
        │ fulfilled │               │ rejected  │   ◀── ab change nahi
        └─────┬─────┘               └─────┬─────┘
            .then                       .catch

CHAIN   (har .then agli ko value deta hai)
  fetchUser()                        ──▶ { id: 1 }
    .then((u) => fetchCart(u.id))    ──▶ returns PROMISE, chain waits
    .then((cart) => cart.total)      ──▶ 999  (plain value aage jaata hai)
    .then((total) => render(total))
    .catch((err) => showError(err))  ──▶ upar kahin bhi reject/throw -> yahan
    .finally(() => hideSpinner())    ──▶ dono outcome pe chalta hai
```

## Code

```js
// Ek callback API ko promise mein wrap karna
const wait = (ms, value) =>
  new Promise((resolve, reject) => {
    if (ms < 0) reject(new Error("ms negative"));
    setTimeout(() => resolve(value), ms); // settle -> fulfilled
  });

wait(100, 2)
  .then((n) => n * 10) // plain value return -> next .then ko 20 milta hai
  .then((n) => wait(50, n + 1)) // PROMISE return -> chain 50ms wait karti hai
  .then((n) => console.log("result:", n)) // result: 21
  .catch((e) => console.error("fail:", e.message)) // koi bhi step fail -> yahan
  .finally(() => console.log("done")); // hamesha, last mein
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Future value ka object — `pending` se shuru, ek baar `fulfilled` ya `rejected` pe settle, phir immutable. |
| Kab/kaise hota hai | `.then` callbacks microtask queue mein jaate hain — current sync code khatam hone ke turant baad, `setTimeout` se pehle. |
| Kyun useful hai | Chaining nesting ko flat karti hai; ek `.catch` poori chain ke errors sambhal leta hai. |
| Interview trap | `.then` ke andar promise return karna bhool jao to chain wait nahi karti aur error swallow ho sakta hai. |

## Wrong vs Right

```js
// Galat: nested promise return nahi kiya -> chain wait nahi karti
fetchUser()
  .then((u) => {
    fetchCart(u.id).then((c) => console.log(c)); // return missing hai
  })
  .then(() => console.log("cart ready?")); // ye pehle chal jaata hai
```

```js
// Sahi: inner promise return karo -> chain properly wait karti hai
fetchUser()
  .then((u) => fetchCart(u.id)) // return -> next .then cart ka wait karega
  .then((c) => console.log(c))
  .then(() => console.log("cart ready")); // ab sach mein baad mein
```

**Ek line mein:** Promise ek baar settle hone wala future-value object hai jiski `.then` chaining callback nesting ko flat karti hai aur ek `.catch` saare errors pakad leta hai.
