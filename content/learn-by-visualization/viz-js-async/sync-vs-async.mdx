**Synchronous vs Asynchronous – Complete Summary**

Sync matlab har line apni baari mein chalti hai, aur jab tak wo poori nahi hoti agli line ruki rehti hai, isliye ek slow kaam poora page freeze kar deta hai. Async matlab slow kaam (timer, network call, file read) runtime ko de do; wo off-thread handle hota hai aur tumhara baaki code aage chalta rehta hai. Kaam poora hone pe result callback, promise ya `await` ke through wapas aata hai. JavaScript ke paas sirf ek call stack hai, isliye async hi wo tareeka hai jisse main thread block na ho.

## Visual

```text
SYNCHRONOUS   (ek hi line, sab wait karte hain)
  task A ▶────done
               task B ▶────done
                            task C ▶────done      total = A + B + C

ASYNCHRONOUS  (slow kaam offload, main thread free)
  main:  start ▶ fire timer ▶ next line ▶ next line ─────▶ (free)
                    │                                    ▲
                    ▼   Web API / OS timer               │  callback wapas
              [ 2s baad ready ] ──▶ [ queue ] ──loop──▶ run callback

  ┌────────────┐   stack   ┌──────────────┐   ready   ┌────────────────┐
  │ Call Stack │◀──empty?──│  Event Loop  │◀──pull────│ Callback Queue │
  │ (1 thread) │           │              │           │ (done tasks)   │
  └────────────┘           └──────────────┘           └────────────────┘
```

## Code

```js
// SYNC — blocking: har line agli ko rokti hai
console.log("1");
const start = Date.now();
while (Date.now() - start < 2000) {} // 2s tak thread jam — UI freeze
console.log("2"); // 2s baad print hota hai

// ASYNC — non-blocking: kaam offload, code aage badhta hai
console.log("A");
setTimeout(() => console.log("B"), 2000); // runtime ko diya, baad mein aayega
console.log("C");
// Output: A, C, ...(2s)... B
// "C" ne "B" ka wait nahi kiya — thread free raha
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Sync = line-by-line blocking; async = kaam start karo, result baad mein callback/promise/await se lo. |
| Kab/kaise hota hai | Slow kaam (timer, `fetch`, `fs`, DB) runtime/OS ko jaata hai; JS thread free rehta hai; ready hone pe callback queue se event loop use stack pe daalta hai. |
| Kyun useful hai | Ek thread hone ke bawajood app responsive rehta hai — 100 network calls ek dusre ka wait nahi karte. |
| Interview trap | Async ka matlab multi-threaded nahi hai. Aapka JS code hamesha ek hi thread pe chalta hai; sirf I/O off-thread hota hai. |

## Wrong vs Right

```js
// Galat: async result ko turant sync tarah use karna
let data;
fetch("/api/user").then((r) => (data = r));
console.log(data); // undefined — fetch abhi complete hi nahi hua
```

```js
// Sahi: result ko uske callback / await ke andar use karo
const res = await fetch("/api/user");
const data = await res.json();
console.log(data); // { id: 1, ... } — ab value ready hai
```

**Ek line mein:** Sync har line pe rukta hai; async slow kaam runtime ko saunp kar aage badhta hai aur result baad mein callback, promise ya await se milta hai.
