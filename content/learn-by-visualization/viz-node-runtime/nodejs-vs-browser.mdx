**Node.js vs Browser JavaScript – Complete Summary**

Language same hai (ECMAScript) — `for`, `map`, `Promise`, classes dono jagah identical. Farak **host environment** ka hai: browser tumhe `window`, `document`, DOM, `localStorage` aur ek strict sandbox deta hai; Node tumhe `global`, `process`, `require`, `Buffer`, `__dirname` aur `fs`/`net`/`os` deta hai jisse disk aur network directly touch hote hain. Event loop dono mein hai par alag implementation (Node = libuv, phases wale). Default module system bhi alag — browser ESM, Node historically CommonJS. Isliye browser ka `fetch`-DOM code Node mein aur Node ka `fs` code browser mein directly nahi chalta.

## Visual

```text
   SAME LANGUAGE CORE (ECMAScript): let/const, functions, Promise, class, JSON
   ───────────────────────────────────────────────────────────────────────────

        BROWSER host                    |            NODE host
   ─────────────────────────────────────┼─────────────────────────────────────
   global object : window / self        |   global object : global / globalThis
   DOM           : document, elements   |   filesystem    : fs, path
   storage       : localStorage, cookie |   process info  : process.argv, .env
   network       : fetch, XHR, WS       |   raw sockets   : net, http, dgram
   timers        : setTimeout (+ frame) |   timers        : setTimeout, setImmediate
   modules       : ESM import (default) |   modules       : CommonJS require (default)
   event loop    : browser's own impl   |   event loop    : libuv (phased)
   sandbox       : no disk, same-origin |   full OS access : disk, env, spawn

   shared today  : console, Promise, fetch(18+), URL, TextEncoder, queueMicrotask
```

## Code

```js
// This file runs cleanly in Node, throws in a browser:
console.log(typeof window); // browser: "object"   | node: "undefined"
console.log(typeof global); // browser: "undefined" | node: "object"

// Node-only: read a file from disk (no browser equivalent — sandbox)
const fs = require("node:fs");
const pkg = JSON.parse(fs.readFileSync("package.json", "utf8"));
console.log("app name:", pkg.name);

// Node-only: process + env vars for config
console.log("running on port", process.env.PORT ?? 3000);

// Browser-only (would be ReferenceError in Node < 18 style code):
// document.querySelector("h1").textContent = "hi";
// localStorage.setItem("token", "abc");

// Shared / portable APIs — safe in both:
const now = new URL("https://ex.com/a?b=1").searchParams.get("b"); // "1"
queueMicrotask(() => console.log("runs after current stack, both hosts"));
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | Ek hi JS language, do alag hosts — browser (UI + sandbox) aur Node (server + OS access). |
| Kab/kaise hota hai | Engine JS parse karta hai; phir host apne global object aur built-in objects inject karta hai (`window` vs `process`/`global`). |
| Kyun useful hai | Language skill transfer hoti hai; par pata hona chahiye kaun sa API kahan milega, warna runtime crash. |
| Interview trap | "`fetch` sirf browser mein hai" — Node 18+ mein `fetch` global hai. Ulta, `require` browser mein nahi. |

## Wrong vs Right

```js
// Galat: browser assumptions ko Node module mein daal dena
function saveToken(t) {
  localStorage.setItem("token", t); // ReferenceError: localStorage is not defined
}
// Node ke paas localStorage nahi — wo browser storage API hai.
```

```js
// Sahi: host ke hisaab se sahi API — Node mein fs / env, browser mein localStorage
const fs = require("node:fs");
function saveToken(t) {
  fs.writeFileSync(".token", t); // Node: file pe likho
}
// Ya config ke liye: process.env.TOKEN (secrets hardcode mat karo)
```

**Ek line mein:** Node aur browser same JavaScript chalate hain par alag khilona-dabbe dete hain — browser mein DOM aur sandbox, Node mein filesystem, process aur network.
