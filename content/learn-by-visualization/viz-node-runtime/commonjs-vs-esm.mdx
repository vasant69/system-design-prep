**CommonJS vs ES Modules – Complete Summary**

Node ke do module systems hain. **CommonJS (CJS)** original hai: `require('x')` **synchronously** file load karta hai, use ek baar run karta hai, `module.exports` return karta hai, aur result **cache** kar deta hai (doosri `require` same object deti hai). Path runtime pe compute ho sakta hai — `require(someVar)` chalta hai. **ES Modules (ESM)** JavaScript standard hai: `import`/`export` **static** hain — Node code chalne se pehle poora import graph resolve karta hai, loading **async** hai, aur exported bindings **live** hote hain (exporter ne value badli to importer ko nayi dikhti hai). Node decide karta hai per file: `.mjs` = ESM, `.cjs` = CJS, warna nearest `package.json` ka `"type"` field (`"module"` = ESM, default/absent = CJS).

## Visual

```text
   CommonJS (require)                    ES Modules (import)
   ─────────────────                     ───────────────────
   line-by-line execution                parse whole file FIRST
      require('./a')  ─── STOP,          collect every import/export
        run a.js fully, cache,           build graph, load async
        return module.exports            THEN run modules bottom-up
      ...next line...

   module.exports = { fn }               export function fn() {}
   const { fn } = require('./a')         import { fn } from './a.js'
        (a COPY of the value)                 (a LIVE binding)

   dynamic:  require(name) OK            import(name)  -> only via import()
   __dirname / __filename: built-in      import.meta.url -> derive them
   top-level await: NO                   top-level await: YES

   file type:  .cjs = CJS   |   .mjs = ESM   |   .js = follows package.json "type"
```

## Code

```js
// ---- CommonJS: math.cjs ----
function add(a, b) { return a + b; }
module.exports = { add };           // attach to the exports object

// ---- consumer.cjs ----
const { add } = require("./math.cjs"); // sync, runs math.cjs once, then cached
console.log(add(2, 3));                 // 5
console.log(__dirname);                 // built-in, no setup

// ---- ES Module: math.mjs ----
export function add(a, b) { return a + b; } // named export, resolved statically

// ---- consumer.mjs ----
import { add } from "./math.mjs";        // hoisted; math.mjs loads before this runs
import { readFile } from "node:fs/promises";
const url = new URL(".", import.meta.url); // __dirname equivalent
const data = await readFile("./config.json", "utf8"); // top-level await: allowed
console.log(add(2, 3), url.pathname);

// ESM can load CJS: import pkg from "some-cjs-lib" (default = module.exports)
// CJS can load ESM only via: const mod = await import("./thing.mjs")
```

## Point vs Short baat

| Point | Short baat |
|---|---|
| Kya hai | CJS = Node ka original `require`/`module.exports` system. ESM = JS standard `import`/`export`. |
| Kab/kaise hota hai | CJS: sync load, run once, cache, return exports copy. ESM: static parse -> async graph resolve -> run; live bindings. File type `.cjs`/`.mjs` ya `package.json` `"type"` se. |
| Kyun useful hai | ESM standard hai (browser + Node same), static analysis se tree-shaking aur circular-dep handling behtar, top-level await milta hai. CJS simple + fully dynamic + har purani lib mein hai. |
| Interview trap | ESM mein `require`, `__dirname`, `module.exports` nahi hote (`import.meta.url` use karo). ESM se CJS `import` kar sakte ho, par CJS se ESM sirf dynamic `import()` se. `.js` ka behaviour `package.json` `"type"` pe depend karta hai — assume mat karo. |

## Wrong vs Right

```js
// Galat: package.json mein "type": "module" hai, par file CJS syntax use kar rahi
// index.js
const express = require("express");   // ReferenceError: require is not defined in ES module scope
console.log(__dirname);               // __dirname is not defined
```

```js
// Sahi: ESM syntax + ESM equivalents (ya file ko .cjs rename karo)
// index.js  (with "type": "module")
import express from "express";
import { dirname } from "node:path";
import { fileURLToPath } from "node:url";
const __dirname = dirname(fileURLToPath(import.meta.url));
```

**Ek line mein:** CommonJS `require` synchronously chalta, cache karta aur value ki copy deta hai, jabki ES Modules static `import`/`export` async graph se resolve hote hain, live bindings dete hain, aur JavaScript ka official standard hain.
