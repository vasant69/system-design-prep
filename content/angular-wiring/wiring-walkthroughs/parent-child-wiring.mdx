Do components: `ParentComponent` ek list rakhta hai, `ItemComponent` ek item dikhata hai aur "remove" event upar bhejta hai. Yahan trace karna hai ki **data neeche kaise jaata hai (`@Input`)** aur **event upar kaise aata hai (`@Output`)**.

## Files

```ts
// app/item.component.ts  — the CHILD
import { Component, Input, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-item',
  templateUrl: './item.component.html',
})
export class ItemComponent {
  @Input() name = '';                    // data comes IN from the parent
  @Output() remove = new EventEmitter<string>();  // events go OUT to the parent

  onRemoveClick() {
    this.remove.emit(this.name);         // fire the event, payload = this.name
  }
}
```

```html
<!-- app/item.component.html  — the CHILD view -->
<li>
  {{ name }}
  <button (click)="onRemoveClick()">remove</button>
</li>
```

```ts
// app/parent.component.ts  — the PARENT
import { Component } from '@angular/core';

@Component({
  selector: 'app-parent',
  templateUrl: './parent.component.html',
})
export class ParentComponent {
  fruits = ['apple', 'banana', 'cherry'];

  handleRemove(name: string) {           // receives the child's event
    this.fruits = this.fruits.filter(f => f !== name);
  }
}
```

```html
<!-- app/parent.component.html  — the PARENT view -->
<h2>Fruits</h2>
<ul>
  <li *ngFor="let fruit of fruits">
    <app-item
      [name]="fruit"
      (remove)="handleRemove($event)">
    </app-item>
  </li>
</ul>
```

```ts
// app/app.module.ts  — both components must be declared
import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { AppComponent } from './app.component';
import { ParentComponent } from './parent.component';
import { ItemComponent } from './item.component';

@NgModule({
  declarations: [AppComponent, ParentComponent, ItemComponent],
  imports: [BrowserModule],
  bootstrap: [AppComponent],
})
export class AppModule {}
```

(`app.component.html` me bas `<app-parent></app-parent>` hai.)

## Step-by-Step Flow Trace

**Render phase (data neeche jaata hai):**

1. App boot hota hai, `AppComponent` render hota hai, uske template me `<app-parent>` hai — Angular `ParentComponent` ka instance banata hai.
2. `ParentComponent` ka template render hota hai. `*ngFor` `fruits` array par ghoomta hai — 3 baar.
3. Har iteration me Angular ek `<app-item>` banata hai, yani `ItemComponent` ka ek naya instance.
4. `[name]="fruit"` ek **property binding** hai: Angular current `fruit` string ko child ke `@Input() name` par set kar deta hai. `'apple'`, phir `'banana'`, phir `'cherry'`.
5. `(remove)="handleRemove($event)"` ek **event binding** hai: Angular child ke `@Output() remove` EventEmitter ko subscribe kar leta hai. Abhi kuch emit nahi hua.
6. Har `ItemComponent` apna template render karta hai — `{{ name }}` ki jagah uska input value aa jaata hai. Screen par 3 list items.

**Event phase (event upar aata hai):**

7. User "banana" wale item ka "remove" button click karta hai.
8. Us `ItemComponent` instance ka `(click)="onRemoveClick()"` fire hota hai.
9. `onRemoveClick()` `this.remove.emit(this.name)` call karta hai — yani us instance ka `name` (`'banana'`) payload ke saath event emit hota hai.
10. Parent ne step 5 me is event ko subscribe kiya tha, isliye `handleRemove('banana')` chalta hai. `$event` = emitted payload = `'banana'`.
11. `handleRemove` `this.fruits` ko ek **naya** array bana deta hai jisme `'banana'` nahi hai.
12. Method return hone ke baad change detection chalta hai. `ParentComponent` ka template re-check hota hai.
13. `*ngFor` dekhta hai ki `fruits` ab 2 items ka hai (pehle 3 tha). Angular `'banana'` wale `<app-item>` ko DOM se hata deta hai (aur us `ItemComponent` instance ko destroy karta hai).
14. Screen par ab sirf "apple" aur "cherry".

## One-Line Wiring Summary

`[name]="fruit"` parent ki value ko child ke `@Input` me push karta hai, aur `(remove)="handleRemove($event)"` child ke `EventEmitter.emit()` ko parent ke handler se jodta hai — data ek taraf neeche, event doosri taraf upar.

## Self-Check Questions

1. Step 4 me `[name]="fruit"` ke bina agar sirf `name="fruit"` (bina square brackets) likha hota, to child ke `name` input me kya value jaati?
2. `handleRemove` agar `this.fruits.splice(...)` se array ko mutate karta (naya array banane ki jagah), to kya UI phir bhi update hota? Kis cheez par depend karta hai?
3. `$event` step 10 me kahan se aata hai — DOM ka click event hai ya kuch aur?
