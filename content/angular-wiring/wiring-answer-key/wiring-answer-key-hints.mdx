Har walkthrough ke Self-Check Questions attempt karne ke baad yahan aa kar apna jawab match karo. Ye **hints** hain — poora explanation nahi. Agar tumhara reasoning in hints se align karta hai, tum flow samajh gaye ho.

## 1. Basic Bootstrap Wiring

1. **`selector` `'my-app'`, index.html me `<app-root>`** — App boot to hoga (koi error nahi), par screen khaali dikhega. `<app-root>` tag DOM me hai par ab kisi component ka `selector` usse match nahi karta, isliye Angular usme kuch mount nahi karta. Wiring ki key: `bootstrap` component ka `selector` aur `index.html` ka tag exactly same hone chahiye.
2. **`declarations` vs `bootstrap`** — `declarations`: ye module `AppComponent` ko "owns" karta hai, isliye uska template/selector is module ke andar use ho sakta hai. `bootstrap`: sirf root module me — Angular ko batata hai ki app start hote hi kaunsa component `index.html` ke matching tag me mount karna hai. `bootstrap` wala component `declarations` me hona bhi zaroori hai.
3. **`{{ count }}` update ka step** — `increment()` sirf `this.count` badalta hai (state change). DOM tab update hota hai jab uske baad Angular **change detection** chalata hai (click ko Zone.js ne patch kiya hua hai). State change aur DOM patch do alag steps hain.

## 2. Parent-Child Communication Wiring

1. **`name="fruit"` (bina brackets)** — Child ke `@Input() name` me literal string `"fruit"` jaata hai (chaaron items ke liye same), tumhari loop variable ki value nahi. Square brackets Angular ko batate hain "right side ek expression hai, static text nahi".
2. **`splice` se mutate** — Is chhote example me UI phir bhi update **ho jaayega**, kyunki default change detection har event ke baad poore tree ko re-check karta hai aur `*ngFor` array ki current length/contents dekh leta hai. Lekin `OnPush` component ya memoized pipe ke saath ye **toot jaata** — wahan reference badalna (naya array) zaroori hai. Isiliye immutable update default best practice hai.
3. **`$event` step 10 me** — Ye DOM ka click event **nahi** hai. Custom `@Output` par `$event` wahi value hai jo child ne `this.remove.emit(this.name)` me pass ki — yani `'banana'` string. DOM event object sirf native events (`(click)`, `(input)`) par milta hai.

## 3. Service + Dependency Injection Wiring

1. **`providers: [CounterService]` in `ControlsComponent`** — `DisplayComponent` ko **alag** instance milega. Component-level `providers` us component (aur uske children) ke liye ek naya instance banata hai jo root wale ko shadow karta hai. `DisplayComponent` component tree me `ControlsComponent` ka child nahi hai, isliye wo root injector se apna alag instance leta hai — dono ka `_count` independent, screen sync nahi hoga.
2. **Instance `new` hone ka step** — Boot par **nahi**. Registration boot par hota hai, par `new CounterService()` tab hota hai jab pehli baar koi component use inject maange — is example me jab Angular `ControlsComponent` ka constructor resolve karta hai (step 5). `DisplayComponent` ko wahi cached instance milta hai (step 8).
3. **`DisplayComponent` update ka trigger** — Click event (jo `ControlsComponent` me hua) Zone.js ke through change detection trigger karta hai. CD poore tree par chalta hai, `DisplayComponent` ka `{{ counter.count }}` re-evaluate hota hai, nayi value milti hai (kyunki service instance shared hai), DOM update ho jaata hai. Koi `@Input` nahi — connection sirf shared service object ke through.

## 4. Routing Wiring

1. **`<router-outlet>` hata do** — "About" link click par URL `/about` ho jaayega aur Router `AboutComponent` ka instance bhi bana lega, par use render karne ki koi jagah nahi hai — isliye screen par kuch naya nahi dikhega (bas nav links). `<router-outlet>` wo marker hai jo batata hai matched component DOM me kahan aayega.
2. **`href="/about"` (plain)** — Browser ek full page navigation karega: poora Angular app phir se download aur boot hoga, saari in-memory state chali jaayegi. `routerLink` iske ulta click intercept karke `preventDefault` karti hai aur client-side navigation karti hai — koi reload nahi, `history.pushState` se URL update.
3. **Home par wapas aana** — Nahi, `HomeComponent` apni purani state yaad **nahi** rakhega. Navigate karte waqt wo instance destroy ho gaya tha; wapas aane par ek **naya** `HomeComponent` instance banega (`ngOnInit` phir chalega). Component-level state chali jaati hai jab tak wo state kisi service me na rakhi ho.

## 5. Observable / RxJS Wiring

1. **`this.users$ = this.userService.getUsers()` se HTTP call?** — Galat, turant call nahi jaati. Ye line sirf ek cold `Observable` object `users$` ko assign karti hai. Actual HTTP request tab jaati hai jab koi subscribe kare — is example me jab template ka `async` pipe render hote waqt subscribe karti hai (step 7).
2. **`| async` hata do** — `*ngFor` ko ek `Observable` object milega, `User[]` array nahi. `*ngFor` us par iterate nahi kar paayega (ya error, ya kuch nahi dikhega). `async` pipe hi wo cheez hai jo stream ko subscribe karke actual value nikaalti hai.
3. **`.subscribe()` in `ngOnInit`** — Tumhe subscription ko ek variable me rakhna padega aur `ngOnDestroy` me `unsubscribe()` call karna padega (ya `takeUntilDestroyed()` / `takeUntil(destroy$)` use karna padega) taaki component destroy hone par leak na ho. `async` pipe ye teardown khud karti hai — uska apna `ngOnDestroy` unsubscribe kar deta hai.
