<SimpleDefinition>

In JavaScript a function is a **value** — just like a number or a string. You can store it in a variable, pass it to another function as an argument, and return it from a function. This is what "functions are first-class citizens" means. A **callback** is a function you hand to some other code so that it can call it back later — usually when a task finishes. Node's whole non-blocking model rests on this single idea.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Node.js seekhne se pehle JavaScript ka **ek** concept solid hona chahiye, kyunki Node ka poora async model isi pe khada hai: **function bhi ek value hai**, aur us value ko "baad mein chalane ke liye" doosre code ko de dena — yahi **callback** hai.

### Ye kya hai — first-class function

"First-class citizen" ka matlab: language function ke saath wahi sab karne deti hai jo ek normal value (number, string, object) ke saath. Concretely:

- function ko **variable** mein rakh sakte ho
- function ko doosre function mein **argument** ki tarah pass kar sakte ho
- function se **function return** kar sakte ho

```javascript
// 1. variable mein function
const greet = function (name) {
  return "Hello " + name;
};

// 2. function ko argument ki tarah pass karna
function runTwice(fn) {
  fn("Vasant");
  fn("Vasant");
}

// 3. function se function return karna
function multiplier(factor) {
  return function (n) {
    return n * factor;
  };
}
```

Jo function doosre function ko leta hai ya return karta hai, use **higher-order function** bolte hain. `map`, `filter`, `forEach`, `setTimeout`, Express ka `app.get` — sab higher-order functions hain.

### Ye kyun exist karta hai

Agar function ek value na hoti, toh tum kisi API ko ye nahi bol sakte: "ye kaam background mein karo, aur jab **ho jaye** toh ye wala function chala dena." Tumhe wo "ye wala function" ek value ki tarah pass karna padta hai. Isi wajah se `fs.readFile`, event listeners, `Array.prototype.map` — sab isi pattern pe bane hain. First-class functions ke bina Node ka non-blocking model possible hi nahi tha.

### Internally kaise kaam karta hai

V8 (Node ka JS engine) mein function ek special **callable object** hota hai. Iske paas properties bhi hoti hain — `fn.name`, `fn.length` (kitne parameters). Jab tum `const g = greet` likhte ho, toh poora function copy nahi hota — sirf uska **reference** (memory address) copy hota hai. Isliye `greet` aur `g` dono ek hi function object ko point karte hain.

Jab tum function ko **call** karte ho (`fn()`), tab engine ek naya **execution context** banata hai (parameters, local variables) aur use call stack pe push karta hai. Function ko sirf **pass** karna (bina `()`) koi execution context nahi banata — wo bas reference ghoomta hai.

### Simple real-life analogy

Function ek **recipe card** hai. Card khud khana nahi — instructions ka set hai. Us card ko tum:

- daraz mein rakh sakte ho (variable)
- dost ko de sakte ho (argument pass)
- ek badi recipe-book se nikaal ke de sakte ho (return)

Card dena = function pass karna. Card padh ke actually khana banana = function call karna (`()` lagana).

Callback: restaurant mein order diya, phir tum waiter ke saamne khade nahi rehte. Tum apna kaam karte ho. Khana ready hone par waiter aake **tumhe bulata hai** — tumne apna phone number (callback) de diya tha.

### Code — line by line

```javascript
const fs = require("fs");

console.log("1. Start");

fs.readFile("note.txt", "utf8", function (err, data) {
  if (err) {
    console.error("File padhne mein error:", err.message);
    return;
  }
  console.log("3. File content:", data);
});

console.log("2. End (file abhi background mein padhi ja rahi hai)");
```

- `const fs = require("fs")` — Node ka built-in File System module load kiya.
- `console.log("1. Start")` — turant chalta hai, call stack pe.
- `fs.readFile("note.txt", "utf8", function (err, data) {...})` — 3 arguments: file ka naam, encoding (`"utf8"` isliye taaki `data` string mile, raw Buffer nahi), aur teesra argument **callback function**. Node ise tab call karega jab file read ho jaye.
- `function (err, data)` — Node ka standard callback shape: **pehla argument hamesha error**, doosra result. Ise **error-first callback** convention bolte hain.
- `if (err) { ...; return; }` — pehle error check. File na mile toh `err` bhara hoga, `data` `undefined`. `return` isliye taaki neeche `data` use na ho.
- `console.log("2. End ...")` — ye line callback se **pehle** print hoti hai, kyunki `readFile` async hai — wo wait nahi karwata.

Output:

```text
1. Start
2. End (file abhi background mein padhi ja rahi hai)
3. File content: <file ka data>
```

Ye `1, 2, 3` ka order hi async ka pura point hai.

### Sync callback vs async callback

Do type ke callbacks hote hain, aur inhe alag karna zaroori hai:

- **Synchronous callback** — turant, isi tick mein chal jata hai. `[1,2,3].map(n => n * 2)` — `map` apna kaam khatam karne se pehle callback ko 3 baar call kar leta hai.
- **Asynchronous callback** — baad mein, kaam khatam hone par chalta hai. `fs.readFile(path, cb)`, `setTimeout(cb, 0)`.

`try/catch` sirf **sync** code pakadta hai. Async callback ke andar ka error `try/catch` nahi pakadega jo `readFile` ke around lipta ho — isi wajah se error-first convention exist karta hai.

### Day-to-day use

- `arr.map(fn)`, `arr.filter(fn)`, `arr.forEach(fn)`, `arr.sort(fn)`
- `setTimeout(fn, ms)`, `setInterval(fn, ms)`
- Express: `app.get("/users", handlerFn)` — route handler ko pass karte ho
- `emitter.on("data", fn)` — event aane par fn chalega
- Middleware factories: `app.use(requireRole("admin"))` — function jo function return karta hai

### Kab use karna chahiye

- Jab koi library sirf callback-based API deti ho (purane npm packages)
- Ek simple, **ek-baar-ka** event listener (`stream.on("end", cb)`)
- Jab callback baar-baar call hoga (event streams) — Promise sirf ek baar resolve hota hai, callback multiple times chal sakta hai

### Kab use nahi karna chahiye

- Jab 2-3 async steps **ek ke baad ek** karne hon — tab nested callbacks "callback hell" ban jate hain:

```javascript
readFile(a, (e, d1) => {
  readFile(b, (e, d2) => {
    readFile(c, (e, d3) => {
      // 3 level deep, error handling har level pe repeat, unreadable
    });
  });
});
```

  Aise case mein Promise / async-await use karo.

### Pros and cons

**Pros**

- Concept simple, koi extra object/wrapper nahi
- Har jagah supported, bahut low overhead
- Multiple invocations possible (events)

**Cons**

- Nesting se code unreadable
- Error handling har level pe dubara likhna padta hai
- `try/catch` async callback pe kaam nahi karta
- Return value seedhe nahi milti — sab callback ke andar

### Alternatives

- **Promises** — chaining se flat code, ek jagah `.catch()`
- **async/await** — sabse readable, `try/catch` wapas kaam karta hai (Promise ke upar syntax sugar)
- **EventEmitter / Streams** — jab ek source se **multiple** values aayengi over time
- **`util.promisify(fn)`** — error-first callback wale function ko Promise-returning bana deta hai

### Interview mein "Why did you use a callback here?"

> "Ye ek single event listener tha — mujhe stream ke `end` event par ek hi baar cleanup chalana tha, isliye callback sabse seedha fit tha; Promise wrap karna over-engineering hota. Jaha mujhe sequential async steps chahiye the, wahan maine async/await use kiya kyunki wo flat rehta hai aur `try/catch` se error handling centralize ho jati hai. Callback-based legacy API ke liye maine `util.promisify` use kiya taaki baaki codebase consistent rahe."

</Hinglish>

<Callout type="tip">

`fn` pass karna aur `fn()` pass karna alag cheezein hain. `setTimeout(greet, 1000)` — 1 second baad `greet` chalega. `setTimeout(greet(), 1000)` — `greet` **abhi** chal gaya, aur uska return value `setTimeout` ko mila (aksar `undefined`). Bracket = "abhi chalao".

</Callout>

## Real World Example

<RealWorld company="Express / Connect middleware">

Har Express app callbacks pe chalti hai. `app.get("/employees", (req, res) => { ... })` mein tum route handler ko pass karte ho — Express use tab call karta hai jab koi request us path pe aati hai. Middleware bhi wahi: `app.use((req, res, next) => { ...; next(); })`. `next` khud ek callback hai jo Express deta hai — use call karke tum "agla middleware chalao" bolte ho. Poora request pipeline first-class functions ki ek chain hai.

</RealWorld>

<RealWorld company="Node core: fs, http, streams">

Node ke core modules ka original API pura error-first callback-based hai: `fs.readFile`, `fs.writeFile`, `dns.lookup`, `crypto.pbkdf2`. `http.createServer((req, res) => { ... })` mein callback har incoming request par chalta hai — ye ek async callback hai jo server ki puri zindagi mein hazaaron baar call hota hai. `fs.promises` aur `stream/promises` baad mein add hue jab Promises standard ban gaye, lekin callback API aaj bhi supported hai backward compatibility ke liye.

</RealWorld>

## Numbers That Matter

<Numbers>

- Ek function reference pass karne ka cost practically **zero** hai — sirf ek pointer copy hota hai, function body dobara allocate nahi hoti.
- `setTimeout(fn, 0)` ka callback **turant nahi** chalta — minimum delay browsers/Node mein historically **~1 ms** clamp hota hai, aur wo bhi tabhi jab call stack khali ho.
- Callback hell ki practical dard-limit: **3+ levels** nesting ke baad code review mein log complain karna shuru karte hain.
- `util.promisify` Node mein **v8.0.0 (2017)** se hai — usse pehle log manually `new Promise` wrap karte the ya `bluebird` jaisi library use karte the.

</Numbers>

## Interview Angle

<InterviewAngle>

Ye topic warm-up round mein aata hai, aur interviewer 2 cheezein dekhta hai: (1) kya tum `fn` vs `fn()` ka farak jaante ho, (2) kya tum samajhte ho ki callback **kab** chalta hai (sync vs async, aur "baad mein" ka matlab event loop).

Achhe jawaab ka shape:

1. **Definition** — "function ek value hai; callback wo function jo main kisi aur code ko deta hoon taaki wo baad mein use call kare."
2. **Kyun** — "Node single-threaded aur non-blocking hai; I/O ke liye main ek callback deta hoon aur main thread free rehta hai."
3. **Error-first** — "async callback mein `try/catch` kaam nahi karta, isliye Node ne convention banayi ki pehla arg error ho."
4. **Trade-off** — "sequential async ke liye ab main async/await pasand karta hoon; callback sirf single event listeners ya legacy API ke liye."

Red flag jo interviewer sunna nahi chahta: "callback aur promise same cheez hai" — nahi, Promise ek object hai jo future value represent karta hai; callback sirf ek function hai.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Function ko pass karte waqt galti se call kar dena.** `arr.forEach(doThing())` likh diya `arr.forEach(doThing)` ke bajaye. Pehle wale mein `doThing` ek baar abhi chal gaya aur uska return value (aksar `undefined`) `forEach` ko mila — loop kuch nahi karega ya crash karega. Bracket tabhi lagao jab tumhe abhi result chahiye.

</Mistake>

<Mistake>

**Async callback ke around `try/catch` lagana aur sochna error pak jayega.** `try { fs.readFile(p, cb) } catch (e) {}` — yahan `catch` sirf `readFile` ko *call karne* ki sync error pakadega, file read fail hone wali error nahi. Wo error `cb` ke `err` argument mein aati hai. Async error hamesha callback ke pehle argument se handle karo.

</Mistake>

<Mistake>

**Error check bhool jana.** Callback ke andar seedhe `data` use kar lena bina `if (err)` ke. Jab file missing ho, `data` `undefined` hoga aur crash "cannot read property of undefined" ke saath hoga — asli wajah (file nahi mili) chhup jayegi. Har error-first callback pehli line: `if (err) return ...`.

</Mistake>

<Mistake>

**Callback se value `return` karke bahar use karne ki koshish.** `function readIt() { fs.readFile(p, (e, d) => { return d; }); }` — ye `d` sirf callback se return hota hai, `readIt` se nahi. `readIt()` `undefined` dega. Async result ko ya toh callback ke andar hi use karo, ya Promise return karo.

</Mistake>

<Mistake>

**Callback ko dono taraf se call karna — error aur success.** Custom function likhte waqt `if (err) callback(err); callback(null, data);` — `return` na hone se error case mein callback do baar chala. Hamesha `return callback(err);` likho.

</Mistake>

## Quick Revision

<QuickRevision>

- **First-class function** = function ek value hai: variable mein rakho, argument pass karo, return karo.
- **Higher-order function** = jo function ko leta ya return karta hai (`map`, `setTimeout`, `app.get`).
- **Callback** = wo function jo tum kisi aur code ko dete ho taaki wo "baad mein" use call kare.
- **Sync callback** turant chalta hai (`map`); **async callback** kaam khatam hone par (`readFile`, `setTimeout`).
- **Error-first convention**: `(err, data) => {}` — pehla arg hamesha error, pehli line `if (err) return ...`.
- `try/catch` async callback ka error **nahi** pakadta — isliye error-first exist karta hai.
- `fn` = "baad mein chalana"; `fn()` = "abhi chalao".
- 3+ levels nesting = **callback hell** → Promise / async-await pe switch karo.
- Legacy callback API ko `util.promisify` se Promise mein badlo.

</QuickRevision>
