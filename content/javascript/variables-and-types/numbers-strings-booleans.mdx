<SimpleDefinition>

`number`, `string`, and `boolean` are three of JavaScript's seven primitives. JavaScript has **one** number type — a 64-bit IEEE-754 float — so there is no separate integer type, and `0.1 + 0.2 !== 0.3`. Strings are **immutable** sequences of UTF-16 code units; every string method returns a new string. Booleans have only `true` and `false`, but the wrapper object `new Boolean(false)` is itself **truthy**. `BigInt` exists for integers beyond `Number.MAX_SAFE_INTEGER`.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Ye teen types tumhare 90% data hain — IDs, names, flags, prices. Inke edge-cases (float precision, string immutability, boolean wrapper trap) interviews mein aur production mein dono jagah bite karte hain.

### Ye kya hai — teen basic primitives

- **`number`** — har numeric value. Integer, decimal, negative, `Infinity`, `NaN` — sab ek hi type.
- **`string`** — text. Single `'`, double `"`, ya backtick `` ` `` (template literal).
- **`boolean`** — sirf `true` ya `false`.

### `number` — ek hi type, IEEE-754 float64

Baaki languages mein `int`, `long`, `float`, `double` alag hote hain. JavaScript mein **sirf `number`**, aur wo hamesha 64-bit floating point (IEEE-754 "double") hai. `42` bhi float hai, bas uska fractional part `0` hai.

```javascript
0.1 + 0.2;              // 0.30000000000000004
0.1 + 0.2 === 0.3;      // false
(0.1 + 0.2).toFixed(2); // "0.30"  -- string, display ke liye
```

- `0.1` aur `0.2` binary floating point mein **exactly** represent nahi ho sakte (jaise `1/3` decimal mein `0.333...`). Chhoti si error har operation mein carry hoti hai.
- Isliye money ko kabhi float mein mat rakho — paise (integer) mein store karo, ya decimal library use karo.

**Safe integer range:**

```javascript
Number.MAX_SAFE_INTEGER;      // 9007199254740991  (2^53 - 1)
Number.MAX_SAFE_INTEGER + 1;  // 9007199254740992
Number.MAX_SAFE_INTEGER + 2;  // 9007199254740992  -- galat! precision khatam
```

Is limit se aage integers reliably represent nahi hote — do alag numbers same bit-pattern share karne lagte hain.

**Special values:**

- `NaN` — "Not a Number", par type `number` hai. `0/0`, `Number("abc")`, `Math.sqrt(-1)` isse dete hain.
- `Infinity` / `-Infinity` — `1/0`, ya overflow (`1e308 * 10`).

**Parsing:**

```javascript
Number("42");      // 42
Number("42px");    // NaN   -- strict, poora string number hona chahiye
Number("");        // 0     -- gotcha
parseInt("42px");  // 42    -- jitna parse ho sake
parseInt("3.9");   // 3     -- integer part only
parseFloat("3.9x");// 3.9
parseInt("ff", 16);// 255   -- radix hamesha do (default base ka bharosa mat karo)
```

### `string` — immutable UTF-16

String **immutable** hai — ek baar bana, badla nahi ja sakta. Har "modify" method ek **naya** string return karta hai.

```javascript
let s = "hello";
s[0] = "H";          // silently ignore -- s abhi bhi "hello"
s = s.toUpperCase(); // "HELLO" -- naya string, reassign kiya
```

**Common methods (koi bhi original ko mutate nahi karta):**

```javascript
"  Hello World  ".trim();          // "Hello World"
"Hello World".slice(0, 5);         // "Hello"
"a,b,c".split(",");                // ["a", "b", "c"]
"Hello".includes("ell");           // true
"2024-01".replace("-", "/");       // "2024/01"
"7".padStart(3, "0");              // "007"
"Hello".indexOf("l");              // 2
"Hello".at(-1);                    // "o"  -- negative index
```

**`.length` aur emoji caveat:**

```javascript
"hello".length;   // 5
"café".length; // 5 -- 'é' as e + combining accent = 2 code units
"\u{1F600}".length;  // 2 -- emoji ek "astral" char, 2 UTF-16 code units
[..."\u{1F600}"].length; // 1 -- spread iterator code points pe chalta hai
```

`.length` **code units** ginta hai, "user-perceived characters" nahi. Emoji, kuch accented chars, flags — ye ek se zyada code unit lete hain. Real character count chahiye to `[...str]` ya `Intl.Segmenter`.

### `boolean` — aur wrapper-object trap

`true` / `false` — bas. Par ek trap:

```javascript
if (new Boolean(false)) {
  console.log("ye chalta hai!"); // YE PRINT HOTA HAI
}
typeof new Boolean(false); // "object"
typeof true;               // "boolean"
```

`new Boolean(false)` ek **object** banata hai, aur **har object truthy hota hai** — chahe andar `false` ho. Isliye `Boolean` (aur `Number`, `String`) ko kabhi `new` ke saath mat use karo. Bina `new` ke — `Boolean(x)` — ye ek honest conversion function hai jo primitive return karta hai.

### Simple real-life analogy

- **`number`** = ek digital scale jiska last digit hamesha thoda round hota hai — chhoti cheezein weigh karo to farak nahi, precise dawai tolna ho to problem.
- **`string`** = pen se likha note — badalna hai to naya note likhna padega, purane pe overwrite nahi.
- **`new Boolean(false)`** = ek band box jispe "khaali" likha hai — box khud to hai (truthy), label kuch bhi kahe.

### Day-to-day use

- IDs jo backend se aati hain aur `2^53` se badi ho sakti hain — **string** mein rakho, `number` mein nahi (Twitter/X ne yahi bug face kiya).
- User input parse karna — `Number(input)` strict validation ke liye, `parseInt`/`parseFloat` lenient extraction ke liye.
- Display formatting — `.toFixed(2)`, `Intl.NumberFormat` (currency, locale).
- Text processing — `split` / `map` / `join`, ya `replaceAll` for all occurrences.

### Kab BigInt use karna chahiye

Jab integers `Number.MAX_SAFE_INTEGER` se aage jaate hain aur exact hone chahiye:

```javascript
const big = 9007199254740993n;   // 'n' suffix
big + 1n;                         // 9007199254740994n  -- exact
```

- Database bigint IDs, Snowflake IDs, cryptographic values, precise timestamps in nanoseconds.
- `BigInt` aur `Number` ko **mix nahi kar sakte** — `1n + 1` `TypeError`. Explicitly convert karo.

### Kab BigInt use nahi karna chahiye

- Normal counting, array indices, loop counters — `Number` bilkul theek, `2^53` bahut bada hai.
- Decimals — `BigInt` sirf integers hai, `1.5n` `SyntaxError`.
- Money — `BigInt` fixed-point ke liye use ho sakta hai par usually ek decimal library (`decimal.js`, `dinero.js`) clearer hai.
- JSON — `BigInt` `JSON.stringify` mein `TypeError` deta hai, custom replacer chahiye.

### Kab decimal library chahiye (money)

Jaise hi paise/currency arithmetic ho — addition, tax, percentage, division. Float rounding errors real money mein audit failures dete hain. Options:

- **Integer paise/cents** mein store karo (`amount: 149900` = ₹1499.00), sirf display pe divide.
- **`decimal.js` / `big.js`** — arbitrary-precision decimal arithmetic.
- **`dinero.js`** — money-specific, currency + rounding rules built in.

### Pros and cons

**Single `number` type**

- **Pros** — koi int/float confusion nahi, koi overflow silently wrap nahi (Java ki tarah), simple mental model.
- **Cons** — float precision errors har jagah, `2^53` safe-integer ceiling, money handling extra care maangta hai.

**Immutable strings**

- **Pros** — safe to share/pass, koi accidental mutation nahi, hashable, cache-friendly.
- **Cons** — bahut saare concatenations ek loop mein naye strings banate hain (garbage); tab array `push` + `join` better.

### Alternatives

- **`BigInt`** — exact integers beyond `2^53`.
- **Typed Arrays** (`Int32Array`, `Float64Array`) — fixed-width numbers, binary data, performance.
- **`Intl.NumberFormat`** — locale-aware number/currency display instead of manual `.toFixed`.
- **`Intl.Segmenter`** — proper grapheme (user-character) counting instead of `.length`.

### Interview mein "0.1 + 0.2 kyun 0.3 nahi?"

> "JavaScript ka `number` IEEE-754 double-precision float hai. `0.1` aur `0.2` binary mein exactly represent nahi ho sakte — jaise `1/3` decimal mein infinite `0.333...` hai. Engine unhe nearest representable value pe round karta hai, aur wo tiny errors add hone pe `0.30000000000000004` deti hain. Isliye floats ko `===` se compare nahi karte — ya `Math.abs(a - b) < Number.EPSILON` use karte hain, ya display ke liye `.toFixed()`. Money ke liye toh integers (paise) mein kaam karta hoon ya `decimal.js`."

</Hinglish>

<Callout type="tip">

`Number("")` `0` deta hai, `Number(" ")` bhi `0`, aur `Number(null)` bhi `0` — par `Number(undefined)` `NaN`. Isliye form input validate karte waqt pehle empty-string check karo, warna khali field silently `0` ban jaayega.

</Callout>

## Real World Example

<RealWorld company="Twitter / X (Snowflake IDs)">

Twitter ki tweet IDs 64-bit integers hain, jo `Number.MAX_SAFE_INTEGER` (`2^53 - 1`) se kaafi badi hain. Jab APIs ye IDs plain JSON number ke roop mein bhejti thin, JavaScript clients unhe parse karke last few digits kho dete the — do alag tweets same ID pe map ho jaate. Fix: API `id_str` field bhi bhejti hai (ID as a **string**), aur clients ko wahi use karne ko kaha gaya. Aaj bhi bahut si APIs (Discord, GitHub GraphQL) large IDs strings mein hi return karti hain isi wajah se.

</RealWorld>

<RealWorld company="E-commerce checkout (money bugs)">

Ek common production bug: cart total `items.reduce((sum, i) => sum + i.price, 0)` se compute hota hai jaha `price` float hai (`19.99`, `4.95`...). Kuch combinations pe total `53.99999999999999` aa jaata hai, phir `.toFixed(2)` `"54.00"` dikhata hai par payment gateway ko `53.999...` jaata hai — ya rounding kabhi seller ke against jaati hai. Teams isse fix karti hain paise ko integer cents mein store karke (`1999`, `495`), sirf display pe `/ 100`, ya `dinero.js` use karke.

</RealWorld>

## Numbers That Matter

<Numbers>

- **1 number type** — 64-bit IEEE-754 double. Koi `int`, `float`, `long` alag nahi.
- `Number.MAX_SAFE_INTEGER` = `9007199254740991` = `2^53 - 1`.
- **52 bits** mantissa (+1 implied) — isliye `2^53` safe-integer ceiling.
- `Number.EPSILON` ≈ `2.22e-16` — smallest meaningful difference between two floats near 1.
- `BigInt` ES2020 mein aaya; `Symbol` ES2015 mein — dono newer primitives.
- Strings **UTF-16**; ek astral character (zyada emoji) = **2** code units, isliye `.length` 2 badhta hai.
- **8 falsy values** overall; `boolean` unme se sirf `false` contribute karta hai.

</Numbers>

## Interview Angle

<InterviewAngle>

Sabse common: "`0.1 + 0.2` kya hai?" ya "`typeof NaN` kya hai?" ya "`new Boolean(false)` truthy hai ya falsy?".

Model answer ka shape:

1. **`number` = float64** — ek hi type, isliye precision errors aur `2^53` limit.
2. **`NaN`** — type `number`, `NaN !== NaN`, check karne ke liye `Number.isNaN`.
3. **String immutable** — methods naya string dete hain, `s[0] = "x"` silently fail.
4. **Boolean wrapper trap** — `new Boolean(false)` ek object hai, sab objects truthy, isliye `if` ke andar chalta hai. `new` mat lagao.
5. **Fix awareness** — money/large IDs ke liye strings/BigInt/decimal library.

Red flag: yeh sochna ki `parseInt` aur `Number` same hain. `Number("12px")` `NaN`, `parseInt("12px")` `12` — lenient vs strict.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Money ko float number mein store karna.** `0.1 + 0.2 !== 0.3` waali error currency arithmetic mein accumulate hoti hai aur audit / reconciliation fail karti hai. Paise ko integer cents mein rakho (`1499` = ₹14.99) ya `decimal.js` / `dinero.js` use karo, sirf display pe convert karo.

</Mistake>

<Mistake>

**Large IDs ko `number` mein parse karna.** Backend 64-bit ID bhejta hai, `JSON.parse` use `number` bana deta hai, `2^53` se aage precision khatam — do records same ID pe collide. In IDs ko **string** rakho end-to-end (`id_str` pattern).

</Mistake>

<Mistake>

**`new Boolean()`, `new Number()`, `new String()` use karna.** Ye wrapper **objects** banate hain — `typeof` `"object"`, aur har object truthy hai, to `if (new Boolean(false))` chalta hai. Hamesha bina `new` ke — `Boolean(x)`, `Number(x)`, `String(x)` — jo primitive return karte hain.

</Mistake>

<Mistake>

**`.length` ko "character count" samajhna.** Emoji, flags, kuch accented characters ek se zyada UTF-16 code unit lete hain. `"\u{1F44D}".length` `2` hai. User-visible character count chahiye to `[...str].length` ya `Intl.Segmenter`.

</Mistake>

<Mistake>

**`parseInt` ko bina radix ke call karna, aur `Number` se confuse karna.** `parseInt("08")` purane engines mein `0` de sakta tha (octal guess). Hamesha `parseInt(str, 10)`. Aur yaad rakho `Number("12px")` `NaN` deta hai jabki `parseInt("12px", 10)` `12` — strict validation ke liye `Number`, best-effort extraction ke liye `parseInt`.

</Mistake>

## Quick Revision

<QuickRevision>

- `number` = **ek** type, 64-bit IEEE-754 float. `42` bhi float hai.
- `0.1 + 0.2 !== 0.3` — binary float precision; floats `===` se compare mat karo.
- `Number.MAX_SAFE_INTEGER` = `2^53 - 1` = `9007199254740991`.
- `NaN` — type `number`, `NaN !== NaN`, check via `Number.isNaN(x)`.
- `Number("")` -> `0` (gotcha); `Number("12px")` -> `NaN`; `parseInt("12px", 10)` -> `12`.
- String **immutable** — methods naya string dete hain; `s[0] = "x"` silently fails.
- Handy string methods: `trim`, `slice`, `split`, `includes`, `replace`/`replaceAll`, `padStart`, `at`.
- `.length` = UTF-16 code units, not characters — emoji = 2. Use `[...str]` for code points.
- `new Boolean(false)` is an **object** -> truthy. Never use `new` with wrappers.
- `BigInt` (`123n`) for exact integers beyond `2^53`; can't mix with `Number`.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Bina chalaye batao: `Number("")`, `Number(" ")`, `Number("12px")`, `parseInt("12px", 10)`, `parseFloat("3.14abc")` — har ek ka result aur ek line reason.

**Medium:** Ek `formatPrice(cents)` function likho jo integer cents le (`149900`) aur `"₹1,499.00"` return kare, bina float arithmetic ke rounding errors introduce kiye. `Intl.NumberFormat` use kar sakte ho.

**Bada:** Ek `safeEquals(a, b)` likho jo do numbers ko float-precision-safe tareeke se compare kare. Phir batao ki `0.1 + 0.2` aur `0.3` ke liye ye `true` kyun deta hai jabki `===` `false` deta hai. Edge cases handle karo: `NaN`, `Infinity`.

</Callout>
