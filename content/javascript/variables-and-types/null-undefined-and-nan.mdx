<SimpleDefinition>

`undefined` means **a value was never assigned** — JavaScript itself hands it to you for uninitialised variables, missing arguments, missing properties, and functions with no `return`. `null` means **deliberately empty** — a developer assigns it to say "no value here, on purpose". `NaN` is a special `number` value meaning "invalid numeric result", and it is the only value in JavaScript **not equal to itself**. The idiom `x == null` is the single accepted use of loose equality: it matches `null` and `undefined`, nothing else.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Teen "khaali/galat" values jo naye JS devs ko sabse zyada confuse karti hain. Farak intent ka hai: `undefined` **JavaScript deta hai**, `null` **tum dete ho**, `NaN` **ek failed calculation** hai.

### Ye kya hai — teen alag "nothing" values

| Value | Kaun deta hai | Matlab | `typeof` |
|---|---|---|---|
| `undefined` | JavaScript (automatic) | "yaha value set hi nahi hui" | `"undefined"` |
| `null` | Developer (manual) | "yaha jaan-boojh ke koi value nahi" | `"object"` (bug) |
| `NaN` | Ek invalid number operation | "number chahiye tha, mila nahi" | `"number"` |

### `undefined` — JavaScript ka default "khaali"

JavaScript ye 5 situations mein khud `undefined` deta hai:

```javascript
let a;                          // 1. declare kiya, assign nahi -> undefined
function f(x) { return x; }
f();                            // 2. missing argument -> x is undefined
const obj = {};
obj.missing;                    // 3. missing property -> undefined
function g() {}
g();                            // 4. no return statement -> undefined
const arr = [1];
arr[5];                         // 5. array hole / out of range -> undefined
```

Tum bhi `x = undefined` likh sakte ho, par style-guides isse discourage karte hain — `undefined` ko "JavaScript ki cheez" rehne do, taaki "developer ne set kiya" hamesha `null` matlab ho.

### `null` — developer ka jaan-boojh ke "khaali"

`null` tab likho jab tumhe kehna hai "is variable/property mein abhi koi value nahi hai, aur ye deliberate hai":

```javascript
let selectedUser = null;   // abhi koi user select nahi -- intentional
function findUser(id) {
  const u = db.get(id);
  return u ?? null;        // "mila nahi" ko explicitly null se signal karo
}
```

APIs aksar `null` return karti hain "not found" ke liye (jaise `document.getElementById` jo element na mile to `null` deta hai), aur JSON mein sirf `null` hota hai — `undefined` JSON mein exist hi nahi karta (`JSON.stringify({ a: undefined })` `"{}"` deta hai).

### `typeof null === "object"` — historical bug

```javascript
typeof null;       // "object"   <- galat, par kabhi fix nahi hoga
typeof undefined;  // "undefined" <- sahi
```

JavaScript ke pehle version mein values ek type tag ke saath store hoti thin, aur `null` ka tag `0` tha — wahi tag objects ka bhi tha. `typeof null` isliye `"object"` deta hai. Ye web ko tode bina fix nahi ho sakta, to spec ne isse "permanent" bana diya. `null` check karne ke liye `typeof` mat use karo — `x === null` use karo.

### `NaN` — "Not a Number", par type `number`

```javascript
Number("abc");     // NaN
0 / 0;             // NaN
Math.sqrt(-1);     // NaN
parseInt("xyz");   // NaN
undefined + 1;     // NaN
NaN === NaN;       // false  <- only value not equal to itself
```

`NaN` check karne ka sahi tarika:

```javascript
Number.isNaN(NaN);        // true
Number.isNaN("abc");      // false  -- koi coercion nahi, ye sahi hai
isNaN("abc");             // true   -- pehle Number("abc") = NaN, phir check -- MISLEADING
isNaN(undefined);         // true   -- same trap

x !== x;                  // true sirf NaN ke liye -- clever check
```

- **`Number.isNaN(x)`** — modern, safe. `true` sirf jab `x` literally `NaN` value ho.
- **global `isNaN(x)`** — pehle `x` ko number mein coerce karta hai, phir check. `isNaN("hello")` `true` deta hai jo galat impression deta hai. **Avoid.**

### `void 0` — undefined paane ka safe tarika

Purane / non-strict code mein `undefined` ek variable tha jise **reassign kiya ja sakta tha** (`undefined = 5`). Isse bachne ke liye log `void 0` likhte the — `void` operator hamesha genuine `undefined` deta hai. Modern strict mode mein `undefined` read-only hai, to `void 0` ab zyada tar minifiers ke output mein hi dikhta hai (chhota hai).

### `x == null` — the one good use of `==`

```javascript
x == null;
// true jab x === null   YA   x === undefined
// baaki har cheez ke liye false (0, "", false, NaN sab false)
```

Ye ek exception hai us rule ka ki "hamesha `===` use karo". `x == null` ek concise, safe idiom hai "kya x null ya undefined hai" check karne ka. Alternative: `x === null || x === undefined` (verbose) ya `x ?? fallback` (agar tum default de rahe ho).

### Simple real-life analogy

- `undefined` = form ka ek field jo tumne bhara hi nahi — system ko nahi pata tumhara jawaab kya hai.
- `null` = form ka ek field jisme tumne likha "N/A" — tumne jaan-boojh ke bataya ki yaha kuch nahi.
- `NaN` = calculator pe `0 ÷ 0` daba ke "Error" aana — operation valid tha nahi, result garbage hai.

### Code — line by line

```javascript
function getDiscount(user) {
  const tier = user.tier;              // 1
  if (tier == null) return 0;          // 2
  const rate = RATES[tier];            // 3
  const pct = Number(rate);            // 4
  if (Number.isNaN(pct)) return 0;     // 5
  return pct;                          // 6
}
```

- Line 1 — agar `user` ke paas `tier` nahi, to `tier` `undefined`.
- Line 2 — `== null` `undefined` aur `null` dono pakadta hai; koi tier nahi to `0` discount.
- Line 3 — agar `tier` galat key hai, `rate` `undefined`.
- Line 4 — `Number(undefined)` `NaN` deta hai.
- Line 5 — `Number.isNaN` se guard; global `isNaN` yaha bhi kaam karta par `isNaN` string inputs pe misleading hai, isliye habit `Number.isNaN` ki rakho.
- Line 6 — clean number return.

### Day-to-day use

- Optional function params: `function f(opts) { opts = opts ?? {}; }`.
- API "not found": `return record ?? null`.
- Nullish default: `const port = config.port ?? 3000` (0 ko valid rakhta hai, `||` nahi rakhta).
- Optional chaining: `user?.address?.city` — beech mein `null`/`undefined` mile to poora expression `undefined`.

### Kab `null` use karna chahiye

- Jab tumhe **explicitly** signal karna hai "value abhi nahi hai / mila nahi", aur wo state meaningful hai (`selectedItem = null`).
- Function return jaha "no result" ek valid, expected outcome hai.
- Object shape stable rakhne ke liye — `{ error: null, data: [...] }` — key hamesha present, value `null` jab error nahi.

### Kab `null` use nahi karna chahiye

- Uninitialised local variables ke liye — unhe `undefined` rehne do (ya better, declare karo jab value ready ho).
- Missing optional data ke liye jaha `undefined` already natural hai (missing property).
- Agar tumhari poori codebase ek convention pe hai (kuch teams "no null, always undefined" follow karti hain) — consistency zyada important hai.

### Pros and cons

**Do alag empty values (`null` + `undefined`)**

- **Pros** — "system ne set nahi kiya" vs "developer ne khaali kiya" ka farak express kar sakte ho.
- **Cons** — do cheezein check karni padti hain; `== null` ya `??` na jaanne wale bugs likhte hain; `typeof null` trap.

**`NaN` as a number**

- **Pros** — numeric operations crash nahi karte, ek sentinel milta hai jise check kar sakte ho.
- **Cons** — `NaN` chup-chaap propagate hota hai (`NaN + 1` = `NaN`), aur `NaN === NaN` `false` naye devs ko trip karta hai.

### Alternatives

- **`??` (nullish coalescing)** — `x ?? default`, sirf `null`/`undefined` pe fallback (0 aur `""` safe).
- **`?.` (optional chaining)** — nested access jaha koi level missing ho sakta hai.
- **TypeScript strict null checks** — compile-time pe `null`/`undefined` ko type mein force karta hai, runtime surprise kam.
- **Option/Maybe types** (fp-ts) — "value ho bhi sakti hai nahi bhi" ko type-safe banate hain.

### Interview mein "null aur undefined mein kya farak?"

> "`undefined` JavaScript khud deta hai — uninitialised variable, missing argument ya property, no-return function. `null` main deliberately assign karta hoon jab kehna ho 'yaha value nahi hai, on purpose'. `typeof undefined` `\"undefined\"` hai par `typeof null` `\"object\"` — ek purana bug jo compat ke liye kabhi fix nahi hua. Practically main rule ye rakhta hoon: `undefined` ko naturally hone deta hoon, `null` ko choose karta hoon; aur dono ek saath check karne ke liye `x == null` — ye `==` ka wo ek case hai jo main allow karta hoon."

</Hinglish>

<Callout type="tip">

`||` aur `??` ka farak yaad rakho: `count || 10` jab `count` `0` ho to `10` de deta hai (0 falsy hai). `count ?? 10` sirf `null`/`undefined` pe `10` deta hai, `0` ko rehne deta hai. Numeric/boolean defaults ke liye hamesha `??`.

</Callout>

## Real World Example

<RealWorld company="DOM APIs (browser)">

`document.getElementById("missing")` element na mile to `null` return karta hai (`undefined` nahi) — ye ek deliberate "not found" signal hai. Isliye `document.getElementById("x").value` likhna aur element ke absent hone pe "Cannot read properties of null" crash aana front-end ka sabse common runtime error hai. Sahi: `const el = document.getElementById("x"); if (el) { ... }` ya `el?.value`. `querySelector` bhi same — no match pe `null`.

</RealWorld>

<RealWorld company="JSON APIs / REST responses">

JSON spec mein `undefined` hai hi nahi — sirf `null`. `JSON.stringify({ a: undefined, b: null })` `'{"b":null}'` deta hai: `undefined` waali key **gayab** ho jaati hai, `null` waali rehti hai. Isliye REST APIs "field explicitly empty hai" batane ke liye `null` bhejti hain, aur "field bheja hi nahi" `undefined`/absent se distinguish karti hain — PATCH endpoints mein ye farak matter karta hai (`null` = clear this field, absent = don't touch it).

</RealWorld>

## Numbers That Matter

<Numbers>

- `x == null` **exactly 2** values ke liye `true` — `null` aur `undefined`. Baaki sab `false`.
- **8 falsy values** — inme `null`, `undefined`, aur `NaN` teeno shaamil hain.
- `typeof null` `"object"` — **1** historical bug, spec ne permanent declare kiya.
- `NaN` — JavaScript ki **only** value jo `x === x` ko `false` banati hai.
- `??` aur `?.` **ES2020** mein aaye — modern nullish handling.
- `JSON.stringify` `undefined` properties ko **drop** karta hai, `null` ko rakhta hai.
- Number of ways JS auto-produces `undefined`: **5** (uninit var, missing arg, missing prop, no return, array hole).

</Numbers>

## Interview Angle

<InterviewAngle>

Classic: "`null` aur `undefined` mein kya farak?" — phir follow-up "`typeof` dono ka kya?" aur "dono ek saath kaise check karoge?".

Model answer ka shape:

1. **Source** — "`undefined` JS deta hai; `null` developer assign karta hai."
2. **`typeof`** — "`undefined` -> `\"undefined\"`, `null` -> `\"object\"` (bug)."
3. **Check both** — "`x == null` — `==` ka ek acceptable use."
4. **NaN** — "type `number`, `NaN !== NaN`, check via `Number.isNaN` not global `isNaN`."
5. **Modern tools** — "`??` for nullish default, `?.` for safe nested access."

Red flag: "`null` aur `undefined` bilkul same hain, koi farak nahi" — ya `NaN` check karne ke liye `x === NaN` likhna.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`NaN` ko `x === NaN` se check karna.** `NaN` khud ke barabar nahi, to ye check hamesha `false`. `Number.isNaN(x)` use karo (ya `Object.is(x, NaN)`, ya `x !== x` trick). Global `isNaN(x)` bhi mat use karo — wo pehle coerce karta hai, `isNaN("abc")` `true` de deta hai.

</Mistake>

<Mistake>

**`typeof x === "object"` se `null` check karna.** `typeof null` `"object"` hai, to `null` is check ko pass kar jaata hai aur baad mein `x.prop` crash karta hai. Pehle `x === null` (ya `x == null`) se guard karo, phir `typeof`.

</Mistake>

<Mistake>

**`||` se default dena jab `0` / `""` / `false` valid values hon.** `const qty = input || 1` — user `0` type kare to bhi `1` ban jaata hai. `const qty = input ?? 1` — sirf `null`/`undefined` pe `1`, `0` respect hota hai.

</Mistake>

<Mistake>

**JSON mein `undefined` bhejne ki koshish.** `JSON.stringify({ status: undefined })` `"{}"` deta hai — key gayab. Agar API ko "ye field khaali hai" batana hai to `null` bhejo, `undefined` nahi.

</Mistake>

<Mistake>

**Har missing cheez ke liye `null` assign karna.** `let result = null` phir kabhi assign na karna — ab tum `null` bhi check kar rahe ho aur `undefined` bhi. Convention pick karo: `undefined` ko natural rehne do, `null` sirf jab "deliberately empty" ka matlab ho.

</Mistake>

## Quick Revision

<QuickRevision>

- `undefined` = JS-produced "never assigned" — uninit var, missing arg/prop, no return, array hole.
- `null` = developer-assigned "deliberately empty".
- `typeof undefined` -> `"undefined"`; `typeof null` -> `"object"` (permanent historical bug).
- `null` check: `x === null`; both: `x == null` (the one OK `==`).
- `NaN` — type `number`; `NaN !== NaN`; only self-unequal value.
- Check NaN: `Number.isNaN(x)`. Avoid global `isNaN` (coerces first).
- `x !== x` is `true` only for `NaN` — a valid trick check.
- `??` — nullish default, respects `0`/`""`/`false`. `||` — falsy default.
- `?.` — optional chaining; short-circuits to `undefined` on `null`/`undefined`.
- JSON has no `undefined` — `JSON.stringify` drops `undefined` keys, keeps `null`.
- Rule of thumb: let `undefined` happen, choose `null` on purpose.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Bina chalaye batao: `typeof undefined`, `typeof null`, `null == undefined`, `null === undefined`, `NaN === NaN`, `Number.isNaN(NaN)`, `isNaN("abc")` — aur har ek ek line reason.

**Medium:** Ek function `getConfigValue(config, key, fallback)` likho jo `config[key]` return kare, par sirf tab fallback de jab value `null` ya `undefined` ho (0, `""`, `false` valid values maane jaayein). `??` use karo aur `||` version se compare karo — kaunse inputs pe farak padta hai?

**Bada:** Ek `safeParseNumber(input)` likho jo: string ko number mein parse kare, `NaN` aane pe `null` return kare, `null`/`undefined`/`""` input pe bhi `null` return kare, aur valid number pe wo number de. `Number.isNaN` aur `== null` dono use karo. Phir 6 test cases likho jo har branch cover karein.

</Callout>
