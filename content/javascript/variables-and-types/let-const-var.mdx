<SimpleDefinition>

`let`, `const`, and `var` are the three ways to declare a variable in JavaScript. They differ in **scope** (`var` is function-scoped; `let`/`const` are block-scoped), in whether the **binding can be reassigned** (`const` cannot), and in **hoisting** behaviour (`var` initialises to `undefined`; `let`/`const` sit in a "temporal dead zone" until their declaration line). Modern code uses `const` by default, `let` when reassignment is genuinely needed, and `var` almost never.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Ye har JavaScript file ki pehli line hoti hai — `const x = ...`. Teen keywords hain, aur inka farak samajhna is liye zaroori hai kyunki galat choice **silent bugs** deti hai jo runtime pe hi pata chalte hain.

### Ye kya hai — teen declarations

Ek variable = ek **naam** jo kisi value ko point karta hai. `var`, `let`, `const` teeno naam banate hain, par teen cheezon mein alag hain: scope, reassignment, hoisting.

| | `var` | `let` | `const` |
|---|---|---|---|
| Scope | function-scoped | block-scoped (`{ }`) | block-scoped (`{ }`) |
| Reassign (`x = ...`) | haan | haan | **nahi** |
| Redeclare same scope | haan | nahi | nahi |
| Hoisting | hoist + `undefined` | hoist, par TDZ | hoist, par TDZ |
| Must initialise on declare | nahi | nahi | **haan** |

### Ye kyun exist karta hai

`var` original JavaScript (1995) ka hissa tha. Uska **function-scope** aur **hoisting** behaviour beginners ke liye bugs deta tha — loop variable leak karna, galti se redeclare kar dena, `undefined` milna crash ke bajaye. ES6 (2015) ne `let` aur `const` diye: block-scoped, predictable, aur `const` se "ye value badalni nahi hai" ka intent code mein dikhta hai. Aaj **`var` naye code mein practically dead hai**.

### Internally kaise kaam karta hai — hoisting aur TDZ

Engine tumhari file ko chalane se pehle ek baar **scan** karta hai aur saare declarations ko us scope ke top pe "utha" leta hai (memory reserve kar deta hai). Isi ko **hoisting** kehte hain.

```javascript
console.log(a); // undefined
var a = 10;

console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 20;
```

- `var a` — hoist hota hai **aur** turant `undefined` set ho jata hai. Isliye pehli line crash nahi karti — chup-chaap `undefined` deti hai. Yahi silent bug hai.
- `let b` — hoist to hota hai, par declaration line tak wo **Temporal Dead Zone (TDZ)** mein rehta hai. Waha access karo to `ReferenceError` — ye loud, helpful error hai jo bug ko turant surface kar deta hai.

### Simple real-life analogy

- `var` = ek whiteboard jo **poore office** (function) mein dikhta hai, aur koi bhi kabhi bhi mita ke dubara likh sakta hai.
- `let` = ek notebook jo sirf **us kamre** (block `{ }`) mein rehta hai. Value badal sakte ho.
- `const` = wahi notebook, par jispe **pen se** likha hai — page (binding) fix, mita nahi sakte, par agar page pe ek list hai to us list mein items add kar sakte ho (object mutation — neeche).

### `const` ka sabse zaroori nuance — binding, value nahi

`const` ka matlab "value constant" **nahi** hai — **binding constant** hai. Yaani `x` hamesha *usi* cheez ko point karega, par agar wo cheez ek object/array hai to uske andar sab badal sakta hai.

```javascript
const user = { name: "Vasant" };
user.name = "Raj";        // OK  -- object mutate kiya, binding wahi
user.age = 30;            // OK
user = { name: "Amit" };  // TypeError -- binding reassign nahi kar sakte

const nums = [1, 2, 3];
nums.push(4);             // OK  -- ab [1, 2, 3, 4]
nums = [];               // TypeError
```

- `user.name = "Raj"` — `user` abhi bhi **wahi object** point kar raha hai, bas andar change hua. `const` isse nahi rokta.
- `user = { ... }` — `user` ko *naye* object pe point karana = reassignment = blocked.

Agar sach mein object bhi freeze karna hai: `Object.freeze(user)` (shallow).

### Day-to-day use

- `const` — API se aaya data, config, imported modules, function references, DOM element references, koi bhi value jo ek baar set hoti hai. **Yeh 90%+ cases hai.**
- `let` — loop counter (`for (let i = 0; ...)`), ek accumulator jo loop mein badalta hai, ek value jo `if/else` ki do branch mein alag-alag set hoti hai.
- `var` — legacy codebases padhte waqt dikhega; naya likhte waqt nahi.

### Kab `const` use karna chahiye

Default hamesha `const`. Sirf tab `let` pe jao jab tum wakai us naam ko **reassign** karne wale ho. Isse code padhne wale ko turant pata chalta hai "ye value fix hai" bina poori body padhe.

### Kab `const` use nahi karna chahiye

Jab reassignment chahiye:

```javascript
let total = 0;
for (const item of cart) {
  total = total + item.price; // total har iteration mein badal raha -> let
}
```

Yaha `total` ko `const` banaoge to `TypeError`. `item` `const` theek hai — har iteration ek naya block, naya binding.

### Pros and cons

**`const` (+ `let`)**

- Block scope = variable sirf wahi zinda jaha use ho raha, kam leak, kam naming clashes.
- TDZ = "use before declare" turant `ReferenceError`, silent `undefined` nahi.
- `const` intent express karta hai — reader ko pata reassignment nahi hogi.
- Redeclare block = ek hi naam do baar galti se declare karna error deta hai.

**`var`**

- Function scope surprising hai — `if` block ke andar `var` bahar bhi visible.
- `undefined` hoisting silent bugs deta hai.
- Loop mein classic closure bug (`var i` sab callbacks mein last value share karte hain).
- Koi practical fayda nahi jo `let`/`const` na dete hon.

### Alternatives

- **`Object.freeze()`** — jab `const` kaafi nahi aur object ke andar bhi immutability chahiye (shallow; nested ke liye deep-freeze helper).
- **TypeScript `readonly` / `as const`** — compile-time immutability guarantees, runtime se aage.
- **Immutable data libraries** (Immer, Immutable.js) — bade state trees ke liye structural sharing ke saath.

### Interview mein "Why const by default?"

> "`const` by default isliye kyunki most variables reassign hote hi nahi — aur jab reader `const` dekhta hai to use poori function body scan kiye bina pata chal jata hai ki ye binding fixed hai, jisse code samajhna aur refactor karna safe hota hai. `let` main sirf tab use karta hoon jab genuinely reassignment chahiye — loop counter ya ek accumulator. `var` bilkul nahi, kyunki uska function-scope aur `undefined`-hoisting silent bugs deta hai jabki `let`/`const` ka TDZ same galti pe loud `ReferenceError` deta hai."

</Hinglish>

<Callout type="tip">

`const` "constant value" nahi, "constant binding" hai. `const arr = []; arr.push(1)` bilkul valid hai — array mutate hua, `arr` ne wahi array point karna jaari rakha.

</Callout>

## Real World Example

<RealWorld company="Any modern codebase / ESLint config">

Practically har team ki ESLint config mein `prefer-const` aur `no-var` rules on hote hain. `prefer-const` build/CI pe fail kar deta hai agar tumne `let` declare kiya par kabhi reassign nahi kiya — tool khud enforce karta hai ki intent sahi dikhe. `no-var` `var` ko outright ban kar deta hai. Iska matlab: modern code review mein `var` ka ek bhi instance red flag hai, aur bina-reason `let` ko reviewer ya linter turant pakad leta hai.

</RealWorld>

<RealWorld company="React / front-end components">

React function components mein `const` har jagah hai — `const [count, setCount] = useState(0)`, `const handleClick = () => {...}`, `const user = useContext(UserContext)`. Ye sab per-render fixed bindings hain. State "change" `setCount` ke through hota hai jo re-render trigger karta hai, seedha reassignment se nahi — isliye `let` ki zaroorat hi nahi padti. Naye React code mein `let` dekhna hi durlabh hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- `let` aur `const` **ES6 (ES2015)** mein aaye — yaani `var` ke akele raaj ke `20` saal baad.
- Modern style guides (Airbnb, Google) `const` ko **default** aur `var` ko **0 allowed uses** rakhte hain.
- `const` reassignment `TypeError` **runtime** pe deta hai (strict mode) — build time pe nahi, jab tak TypeScript/linter na ho.
- TDZ ka scope: block ke shuru se `let`/`const` ki declaration line tak — is window mein har access `ReferenceError`.
- `typeof` bhi TDZ mein safe nahi — `typeof b` before `let b` bhi `ReferenceError` deta hai (jabki undeclared variable pe `typeof` `"undefined"` deta hai).

</Numbers>

## Interview Angle

<InterviewAngle>

Ye warm-up question hai, lekin interviewer 3 layers check karta hai: (1) surface farak (scope/reassign), (2) hoisting + TDZ samajhte ho, (3) `const` ka object-mutation nuance pata hai.

Achhe jawaab ka shape:

1. **Scope** — "`var` function-scoped, `let`/`const` block-scoped."
2. **Reassign** — "`const` ka binding reassign nahi hota; `let`/`var` ka hota hai."
3. **Hoisting** — "`var` hoist hoke `undefined` ban jata hai; `let`/`const` TDZ mein rehte hain, declaration se pehle access `ReferenceError`."
4. **Nuance** — "`const` value ko freeze nahi karta — `const obj = {}; obj.x = 1` valid hai."
5. **Practice** — "Main `const` default rakhta hoon, `let` sirf reassignment pe, `var` kabhi nahi."

Red flag jo interviewer sunna nahi chahta: "`const` matlab value kabhi change nahi hoti" — galat, wo binding ki baat hai.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`const` ko "immutable value" samajhna.** `const config = { timeout: 5000 }; config.timeout = 3000` bilkul chalta hai — sirf `config = {...}` block hota hai. Agar object ke andar bhi change rokna hai to `Object.freeze()` chahiye (aur wo bhi shallow).

</Mistake>

<Mistake>

**Loop mein `var` use karke closure banana.** `for (var i = 0; i < 3; i++) setTimeout(() => console.log(i))` teeno baar `3` print karta hai, kyunki teeno callbacks **ek hi** `i` share karte hain. `let i` likho to har iteration ka apna `i` binding hota hai — `0, 1, 2` milta hai.

</Mistake>

<Mistake>

**`let`/`const` ko declaration se pehle use karna aur `undefined` expect karna.** `var` ki aadat se log sochte hain hoisting se `undefined` milega. `let`/`const` ke saath TDZ ki wajah se `ReferenceError` milta hai — jo actually better hai, kyunki bug chhupta nahi.

</Mistake>

<Mistake>

**Har cheez `let` declare karna "just in case".** Isse reader ko har jagah lagta hai value badal sakti hai, aur `prefer-const` linter warning deta hai. Default `const`; `let` sirf jab pakka reassign karna ho.

</Mistake>

<Mistake>

**`const` bina initialise kiye declare karna.** `const x;` `SyntaxError` deta hai — `const` ko declaration ke waqt hi value chahiye. Agar value baad mein aane wali hai (do branches mein set hogi) to `let` use karo.

</Mistake>

## Quick Revision

<QuickRevision>

- `var` = function-scoped, hoist + `undefined`, reassign + redeclare dono OK — **avoid**.
- `let` = block-scoped, TDZ, reassign OK, redeclare nahi.
- `const` = block-scoped, TDZ, reassign **nahi**, initialise on declare mandatory.
- **Hoisting** = engine declarations ko scope ke top pe utha leta hai (pre-scan).
- **TDZ** = block start se `let`/`const` declaration line tak — access = `ReferenceError`.
- `const` binding freeze karta hai, **value nahi** — `const obj = {}; obj.x = 1` valid; `obj = {}` invalid.
- Object ke andar bhi rokna ho: `Object.freeze()` (shallow).
- Loop counters: `for (let i ...)` — har iteration naya binding, closure-safe.
- Default `const` -> reader ko intent turant dikhe; `let` sirf reassignment pe.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Ye chala ke, phir bina chalaye predict karo aur reason likho: `const a = [1]; const b = a; b.push(2); console.log(a);` — `a` kya print hoga aur kyun?

**Medium:** Ek `for` loop likho jo 3 buttons (ya 3 `setTimeout`s) banaye, har ek apna index `0`, `1`, `2` log kare. Pehle `var` se likho aur dekho kya hota hai, phir `let` se fix karo. Do line mein likho ki `let` ne kya badla.

**Bada:** Ek chhoti function likho `parseConfig(raw)` jo: agar `raw` string hai to `JSON.parse` kare, warna `raw` waise hi le. Result ek `const config` mein rakho. Ab `config` ke andar ek default value set karo (`config.retries ??= 3`). Explain karo ki `config` `const` hote hue bhi `config.retries` set karna kyun valid hai.

</Callout>
