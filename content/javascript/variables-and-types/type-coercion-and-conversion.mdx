<SimpleDefinition>

**Conversion** is changing a value's type **on purpose** — `String(x)`, `Number(x)`, `Boolean(x)`. **Coercion** is JavaScript doing it **automatically** when an operator or context expects another type. Coercion runs through three abstract operations: **ToString**, **ToNumber**, **ToBoolean**. The `+` operator **concatenates** if either operand is a string; `-`, `*`, `/`, `%` always force numbers. There are exactly **8 falsy values**; everything else is truthy — including `"0"`, `"false"`, `[]`, and `{}`.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

JavaScript ka sabse mazak-udaya-jaane-wala part — `"5" + 1` is `"51"` par `"5" - 1` is `4`. Ye random nahi hai; teen simple rules hain. Ek baar wo pata hon, "WTF JS" wale examples predictable ho jaate hain.

### Ye kya hai — do cheezein, ek naam jaisa

- **Conversion (explicit)** — tum khud likhte ho: `Number("42")`, `String(42)`, `Boolean(0)`. Intent clear, code readable.
- **Coercion (implicit)** — JavaScript operator ya context ke hisaab se automatically type badal deta hai: `"5" * 2`, `if (value)`, `` `${count}` ``, `x == y`.

Dono andar same machinery use karte hain — sirf trigger alag hai (tumne bola vs engine ne khud kiya).

### Ye kyun exist karta hai

JavaScript 1995 mein non-programmers (web designers) ke liye "forgiving" banaya gaya tha — form field se `"42"` aaye to `"42" * 1` kaam kar jaaye, crash na ho. Wo forgiveness aaj implicit coercion ke roop mein hai. Achha intent, par edge-cases (`[] == ![]` is `true`) itne weird hain ki modern practice hai: **explicit conversion likho, implicit coercion pe kabhi rely mat karo** (sivaay `x == null` ke).

### Internally kaise kaam karta hai — teen abstract operations

Spec har coercion ko in teen internal functions se define karta hai:

**1. ToBoolean(x)** — sirf ek lookup, koi computation nahi:

```
falsy (8):  false, 0, -0, 0n, "", null, undefined, NaN
truthy:     BAAKI SAB -- including "0", "false", " ", [], {}, function(){}
```

**2. ToNumber(x):**

```javascript
Number("");        // 0      <- gotcha
Number("  12  ");  // 12     <- trimmed
Number("12px");    // NaN    <- non-numeric char
Number(true);      // 1
Number(false);     // 0
Number(null);      // 0
Number(undefined); // NaN
Number([]);        // 0      <- [] -> "" -> 0
Number([5]);       // 5      <- [5] -> "5" -> 5
Number([1, 2]);    // NaN    <- "1,2" -> NaN
Number({});        // NaN
```

**3. ToString(x):**

```javascript
String(42);        // "42"
String(null);      // "null"
String(undefined); // "undefined"
String(true);      // "true"
String([1, 2, 3]); // "1,2,3"   <- join(",")
String({});        // "[object Object]"
String([]);        // ""
```

### `+` banaam baaki arithmetic operators

`+` **overloaded** hai — string concatenation bhi karta hai aur addition bhi. Rule: **agar koi bhi operand string hai (ya string ban jaata hai object-to-primitive ke baad), to concatenation** — dono sides ToString. Warna dono sides ToNumber, addition.

```javascript
"5" + 1;    // "51"    <- string present -> concat
"5" - 1;    // 4       <- '-' sirf numbers -> ToNumber("5") = 5
"5" * "2";  // 10      <- dono ToNumber
1 + "1";    // "11"
1 + 1 + "1";// "21"    <- left-to-right: (1+1)=2, then 2+"1"="21"
"1" + 1 + 1;// "111"   <- ("1"+1)="11", then "11"+1="111"
true + 1;   // 2       <- true -> 1
[] + [];    // ""      <- dono "" -> "" + "" -> ""
[] + {};    // "[object Object]"  <- "" + "[object Object]"
```

`-`, `*`, `/`, `%`, `**` ke paas string version nahi — wo hamesha dono sides ToNumber karte hain.

### The 8 falsy values — inhe rat lo

```javascript
false
0
-0
0n          // BigInt zero
""          // empty string (aur '' aur ``)
null
undefined
NaN
```

**In 8 ke alawa SAB truthy hai.** Common surprises jo truthy hain:

```javascript
Boolean("0");      // true   <- non-empty string
Boolean("false");  // true   <- non-empty string
Boolean(" ");      // true   <- space bhi ek char hai
Boolean([]);       // true   <- empty array bhi ek object
Boolean({});       // true   <- empty object
Boolean(function(){}); // true
Boolean(Infinity); // true
Boolean(-1);       // true   <- sirf 0 falsy hai, koi bhi non-zero truthy
```

### Explicit conversion — ye likho

| Chahiye | Idiomatic | Alternative |
|---|---|---|
| Boolean | `Boolean(x)` | `!!x` |
| String | `String(x)` | `` `${x}` `` |
| Number | `Number(x)` | `+x`, `parseInt(x, 10)`, `parseFloat(x)` |

`Number(x)` vs `parseInt(x, 10)`:

- `Number("12px")` -> `NaN` (strict, poora string number hona chahiye)
- `parseInt("12px", 10)` -> `12` (jitna parse ho, le lo)
- `Number("")` -> `0` (gotcha), `parseInt("", 10)` -> `NaN`

### Array-to-primitive — kyun `[] + []` is `""`

Jab ek object ko primitive chahiye (jaise `+` ke saath), engine `ToPrimitive` chalata hai: pehle `valueOf()` try karta hai, phir `toString()`. Arrays ka `valueOf` khud array deta hai (primitive nahi), to `toString()` use hota hai -> `join(",")`.

```javascript
[].toString();       // ""
[1, 2].toString();   // "1,2"
({}).toString();     // "[object Object]"

[] + [];   // "" + ""  = ""
[] + {};   // "" + "[object Object]"  = "[object Object]"
{} + [];   // browser console mein 0 dikha sakta hai -- {} ko block samajh liya jaata hai, phir +[] = 0
```

### Simple real-life analogy

- **Explicit conversion** = form bhar ke bank ko bolna "meri EUR ko INR karo" — tum decide karte ho.
- **Implicit coercion** = ATM se foreign card use karna aur bank apne hisaab se rate laga ke convert kar deta hai — convenient, par kabhi surprise rate mil jaata hai.

### Day-to-day use

- Form input: `Number(input.value)` — hamesha string aata hai `<input>` se, even `type="number"`.
- Conditional render: `{count > 0 && <Badge />}` — theek. Par `{count && <Badge />}` jab `count` `0` ho to `0` render kar deta hai screen pe (React `0` ko render karta hai). `{count > 0 && ...}` ya `{Boolean(count) && ...}` use karo.
- Query params: URL se sab string aata hai — `Number(params.get("page"))`, `params.get("active") === "true"`.
- Logging: `` `User ${user}` `` — object ho to `"[object Object]"` milega, `JSON.stringify` use karo.

### Kab implicit coercion "theek" hai

- `` `${value}` `` template literal mein — readable aur intended.
- `if (value)` jab tum genuinely "truthy" check kar rahe ho (koi non-empty string, non-null object).
- `x == null` — null + undefined ke liye, discussed.
- `!!x` boolean banane ka short idiom (kuch teams `Boolean(x)` prefer karti hain readability ke liye).

### Kab implicit coercion se bachna chahiye

- `==` (double equals) — hamesha `===`, sivaay `== null`.
- `+` se numbers add karte waqt jab koi operand string ho sakta hai — pehle `Number()` karo.
- `if (arr)` / `if (obj)` se "khaali hai kya" check karna — `[]` aur `{}` truthy hain; `arr.length === 0` / `Object.keys(obj).length === 0` use karo.
- User-facing numbers display karte waqt `+` concatenation pe bharosa — explicitly `String()` ya `.toLocaleString()`.

### Pros and cons

**Implicit coercion**

- **Pros** — kam code, `` `${x}` `` jaise cases mein natural, forgiving for quick scripts.
- **Cons** — `"5" + 1 !== "5" - 1` jaise traps, `[] == ![]` jaise absurdities, silent bugs jo runtime pe hi milte hain, code review mein "ye intentional hai?" doubt.

**Explicit conversion**

- **Pros** — intent clear, predictable, linter-friendly, review mein self-documenting.
- **Cons** — thoda verbose, `Number("")` jaise conversion-function edge-cases abhi bhi yaad rakhne padte hain.

### Alternatives

- **`parseInt` / `parseFloat`** — lenient numeric parsing (trailing units OK).
- **`Number.parseInt`** — same as global, namespaced (ESLint `prefer-number` kuch configs mein).
- **Unary `+`** — terse number conversion (`+"42"`), par kam readable.
- **TypeScript** — compile-time pe mismatched types pakadta hai, bahut se coercion bugs ship hone se pehle rukte hain.
- **`Intl` / `.toLocaleString`** — display conversion jaha formatting matter karti hai.

### Interview mein "`[] + {}` kya deta hai?"

> "`+` ke saath dono operands ko ToPrimitive kiya jaata hai. `[]` ka `toString()` `\"\"` deta hai, `{}` ka `\"[object Object]\"`. Phir `+` dekhta hai ek operand string hai, to concatenation: `\"\" + \"[object Object]\"` = `\"[object Object]\"`. Agar positions swap karo — statement-position pe `{}` ko block-statement samjha ja sakta hai aur `+[]` `0` de deta hai, isliye `{} + []` console mein `0` dikha sakta hai. Practically main aise expressions likhta hi nahi — ye samajhne ke liye important hai ki `+` overloaded hai aur objects string ke through jaate hain."

</Hinglish>

<Callout type="tip">

React mein `{list.length && <List />}` likhoge aur `list` khaali hoga to screen pe literal `0` aa jaayega — `0` falsy hai par React use render karta hai. Hamesha `{list.length > 0 && <List />}` ya `{!!list.length && <List />}`.

</Callout>

## Real World Example

<RealWorld company="React (conditional rendering)">

React ka sabse common coercion bug: `{count && <Notifications count={count} />}`. Jab `count` `0` hota hai, `0 && x` `0` evaluate hota hai, aur React `0` ko **render** karta hai — UI mein ek akela "0" dikh jaata hai jaha kuch nahi hona chahiye. `null`, `undefined`, `false`, `""` ko React skip karta hai, par `0` aur `NaN` ko print karta hai. Fix: `{count > 0 && ...}` ya `{count ? <...> : null}`. Ye har React codebase mein at least ek baar hota hai.

</RealWorld>

<RealWorld company="Express / URL query params">

`req.query` aur `URLSearchParams` se **sab kuch string** aata hai. `?limit=0` par `Number(req.query.limit) || 20` likhoge to `limit` `20` ban jaata hai (`0` falsy). `?active=false` par `if (req.query.active)` `true` hai kyunki `"false"` ek non-empty string hai. Robust code explicitly parse karta hai: `const limit = Number(req.query.limit ?? 20)`, `const active = req.query.active === "true"`. Ye query-param coercion bugs production APIs mein bahut common hain.

</RealWorld>

## Numbers That Matter

<Numbers>

- **Exactly 8 falsy values**: `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`.
- `"0"`, `"false"`, `" "`, `[]`, `{}` — **sab truthy** (falsy list mein nahi).
- **3 abstract operations**: ToString, ToNumber, ToBoolean.
- `+` ka behaviour operand types pe depend — string present ho to concat, warna numeric add.
- `Number("")` -> `0`; `Number(" ")` -> `0`; `Number(undefined)` -> `NaN`; `Number(null)` -> `0`.
- `String([1,2,3])` -> `"1,2,3"`; `String({})` -> `"[object Object]"`.
- `-`, `*`, `/`, `%`, `**` — **hamesha** dono operands ToNumber, koi string variant nahi.

</Numbers>

## Interview Angle

<InterviewAngle>

Ye guaranteed question hai. Formats: "`"5" + 1` vs `"5" - 1`?", "falsy values list karo", "`[] == false` kyun `true`?", "explicit vs implicit conversion".

Model answer ka shape:

1. **Do terms** — "Conversion = maine kiya (`Number(x)`); coercion = engine ne kiya (`"5" * 2`)."
2. **3 operations** — "ToString, ToNumber, ToBoolean — spec inhi se define karta hai."
3. **`+` special** — "`+` string ho to concat, warna add; baaki arithmetic operators hamesha number."
4. **8 falsy** — poori list bolo, phir "`"0"`, `[]`, `{}` truthy hain" add karo.
5. **Practice** — "Main explicit conversion likhta hoon, `==` avoid karta hoon sivaay `== null`."

Red flag: falsy list mein `"0"` ya `[]` add kar dena, ya ye kehna ki `+` aur `-` same tarah kaam karte hain.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`[]` ya `{}` ko `if` mein "empty check" ke liye use karna.** `if (arr)` empty array pe bhi `true` hai (`[]` truthy). Emptiness check: `if (arr.length === 0)` arrays ke liye, `if (Object.keys(obj).length === 0)` plain objects ke liye.

</Mistake>

<Mistake>

**`||` se numeric/string defaults dena.** `port || 3000` jab `port` `0` ho to `3000`; `name || "Guest"` jab `name` `""` ho to `"Guest"`. Agar `0` / `""` valid hain to `??` use karo (`port ?? 3000`).

</Mistake>

<Mistake>

**`+` se numbers add karna jab ek operand string ho sakta hai.** `total = price + qty` jaha `price` form se `"100"` aaya — result `"1002"` jaisa string. Pehle `Number(price)` karo, ya poori arithmetic ke pehle inputs sanitize karo.

</Mistake>

<Mistake>

**React mein `{count && <X />}` likhna.** `count` `0` hone pe screen pe akela `0` render ho jaata hai. `{count > 0 && <X />}` ya `{count ? <X /> : null}` likho.

</Mistake>

<Mistake>

**`Number(userInput)` ka `""` result bhool jaana.** Empty input `Number("")` `0` deta hai, `NaN` nahi. To "khaali field" silently `0` ban jaata hai. Pehle `input.trim() === ""` check karo, phir convert.

</Mistake>

## Quick Revision

<QuickRevision>

- **Conversion** = explicit (`Number(x)`); **coercion** = implicit (engine, operator/context).
- 3 abstract ops: **ToString, ToNumber, ToBoolean**.
- `+` — koi operand string -> concat; warna numeric add. `-` `*` `/` `%` `**` — hamesha ToNumber.
- `"5" + 1` -> `"51"`; `"5" - 1` -> `4`; `1 + 1 + "1"` -> `"21"`; `"1" + 1 + 1` -> `"111"`.
- **8 falsy**: `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`.
- Truthy surprises: `"0"`, `"false"`, `" "`, `[]`, `{}`, `Infinity`, `-1`.
- `Number("")` -> `0`; `Number("12px")` -> `NaN`; `parseInt("12px", 10)` -> `12`.
- `String([1,2,3])` -> `"1,2,3"`; `String({})` -> `"[object Object]"`.
- Empty check: `arr.length === 0`, not `!arr`. Numeric default: `??`, not `||`.
- `[] + []` -> `""`; `[] + {}` -> `"[object Object]"` (array/object -> string via `toString`).
- Rule: write explicit conversions; avoid `==` except `x == null`.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Bina chalaye har ek ka result aur one-line reason: `"5" + 3`, `"5" - 3`, `5 + 3 + "3"`, `"5" + 3 + 3`, `Number("")`, `Boolean("0")`, `Boolean([])`, `[] + []`.

**Medium:** Ek `toNumberOrNull(input)` likho jo: `"42"` -> `42`, `"42px"` -> `null`, `""` -> `null`, `"  7  "` -> `7`, `null`/`undefined` -> `null`, `"3.14"` -> `3.14`. `Number()` aur `Number.isNaN` aur `trim` use karo. Ek line mein batao `Number("")` ko explicitly kyun handle karna pada.

**Bada:** Ek `truthyReport(values)` function likho jo ek array le aur har value ke liye `{ value, truthy: boolean, why: string }` return kare — `why` mein batao ki value falsy list ke kis entry se match kar rahi hai ya "not in the 8 falsy values". Test karo `[0, "0", "", " ", [], {}, null, NaN, "false", -1]` ke saath.

</Callout>
