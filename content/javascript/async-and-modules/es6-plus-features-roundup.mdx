<SimpleDefinition>

Since 2015, JavaScript (ECMAScript) follows a **yearly release cycle**, each version adding a small batch of features. **ES2015 (ES6)** was the largest — `let`/`const`, arrow functions, template literals, destructuring, spread/rest, classes, modules, promises, `Map`/`Set`. Later years added smaller batches: async/await (2017), optional chaining and nullish coalescing (2020), top-level `await` and private class fields (2022), immutable array methods (2023). Which features actually **ship to users** is decided by transpilers like Babel plus a `browserslist` target.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

"ES6+" ka matlab hai 2015 ke baad JavaScript mein jo bhi add hua. Interview mein aksar poocha jaata hai "kaunsa feature kaunse version mein aaya" ya "ye syntax kya karta hai" — isliye ek quick mental map hona zaroori hai: har saal ne kya diya aur kyun matter karta hai.

### Ye kya hai — yearly ECMAScript cycle

ECMAScript JavaScript ka official spec hai (TC39 committee banati hai). **ES2015 se har June mein** ek naya version release hota hai jo pichle 12 mahine mein "finished" (Stage 4) proposals include karta hai. Naam do tarah se: version-based (`ES6`) ya year-based (`ES2015`) — dono same cheez.

### Ye kyun exist karta hai

Pehle bade "mega releases" hote the (ES4 kabhi ship hi nahi hua, ES5 aur ES6 ke beech 6 saal). Yearly cycle chhote, predictable batches deta hai — features fragment nahi hote, aur browsers incrementally support add karte hain.

### ES2015 (ES6) — the big bang

Ye sabse bada release. Highlights:

- **`let` / `const`** — block-scoped variables, `var` ki jagah.
- **Arrow functions** `() => {}` — chhota syntax, `this` lexically bind hota hai.
- **Template literals** `` `Hi ${name}` `` — string interpolation + multi-line strings.
- **Destructuring** — `const { a, b } = obj`, `const [x, y] = arr`.
- **Spread / rest** — `[...arr]`, `f(...args)`, `function f(...args)`.
- **Default parameters** — `function f(x = 10) {}`.
- **Classes** — `class X extends Y {}` — prototype ke upar syntax sugar.
- **Modules** — `import` / `export` (standard module system).
- **Promises** — async ka foundation, callback hell se nikalne ka rasta.
- **`Map` / `Set`** — proper keyed collections aur unique-value collections.
- **`for...of`** — iterables (arrays, strings, Map, Set) pe clean looping.
- **`Symbol`** — unique primitive, mostly library/protocol use (`Symbol.iterator`).

### ES2016 — tiny

- **`**` operator** — `2 ** 10` (exponentiation), `Math.pow` ki jagah.
- **`Array.prototype.includes`** — `arr.includes(x)` — `indexOf(x) !== -1` se saaf, aur `NaN` bhi sahi handle karta hai.

### ES2017

- **`async` / `await`** — promises ke upar synchronous-dikhne wala syntax. Ye async JS ka game-changer hai.
- **`Object.entries` / `Object.values`** — object ko `[key, value]` pairs / values array mein.
- **`String.prototype.padStart` / `padEnd`** — `"5".padStart(3, "0")` -> `"005"`.
- **`Object.getOwnPropertyDescriptors`** — proper object cloning ke liye (getters/setters sameet).

### ES2018

- **Object spread / rest** — `const merged = { ...a, ...b }`, `const { x, ...others } = obj` (ES2015 ne ye sirf arrays ke liye diya tha).
- **`Promise.prototype.finally`** — success/failure dono ke baad cleanup (spinner hide).
- **`for await...of`** — async iterables pe looping (streams, paginated APIs).
- **RegExp named groups** — `(?<year>\d{4})` -> `match.groups.year`.

### ES2019

- **`Array.prototype.flat` / `flatMap`** — nested arrays ko ek level flatten; `flatMap` = map + flat.
- **`Object.fromEntries`** — `[key, value]` pairs ko wapas object mein (`Object.entries` ka ulta).
- **`String.prototype.trimStart` / `trimEnd`** — ek side ki whitespace.
- **Optional catch binding** — `catch {` bina `(err)` ke, jab error object chahiye hi nahi.

### ES2020

- **Optional chaining `?.`** — `user?.address?.city` — beech mein `null`/`undefined` mile to poora expression `undefined`, crash nahi.
- **Nullish coalescing `??`** — `x ?? "default"` — sirf `null`/`undefined` pe fallback (`0` aur `""` ko bachaata hai, `||` unhe bhi replace kar deta).
- **`Promise.allSettled`** — sab promises ka result do, chahe koi reject ho.
- **`BigInt`** — arbitrary-precision integers (`9007199254740993n`).
- **`globalThis`** — browser/Node/worker sab jagah global object ka ek naam.
- **Dynamic `import()`** — lazy module loading, ek Promise return karta hai.
- **`String.prototype.matchAll`** — ek regex ke saare matches ek iterator mein.

### ES2021

- **Logical assignment** — `a ??= b`, `a ||= b`, `a &&= b` (assign-if).
- **`String.prototype.replaceAll`** — bina `/g` regex ke saare occurrences replace.
- **`Promise.any`** — pehla **fulfilled** promise jeet ta hai (sab reject hue to `AggregateError`).
- **Numeric separators** — `1_000_000` readability ke liye (runtime pe ignore).
- **`WeakRef`** — advanced memory management (rare).

### ES2022

- **Top-level `await`** — ESM module ke top pe seedha `await` (async wrapper ki zaroorat nahi).
- **Class fields** — `class X { count = 0; }` — constructor ke bina instance fields.
- **Private fields / methods** — `#balance`, `#validate()` — sach mein private, `this.#balance`.
- **`Array.prototype.at`** — `arr.at(-1)` — last element (negative index support).
- **`Object.hasOwn(obj, key)`** — `Object.prototype.hasOwnProperty.call(...)` ka clean replacement.
- **`error.cause`** — `new Error("msg", { cause: original })` — error chaining.

### ES2023

- **`Array.prototype.findLast` / `findLastIndex`** — end se search.
- **Immutable-copy array methods** — `toSorted()`, `toReversed()`, `toSpliced()`, `with(i, val)` — original ko mutate kiye bina naya array dete hain (`sort`/`reverse`/`splice` in-place mutate karte the).
- **Hashbang grammar** — `#!/usr/bin/env node` ab spec mein.

### ES2024

- **`Object.groupBy` / `Map.groupBy`** — array items ko ek key-function ke hisaab se group karo.
- **`Promise.withResolvers()`** — `resolve`/`reject` ko promise ke bahar nikaalne ka clean tarika.
- **`Array.prototype.with` aur immutable methods** widely shipped.
- **`String.prototype.isWellFormed` / `toWellFormed`** — lone surrogates handle karna.

### Internally: transpiler + browserslist decide karta hai kya ship hoga

Tum modern syntax likhte ho, par tumhare users ke browsers utne naye na ho. Isliye:

- **Babel / SWC / TypeScript** — modern syntax ko purane equivalent syntax mein compile karte hain (optional chaining -> nested `&&` checks).
- **`browserslist`** — ek config (`> 0.5%, last 2 versions, not dead`) jo batata hai kitna peeche tak support chahiye. Babel isi ko dekhkar decide karta hai kya transpile karna hai.
- **Polyfills (core-js)** — naye *APIs* (`Array.prototype.flat`, `Promise`) ke liye — syntax nahi, missing functions runtime pe add karte hain.
- Aaj ke evergreen browsers bahut kuch natively support karte hain, isliye transpile kam hota jaa raha hai — bundle chhota.

### Kab naye features use karne chahiye

- Frontend app jismein build step (Babel/Vite/Next) hai — bindaas, jo compile ho jaaye use karo.
- Modern Node (18+) — ES2022 tak sab native.
- Library likhte waqt — target audience ke `browserslist` ke hisaab se decide karo aur documented karo.

### Kab nahi

- Bina build step ke, purane browsers ko directly serve karne wala script — sirf wahi syntax jo target support karta ho.
- Bahut naya feature (last 1-2 saal ka) production-critical path pe bina polyfill/transpile check kiye.
- `Object.groupBy` / immutable array methods jaise fresh features — pehle apne minimum runtime pe verify karo.

### Pros and cons — new syntax adopt karne ke

**Pros**

- Kam code, kam bugs (`?.` vs manual null checks, `??` vs `||` edge cases).
- Intent clearer — `#private`, `const`, immutable array methods self-documenting.
- Standard hai — har naya dev samajhta hai, framework-specific nahi.

**Cons**

- Bina transpile ke purane environments todta hai.
- Bahut naya feature = kam Stack Overflow answers, tooling lag.
- Har feature ka edge-case pata hona chahiye (`??` `0` ko bachata hai, `flat` default depth `1`).

### Interview mein "async/await kaunse ES version mein aaya?"

> "async/await ES2017 mein aaya — wo promises ke upar ek syntax layer hai, koi naya concurrency model nahi. Promises khud ES2015 (ES6) ke saath aaye the, jismein classes, arrow functions, `let`/`const`, destructuring, modules aur `Map`/`Set` bhi the — wo sabse bada release tha. Uske baad har saal chhote batches: ES2020 mein optional chaining `?.` aur nullish `??`, ES2022 mein top-level await aur `#private` class fields, ES2023 mein `toSorted`/`toReversed` jaise immutable array methods. Practically kaunsa feature ship hota hai wo Babel plus `browserslist` target decide karta hai — main modern syntax likhta hoon aur build step use karke old browsers ke liye down-level karta hoon."

</Hinglish>

<Callout type="tip">

`??` aur `||` ka farak yaad rakho: `||` har falsy value pe fallback deta hai (`0`, `""`, `false`, `NaN` bhi), `??` sirf `null` aur `undefined` pe. `count || 10` `count` ke `0` hone pe `10` de dega — bug; `count ?? 10` `0` ko rakhega.

</Callout>

## Real World Example

<RealWorld company="Next.js / Vite projects">

In frameworks mein tum bindaas latest syntax likhte ho — optional chaining, top-level `await` in Server Components, `#private` fields — kyunki build pipeline (SWC in Next.js, esbuild in Vite) usse tumhare configured target ke hisaab se down-level kar deta hai. `browserslist` field `package.json` mein hoti hai; usse badal do to bundle ka output syntax bhi badal jaata hai. "Modern build" mode do bundles bhejta hai — ek modern browsers ke liye (kam transpile, chhota) aur ek legacy fallback.

</RealWorld>

<RealWorld company="npm library authors">

Library banane wale `browserslist` aur `engines` field carefully set karte hain aur README mein "supports Node 18+" likhte hain, kyunki jo syntax wo bina transpile ke ship karte hain wo har consumer ke build ko affect karta hai. Kai libraries do builds publish karti hain (`main` = CJS/ES2018, `module` = ESM/modern) `package.json` `exports` field ke through, taaki bundler consumer ke target ke hisaab se sahi version utha le. Isiliye ek library mein `Object.groupBy` use karna abhi risky hai — sabhi consumers ka runtime utna naya nahi.

</RealWorld>

## Numbers That Matter

<Numbers>

- Yearly ECMAScript releases **ES2015 (June 2015)** se shuru — har June.
- **ES2015 (ES6)** sabse bada release — 20+ major features ek saath.
- **async/await**: ES2017. **Optional chaining `?.` + nullish `??`**: ES2020. **Top-level await + `#private`**: ES2022.
- Falsy values total **6** — `false`, `0`, `""`, `null`, `undefined`, `NaN` — `??` in mein se sirf 2 (`null`, `undefined`) pe trigger hota hai.
- `Array.prototype.flat()` ka default depth **1**; `Infinity` do to fully flatten.
- Immutable array copy methods (`toSorted` etc.) **ES2023** — teen mutating originals (`sort`, `reverse`, `splice`) ke non-mutating versions.

</Numbers>

## Interview Angle

<InterviewAngle>

Ye "breadth" check hai — interviewer dekhna chahta hai ki tum modern JS follow karte ho, sirf ek purani syntax mein atke nahi ho. Poocha jaata hai: "X feature kaunse version ka hai?", "`?.` / `??` kya karte hain aur `||` se kaise alag?", "transpiler ka kaam kya hai?".

Achhe jawaab ka shape:

1. **Cycle** — "ES2015 se har saal ek release; ES2015 sabse bada."
2. **Version anchors** — "ES2015: let/const/arrow/class/module/Promise. ES2017: async/await. ES2020: `?.` `??`. ES2022: top-level await, `#private`. ES2023: immutable array methods."
3. **`?.` / `??`** — "`?.` safe property access; `??` fallback sirf null/undefined pe, `||` har falsy pe."
4. **Ship reality** — "Babel + `browserslist` decide karte hain kya transpile hoga; polyfills naye APIs ke liye."
5. **Judgement** — "build step hai to latest syntax OK; library / no-build to target ke hisaab se conservative."

Red flag: "ES6 aur ES2015 alag versions hain" — ye same release hai, do naam.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`||` ko `??` ki jagah default ke liye use karna.** `const limit = input || 20` `input` ke `0` hone pe `20` de dega — kyunki `0` falsy hai. `const limit = input ?? 20` sirf `null`/`undefined` pe fallback karta hai aur `0` ko preserve karta hai.

</Mistake>

<Mistake>

**Optional chaining ke baad bhi crash.** `user?.profile.avatar` — agar `profile` `null` hai to `.avatar` phir bhi crash karega, kyunki `?.` sirf usi step ko guard karta hai jahaan wo likha hai. Har uncertain step pe `?.` chahiye: `user?.profile?.avatar`.

</Mistake>

<Mistake>

**`ES6` aur `ES2015` ko alag versions samajhna.** Ye ek hi release ke do naam hain. Isi tarah `ES7` = `ES2016`, `ES8` = `ES2017`. Version numbering ES2016 ke baad practically chhod di gayi — year-based naam standard hai.

</Mistake>

<Mistake>

**Bina build/transpile check ke bleeding-edge feature production mein daalna.** `Object.groupBy`, `toSorted`, `Promise.withResolvers` bahut naye hain — agar tumhare target browsers/Node versions unhe support nahi karte aur polyfill/transpile setup nahi hai, runtime pe `TypeError: ... is not a function`.

</Mistake>

<Mistake>

**Polyfill aur transpile ko ek samajhna.** Babel *syntax* transform karta hai (`?.` -> old checks). Naye *APIs* (`Array.prototype.flat`, `Promise.any`) ke liye alag se polyfill (core-js) chahiye — Babel unhe khud add nahi karta jab tak `useBuiltIns` configure na ho.

</Mistake>

## Quick Revision

<QuickRevision>

- ECMAScript: **ES2015 se har saal** ek release. `ES6` = `ES2015` (do naam, ek release).
- **ES2015 (ES6)** biggest: `let`/`const`, arrow fns, template literals, destructuring, spread/rest, classes, modules, `Promise`, `Map`/`Set`, `for...of`, `Symbol`.
- **ES2016**: `**`, `Array.includes`. **ES2017**: `async`/`await`, `Object.entries`/`values`, `padStart`.
- **ES2018**: object spread/rest, `Promise.finally`, `for await...of`. **ES2019**: `flat`/`flatMap`, `Object.fromEntries`, optional catch binding.
- **ES2020**: `?.`, `??`, `Promise.allSettled`, `BigInt`, `globalThis`, dynamic `import()`.
- **ES2021**: `??=` `&&=` `||=`, `replaceAll`, `Promise.any`, numeric separators.
- **ES2022**: top-level `await`, class fields + `#private`, `Array.at`, `Object.hasOwn`, `error.cause`.
- **ES2023**: `findLast`, immutable copies `toSorted`/`toReversed`/`with`. **ES2024**: `Object.groupBy`, `Promise.withResolvers`.
- `??` vs `||`: `??` sirf `null`/`undefined` pe fallback; `||` har falsy pe.
- **Transpiler (Babel) + `browserslist`** decide karte hain kya actually ship hota hai; polyfills naye APIs ke liye.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** In pairs ke output likho bina chalaye: `0 || "x"` vs `0 ?? "x"`; `"" || "y"` vs `"" ?? "y"`; `null ?? "z"`. Phir ek line mein rule likho.

**Medium:** Ek purane style ka function lo jo nested null checks aur `Object.keys(...).forEach` use karta hai, aur use rewrite karo: optional chaining `?.`, nullish `??`, `Object.entries` + destructuring, aur `Array.prototype.at(-1)` ke saath. Har change ke aage ES version comment likho.

**Bada:** Ek chhoti table banao 10 features ki (async/await, `?.`, `??`, `#private`, top-level await, `flat`, `Object.fromEntries`, `Promise.allSettled`, `toSorted`, `Object.groupBy`) — columns: feature | ES year | ek-line "kya karta hai" | "kya bina build step ke aaj safe hai?". Aakhri column ke liye apna assume kiya hua `browserslist` target likho.

</Callout>
