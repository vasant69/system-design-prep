<SimpleDefinition>

JSON (JavaScript Object Notation) is a lightweight, **text-based data format** for sending and storing structured data. Its syntax is a strict subset of JavaScript object-literal syntax: keys must be **double-quoted** strings, no comments, no trailing commas, no functions or `undefined`. JavaScript gives you `JSON.stringify` to turn a value into a JSON string and `JSON.parse` to turn a JSON string back into a value. Because `JSON.parse` **throws** on malformed input, always wrap it in `try/catch`.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Har API response, har config file, har `localStorage` entry — sab JSON hai. Ye internet ka default data format hai. Interview mein isliye aata hai kyunki iske chhote gotchas (Date string ban jaana, `undefined` gayab ho jaana) real bugs dete hain.

### Ye kya hai — ek text format

JSON ek **string** hai, JavaScript object nahi. Wo bas dikhne mein JS object literal jaisa lagta hai. Ek JSON string aisi hoti hai:

```json
{
  "name": "Vasant",
  "age": 30,
  "active": true,
  "roles": ["admin", "editor"],
  "address": null
}
```

Rules (JS object se strict):

- Keys **hamesha** double-quoted strings — `'name'` ya `name` invalid.
- Strings sirf double quotes mein — single quotes invalid.
- Allowed values: string, number, `true`/`false`, `null`, array, object. Bas.
- **Nahi** allowed: comments, trailing comma, `undefined`, functions, `NaN`, `Infinity`, `BigInt`, single quotes.

### Ye kyun exist karta hai

Programs ko ek dusre ko structured data bhejna hota hai — network pe, ya disk pe. Network sirf **bytes/text** samajhta hai, in-memory objects nahi. Toh chahiye ek format jo: (1) plain text ho, (2) har language padh sake, (3) insaan bhi padh le. XML ye karta tha par bhaari tha. JSON minimal hai aur har JS runtime mein native parser aata hai — isliye jeet gaya.

### Internally kaise kaam karta hai

- **`JSON.stringify(value)`** — value ko recursively traverse karta hai. Har object pe, agar uska `toJSON()` method hai to pehle wo call karta hai. Phir primitives ko text mein likhta hai, arrays ko `[...]`, objects ko `{...}`. Jo cheez JSON mein represent nahi ho sakti (function, `undefined`, Symbol) use **object mein skip** kar deta hai aur **array mein `null`** likh deta hai.
- **`JSON.parse(text)`** — text ko left-to-right scan karke tokens (`{`, `"`, `:`, numbers) padhta hai aur ek naya JS value banata hai. Grammar se ek bhi character idhar-udhar (extra comma, missing quote) — `SyntaxError` throw.

### Simple real-life analogy

JSON ek **flat-pack furniture box** jaisa hai. Ghar ka sofa (live object, memory mein, references ke saath) jaisa ka waisa courier nahi kar sakte. Usko todkar flat pieces + instructions (text) banate ho = `stringify`. Doosri jagah box khol ke wapas jodte ho = `parse`. Kuch cheezein (glued cushions = functions, methods) box mein aa hi nahi sakti — wo peeche chhoot jaati hain.

### Code — line by line

```javascript
const user = { name: "Vasant", joined: new Date("2024-01-01"), token: undefined };

const json = JSON.stringify(user);
// '{"name":"Vasant","joined":"2024-01-01T00:00:00.000Z"}'

const back = JSON.parse(json);
// { name: "Vasant", joined: "2024-01-01T00:00:00.000Z" }
```

- `JSON.stringify(user)` — object ko JSON text banaya.
- `joined` — `Date` ka apna `toJSON()` hai jo ISO string deta hai. Round-trip ke baad ye **string** hai, `Date` nahi.
- `token: undefined` — object mein `undefined` value wali key **poori tarah drop** ho gayi.
- `JSON.parse(json)` — wapas ek naya object; `joined` abhi bhi string.

### stringify ke extra arguments

```javascript
JSON.stringify(value, replacer, space);
```

- **`replacer`** — ya to keys ka array (sirf ye keys rakho — whitelist), ya ek function `(key, val) => newVal` jo har pair transform kare (`undefined` return karo to key hataao).
- **`space`** — pretty-print indentation. `JSON.stringify(obj, null, 2)` — 2-space indented, logs/config files ke liye readable.

### parse ka reviver — Date wapas laao

```javascript
const back = JSON.parse(json, (key, value) => {
  if (key === "joined" && typeof value === "string") {
    return new Date(value);
  }
  return value;
});
// back.joined ab ek asli Date object hai
```

`reviver` har key-value pair pe chalta hai (bottom-up); jo return karo wo final value banti hai.

### Gotchas ki poori list

- **`Date` -> string.** Round-trip ke baad `Date` nahi rehta. Reviver se restore karo.
- **`undefined`, function, Symbol** — object mein key **drop**, array mein `null` ban jaate hain.
- **`NaN`, `Infinity`, `-Infinity`** — `null` ban jaate hain.
- **`BigInt`** — `JSON.stringify` **throw** karta hai ("Do not know how to serialize a BigInt").
- **Circular reference** — `obj.self = obj` -> `TypeError: Converting circular structure to JSON`.
- **Key order** — insertion order roughly preserve hota hai (numeric-string keys pehle, ascending).
- **`-0`** -> `0`. Map/Set -> `{}` (empty object, kyunki koi own enumerable string keys nahi).

### JSON.parse ko hamesha try/catch mein rakho

```javascript
function safeParse(text, fallback = null) {
  try {
    return JSON.parse(text);
  } catch {
    return fallback;
  }
}
```

`localStorage`, API bodies, query params — ye kabhi bhi corrupt/truncated aa sakte hain. Bina `try/catch` ke ek invalid character poora function crash kar deta hai.

### Deep-clone hack: JSON.parse(JSON.stringify(x))

```javascript
const copy = JSON.parse(JSON.stringify(original));
```

Ek nested object/array ka **deep copy** banane ka purana one-liner. Kaam karta hai simple data ke liye, par limits hain:

- `Date` -> string ban jaata hai.
- `undefined`, functions, Symbols **kho jaate hain**.
- `NaN`/`Infinity` -> `null`.
- `Map`, `Set`, `RegExp` -> tut jaate hain (`{}` ya galat).
- Circular reference pe **crash**.
- Bade objects ke liye slow (do full passes).

Modern replacement: **`structuredClone(original)`** — built-in, `Date`/`Map`/`Set`/typed arrays/circular refs sab handle karta hai. Functions aur DOM nodes phir bhi nahi (wo clone ho hi nahi sakte). Naye code mein `structuredClone` use karo.

### toJSON() hook

Agar kisi object pe `toJSON()` method hai, `JSON.stringify` us object ke **jagah** us method ka return serialize karta hai:

```javascript
class Money {
  constructor(cents) { this.cents = cents; }
  toJSON() { return (this.cents / 100).toFixed(2); }
}
JSON.stringify({ price: new Money(1999) }); // '{"price":"19.99"}'
```

`Date.prototype.toJSON` isi hook ka use karke ISO string deta hai.

### Kab JSON use karna chahiye

- HTTP APIs (REST), config files (`package.json`, `tsconfig.json`), `localStorage`/`sessionStorage`, logs, inter-process messages.
- Jab human-readability aur cross-language support chahiye.

### Kab JSON use nahi karna chahiye

- **Binary data** (images, files) — base64 mein encode karna 33% size badha deta hai; use `ArrayBuffer`/`Blob`/multipart.
- **Bahut bade / high-throughput payloads** — `Protocol Buffers`, `MessagePack`, `Avro` chhote aur tez hain.
- **Jab types matter karte hain** — JSON mein `Date`, `BigInt`, `Map` nahi; agar wo zaroori hain to ek schema/encoding layer chahiye.
- Config jismein comments chahiye — JSON comments allow nahi karta (JSON5 / YAML / TOML dekho).

### Pros and cons

**Pros**

- Har language mein native ya easy parser.
- Human-readable aur diff-friendly.
- JS mein zero-dependency (`JSON.stringify`/`parse` built-in).

**Cons**

- Type-poor — `Date`, `BigInt`, `Map`, `Set`, `undefined`, circular refs nahi.
- Text-based — binary ke liye inefficient.
- Koi schema/validation built-in nahi (JSON Schema alag layer hai).
- Repeated keys se verbose (columnar/binary formats se bada).

### Alternatives

- **`structuredClone`** — deep cloning ke liye, JSON hack ki jagah.
- **YAML / TOML / JSON5** — human-written config ke liye (comments, kam quotes).
- **Protocol Buffers / MessagePack** — compact binary, schema-driven, high-performance RPC.
- **`FormData` / multipart** — file uploads ke liye.

### Interview mein "JSON.parse(JSON.stringify(obj)) se deep clone karna theek hai?"

> "Chhote plain-data objects ke liye chalta hai, par ye lossy hai — `Date` string ban jaata hai, `undefined` aur functions gayab ho jaate hain, `NaN`/`Infinity` `null` ban jaate hain, aur `Map`/`Set` tut jaate hain; circular reference pe to crash hi ho jaata hai. Aur ye do full passes karta hai isliye bade objects pe slow. Aaj main `structuredClone()` use karta hoon jo `Date`, `Map`, `Set`, typed arrays aur circular refs sab sahi clone karta hai. Functions aur DOM nodes phir bhi clone nahi hote — un cases mein manual copy karna padta hai."

</Hinglish>

<Callout type="tip">

`JSON.stringify` ek object ki `undefined`-valued key ko chhod deta hai, par ek array mein `undefined` ko `null` bana deta hai. `JSON.stringify({a: undefined})` -> `"{}"`, `JSON.stringify([undefined])` -> `"[null]"`.

</Callout>

## Real World Example

<RealWorld company="Browser fetch / REST APIs">

`fetch` ke saath body bhejte waqt tum `body: JSON.stringify(payload)` karte ho aur `Content-Type: application/json` header set karte ho; response padhte waqt `await res.json()` internally `JSON.parse` karta hai. Yahi wajah hai ki API se aaya `createdAt` field ek string hota hai, `Date` nahi — front-end ko usko `new Date(str)` se convert karna padta hai ya ek reviver use karna padta hai. Agar server truncated/HTML error page bhej de, `res.json()` `SyntaxError` throw karta hai — isliye robust clients `res.ok` check karte hain aur `.json()` ko `try/catch` mein rakhte hain.

</RealWorld>

<RealWorld company="localStorage persistence">

`localStorage` sirf strings store karta hai. App state save karne ke liye teams `localStorage.setItem("cart", JSON.stringify(cart))` karti hain aur load pe `JSON.parse(localStorage.getItem("cart") ?? "[]")`. Do real bugs yahaan common hain: (1) purana schema — pehle store kiya data naye code ke shape se match nahi karta, isliye parse ke baad validation chahiye; (2) `JSON.parse(null)` `SyntaxError` deta hai agar key missing ho aur tum fallback na do — isliye `?? "[]"` ya `try/catch` wrapper zaroori hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- JSON spec: **ECMA-404** / **RFC 8259**. Sirf **6** value types: string, number, boolean, null, array, object.
- `JSON` object JavaScript mein **ES5 (2009)** se native hai — usse pehle `eval` ya third-party parser use hota tha.
- `JSON.stringify` ka third arg (`space`) max **10** — usse zyada 10 hi maana jaata hai.
- Base64-encoded binary data JSON mein rakhne se size ~**33%** badhta hai.
- `structuredClone` **2022** mein sab major browsers aur Node 17+ mein aaya.
- `JSON.stringify` circular reference aur `BigInt` pe **throw** karta hai — baaki unsupported values ko silently drop/`null` karta hai.

</Numbers>

## Interview Angle

<InterviewAngle>

Poocha jaata hai as: "JSON aur JS object mein farak?", "`JSON.stringify` kaunse values drop karta hai?", "deep clone kaise karoge?", ya ek code-output trap (`JSON.stringify` of an object with `undefined`/`Date`/function).

Achhe jawaab ka shape:

1. **Format** — "JSON ek text data format hai, JS object ka strict subset — double-quoted keys, no comments, no trailing comma, no functions/undefined."
2. **Two functions** — "`JSON.stringify(value, replacer?, space?)` object -> string; `JSON.parse(text, reviver?)` string -> value."
3. **Safety** — "`JSON.parse` invalid input pe `SyntaxError` throw karta hai, isliye hamesha `try/catch`."
4. **Lossy round-trip** — "`Date` -> string, `undefined`/function drop, `NaN`/`Infinity` -> `null`, `BigInt` throw, circular throw."
5. **Clone** — "deep clone ke liye `structuredClone`, purana `JSON.parse(JSON.stringify())` hack lossy hai."

Red flag: JSON ko ek JavaScript object samajhna ("JSON pass karo function ko") — JSON hamesha ek string hai.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`JSON.parse` ko `try/catch` ke bina call karna.** API body, `localStorage`, cookie — koi bhi corrupt ya truncated aa sakta hai. Ek invalid character `SyntaxError` throw karke poora function gira deta hai. Hamesha wrap karo aur ek fallback do.

</Mistake>

<Mistake>

**Round-trip ke baad `Date` object expect karna.** `JSON.stringify` ke baad `Date` ek ISO string hai. `JSON.parse` use wapas `Date` nahi banata — wo string hi rehta hai. `new Date(str)` ya ek `reviver` se restore karo.

</Mistake>

<Mistake>

**`undefined` values ke chup-chaap gayab hone se surprise hona.** `JSON.stringify({ a: 1, b: undefined })` deta hai `"{\"a\":1}"` — `b` gaya. Array mein `[1, undefined, 3]` banta hai `"[1,null,3]"`. Agar "missing" aur "null" ka farak matter karta hai to iska dhyaan rakho.

</Mistake>

<Mistake>

**`JSON.parse(JSON.stringify(x))` ko universal deep-clone maan lena.** Ye `Map`/`Set`/`RegExp` todta hai, `Date` ko string banata hai, functions/`undefined` drop karta hai, aur circular reference pe crash karta hai. `structuredClone(x)` use karo.

</Mistake>

<Mistake>

**JSON config file mein comment ya trailing comma likhna.** `{ "a": 1, }` ya `// note` — dono `SyntaxError`. JSON mein comments allowed hi nahi. Agar comments chahiye to JSON5, YAML, ya TOML use karo, ya build step mein strip karo.

</Mistake>

## Quick Revision

<QuickRevision>

- JSON ek **string** hai, JS object nahi. Double-quoted keys, no comments, no trailing comma.
- `JSON.stringify(value, replacer?, space?)` -> string; `JSON.parse(text, reviver?)` -> value.
- `JSON.parse` invalid input pe `SyntaxError` throw karta hai -> **hamesha `try/catch`**.
- Lossy: `Date` -> ISO string; object mein `undefined`/function/Symbol **drop**, array mein `null`; `NaN`/`Infinity` -> `null`.
- **Throws**: `BigInt`, circular reference.
- `JSON.stringify(obj, null, 2)` — pretty-print logs/config ke liye.
- `reviver` se `Date` wapas: `(k, v) => k === "date" ? new Date(v) : v`.
- Deep clone: `structuredClone(x)` — `JSON.parse(JSON.stringify(x))` hack lossy hai.
- `toJSON()` method object ki serialized form override karta hai (`Date` isi se ISO deta hai).

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `JSON.stringify({ a: undefined, b: NaN, c: [undefined], d: () => 1 })` ka output likho bina chalaye, phir verify karo. Har key ka kya hua aur kyun?

**Medium:** Ek `safeParse(text, fallback)` helper likho jo `JSON.parse` ko `try/catch` mein karta hai aur invalid input pe `fallback` deta hai. Phir ek `parseWithDates(text)` likho jo ek `reviver` use karke har ISO-date-looking string ko `Date` mein convert kare.

**Bada:** Ek object banao jismein `Date`, `Map`, ek circular reference, aur `undefined` ho. Use `JSON.parse(JSON.stringify(obj))` se clone karne ki koshish karo aur note karo kya-kya toota / crash hua. Phir `structuredClone(obj)` se karo aur difference likho. Ek chhoti table banao: value type | JSON hack | structuredClone.

</Callout>
