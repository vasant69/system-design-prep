<SimpleDefinition>

**Optional chaining (`?.`)** accesses a nested property, index, or method and **short-circuits to `undefined`** the moment the value on its left is `null` or `undefined`, instead of throwing a `TypeError`. **Nullish coalescing (`??`)** returns its right-hand side **only when the left is `null` or `undefined`** — unlike `||`, it does **not** treat `0`, `""`, or `false` as missing. The logical assignment operators `??=`, `&&=`, `||=` combine these tests with assignment. Together they replace long `&&` guard chains and unsafe `||` defaults.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

API se aaya data aksar deep-nested hota hai — `response.data.user.address.city`. Beech mein koi bhi cheez `null`/`undefined` hui to `Cannot read properties of undefined` crash. Purane din mein `data && data.user && data.user.address && ...` likhna padta tha. `?.` aur `??` (dono **ES2020**) ne isko ek line kar diya — par `??` vs `||` ka farak samajhna zaroori hai warna naye bugs aate hain.

### Ye kya hai — `?.` optional chaining

Teen forms:

```javascript
user?.name          // property access
user?.["name"]      // dynamic/bracket access
user?.getName()     // method call
arr?.[0]            // array index
```

`user?.name` ka matlab: "agar `user` `null` ya `undefined` hai to poori expression `undefined` de do (crash mat karo); warna `user.name` de do."

### Ye kyun exist karta hai

Do purane patterns replace karne:

```javascript
// purana guard chain
const city = user && user.address && user.address.city;
// ab
const city = user?.address?.city;

// purana default (bug-prone)
const count = data.count || 0;   // 0 aur "" ko bhi replace kar deta
// ab
const count = data.count ?? 0;   // sirf null/undefined pe 0
```

### Internally kaise kaam karta hai — short-circuit + "undefined, not error"

`a?.b.c.d` — jaise hi `a` **`null` ya `undefined`** milta hai, engine poore baaki chain (`.b.c.d`) ko **skip** kar deta hai aur `undefined` return karta hai. Sirf `null`/`undefined` par trigger hota hai — `0`, `""`, `false` par **nahi** (wo valid values hain, unpe `.b` access karna theek hai... well, `0..b` `undefined` deta hai, crash nahi).

```javascript
const obj = { a: { b: null } };
obj?.a?.b?.c    // undefined  (b null tha, ".c" skip hua)
obj?.x?.y?.z    // undefined  (x undefined tha)
obj?.a?.b?.c.d  // TypeError!  (?. sirf apne left ko guard karta hai;
                //  ".c.d" me c undefined tha aur ".d" plain access hai)
```

Method call form `?.()`:

```javascript
callbacks.onDone?.()   // onDone hai to call karo, warna kuch mat karo
```

### `??` — nullish coalescing

`a ?? b` = `a` **jab tak wo `null` ya `undefined` na ho**; warna `b`.

```javascript
null      ?? "d"   // "d"
undefined ?? "d"   // "d"
0         ?? "d"   // 0     <- || hota to "d" deta
""        ?? "d"   // ""    <- || hota to "d" deta
false     ?? "d"   // false <- || hota to "d" deta
NaN       ?? "d"   // NaN   <- || hota to "d" deta
```

Yahi `||` se **poora farak**: `||` **saari 8 falsy values** pe fallback deta hai; `??` sirf `null`/`undefined` pe.

### `??=`, `&&=`, `||=` — logical assignment

```javascript
a ??= b    // a null/undefined hai to hi a = b
a ||= b    // a falsy hai to a = b
a &&= b    // a truthy hai to a = b
```

Short-circuit hote hain — right side tabhi evaluate/assign hota hai jab test pass ho.

```javascript
config.timeout ??= 5000;          // sirf tab set jab missing
options.headers ??= {};           // ensure object exists
user.name ||= "Anonymous";        // falsy (incl "") ko replace
cache[key] ??= expensiveCompute(key);  // compute sirf pehli baar
```

### Simple real-life analogy

- `?.` = ek building mein andar jaate hue: har darwaze pe "agar band hai to wapas mud jao" (return `undefined`), "darwaza tod ke aage mat jao" (no crash).
- `??` = "agar box khaali hai (`null`/`undefined`) to spare use karo" — par box mein `0` rakha hai to wo `0` valid hai, spare mat lagao. `||` galti se `0` wale box ko bhi "khaali" maan leta hai.

### Code — line by line

```javascript
function getCity(response) {
  const city = response?.data?.user?.address?.city ?? "Unknown";
  return city;
}

getCity({ data: { user: { address: { city: "Pune" } } } }); // "Pune"
getCity({ data: { user: null } });                          // "Unknown"
getCity(undefined);                                          // "Unknown"
getCity({ data: { user: { address: { city: "" } } } });     // ""  (khaali string valid!)
```

- `response?.data?.user?.address?.city` — koi bhi level `null`/`undefined` -> poori cheez `undefined`, koi crash nahi.
- `?? "Unknown"` — agar upar wali `undefined` hai to `"Unknown"`. **Par** `city: ""` case mein `""` return hota hai — `??` `""` ko valid maanta hai. Agar tum chahte ho `""` bhi "Unknown" ban jaaye to `?? ` galat, `||` chahiye — ya explicit check.

### DECISION: `??` vs `||`

| Left value | `a || b` | `a ?? b` | Kaunsa chahiye? |
|---|---|---|---|
| `null` / `undefined` | `b` | `b` | dono same |
| `0` | `b` | `0` | **`??`** — 0 valid quantity/index/price |
| `""` | `b` | `""` | **`??`** — empty string valid input |
| `false` | `b` | `false` | **`??`** — explicit off |
| `NaN` | `b` | `NaN` | usually `||` (NaN rarely intended) |
| `"text"` / `{}` / `5` | `a` | `a` | dono same |

**Rule:** default value chahiye aur `0` / `""` / `false` **legitimate values** ho sakti hain -> `??`. Agar left sirf "ek object/non-empty-string ya kuch nahi" ho sakta hai (jaise `config.user || {}`) -> `||` bhi theek, farak nahi padta.

### Real use — deep API access

```javascript
// paginated API response
const firstItemName = res?.data?.items?.[0]?.name ?? "N/A";

// optional callback
props.onChange?.(newValue);

// config with valid-zero
const retries = settings?.network?.retries ?? 3;   // retries: 0 respected
```

### Caveats — jahan `?.` help nahi karta

1. **Assignment target guard nahi karta:**
   ```javascript
   user?.name = "X";   // SyntaxError -- LHS pe ?. allowed nahi
   ```
2. **Chain ke turant baad plain access:**
   ```javascript
   const d = obj?.a.b;   // agar obj hai par a undefined -> ".b" plain access -> TypeError
   // sahi: obj?.a?.b
   ```
   `?.` sirf apne **immediate left** ko guard karta hai, poori chain ko nahi.
3. **Over-use se real bugs chhup jaate hain.** Agar `user` ko kabhi `null` hona hi nahi chahiye (tumne abhi create kiya), to `user?.name` likhne se ek genuine bug (`user` galti se `null` aa gaya) silently `undefined` ban jaata hai instead of loudly crashing. `?.` sirf wahaan jahaan `null`/`undefined` **legitimate expected state** hai.
4. **`??` ko `||`/`&&` ke saath bina parentheses mix karna `SyntaxError`:** `a ?? b || c` invalid -> `(a ?? b) || c`.

### Kab `?.` / `??` use karna chahiye

- Deep-nested optional data (API responses, config, `ref.current`).
- Optional callbacks/methods — `onX?.()`.
- Default values jahaan `0`/`""`/`false` valid hon — `??`.
- "Ensure exists" assignment — `obj.list ??= []`.

### Kab use nahi karna chahiye

- Values jinhe kabhi `null` hona hi nahi chahiye — `?.` genuine bug chhupata hai.
- `??` jahaan tum genuinely **koi bhi falsy** ko replace karna chahte ho (e.g. empty string ko bhi "N/A") — wahaan `||`.
- Har jagah reflexively `?.` lagana — code noisy aur intent-blurred ho jaata hai.

### Pros and cons

**`?.` / `??`**

- **Pros:** deep access ek line, crash-safe; `??` `||` ka `0`/`""` bug fix karta hai; `?.()` optional callbacks clean; `??=` "compute/ensure once" pattern.
- **Cons:** over-use se real null-bugs silent; `?.` sirf immediate-left guard (chain ke baad plain access phir bhi throw); `??` mix karne pe parentheses mandatory; assignment LHS pe kaam nahi.

### Alternatives

- **`||`** — default jab koi bhi falsy replace karni ho.
- **Explicit `if (x == null)`** — jab crash ke bajaye custom handling (log, throw, fallback fetch) chahiye.
- **Default parameters / destructuring defaults** — `function f({ timeout = 5000 } = {})` — function boundary pe.
- **Schema validation (Zod, Yup)** — jab nested shape guarantee chahiye, guessing nahi.

### Interview mein "`??` aur `||` mein farak?"

> "`||` apne left ko **truthiness** pe judge karta hai — saari 8 falsy values (`0`, empty string, `false`, `NaN`, `null`, `undefined`, ...) pe wo right side de deta hai. `??` sirf `null` aur `undefined` pe right side deta hai. Isliye `count || 10` `count` `0` hone pe galti se `10` de deta hai, jabki `count ?? 10` `0` ko respect karta hai. Main `??` use karta hoon jab `0`, empty string, ya `false` legitimate values ho sakti hain — jo config aur numeric data mein aksar hota hai. `?.` iske saath pair hota hai deep access ke liye: `res?.data?.items?.[0]?.name ?? fallback` — koi bhi level missing ho to crash ke bajaye `undefined`, phir `??` se fallback. Caveat: `?.` sirf apne turant baaye ko guard karta hai, aur jahaan value kabhi null honi hi nahi chahiye wahaan `?.` lagana genuine bug ko chhupa deta hai."

</Hinglish>

<Callout type="trap">

`obj?.a.b` — agar `obj` maujood hai par `obj.a` `undefined` hai, to `.b` ek **plain** access hai aur phir bhi `TypeError` deta hai. Har optional link pe `?.` chahiye: `obj?.a?.b`.

</Callout>

## Real World Example

<RealWorld company="React">

React mein `?.` refs aur optional props ke liye har jagah hai: `inputRef.current?.focus()` (ref abhi mount nahi hua to no-op), `props.onSubmit?.(data)` (parent ne handler diya to call). `??` `useState` defaults aur config merging mein: `const pageSize = props.pageSize ?? 20` — yahaan `props.pageSize = 0` (jo galti se pass ho sakta hai) `20` nahi banta, jabki `|| 20` bana deta. Redux selectors mein `state.user?.profile?.avatarUrl ?? DEFAULT_AVATAR` common pattern hai.

</RealWorld>

<RealWorld company="Node.js — parsing external data">

Webhook/3rd-party API handlers mein incoming JSON ka shape guaranteed nahi hota: `payload?.event?.data?.object?.id`. `?.` ke bina ek malformed payload poora process crash kar deta. Par experienced teams isko schema validation (Zod) ke saath balance karti hain — critical fields ke liye `?.` se "silently undefined" allow karna khatarnak hai; wahaan explicit validation + reject better hai. `?.` genuinely-optional analytics/metadata fields ke liye.

</RealWorld>

## Numbers That Matter

<Numbers>

- `?.` aur `??` dono **ES2020** mein aaye; `??=`/`&&=`/`||=` **ES2021** mein.
- `??` sirf **2 values** pe trigger hota hai — `null` aur `undefined`. `||` **8 falsy values** pe.
- `??` ko `||` ya `&&` ke saath bina parentheses mix karna **SyntaxError** hai (spec-level, deliberate).
- `?.` short-circuit poori remaining chain ko skip karta hai — `a?.b().c().d()` mein `a` null ho to koi bhi call nahi chalti.
- `?.` **assignment ke LHS pe** allowed nahi — `a?.b = c` SyntaxError.
- `delete obj?.prop` valid hai — `obj` null ho to no-op.

</Numbers>

## Interview Angle

<InterviewAngle>

Guaranteed: "`??` vs `||`?" Aksar code output bhi: `0 || 5` vs `0 ?? 5`. Aur "`?.` kis case mein phir bhi throw karega?"

Model answer shape:

1. **`?.`** — "left `null`/`undefined` ho to poori chain skip, `undefined` return, no throw."
2. **`??`** — "right side sirf `null`/`undefined` pe; `0`/`\"\"`/`false` ko as-is rakhta hai."
3. **`||` contrast** — "`||` saari falsy pe fallback deta hai — 0/'' bug."
4. **Logical assignment** — "`??=` = 'set only if missing', ek expensive compute ya default ensure karne ke liye."
5. **Caveat** — "`?.` sirf immediate-left guard; kabhi-null-nahi values pe use se bug chhupta hai; `||`/`&&` ke saath `()` chahiye."

Red flag: "`??` aur `||` basically same hain."

</InterviewAngle>

## Common Mistakes

<Mistake>

**`??` aur `||` ko interchangeable samajhna.** `settings.retries || 3` `retries: 0` ko `3` bana deta hai; `settings.retries ?? 3` `0` respect karta hai. Numeric/boolean/string-input defaults mein hamesha `??`.

</Mistake>

<Mistake>

**Chain ke beech ek `?.` chhod dena.** `a?.b.c` — `a` hai par `b` undefined -> `.c` plain access -> `TypeError`. Har optional hop pe `?.`: `a?.b?.c`.

</Mistake>

<Mistake>

**`?.` har jagah reflexively lagana.** `user?.id` jahaan `user` abhi-abhi banaya gaya aur kabhi `null` nahi ho sakta — ab agar `user` galti se `null` aa gaya to bug `undefined` ban ke chhup jaata hai crash ke bajaye. `?.` sirf genuinely-optional par.

</Mistake>

<Mistake>

**`a ?? b || c` bina parentheses likhna.** Ye seedha `SyntaxError` hai. `(a ?? b) || c` ya `a ?? (b || c)` — intent explicitly.

</Mistake>

<Mistake>

**`?.` ko assignment target pe use karna.** `form?.value = "x"` `SyntaxError`. Pehle guard karo: `if (form) form.value = "x";`.

</Mistake>

## Quick Revision

<QuickRevision>

- `?.` — left `null`/`undefined` ho to poori remaining chain skip, `undefined` return, **no `TypeError`**.
- Forms: `a?.b`, `a?.[i]`, `a?.()`, `arr?.[0]`.
- `?.` sirf **apne turant left** ko guard karta hai — `a?.b.c` phir bhi throw kar sakta hai; `a?.b?.c` likho.
- `??` — right side **sirf `null`/`undefined`** pe. `0`, `""`, `false`, `NaN` ko as-is rakhta hai.
- `||` — **saari 8 falsy** pe fallback. `count || 10` `0` ko `10` bana deta = bug.
- **Rule:** `0`/`""`/`false` valid ho sakte -> `??`. Koi bhi falsy replace karni -> `||`.
- `??=` / `&&=` / `||=` — test + assign, short-circuit. `obj.list ??= []`, `cache[k] ??= compute()`.
- `?? ` ko `||`/`&&` ke saath bina `()` mix karna = **SyntaxError**.
- `?.` **assignment LHS** pe allowed nahi.
- Over-use se real null-bugs silent — `?.` sirf jahaan `null`/`undefined` legit expected ho.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Predict: `0 ?? "a"`, `0 || "a"`, `"" ?? "a"`, `"" || "a"`, `null ?? "a"`, `false ?? "a"`. Har ek ek line mein kyun.

**Medium:** Ek `getAvatar(user)` likho jo `user?.profile?.image?.url` return kare, warna `"/default.png"`. Ab ek test case socho jahaan `image.url` `""` (empty string) hai — tumhara function kya return karega, aur agar requirement ye ho ki empty string bhi `"/default.png"` ban jaaye to kaunsa operator badloge?

**Bada:** Ek config-merge function `resolve(userCfg)` likho jo `{ retries, timeout, baseUrl, verbose }` fields ko defaults ke saath merge kare: `retries` default `3` (0 valid), `timeout` default `10000` (0 valid = no timeout), `baseUrl` default `"http://localhost"` (empty string INVALID -> default), `verbose` default `false` (explicit false valid). Har field ke liye `??` ya `||` chuno aur ek comment mein reason likho. Phir `userCfg = { retries: 0, timeout: undefined, baseUrl: "", verbose: false }` ke liye expected output likho.

</Callout>
