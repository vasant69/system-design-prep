<SimpleDefinition>

JavaScript has several loops. Classic `for` and `while` run while a condition holds. `for...of` iterates the **values** of any **iterable** (array, string, `Map`, `Set`, `NodeList`, `arguments`) and supports `break`, `continue`, and `await`. `for...in` iterates the **enumerable keys** of an object, **including inherited ones**, and is not meant for arrays. Choosing a loop vs `.map()` comes down to this: use `.map()` when you are **building and using a new array** (pure transform); use a loop when you need **side effects only**, an **early exit** (`break`), or **`await` in sequence**.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Loop = "yeh kaam baar-baar karo". JavaScript mein 5-6 tarike hain aur naye developers galat wala chun lete hain — arrays pe `for...in`, side-effects ke liye `.map()`, ya `forEach` ke andar `await` (jo chalta hi nahi). Har ek ka apna sahi use case hai.

### Ye kya hai — loop family

| Loop | Kya iterate karta hai | `break`/`continue` | `await` andar |
|---|---|---|---|
| `for (let i...)` | jo tum likho (usually index) | haan | haan |
| `while` / `do...while` | jab tak condition truthy | haan | haan |
| `for...of` | iterable ke **values** | haan | haan |
| `for...in` | object ke **enumerable keys** (+ inherited) | haan | haan |
| `.forEach()` | array ke values (callback) | **nahi** | **effectively nahi** |
| `.map()` | array ke values -> naya array | nahi | nahi (sync) |

### Ye kyun exist karta hai

`for`/`while` C se aaye — full manual control. `for...of` (ES6) ne "bas values chahiye" ka clean syntax diya jo har iterable pe kaam karta hai, index book-keeping ke bina. `for...in` object keys ke liye tha, par arrays pe galti se use hone laga — isliye guidance hai "`for...in` sirf plain objects".

### `for` — classic index loop

```javascript
for (let i = 0; i < arr.length; i++) {
  // i = 0, 1, 2, ...
}
```

Teen parts: init (`let i = 0`), condition (`i < arr.length`), update (`i++`). `let` use karo `var` nahi — har iteration ka apna `i` binding milta hai (closure-safe). Tab use karo jab: index chahiye, peeche-se-aage (`i--`), do steps (`i += 2`), ya do arrays parallel mein.

### `while` / `do...while`

```javascript
while (queue.length > 0) {
  const job = queue.shift();
  process(job);
}

do {
  answer = prompt("Number?");
} while (isNaN(answer));   // body kam se kam ek baar chalti hai
```

`while` — iterations count pata nahi (queue drain, retgeneration, stream). `do...while` — body pehle chalao, phir check (rare).

### `for...of` — the modern default for values

```javascript
for (const item of cart) {
  console.log(item.name);
}

for (const ch of "abc") { ... }          // strings
for (const [key, val] of map) { ... }     // Map entries
for (const node of document.querySelectorAll("li")) { ... }  // NodeList
```

- **Values** deta hai, index nahi. Index bhi chahiye: `for (const [i, item] of arr.entries())`.
- Har **iterable** pe chalta hai — array, string, `Map`, `Set`, `NodeList`, `arguments`, generators.
- `break` / `continue` support karta hai.
- **`await` sequential** kaam karta hai:

```javascript
for (const url of urls) {
  const res = await fetch(url);   // ek-ek karke, in order
  console.log(await res.json());
}
```

Plain object pe `for...of` **nahi** chalta (`TypeError: obj is not iterable`) — uske liye `for...of Object.entries(obj)`.

### `for...in` — object keys, aur iske traps

```javascript
const user = { name: "V", role: "admin" };
for (const key in user) {
  console.log(key, user[key]);   // "name" "V", "role" "admin"
}
```

Do problems jo isse arrays ke liye galat banate hain:

1. **Inherited enumerable keys bhi aate hain.** Agar kisi ne `Array.prototype` ya `Object.prototype` pe kuch add kiya (old polyfills karte the), wo bhi loop mein dikhega. `Object.hasOwn(obj, key)` se guard karna padta hai.
2. **Order guaranteed nahi** (integer-like keys ke alawa) — arrays ke liye order matters.
3. Arrays pe keys **strings** hoti hain (`"0"`, `"1"`), numbers nahi — aur array ki custom properties bhi aa jaati hain.

Rule: **`for...in` sirf plain objects ke liye, aur `Object.keys()` / `Object.entries()` usually behtar hai** kyunki wo sirf own enumerable keys deta hai aur array bhi return karta hai jise tum `for...of` kar sakte ho.

### `break` / `continue` / labeled loops

```javascript
for (const n of nums) {
  if (n < 0) continue;   // is iteration ka baaki skip
  if (n > 100) break;    // poora loop chhodo
  total += n;
}

outer: for (const row of grid) {
  for (const cell of row) {
    if (cell === target) break outer;   // dono loops se bahar
  }
}
```

`continue` = agli iteration pe jaao. `break` = loop khatam. Labels (`outer:`) nested loops se ek saath bahar nikalne ke liye — rare, par nesting mein flag-variable se saaf.

### DECISION: for-loop / for-of vs `.map()`

Ye interview ka favourite hai. Rule ek line mein: **`.map()` jab tum har element se ek naya element bana rahe ho AUR wo naya array use kar rahe ho.** Warna loop (`for...of`).

| Situation | Use | Kyun |
|---|---|---|
| `[1,2,3]` -> `[2,4,6]`, result chahiye | `.map()` | Pure transform, ek expression, declarative |
| Har item ko DB mein save karna (koi return nahi) | `for...of` | Side effect hai, naya array nahi banana |
| Pehla matching item mil gaya to ruk jaana | `for...of` + `break` | `.map()` ruk nahi sakta |
| Har item pe `await` ek-ek karke | `for...of` + `await` | `.map()` sync hai; `forEach` `await` ignore karta hai |
| Index ke saath complex conditional logic | `for` loop | Full control |
| Naya array chahiye par kuch items skip karne hain | `.filter().map()` ya `for...of` + `push` | `.map()` hamesha same length deta hai |

**Anti-pattern — `.map()` for side effects:**

```javascript
// BURA: naya array banaya aur phenk diya
users.map(u => sendEmail(u));

// SAHI:
for (const u of users) sendEmail(u);
// ya
users.forEach(u => sendEmail(u));
```

`.map()` ka poora point transformed array return karna hai. Use side-effect ke liye use karna reader ko mislead karta hai ("iska result kahan gaya?") aur linters (`no-array-constructor`, `array-callback-return`) complain karte hain.

**`forEach` `await` nahi karta:**

```javascript
// GALAT: ye "done" pehle print karega, saves background mein
items.forEach(async (item) => {
  await save(item);
});
console.log("done");

// SAHI (sequential):
for (const item of items) {
  await save(item);
}
console.log("done");

// SAHI (parallel, agar order/limit matter nahi):
await Promise.all(items.map(item => save(item)));
```

`forEach` apne async callback ka promise ignore kar deta hai — na wait karta hai, na `break` support karta hai. Isliye `await`/`break` chahiye to `for...of`.

### Simple real-life analogy

- `for...of` = ek plate se ek-ek samosa uthana (values). Kitne hain, kaunse index pe — parwah nahi.
- `for...in` = ek dabbe ke saare **labels** padhna — apne bhi aur baap-dada ke chipkaye hue bhi (inherited).
- `.map()` = ek assembly line: har cheez andar jaati hai, transform hoke doosri taraf **nayi cheez** nikalti hai. Agar output nahi chahiye to assembly line kyun chalayi?

### Day-to-day use

- `for...of` — array/Map/Set pe iterate, sequential `await`, jab `break` chahiye.
- `.map()` — React list rendering (`items.map(i => <Row key={i.id} .../>)`), data reshape.
- `for` — reverse iteration, step != 1, algorithm code (two pointers).
- `while` — queue/stack drain, retry loop, "jab tak condition".
- `for...in` — plain object ke keys debug karna (par `Object.keys` prefer).

### Kab plain `for` use karna chahiye

Index chahiye, non-1 step, reverse, ya do collections parallel. Performance-critical tight loops mein `for` thoda fast hota hai (negligible for most apps).

### Kab `for...of` use nahi karna chahiye

Plain objects pe (`not iterable`) — `Object.entries()` pehle. Aur jab tum genuinely naya array bana rahe ho aur use karoge — wahan `.map()` intent clearer hai.

### Kab `for...in` use nahi karna chahiye

Arrays pe (order + inherited keys + string indices). Modern code mein almost never — `Object.keys/values/entries` + `for...of` har case cover karta hai zyada safely.

### Pros and cons

**`for...of`**

- **Pros:** har iterable pe same syntax; values seedhe; `break`/`continue`/`await` sab kaam; index book-keeping nahi.
- **Cons:** plain objects pe nahi; naya array banane ke liye `.map()` se kam declarative; thoda slower than raw `for` in hot loops.

**`.map()` / `.forEach()` / `.filter()`**

- **Pros:** declarative, chainable, no manual index, immutable-friendly (`.map` naya array).
- **Cons:** `break`/early-exit nahi; `await` sequential nahi hota; `.map` for side-effects = anti-pattern; har call ek naya array allocate karta hai.

### Alternatives

- **`.reduce()`** — ek array ko ek single value/shape mein fold karna.
- **`.some()` / `.every()` / `.find()`** — "koi/sab match karta hai?" ya "pehla match" — inbuilt early-exit ke saath.
- **`for await...of`** — async iterables (streams, paginated APIs).
- **Recursion** — tree/nested structures jahaan depth pata nahi.

### Interview mein "for-of vs map kab?"

> "Main `.map()` tab use karta hoon jab har element se ek naya element bana raha hoon aur wo naya array aage use hoga — ek pure transform, jaise list rendering ya data reshape. Agar mujhe sirf side-effects chahiye (har item save karna, log karna), ya beech mein `break` karna hai, ya har item pe sequential `await` chahiye — to `for...of`. `.map()` ko side-effects ke liye use karna anti-pattern hai kyunki wo ek array banata hai jise tum phenk dete ho, aur `forEach` async callback ka `await` ignore kar deta hai — na wait, na `break`. `for...in` main sirf plain objects pe use karta hoon, aur wahan bhi usually `Object.entries()` + `for...of` behtar hai kyunki `for...in` inherited enumerable keys bhi laata hai aur order guarantee nahi karta."

</Hinglish>

<Callout type="trap">

`array.forEach(async item => { await save(item); })` sequential **nahi** chalta aur `console.log` uske baad turant chal jaata hai — `forEach` async callback ka promise ignore karta hai. Sequential chahiye: `for...of` + `await`. Parallel chahiye: `Promise.all(array.map(...))`.

</Callout>

## Real World Example

<RealWorld company="React">

List rendering React mein `.map()` ka canonical use hai: `{todos.map(t => <TodoItem key={t.id} todo={t} />)}` — har element se ek naya element (JSX), aur wo naya array React ko render ke liye chahiye. Ulta, ek `useEffect` ke andar "har subscription pe cleanup register karo" jaisa side-effect `for...of` ya `forEach` se hota hai — wahan naya array nahi banana. Naye devs ka common bug: `todos.map(t => { updateServer(t); })` — server calls to ho jaate hain par ek `undefined`-bhara array ban ke phink jaata hai, aur ESLint `array-callback-return` warn karta hai.

</RealWorld>

<RealWorld company="Node.js — batch processing">

Node scripts mein "1000 records process karo, ek-ek karke, rate-limit respect karte hue" ke liye `for...of` + `await` standard hai — `for (const rec of records) { await api.push(rec); }`. Agar koi `records.forEach(async r => await api.push(r))` likhe to saari 1000 calls ek saath fire ho jaati hain (rate-limit blow), aur script "done" bol ke exit kar sakti hai jab calls abhi pending hain. Jab parallelism chahiye par bounded, `p-limit` jaisi library ya manual chunking ke saath `Promise.all`.

</RealWorld>

## Numbers That Matter

<Numbers>

- `for...of` aur `for...in` dono `break`/`continue`/`await` support karte hain; `.forEach()` **na** `break` na effective `await`.
- `for...of` **ES6 (2015)**; `for...in` original JavaScript (1997) se.
- `.map()` hamesha input ke **exactly same length** ka naya array deta hai — items skip nahi kar sakte (uske liye `.filter()`).
- `for...in` **inherited** enumerable properties bhi iterate karta hai — isliye `Object.hasOwn()` guard historically zaroori tha.
- `for await...of` **ES2018** mein aaya — async iterables (streams, paginated fetch) ke liye.
- Raw `for` loop tight numeric loops mein `for...of` se thoda fast — but real-world app code mein difference measure karne layak nahi.

</Numbers>

## Interview Angle

<InterviewAngle>

Do sure-shot questions: (1) "`for...of` vs `for...in` — farak aur kab kaunsa?" (2) "`.map()` vs `for...of` / `forEach` — kab kya?" Aksar ek code snippet bhi: `forEach` ke andar `await` jo kaam nahi karta.

Model answer shape:

1. **`for...of`** — "kisi bhi iterable ke values; `break`/`continue`/`await` chalte hain; modern default."
2. **`for...in`** — "object ke enumerable keys, inherited bhi; arrays pe mat; `Object.keys/entries` prefer."
3. **`.map()`** — "naya array from transform, aur wo array use hona chahiye; side-effects ke liye nahi."
4. **`forEach`** — "side-effects OK, par no `break`, no real `await`."
5. **`await` in loops** — "`for...of` + `await` = sequential; `Promise.all(map(...))` = parallel; `forEach(async)` = broken."

Red flag: arrays pe `for...in` recommend karna, ya `.map()` ko side-effect ke liye use karna.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Arrays pe `for...in` use karna.** Ye string keys (`"0"`, `"1"`) deta hai, inherited enumerable properties bhi laata hai, aur order guarantee nahi karta. Values chahiye to `for...of`; index chahiye to `for` ya `arr.entries()`.

</Mistake>

<Mistake>

**`.map()` ko side-effect ke liye use karna.** `users.map(u => sendEmail(u))` ek naya array banata hai jo phenk diya jaata hai — intent-misleading aur lint-flagged. Side-effects ke liye `for...of` ya `forEach`.

</Mistake>

<Mistake>

**`forEach(async ...)` se sequential await expect karna.** `forEach` callback ka promise ignore karta hai — loop wait nahi karta, uske baad ka code turant chalta hai. Sequential = `for...of` + `await`; parallel = `Promise.all(arr.map(...))`.

</Mistake>

<Mistake>

**Loop ke andar `array.push`/`splice` karke length shift karna.** `for (let i = 0; i < arr.length; i++)` jisme tum `arr.splice(i, 1)` karte ho — indices shift ho jaate hain, items skip hote hain. Reverse iterate karo ya `.filter()` se naya array banao.

</Mistake>

<Mistake>

**Nested loop se bahar nikalne ke liye sirf `break` likhna.** Inner `break` sirf inner loop chhodta hai. Dono se nikalna ho to labeled `break outer;` ya ek `found` flag ya loop ko function mein daal ke `return`.

</Mistake>

## Quick Revision

<QuickRevision>

- `for...of` = kisi bhi **iterable** ke **values** (array, string, Map, Set, NodeList, arguments). `break`/`continue`/`await` sab chalte hain. Modern default.
- `for...in` = object ke **enumerable keys**, **inherited bhi**, order guaranteed nahi. **Arrays pe kabhi nahi.** `Object.keys/entries` + `for...of` prefer.
- `.map()` = har element -> naya element, **same length** naya array. Sirf jab wo array use hoga.
- `.map()` for side-effects = **anti-pattern** (array banake phenkna). `for...of` / `forEach` use karo.
- `forEach` — no `break`, aur `async` callback ka `await` **ignore** karta hai.
- Sequential await: `for...of` + `await`. Parallel: `Promise.all(arr.map(...))`. `forEach(async)` broken.
- Classic `for` — index, reverse, `i += 2`, do arrays parallel, hot numeric loops.
- `while` — iteration count unknown (queue drain, retry).
- `continue` = agli iteration; `break` = loop khatam; `break outer:` = nested se bahar.
- Loop ke andar array mutate (`splice`) mat karo — indices shift, items skip. Reverse iterate ya `.filter()`.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `const arr = [10, 20, 30]; arr.foo = "bar";` — ab `for (const x of arr)` aur `for (const k in arr)` dono chala ke output likho. Farak explain karo.

**Medium:** Ye code fix karo taaki "done" tabhi print ho jab saare saves complete ho jaayein:
```
[1,2,3].forEach(async (n) => { await save(n); });
console.log("done");
```
Do versions do — ek sequential, ek parallel — aur batao kaunsa kab.

**Bada:** Ek `firstDuplicate(arr)` likho jo pehla element return kare jo do baar aata hai, warna `null`. `for...of` + `break` (ya early `return`) use karo — poora array scan mat karo agar jaldi mil jaaye. Phir explain karo ki `.map()` ya `.forEach()` yahan kyun galat tool hote.

</Callout>
