<SimpleDefinition>

**Template literals** are strings written with **backticks** instead of quotes. They support **interpolation** with the `${expression}` syntax — any expression (not just a variable) is evaluated and inserted — and they can span **multiple lines** without `\n`. A **tag function** placed before the literal receives the static string parts and the interpolated values **separately**, letting it build a custom result — the basis of `styled-components` and of HTML/SQL escapers.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Purane JavaScript mein strings jodna painful tha — `"Hello, " + name + "! Tumhare paas " + count + " messages hain."` — quotes, plus signs, spacing sab manually. Template literals (ES6) ne ise readable bana diya, aur saath mein multiline strings aur ek advanced feature (tagged templates) diya jo React/CSS-in-JS ki backbone hai.

### Ye kya hai — backtick strings

```javascript
const name = "Vasant";
const greeting = `Hello, ${name}!`;   // "Hello, Vasant!"
```

Backtick (`` ` ``) — keyboard pe `1` ke left, `Esc` ke neeche. Iske andar `${...}` ek **placeholder** hai jo evaluate hoke string mein daal diya jaata hai.

### Ye kyun exist karta hai

Teen problems solve karne:

1. **String concatenation ka clutter** — `+`, quote-juggling, spacing bugs.
2. **Multiline strings** — pehle `"line1\n" + "line2"` ya `\` line-continuation.
3. **Extensible string building** — tagged templates se libraries apna syntax bana sakti hain.

### `${expression}` — sirf variable nahi, koi bhi expression

```javascript
`Total: ${price * qty}`
`Status: ${isActive ? "on" : "off"}`
`Items: ${cart.length}`
`Name: ${user.name.toUpperCase()}`
`Next: ${arr.map(x => x + 1).join(", ")}`
`Now: ${new Date().getFullYear()}`
```

Andar function calls, ternary, arithmetic, method chains — kuch bhi jo ek value return kare. **Statements nahi** (`if`, `for` nahi) — expression hona chahiye.

### Multiline — bina `\n`

```javascript
const html = `
  <div>
    <h1>${title}</h1>
    <p>${body}</p>
  </div>
`;
```

Jo bhi whitespace/newline backticks ke andar likhoge wo **literally** string mein aata hai — indentation bhi. Isliye leading spaces ka dhyan rakho (ya `.trim()` / dedent helper).

### Nesting template literals

```javascript
const rows = items
  .map(item => `<li class="${item.done ? "done" : ""}">${item.text}</li>`)
  .join("");
const list = `<ul>${rows}</ul>`;
```

Ek `${...}` ke andar doosra template literal bilkul valid hai — bas readability ke liye aksar bahar nikaal ke variable bana lena behtar.

### Internally kaise kaam karta hai — tagged templates

Ek **tag** = ek function jiska naam tumne template literal ke **theek pehle** likha (no parentheses):

```javascript
function tag(strings, ...values) {
  // strings = static text ke tukde (array)
  // values  = har ${...} ka evaluated result
}

const a = 5, b = 10;
tag`Sum of ${a} and ${b} is ${a + b}.`;
// strings = ["Sum of ", " and ", " is ", "."]
// values  = [5, 10, 15]
```

Tag function ko raw string **nahi** milti — use static parts aur dynamic values **alag-alag** milte hain, aur wo decide karta hai final result kaise banega (string hona bhi zaroori nahi). `strings` array pe ek `.raw` property bhi hoti hai (escape sequences un-processed) — `String.raw` isi ka use karta hai.

### Ek practical tag — HTML escaper

```javascript
function safeHtml(strings, ...values) {
  return strings.reduce((out, str, i) => {
    const val = values[i - 1];
    const escaped = String(val)
      .replace(/&/g, "&amp;")
      .replace(/</g, "&lt;")
      .replace(/>/g, "&gt;");
    return out + escaped + str;
  });
}

const userInput = `<script>alert(1)</script>`;
safeHtml`<p>${userInput}</p>`;
// "<p>&lt;script&gt;alert(1)&lt;/script&gt;</p>"
```

Static markup as-is, sirf **interpolated** values escape — yeh injection se bachne ka pattern hai. `styled-components` (`` styled.div`color: red` ``), `graphql-tag` (`` gql`{ user { id } }` ``), aur SQL query builders isi mechanism pe bane hain.

### Simple real-life analogy

- Normal template literal = ek **fill-in-the-blanks form** — fixed text chhpa hua, `${}` blanks tum bharte ho.
- Tagged template = wahi form ek **clerk** ke paas jaata hai jo blanks ko process karta hai (escape, validate, transform) fixed text ko chhone ke bina — clerk = tag function.

### Day-to-day use

- UI strings: `` `${count} unread` ``, `` `Welcome back, ${user.firstName}` ``.
- URLs: `` `/api/users/${id}/posts?page=${page}` `` (par values ko `encodeURIComponent` karo).
- Logs/errors: `` `Failed to load ${resource}: ${err.message}` ``.
- Class names: `` `btn btn-${variant} ${disabled ? "btn-disabled" : ""}` ``.
- CSS-in-JS: `` styled.button`padding: ${p => p.large ? 16 : 8}px` ``.

### Kab template literals use karne chahiye

- Koi bhi string jisme ek bhi dynamic value ho — concatenation se hamesha readable.
- Multiline text (SQL, HTML fragments, help text).
- Jab expression inline chahiye (`${a ? b : c}`).

### Kab use nahi karne chahiye

- Bilkul static string — `` `hello` `` vs `"hello"` mein koi fayda nahi, aur kuch style guides plain quotes prefer karte hain jab interpolation na ho (ESLint `prefer-template` ka ulta case).
- User-generated HTML jodna bina escaping ke — `` `<div>${userInput}</div>` `` seedha XSS. React JSX, `textContent`, ya ek escaper tag use karo.
- Bahut lambi multiline strings jinme indentation-sensitivity ho — leading whitespace silently ghus jaata hai.

### Pros and cons

**Template literals**

- **Pros:** interpolation readable; multiline native; koi bhi expression embed; tagged templates se extensible (CSS-in-JS, gql, escapers); nesting allowed.
- **Cons:** `${}` sirf backticks mein — `'...'`/`"..."` mein literal text ban jaata hai (silent bug); indentation string mein ghus jaata hai; raw HTML interpolation = XSS agar escape na karo; tagged-template API (`strings`/`values`) pehli baar confusing.

### Alternatives

- **`String.prototype.concat` / `+`** — ek chhoti static-ish join; modern code interpolation prefer karta hai.
- **`Array.join("")`** — bahut saare tukde (loop se bane rows) jodne ke liye.
- **`Intl` APIs / i18n libraries** — user-facing text jisme pluralization, dates, currency ho — raw interpolation kaafi nahi.
- **JSX** — UI markup ke liye interpolation string ke bajaye elements.

### Interview mein "Template literals kya dete hain concatenation se upar?"

> "Teen cheezein: (1) interpolation — `${expression}` mein koi bhi expression, `+` aur quote-juggling ke bina, jo readability aur fewer bugs deta hai; (2) native multiline strings bina `\\n`; (3) tagged templates — literal ke aage ek function naam likho aur use static string parts aur interpolated values alag-alag milte hain, jisse wo custom output bana sakta hai. Yahi mechanism `styled-components`, `graphql-tag`, aur HTML/SQL escapers ke peeche hai. Ek gotcha: `${}` sirf backticks mein kaam karta hai — single/double quotes mein wo literal text hai, jo ek common silent bug hai. Aur raw user input ko markup mein interpolate karna XSS deta hai, isliye wahaan escaping ya JSX chahiye."

</Hinglish>

<Callout type="trap">

`${}` sirf backticks ke andar interpolate hota hai. `'Hi ${name}'` (single quotes) literally `Hi ${name}` string deta hai — koi error nahi, bas galat output. `prefer-template` / template-literal linting isse pakadta hai.

</Callout>

## Real World Example

<RealWorld company="styled-components / Emotion (React CSS-in-JS)">

`` const Button = styled.button`background: ${p => p.primary ? "blue" : "gray"}; padding: 8px 16px;` `` — yahaan `` styled.button`...` `` ek tagged template hai. Tag function ko CSS ke static parts aur functions (`p => ...`) alag-alag milte hain; render time pe wo props ke saath call hote hain aur ek real CSS class generate hoti hai. Bina tagged templates ke ye poori library ka ergonomic API possible hi nahi tha.

</RealWorld>

<RealWorld company="Node.js — SQL query builders / logging">

`` `SELECT * FROM users WHERE id = ${userId}` `` seedha likhna **SQL injection** hai. Isliye libraries jaise `sql-template-strings` ya `postgres` ek tagged template deti hain: `` sql`SELECT * FROM users WHERE id = ${userId}` `` — tag `userId` ko as-is string mein daalne ke bajaye ek parameterized query (`... WHERE id = $1`, values `[userId]`) banata hai. Same idea structured logging mein — pino/winston helpers static message aur interpolated fields ko alag rakhte hain taaki logs machine-parseable rahein.

</RealWorld>

## Numbers That Matter

<Numbers>

- Template literals **ES6 (ES2015)** mein aaye — `String.raw` aur tagged templates bhi tabhi.
- Tag function ko `strings.length === values.length + 1` hamesha — static parts hamesha ek zyada.
- `${}` ke andar **expressions** allowed hain, **statements nahi** — `if`/`for`/`let` nahi chalega.
- `String.raw` escape sequences ko process nahi karta — `` String.raw`\n` `` do characters (`\` aur `n`), ek newline nahi.
- ESLint `prefer-template` rule `"a" + b` ko template literal mein convert karne ko kehta hai.
- Backticks ke andar literal backtick chahiye to escape: `` \` ``; literal `${` chahiye to `\${`.

</Numbers>

## Interview Angle

<InterviewAngle>

Common: "Template literals concatenation se better kyun?" aur "Tagged template kya hai, ek use batao." Kabhi output-prediction: `${}` single quotes mein.

Model answer shape:

1. **Interpolation** — "`${expression}` — koi bhi expression, `+` ke bina."
2. **Multiline** — "backticks ke andar newline literal, `\\n` nahi chahiye."
3. **Expression scope** — "ternary, method calls, arithmetic OK; statements nahi."
4. **Tagged templates** — "literal ke aage function naam; use `(strings, ...values)` milta hai; custom output."
5. **Use / risk** — "styled-components, gql, SQL/HTML escapers; raw user input interpolate = XSS."

Red flag: `${}` ko har string mein kaam karta samajhna, ya tagged template ko "sirf ek function call" bolna.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`${}` ko single/double quotes mein likhna.** `"Total: ${sum}"` literally `Total: ${sum}` deta hai — no error, galat output. Interpolation ke liye backticks mandatory.

</Mistake>

<Mistake>

**Raw user input ko markup mein interpolate karna.** `` element.innerHTML = `<div>${userInput}</div>` `` — agar `userInput` mein `<script>` ho to XSS. `textContent`, React JSX, ya escaper tag use karo.

</Mistake>

<Mistake>

**Multiline literal ka indentation bhoolna.** Backticks ke andar har leading space string mein aata hai — ek indented code block mein likha template literal expected se zyada whitespace-bhara hota hai. `.trim()` ya dedent helper.

</Mistake>

<Mistake>

**`${}` ke andar statement daalne ki koshish.** `` `${if (x) "a" else "b"}` `` invalid — sirf expressions. Ternary use karo: `` `${x ? "a" : "b"}` ``.

</Mistake>

<Mistake>

**URL/query values ko bina encode kiye interpolate karna.** `` `/search?q=${term}` `` jahaan `term` mein space ya `&` ho — broken URL. `${encodeURIComponent(term)}`.

</Mistake>

## Quick Revision

<QuickRevision>

- Backtick strings — `` `text ${expr} text` ``.
- `${...}` — koi bhi **expression** (ternary, call, arithmetic, method chain). **Statements nahi.**
- Multiline native — backticks ke andar newline literal, `\n` nahi chahiye; **indentation bhi string mein aata hai**.
- Nesting allowed — `${...}` ke andar doosra template literal.
- `${}` **sirf backticks mein** — `'...'`/`"..."` mein literal text (silent bug).
- **Tagged template**: `` tag`...` `` — `tag(strings, ...values)`; static parts + interpolated values alag; output kuch bhi ho sakta hai.
- `strings.length === values.length + 1` hamesha; `strings.raw` un-processed escapes.
- Use: UI text, URLs, logs, class names, CSS-in-JS, `gql`, SQL/HTML escapers.
- Raw user input + markup interpolation = **XSS** — escaper tag / JSX / `textContent`.
- URL values -> `encodeURIComponent`; SQL values -> parameterized / `sql` tag.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** In dono ka output batao: `` `2 + 2 = ${2 + 2}` `` aur `'2 + 2 = ${2 + 2}'`. Farak kyun hai?

**Medium:** Ek `summary(user)` likho jo ek multiline string return kare jisme `user.name` (uppercase), `user.posts.length`, aur ek line `` `Status: ${user.active ? "active" : "inactive"}` `` ho. Phir `.trim()` laga ke leading/trailing whitespace hatao aur explain karo wo kyun zaroori tha.

**Bada:** Ek chhota tagged template `highlight` likho jo har interpolated value ko `**...**` (markdown bold) mein wrap karke baaki static text ke saath jod de. `` highlight`Hello ${name}, you have ${count} new messages` `` ka output `"Hello **Vasant**, you have **3** new messages"` hona chahiye. `(strings, ...values)` signature use karo aur `strings.length === values.length + 1` ko dhyan mein rakho.

</Callout>
