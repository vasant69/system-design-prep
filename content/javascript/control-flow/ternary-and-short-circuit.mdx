<SimpleDefinition>

The **ternary** operator `cond ? a : b` is an **expression** — it evaluates to `a` when `cond` is truthy and to `b` otherwise, so it can sit inline in an assignment, a `return`, or JSX where a statement like `if` cannot. The logical operators `&&` and `||` do **not** return a boolean — they return **one of their two operands**: `a && b` gives `a` if `a` is falsy, else `b`; `a || b` gives `a` if `a` is truthy, else `b`. That is why `||` is used for defaults and `&&` for conditional evaluation and rendering.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

`if` ek **statement** hai — wo kuch return nahi karta, sirf code chalata hai. Par bahut baar tumhe ek *value* chahiye hoti hai condition ke basis pe: "agar logged in to naam, warna Guest". Uske liye ternary aur short-circuit operators hain — ye sab **expressions** hain, yaani inka result kahin bhi use ho sakta hai.

### Ye kya hai — ternary `cond ? a : b`

Teen parts: condition, `?`, truthy-value, `:`, falsy-value. Poora cheez ek value banti hai.

```javascript
const label = isLoggedIn ? "Logout" : "Login";
const fee = amount > 1000 ? amount * 0.02 : 20;
return <p>{count === 1 ? "1 item" : count + " items"}</p>;
```

`if` se yahi likhna verbose hai:

```javascript
let label;
if (isLoggedIn) {
  label = "Logout";
} else {
  label = "Login";
}
```

4 lines vs 1, aur `let` bhi banana pada (`const` nahi ho sakta kyunki do jagah assign). Ternary se `const` rehta hai.

### Ye kyun exist karta hai

JSX aur JSON jaisi jagah pe tum `if` statement nahi likh sakte — sirf expressions allowed hain. Ternary + `&&`/`||` in jagahon pe "conditional logic" ka only tarika hai. React code mein ye har doosri line pe dikhte hain.

### Internally kaise kaam karta hai — `&&` aur `||` operands return karte hain

Ye sabse important insight hai. `&&` aur `||` boolean **nahi** dete — ye apne do operands mein se **ek** return karte hain, waise ka waisa:

- **`a || b`** — pehle `a` evaluate karo. `a` **truthy** hai? `a` return karo, `b` ko chhuo bhi mat. Warna `b` return karo.
- **`a && b`** — pehle `a` evaluate karo. `a` **falsy** hai? `a` return karo, `b` ko chhuo bhi mat. Warna `b` return karo.

```javascript
"hello" || "world"   // "hello"  (a truthy -> a)
""      || "world"   // "world"  (a falsy  -> b)
0       || 42        // 42
null    || "default" // "default"

"hello" && "world"   // "world"  (a truthy -> b)
""      && "world"   // ""       (a falsy  -> a)
0       && crash()   // 0        (crash() kabhi nahi chala!)
user    && user.name // user.name only if user truthy
```

"Jo cheez evaluation ko decide kar deti hai, wahi return hoti hai" — `||` ke liye pehla truthy, `&&` ke liye pehla falsy. Agar aisi koi na mile to aakhri operand return hota hai.

**Short-circuit** ka matlab: right side evaluate hi nahi hoti agar left side ne decision de diya. `isReady && doExpensiveThing()` — `doExpensiveThing()` sirf tab chalega jab `isReady` truthy ho.

### Simple real-life analogy

- `||` = "Plan A try karo. Kaam ho gaya? Ruk jao. Nahi? Plan B pe jao." — `const port = userPort || 3000`.
- `&&` = "Pehle key check karo. Key hai? Tabhi darwaza kholne ki koshish karo." — `door && door.open()`.
- Ternary = ek switchboard: ek input, do wire, jo condition kehti hai wahi wire connect hoti hai.

### Code — line by line

```javascript
function getGreeting(user) {
  const name = user.name || "Guest";
  const isAdmin = user.role === "admin";
  return isAdmin
    ? `Welcome back, ${name} (admin)`
    : `Hi, ${name}`;
}
```

- `user.name || "Guest"` — `user.name` truthy (koi real string) hai to wahi; `""` ya `undefined` hai to `"Guest"`. Ye "default value" pattern hai.
- `user.role === "admin"` — `===` ek genuine boolean deta hai, `isAdmin` clean rehta hai.
- `return isAdmin ? ... : ...` — ternary ek value return karta hai; multi-line pe indent karke padhne layak rakha.

### Day-to-day use — teen classic patterns

**1. Default value (`||` ya `??`):**

```javascript
const timeout = options.timeout || 5000;
const name = user.displayName || user.email || "Anonymous";  // chain
```

**2. Conditional render (`&&`):**

```jsx
{isOpen && <Modal />}
{errors.length > 0 && <ErrorBanner errors={errors} />}
{user?.isPremium && <Badge>PRO</Badge>}
```

**3. Pre-optional-chaining guard (`&&`):**

```javascript
const city = user && user.address && user.address.city;
// aaj: user?.address?.city
```

### Nested ternary — readability limit

Ek level theek hai. Do se zyada nesting = padhna mushkil:

```javascript
// theek — flat, ek level
const size = w < 600 ? "sm" : w < 1024 ? "md" : "lg";

// bura — nested, dimaag ghoom jaata hai
const x = a ? (b ? c : d) : (e ? f : g);
```

Nested case mein `if/else if` ya ek lookup object zyada readable hota hai. Prettier nested ternary ko indent karke thoda bearable bana deta hai, par 3+ branches pe rethink karo.

### `||` default ka bug — jab `0` / `""` valid hon

```javascript
function createUser(opts) {
  const retries = opts.retries || 3;   // BUG
  const name = opts.name || "Anon";     // BUG
}

createUser({ retries: 0, name: "" });
// retries -> 3 (user ne 0 maanga tha!)
// name    -> "Anon" (user ne blank maanga tha!)
```

`0` aur `""` falsy hain, to `||` unhe "not provided" samajh ke default de deta hai. Jab `0`/`""`/`false` legitimate values hain, `||` ki jagah **`??`** (nullish coalescing) chahiye — wo sirf `null`/`undefined` pe default deta hai. `opts.retries ?? 3` `0` ko respect karega. (Poora `??` topic aage hai.)

### Kab ternary use karna chahiye

- Do values mein se ek choose karke turant use/return/assign karni ho.
- JSX/template ke andar do alternatives ke beech.
- Ek `const` chahiye jise condition set kare (variable ko `let` banane se bachao).

### Kab ternary use nahi karna chahiye

- Do se zyada branches (nested) — `if/else if` ya lookup.
- Har branch mein multi-line side-effects (logging, multiple statements) — `if` block.
- Sirf ek side pe action, dusri side "kuch nahi" — `&&` ya `if` better (`cond ? doThing() : null` awkward hai).

### Kab `&&` / `||` use karna chahiye

- `||` / `??` — default value dena.
- `&&` — "agar ye truthy hai tabhi ye karo/render karo" (ek-tarfa).
- Guard chains — `obj && obj.method && obj.method()` (aaj `?.` better).

### Kab `&&` / `||` use nahi karna chahiye

- `&&` ko JSX mein number ke saath: `{count && <X/>}` `0` render kar deta hai — `{count > 0 && <X/>}` likho.
- `||` ko default ke liye jab `0`/`""` valid — `??` use karo.
- `&&` ko statement ki tarah side-effect ke liye (`cond && doStuff()`) — technically chalta hai par `if` zyada readable, lint (`no-unused-expressions`) complain kar sakta hai.

### Pros and cons

**Ternary**

- **Pros:** expression hai — assignment/return/JSX mein fit; `const` friendly; ek-line mein do-value choice.
- **Cons:** nesting jaldi unreadable; multi-statement branches ke liye galat tool; over-use se code dense.

**`&&` / `||` short-circuit**

- **Pros:** default values aur conditional rendering ka concise idiom; right side lazily evaluate hoti hai (guard side-effects); chain ho sakte hain.
- **Cons:** truthy/falsy semantics — `0`/`""` ke sa_th `||` bug; `&&` JSX mein `0` leak karta hai; over-clever chains debug karna mushkil.

### Alternatives

- **`if / else`** — multi-line branches, 3+ cases, side-effects.
- **`??` (nullish coalescing)** — default value jab `0`/`""`/`false` valid hon.
- **`?.` (optional chaining)** — `a && a.b && a.b.c` ki jagah.
- **Lookup object/Map** — `{ sm: ..., md: ..., lg: ... }[size]` — 3+ discrete mappings.

### Interview mein "`&&` boolean return karta hai kya?"

> "Nahi. `&&` aur `||` apne operands mein se ek return karte hain, boolean nahi. `a || b` `a` deta hai agar `a` truthy hai warna `b` — isliye `userName || 'Guest'` default pattern kaam karta hai. `a && b` `a` deta hai agar `a` falsy hai warna `b` — isliye `isOpen && <Modal/>` kaam karta hai aur `user && user.name` guard ki tarah. Dono short-circuit karte hain: right side tabhi evaluate hoti hai jab left side decision na de. Ek gotcha: `||` `0` aur `\"\"` ko falsy maan ke default de deta hai, isliye jab wo valid values hon to `??` use karta hoon."

</Hinglish>

<Callout type="trap">

`&&` / `||` ka result **boolean nahi** hota. `const flag = a || b` mein `flag` `b` ki poori value ho sakti hai (ek object, ek string). Genuine boolean chahiye to `Boolean(a || b)` ya `!!(a || b)`.

</Callout>

## Real World Example

<RealWorld company="React">

React mein `{isLoading ? <Spinner /> : <Content data={data} />}` conditional rendering ka standard hai, aur `{hasError && <Alert />}` "sirf jab error ho" ke liye. Sabse common production bug: `{cart.items.length && <Cart />}` — jab cart khaali hai `0` screen pe print ho jaata hai. Codebases mein iske liye ESLint rule (`react/jsx-no-leaked-render`) hota hai jo `&&` ke left side ko boolean force karwata hai ya ternary suggest karta hai.

</RealWorld>

<RealWorld company="Node.js / config loading">

`const PORT = process.env.PORT || 3000;` har Express app mein dikhta hai — env var na ho to fallback. Ye zyaadatar theek hai kyunki `PORT=""` rare hai, par `const RETRIES = process.env.MAX_RETRIES || 3` `MAX_RETRIES=0` ("retry mat karo") ko silently `3` bana deta hai. Modern configs `??` pe shift ho rahe hain exactly is class of bug ke liye.

</RealWorld>

## Numbers That Matter

<Numbers>

- Ternary hi JavaScript ka **ekmatra 3-operand** operator hai — isliye "ternary" naam.
- `&&` aur `||` **ES1 (1997)** se hain; `??` bahut baad mein **ES2020** mein aaya isi `||`-default bug ko fix karne.
- `&&` ki precedence `||` se **zyada** hai — `a || b && c` ka matlab `a || (b && c)`.
- Short-circuit ka matlab: `false && anyExpensiveCall()` mein woh call **0 baar** chalti hai.
- `??` ko `||` ya `&&` ke saath bina parentheses mix karna **SyntaxError** hai — `(a ?? b) || c` explicitly likho.
- Nested ternary readability studies aur most style guides: **1 level max** recommended.

</Numbers>

## Interview Angle

<InterviewAngle>

Sabse common single question: "`&&` / `||` kya return karte hain?" Sahi jawaab: "operands, boolean nahi." Uske baad output-prediction: `0 || 42`, `null && x`, `"" || "x"`.

Model answer shape:

1. **Ternary** — "expression hai, value deta hai, `if` statement se alag; `const` aur JSX friendly."
2. **`||`** — "pehla truthy operand, warna aakhri; default value pattern."
3. **`&&`** — "pehla falsy operand, warna aakhri; conditional-render aur guard pattern."
4. **Short-circuit** — "right side lazily evaluate hoti hai."
5. **Gotcha** — "`||` `0`/`""` pe default de deta hai — `??` better jab wo valid."

Red flag: "`&&` hamesha `true`/`false` deta hai" — galat.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Ye maanna ki `&&`/`||` boolean dete hain.** `const x = data || {}` mein `x` `data` ki poori value ya `{}` hai. Agar tumhe `true`/`false` chahiye to `!!(data)` ya `Boolean(data)` likho.

</Mistake>

<Mistake>

**`||` ko default ke liye jab `0` / `""` / `false` valid hon.** `const qty = input || 1` `input = 0` ko `1` bana deta hai. `input ?? 1` use karo — wo sirf `null`/`undefined` pe default deta hai.

</Mistake>

<Mistake>

**JSX mein `{count && <List/>}`.** `count` `0` hone pe React `0` text render kar deta hai. `{count > 0 && <List/>}` ya `{count ? <List/> : null}` likho.

</Mistake>

<Mistake>

**Nested ternary ko 2+ levels tak stretch karna.** `a ? b : c ? d : e ? f : g` padhne mein torture hai. 3+ branches pe `if/else if`, lookup object, ya alag function use karo.

</Mistake>

<Mistake>

**`??` ko `||` / `&&` ke saath bina brackets mix karna.** `a ?? b || c` seedha `SyntaxError` deta hai. `(a ?? b) || c` ya `a ?? (b || c)` — intent explicitly likho.

</Mistake>

## Quick Revision

<QuickRevision>

- Ternary `cond ? a : b` ek **expression** — value deta hai, `if` (statement) se alag. `const`/JSX friendly.
- `a || b` = pehla **truthy** operand, warna aakhri. Default-value pattern: `name || "Guest"`.
- `a && b` = pehla **falsy** operand, warna aakhri. Guard/render pattern: `isOpen && <Modal/>`.
- Result **operand hota hai, boolean nahi**. Boolean chahiye: `!!x` ya `Boolean(x)`.
- **Short-circuit**: right side evaluate hi nahi hoti agar left decision de de — `ready && expensive()`.
- `||` bug: `0` / `""` / `false` ko default se replace kar deta hai — un cases mein `??` use karo.
- JSX: `{count && <X/>}` `0` leak karta hai — `{count > 0 && <X/>}`.
- Nested ternary: **1 level max**. 3+ branches: `if/else if` ya lookup object.
- `&&` precedence `||` se zyada: `a || b && c` = `a || (b && c)`.
- `??` ko `||`/`&&` ke saath bina `()` mix karna `SyntaxError`.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Predict, phir run: `0 || "a"`, `"a" || "b"`, `null && "x"`, `1 && 2 && 3`, `"" ?? "d"`, `0 ?? "d"`, `0 || "d"`. Batao har ek kyun.

**Medium:** Ek `formatCount(n)` likho jo ternary use kare: `n === 0` pe `"empty"`, `n === 1` pe `"1 item"`, warna `` `${n} items` ``. Ek level ternary mein rakho ya batao kyun nesting yahan avoid karna chaho.

**Bada:** Ek `resolveConfig(userOpts)` likho jinme `retries`, `timeout`, `label` fields ho. `retries` aur `timeout` numeric hain jahan `0` valid hai; `label` string hai jahan `""` valid hai. Sahi operator (`??` vs `||`) chuno har field ke liye aur ek comment mein likho kyun `retries || 5` bug hota. Phir `userOpts = { retries: 0, timeout: undefined, label: "" }` ke liye expected output likho.

</Callout>
