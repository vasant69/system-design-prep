<SimpleDefinition>

Conditionals (`if` / `else if` / `else`) run a block of code only when a condition is **truthy**. JavaScript first coerces the condition to a boolean using its truthiness rules: there are exactly **eight falsy values** (`false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`) and **everything else is truthy** — including the strings `"0"` and `"false"`, a single space `" "`, `[]`, `{}`, and any function. Writing `if (value)` as a shortcut is idiomatic, but it becomes a bug when `0` or `""` are legitimate values.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Har program ko decisions lene padte hain — "agar user logged in hai to dashboard dikhao, warna login page". JavaScript mein ye kaam `if` karta hai, aur iska sabse tricky hissa ye hai ki `if` ke bracket mein jo bhi daaloge use JS pehle `true`/`false` mein badal deta hai — aur ye rules yaad na hon to silent bugs aate hain.

### Ye kya hai — if / else if / else

`if (condition) { ... }` — condition truthy hui to block chalta hai. `else if` se aur conditions check kar sakte ho, `else` baaki sab cases ke liye.

```javascript
if (score >= 90) {
  grade = "A";
} else if (score >= 75) {
  grade = "B";
} else {
  grade = "C";
}
```

Engine upar se neeche chalta hai — jo pehli condition truthy milti hai, uska block chalta hai, baaki skip. Isliye order matmatta hai: general condition pehle likh di to specific wali kabhi nahi chalegi.

### Ye kyun exist karta hai

Bina conditionals ke program ek hi straight line mein chalta — koi branching nahi, koi "agar/warna" nahi. `if` control flow ka sabse basic tool hai; ternary, `switch`, short-circuit — sab isi ke variations hain.

### Internally kaise kaam karta hai — ToBoolean coercion

`if (x)` ka matlab JS internally `if (Boolean(x) === true)` jaisa karta hai — spec ise **ToBoolean** abstract operation kehta hai. Ye ek chhoti si fixed list check karta hai:

**Falsy — exactly 8 values:**

```javascript
false
0
-0
0n        // BigInt zero
""        // empty string (aur '' aur ``)
null
undefined
NaN
```

**Truthy — literally everything else**, jisme kuch surprising cheezein:

```javascript
"0"        // truthy -- non-empty string
"false"    // truthy -- non-empty string
" "        // truthy -- space bhi ek character hai
[]         // truthy -- empty array bhi object hai
{}         // truthy -- empty object
function(){}   // truthy
Infinity   // truthy
new Date() // truthy
```

Rule yaad rakhne ka short-cut: **8 falsy values ratt lo, baaki sab truthy.** Koi "empty-ish" check nahi hota — `[]` aur `{}` truthy hain kyunki wo objects hain, unka content nahi dekha jaata.

### Simple real-life analogy

Security guard gate pe khada hai. Uske paas ek chhoti list hai (8 naam) jinhe andar nahi jaane dena. Baaki jo bhi aaye — chahe khaali haath ho (`""`), chahe "0" likha badge pehne ho — andar jaa sakta hai. Guard content nahi dekhta, bas apni 8-naam wali list check karta hai.

### Code — line by line

```javascript
function greet(name) {
  if (!name) {
    return "Hello, Guest";
  }
  return "Hello, " + name;
}

greet("Vasant");  // "Hello, Vasant"
greet("");        // "Hello, Guest"  <- "" falsy
greet();          // "Hello, Guest"  <- undefined falsy
greet("0");       // "Hello, 0"      <- "0" truthy!
```

- `if (!name)` — `name` ko boolean mein badla, phir `!` se ulta. `""` aur `undefined` falsy the, to `!name` `true` — guest branch.
- `greet("0")` — `"0"` non-empty string hai, truthy, `!name` `false` — normal greeting. Ye theek hai yahan, par agar `name` ki jagah `count` hota to `"0"` waala case bug ban sakta tha.

### The classic bug — `if (!count)` treats 0 as missing

```javascript
function render(count) {
  if (!count) {
    return "No items yet";
  }
  return count + " items";
}

render(5);          // "5 items"
render(0);          // "No items yet"  <- BUG: 0 items is a real answer!
render(undefined);  // "No items yet"  <- yahan sahi
```

`0` ek valid count hai ("cart mein 0 items"), par `!count` use `undefined` ki tarah treat kar raha hai. Same problem strings ke saath: `if (!name)` empty string `""` ko "missing" maan leta hai, jabki user ne shayad jaan-boojh ke blank chhoda ho.

**Fix — jab tumhara matlab sirf "null ya undefined" ho:**

```javascript
if (count == null) { ... }        // == null matches BOTH null and undefined, nothing else
if (count === undefined) { ... }  // only undefined
if (count === null) { ... }       // only null
```

`count == null` ek deliberate exception hai `==` avoid-karo rule ka — ye sirf `null` aur `undefined` ko match karta hai, `0`/`""`/`false`/`NaN` ko nahi. Bahut common aur safe pattern hai.

### Guard clauses / early return — flatter code

Nested `if` ki jagah pehle hi "bura case" nikaal do:

```javascript
// nested -- padhna mushkil
function processOrder(order) {
  if (order) {
    if (order.items.length > 0) {
      if (order.paid) {
        // asli kaam yahan, 3 levels andar
      }
    }
  }
}

// guard clauses -- flat
function processOrder(order) {
  if (!order) return;
  if (order.items.length === 0) return;
  if (!order.paid) return;
  // asli kaam yahan, 0 levels andar
}
```

Guard clause = "agar precondition fail, turant return/throw/continue". Isse "happy path" left margin pe seedha rehta hai, `else` ki zaroorat khatam.

### Comparison operators

- `===` / `!==` — strict, koi type coercion nahi. **Default yahi use karo.**
- `==` / `!=` — loose, types alag hon to coerce karta hai. Sirf `x == null` idiom ke liye.
- `<` `>` `<=` `>=` — numbers pe obvious. Strings pe **lexicographic** (dictionary jaisa, character code order): `"apple" < "banana"` `true`, par `"Z" < "a"` bhi `true` kyunki uppercase letters ke char codes lowercase se chhote hote hain. `"10" < "9"` `true` hai (string comparison — pehla char `"1"` vs `"9"`), jabki `10 < 9` `false`.

### Day-to-day use

- Feature flags: `if (config.betaEnabled) { ... }`
- Null-safety guards: `if (!user) return null;` component ke top pe.
- Input validation: `if (!email.includes("@")) { showError(); }`
- Default values: `if (options.timeout === undefined) options.timeout = 5000;`

### Kab `if (value)` shortcut use karna theek hai

Jab `value` genuinely ek object/array/string ho jo ya to "hai" ya `null`/`undefined` hai, aur `0` / `""` / `false` uske valid values nahi hain. Example: `if (user)`, `if (response.data)`, `if (elementRef.current)`.

### Kab `if (value)` use nahi karna chahiye

Jab `0`, `""`, ya `false` legitimate values hain:

- Counts, quantities, prices, array indexes (`indexOf` `-1` ke liye — but `0` valid index).
- User-entered text fields (empty string is a real state).
- Boolean config jahan `false` ka matlab "explicitly off" hai vs "not set".

In cases mein explicit check: `if (count === 0)`, `if (text === "")`, ya `if (value == null)` for the "not set" case.

### Pros and cons

**`if` / `else`**

- **Pros:** har situation handle kar sakta hai (ranges, multiple variables, complex boolean logic), sabse readable for non-trivial conditions, `return`/`throw` ke saath guard clauses banate hain.
- **Cons:** simple value-choice ke liye verbose (ternary better), ek hi variable ke against 5+ exact values check karne ho to `switch`/lookup better, deep nesting jaldi unreadable ho jaata hai.

### Alternatives

- **Ternary `a ? b : c`** — jab do values mein se ek choose karni ho aur result use karna ho (assignment, JSX).
- **`switch`** — ek variable, kai exact-match cases.
- **Object/Map lookup** — `const label = { a: "Apple", b: "Ball" }[key]` — data-driven branching.
- **Short-circuit `&&` / `||`** — ek chhoti conditional action ya default value.

### Interview mein "How does JS decide truthy vs falsy?"

> "JavaScript `if` condition ko ToBoolean se coerce karta hai. Sirf 8 falsy values hain — `false`, `0`, `-0`, `0n`, empty string, `null`, `undefined`, aur `NaN` — aur baaki literally sab truthy hai, including `"0"`, `"false"`, `" "`, `[]`, aur `{}`. Isliye `if (value)` shortcut tab dangerous hai jab `0` ya `""` valid data hon — `if (!count)` `0` ko missing samajh leta hai. Jab mera matlab sirf 'null ya undefined' ho to main `value == null` likhta hoon, jo deliberately in dono ko match karta hai aur kisi aur falsy value ko nahi."

</Hinglish>

<Callout type="trap">

`[]` aur `{}` **truthy** hain. `if (arr)` kabhi bhi "array khaali hai" nahi batata — us ke liye `if (arr.length === 0)` chahiye. `if (arr)` sirf `null`/`undefined` se bachata hai.

</Callout>

## Real World Example

<RealWorld company="React">

React components mein guard clauses har jagah hote hain: `if (!data) return <Spinner />;` component body ke top pe, taaki neeche ka JSX assume kar sake `data` maujood hai. Lekin conditional rendering mein truthy/falsy bug bahut common hai — `{items.length && <List items={items} />}` jab `items` khaali ho to screen pe literal `0` render kar deta hai, kyunki `0 && ...` `0` return karta hai aur React `0` ko text ki tarah dikhata hai. Fix: `{items.length > 0 && <List .../>}` ya `{items.length ? <List .../> : null}`.

</RealWorld>

<RealWorld company="Node.js / Express">

Express middleware mein `if (!req.headers.authorization) return res.status(401).end();` — guard clause pattern se har route handler apni preconditions upar check kar leta hai. Config loading mein bug aata hai jab `if (!process.env.PORT) port = 3000;` likha ho aur koi `PORT=0` set kare (valid — OS random free port deta hai) — `0` falsy hai to override ho jaata hai. Sahi check: `process.env.PORT ?? 3000` ya explicit `=== undefined`.

</RealWorld>

## Numbers That Matter

<Numbers>

- **Exactly 8** falsy values — memorise the list; everything else is truthy.
- `-0` aur `0n` (BigInt zero) bhi falsy — practically `0` ke saath hi count hote hain, so log "5-ish" bolte hain but spec mein 8.
- `NaN` hi ek aisi value hai jo apne aap ke `===` nahi — `NaN === NaN` `false`. Isliye `Number.isNaN()` use hota hai.
- `document.all` historically ek 9th "falsy-ish" object tha (legacy browser quirk) — modern code mein ignore karo.
- `if` / `else` original JavaScript (1995) se hai; kuch naya nahi.
- `==` ki coercion table itni confusing thi ki `===` add kiya gaya — aaj lint rules `==` ko `== null` ke alawa ban karte hain.

</Numbers>

## Common Mistakes

<Mistake>

**`if (arr.length)` vs `if (arr)` confuse karna.** `if (arr)` sirf batata hai `arr` `null`/`undefined` nahi hai — khaali array phir bhi truthy. "Kuch items hain kya" ke liye `if (arr.length > 0)` chahiye.

</Mistake>

<Mistake>

**`if (!count)` se "count nahi mila" check karna.** `0` ek valid count hai par falsy hai, to legitimate zero "missing" ban jaata hai. Jab sirf null/undefined check karna ho: `if (count == null)`.

</Mistake>

<Mistake>

**`if (x = 5)` — assignment vs comparison.** Ek `=` likh diya to `x` ko `5` assign hota hai aur condition `5` (truthy) ban jaati hai — hamesha chalega. `===` use karo; linters `no-cond-assign` se pakadte hain.

</Mistake>

<Mistake>

**`if (value === true)` likhna jab `value` boolean nahi hai.** Agar `value` `1` ya `"yes"` hai to `=== true` `false` dega. Boolean context chahiye to seedha `if (value)` ya `if (Boolean(value))`.

</Mistake>

<Mistake>

**else-if order galat rakhna.** `if (n > 0) ... else if (n > 100) ...` — dusri branch kabhi nahi chalegi, kyunki `n > 100` waali values pehli `n > 0` mein hi pakdi jaati hain. Specific/narrow conditions pehle.

</Mistake>

## Quick Revision

<QuickRevision>

- **8 falsy values:** `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`. Sab kuch aur truthy.
- Surprising truthy: `"0"`, `"false"`, `" "`, `[]`, `{}`, `function(){}`, `Infinity`.
- `if (value)` = `if (Boolean(value) === true)` internally (ToBoolean).
- `if (!count)` bug: `0` ko missing samajhta hai. `if (!name)` bug: `""` ko missing samajhta hai.
- "null ya undefined only" chahiye: `value == null` (deliberate `==` exception) ya `=== undefined` / `=== null`.
- `[]` khaali hai check: `arr.length === 0` — `if (arr)` se nahi hota.
- Guard clause = precondition fail pe turant `return`/`throw`/`continue` — nesting flat rakhta hai.
- Strings pe `<` `>` lexicographic (char-code order): `"Z" < "a"` `true`.
- `===` default; `==` sirf `== null` ke liye.
- else-if chain: specific conditions pehle, general baad mein.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Bina chalaye predict karo: `Boolean("0")`, `Boolean([])`, `Boolean(0)`, `Boolean(" ")`, `Boolean(NaN)`, `Boolean({})`. Phir chala ke check karo.

**Medium:** Ek function `describe(value)` likho jo return kare `"empty"` sirf jab `value` `null`, `undefined`, ya `""` ho; `"zero"` jab exactly `0` ho; warna `"has value"`. `render(0)` ko `"zero"` dena chahiye, `"missing"` nahi. Batao kyun `if (!value)` yahan galat hota.

**Bada:** Ek `getDisplayName(user)` likho jo guard clauses use kare: `user` `null` ho to `"Anonymous"`, `user.name` empty string ho to `"Unnamed"`, `user.name` `"0"` ho to wahi `"0"` return kare (valid name). Teeno branches ko flat rakho, koi nested `if` nahi. Phir ek line mein likho ki `"0"` case `if (user.name)` se kyun toot jaata.

</Callout>
