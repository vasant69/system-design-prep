<SimpleDefinition>

A **function declaration** (`function foo() {}`) is a statement that is fully **hoisted** — both its name and its body are available before the line it is written on, so it can be called earlier in the scope. A **function expression** (`const foo = function () {}` or `const foo = () => {}`) creates a function as a **value** assigned to a variable; only the variable binding is hoisted, following `let`/`const` rules, so it sits in the temporal dead zone until its line runs. Functions in JavaScript are **first-class values**: they can be stored in variables, passed as arguments, and returned from other functions.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Function banane ke do main tarike hain, aur farak sirf syntax ka nahi hai — **kab function callable banta hai** wo badalta hai. Interview mein ye "hoisting" question ke saath hamesha aata hai.

### Ye kya hai — declaration vs expression

**Function declaration** — statement jo `function` keyword se *shuru* hoti hai:

```javascript
function add(a, b) {
  return a + b;
}
```

**Function expression** — function ko ek value ki tarah kisi variable mein daala jaata hai. Line `const`/`let`/`var` se shuru hoti hai, `function` se nahi:

```javascript
const add = function (a, b) {
  return a + b;
};

const multiply = (a, b) => a * b; // arrow bhi ek expression hi hai
```

Dono ke andar ka function same kaam karta hai. Farak: declaration ko engine pehle se poora jaanta hai; expression tab tak exist nahi karta jab tak uski line run na ho.

### Ye kyun exist karta hai

Declaration original JavaScript se hai — mutual recursion aur "helper functions neeche, main logic upar" style ke liye handy: engine sab declarations pehle padh leta hai, isliye order matter nahi karta.

Expression tab zaroori hua jab functions ko **data** ki tarah treat karna common ho gaya — callback pass karna, ek object ki property banana, conditionally alag function assign karna, ya module se export karna. Ek value ko variable mein daalna = expression.

### Internally kaise kaam karta hai — hoisting

Engine har scope ko run karne se pehle scan karta hai (creation phase):

- **Declaration** — naam *aur* poora function body dono top pe register ho jaate hain. Isliye declaration ko uski line se pehle call karna valid hai.
- **Expression** — sirf variable ka binding hoist hota hai. `var` ho to `undefined`; `let`/`const` ho to **TDZ**. Function body us line pe hi assign hoti hai.

```javascript
greet(); // "Hi" -- declaration, pehle se ready

function greet() {
  console.log("Hi");
}

sayBye(); // TypeError: sayBye is not a function   (var)
           // ReferenceError: Cannot access 'sayBye' (const)

const sayBye = function () {
  console.log("Bye");
};
```

### Named function expression

Expression ko ek naam bhi de sakte ho:

```javascript
const fact = function factorial(n) {
  return n <= 1 ? 1 : n * factorial(n - 1); // andar naam se recurse
};
```

- `factorial` naam **sirf function ke andar** dikhta hai — bahar `factorial(5)` `ReferenceError` dega, `fact(5)` chalega.
- Fayda: stack traces mein "anonymous" ki jagah `factorial` dikhta hai — debugging aasan.

### Functions are values (first-class)

Function ek normal value hai — number ya string ki tarah:

```javascript
const ops = { add: (a, b) => a + b };      // object ki property
const list = [() => 1, () => 2];           // array ka element
[1, 2, 3].map(function (x) { return x * 2; }); // argument
function makeAdder(n) { return x => x + n; }    // return value
```

Yahi baat higher-order functions, callbacks, aur closures — sab ko possible banati hai.

### IIFE — Immediately Invoked Function Expression

```javascript
(function () {
  const secret = 42; // bahar leak nahi hota
  console.log("runs immediately");
})();
```

Function ko `( )` mein wrap karke turant `()` se call kar do. Pre-modules era mein iska bada use tha: **apna private scope** banana taaki `var` globals na banein aur libraries aapas mein clash na karein (jQuery plugins, `(function ($) { ... })(jQuery)`). Aaj ES modules har file ko apna scope de dete hain, isliye naye code mein IIFE kam dikhta hai — par legacy bundles aur `<script>` snippets mein abhi bhi milta hai.

### Day-to-day use

- Declaration — top-level helpers, utility modules, recursive functions.
- Expression — callbacks (`arr.map(...)`), event handlers, React component ke andar `const handleClick = () => {}`, conditionally assigned function.
- IIFE — legacy scope isolation; modern code mein `{ }` block ya module se replace.

### Kab declaration use karna chahiye

- Module ke top-level named helpers jinhe file mein kahin bhi call karna hai — hoisting se order ki tension nahi.
- Mutual recursion (`isEven`/`isOdd` ek dusre ko call karte hain).
- Jab "main logic upar, chhote helpers neeche" padhne mein saaf lage.

### Kab declaration use nahi karna chahiye

- Jab function ek value ki tarah pass/return/assign ho raha ho — waha expression natural hai.
- `if`/`else` block ke andar declaration — behaviour engine-dependent aur confusing; waha `let fn; if (...) fn = ...` use karo.
- Jab tum chahte ho function "use before define" pe crash kare (bug jaldi pakdo) — `const` expression TDZ deta hai.

### Pros and cons

**Declaration**

- Pros: hoisted, order-free, stack trace mein naam, `if`/`else`-independent readability.
- Cons: accidentally call-before-define bug chhup jaata hai; block ke andar unreliable.

**Expression (`const fn = ...`)**

- Pros: TDZ se "use before define" turant error; ek value ki tarah natural; `const` reassignment rokta hai.
- Cons: apni line se pehle callable nahi; anonymous expression stack trace mein naam nahi deta (named form se fix).

### Alternatives

- **Arrow function expression** — jab lexical `this` chahiye ya short callback ho (alag topic).
- **Method shorthand** — object/class ke andar `foo() {}` — internally ek function value banata hai bina `function` keyword ke.
- **`new Function("...")`** — string se function; sirf edge cases (templating), warna avoid — no closure, slow, CSP issues.

### Interview mein "Why declaration ya why expression?"

> "Top-level named helpers ke liye main declaration use karta hoon — hoisted hone ki wajah se main file ke top pe main flow rakh sakta hoon aur helpers neeche, order ki chinta ke bina. Jab function ek value ki tarah move kar raha ho — callback, object method, conditional assignment, export — tab expression, usually `const` ke saath, taaki reassignment na ho aur 'use before define' TDZ pe loud error de. Anonymous expression ki jagah named expression tab jab stack trace readability important ho."

</Hinglish>

<Callout type="tip">

`if (cond) { function foo() {} }` — block ke andar function declaration ka behaviour strict vs sloppy mode mein alag hai aur browsers mein historically buggy tha. Conditional function chahiye to `let foo; if (cond) foo = () => {...}` likho.

</Callout>

## Real World Example

<RealWorld company="Node.js / utility modules">

Bahut se Node utility files declaration style use karte hain — `function parseUrl(raw) {}`, `function normalize(path) {}` — file mein jahan bhi zaroorat ho call kar liya jaata hai, chahe definition neeche ho. Hoisting yahaan feature hai: reviewer top pe `module.exports` aur main function dekh leta hai, implementation details neeche. Agar ye sab `const` expressions hote to har helper ko use hone se pehle define karna padta.

</RealWorld>

<RealWorld company="React components">

React function components ke andar handlers hamesha expressions hote hain — `const handleSubmit = (e) => {...}`. Wajah: har render pe ye function component scope ki current props/state pe closure banata hai, aur ise `onClick={handleSubmit}` ki tarah ek value pass kiya jaata hai. Component khud usually ek declaration hota hai (`export default function Page() {}`) taaki module mein kahin bhi reference ho sake.

</RealWorld>

## Numbers That Matter

<Numbers>

- Function declarations **body ke saath** hoist hoti hain — call-before-line 100% valid.
- Function expressions ka sirf **binding** hoist hota hai — `var` -> `undefined`, `let`/`const` -> TDZ.
- Named function expression ka naam **sirf function scope** mein visible — bahar `ReferenceError`.
- IIFE pattern **ES6 modules (2015)** se pehle scope isolation ka standard tha; aaj har `.mjs`/`import`-based file apne aap scoped hai.
- `function.name` property: named expression `"factorial"` deti hai, `const f = () => {}` bhi inference se `"f"` deta hai, `[fn]` array element `""` (empty).

</Numbers>

## Interview Angle

<InterviewAngle>

Ye "hoisting" ka practical version hai. Interviewer ek chhota snippet dikhaega jismein function ko uski line se pehle call kiya gaya hai, aur poochega output.

Achhe jawaab ka shape:

1. **Pehchano** — "Ye declaration hai ya expression?" Line `function` se shuru = declaration.
2. **Declaration** — poora hoist, isliye pehle call chal jaayega.
3. **Expression** — binding hoist, body nahi. `var` ke saath call `TypeError: not a function`; `const`/`let` ke saath `ReferenceError` (TDZ).
4. **Kyun** — creation phase mein engine declaration ka body register karta hai, expression ka assignment line pe hota hai.
5. **First-class** — "functions values hain, isliye assign/pass/return sab valid."

Red flag: "Dono same hain, sirf style ka farak" — hoisting difference miss karna.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Function expression ko uski line se pehle call karna.** `const` ke saath ye `ReferenceError: Cannot access 'foo' before initialization` deta hai, `var` ke saath `TypeError: foo is not a function` (binding `undefined` hai). Log expect karte hain declaration jaisa hoisting mil jaayega — nahi milta.

</Mistake>

<Mistake>

**`if`/`else` block ke andar function declaration rakhna.** Sloppy aur strict mode mein alag behaviour, aur purane browsers mein buggy. Conditional function chahiye to bahar `let fn;` declare karke branches mein assign karo.

</Mistake>

<Mistake>

**Named function expression ke naam ko bahar se call karna.** `const f = function g() {}` — `g()` sirf function ke andar valid hai. Bahar `g` undefined hai; call karne pe `ReferenceError`.

</Mistake>

<Mistake>

**Sirf anonymous expressions use karna aur phir stack trace na padh paana.** `const handlers = [function () {}, function () {}]` — error hone pe trace mein "anonymous" dikhta hai. Naam de do (`function onSave() {}`) to debugging bahut aasan.

</Mistake>

<Mistake>

**IIFE ko modern module code mein zabardasti daalna.** Agar file already ES module hai to uska apna scope hai — IIFE se wrap karna sirf noise hai. IIFE tab tak useful jab `<script>` tag ya bundling without modules ho.

</Mistake>

## Quick Revision

<QuickRevision>

- Line `function` se shuru = **declaration**; `const`/`let`/`=` ke baad = **expression**.
- Declaration: naam + body dono hoist — line se pehle call OK.
- Expression: sirf binding hoist — `var` -> `undefined` (`TypeError` on call), `const`/`let` -> TDZ (`ReferenceError`).
- Named function expression: naam sirf function ke **andar** visible; stack trace behtar.
- Functions first-class values hain — assign, pass as arg, return.
- IIFE `(function(){})()` = turant chalne wala private scope; pre-modules pattern.
- Modern ES modules har file ko scope dete hain — IIFE ki zaroorat kam.
- Conditional function: `let fn; if (...) fn = ...` — block ke andar declaration nahi.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Bina chalaye output predict karo: `foo(); function foo() { console.log("A"); } bar(); var bar = function () { console.log("B"); };` — kaunsi line print hogi, kaunsi crash karegi, aur kyun?

**Medium:** Ek named function expression `const gcd = function g(a, b) { ... }` likho jo Euclid's algorithm se GCD nikaale, andar `g` se recurse kare. Phir bahar `g(12, 8)` call karke dekho kya error aata hai aur explain karo kyun.

**Bada:** Ek chhota counter module IIFE se banao: `const counter = (function () { let n = 0; return { inc() { n++; }, value() { return n; } }; })();`. `n` ko bahar se access karne ki koshish karo aur explain karo ki IIFE ne kya isolate kiya aur ES module hone par ye pattern kaise badal jaata.

</Callout>
