<SimpleDefinition>

**Parameters** are the named placeholders listed in a function definition; **arguments** are the actual values passed when the function is called. **Default parameters** (`function f(x = 1)`) supply a value when an argument is missing or `undefined`, and are evaluated per call. The legacy **`arguments` object** is an array-like collection of all passed values, available only in non-arrow functions. **Rest parameters** (`function f(...args)`) collect any extra arguments into a real array and are the modern replacement for `arguments`.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Ye topic chhota lagta hai par yahaan bahut se silent bugs chhupte hain — missing args, default kab trigger hota hai, `arguments` vs `...rest`, aur `function.length` ka behaviour. Interview mein "in dono mein farak batao" ke roop mein aata hai.

### Ye kya hai — parameter vs argument

- **Parameter** — function *define* karte waqt likha naam. `function greet(name, greeting) { }` — `name`, `greeting` parameters hain.
- **Argument** — function *call* karte waqt di gayi actual value. `greet("Vasant", "Hi")` — `"Vasant"`, `"Hi"` arguments hain.

Ek sentence: parameters definition ke, arguments call ke.

### Ye kyun exist karta hai

Function ko reusable banane ke liye — input placeholder (parameter) chahiye jise har call alag value (argument) de sake. Defaults isliye aaye ki har call pe optional cheez pass na karni pade; rest isliye ki variable number of args ko clean array mein le sako bina purane `arguments` object ke.

### Internally kaise kaam karta hai

Call ke waqt engine ek naya scope banata hai aur arguments ko positionally parameters se bind karta hai:

- **Zyada arguments** — extra values ignore (par `arguments` mein dikhte hain, aur `...rest` unhe pakad leta hai).
- **Kam arguments** — missing parameters ko `undefined` mil jaata hai.
- **Default** — sirf tab chalta hai jab us position ki value `undefined` ho (ya missing ho). `null`, `0`, `""`, `false` pe default **nahi** chalta.

```javascript
function f(a, b = 10) {
  console.log(a, b);
}
f(1);          // 1 10   -> b missing -> default
f(1, undefined); // 1 10 -> explicitly undefined -> default
f(1, null);    // 1 null -> null is a real value -> no default
f(1, 0);       // 1 0    -> 0 is a real value -> no default
```

### Default parameters — per call, left se right evaluate

Default expression **har call pe** evaluate hota hai (shared nahi), aur pehle wale params ko refer kar sakta hai:

```javascript
function makeId(prefix = "u", id = Date.now(), tag = prefix + "-" + id) {
  return tag;
}
```

- `Date.now()` har call pe naya — isliye "default = fixed" sochna galat.
- `tag` ka default `prefix` aur `id` use kar raha hai (jo left mein hain). Right-side param ko refer karo to TDZ error.

### `arguments` object — array-LIKE, legacy

Har **non-arrow** function ke andar `arguments` naam ka object automatically milta hai — saare passed values, chahe parameters listed ho ya nahi.

```javascript
function sum() {
  let total = 0;
  for (let i = 0; i < arguments.length; i++) total += arguments[i];
  return total;
}
sum(1, 2, 3); // 6
```

Problems:

- Array **nahi** hai — `.map`, `.filter`, `.reduce` directly nahi (`Array.from(arguments)` ya `[...arguments]` chahiye).
- Arrow functions mein **hota hi nahi**.
- Readability kharab — signature se pata nahi chalta function kya leta hai.

### Rest parameters — real Array, modern

```javascript
function sum(...nums) {
  return nums.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3); // 6

function log(level, ...messages) {
  console.log(`[${level}]`, messages.join(" "));
}
```

- `nums` ek **real Array** hai — saare array methods available.
- Sirf **last** parameter ho sakta hai, aur ek hi.
- `arguments` ke saath sab args milte hain; `...rest` ke saath sirf jo listed params ke baad bache.
- Arrow functions mein bhi kaam karta hai.

### `function.length` — defaults + rest count nahi hote

```javascript
function a(x, y) {}          a.length; // 2
function b(x, y = 1) {}      b.length; // 1  -> default se pehle wale hi
function c(x, ...rest) {}    c.length; // 1  -> rest count nahi hota
function d(x = 1, y) {}      d.length; // 0  -> first default ke baad sab chhoot gaye
```

`fn.length` = "expected pehle mandatory param count". Libraries (Express, curry helpers) isse arity detect karti hain.

### Destructuring params with defaults — options object pattern

```javascript
function connect({ host = "localhost", port = 5432, ssl = false } = {}) {
  return `${host}:${port} ssl=${ssl}`;
}
connect();                       // localhost:5432 ssl=false
connect({ port: 6000 });         // localhost:6000 ssl=false
```

- Outer `= {}` isliye ki bina argument ke bhi call ho sake (warna `undefined` ko destructure karne pe crash).
- Har key ka apna default. Ye 4+ params wali functions ke liye best practice hai — call-site pe naam dikhta hai, order yaad nahi rakhna.

### Day-to-day use

- Defaults: config options, optional flags, retry counts.
- Rest: variadic helpers (`Math.max`-style), logging, forwarding args (`(...args) => wrapped(...args)`).
- Destructured params: React component props, API client options, any function with 3+ optional inputs.

### Kab defaults / rest use karna chahiye

- Default — jab ek param optional ho aur ek sensible fallback ho.
- Rest — jab call count variable ho, ya jab tumhe `arguments` chahiye tha (hamesha `...args` prefer).
- Destructured + default — 3+ options wali function.

### Kab use nahi karna chahiye

- Default expression mein heavy work (DB call) — har call pe chalega; bahar nikaalo.
- Rest ko beech mein rakhne ki koshish — sirf last position legal.
- `arguments` naye code mein — bug-prone, arrow-incompatible; `...args` use karo.
- Bahut saare positional params (`f(a, b, c, d, e)`) — options object mein badlo.

### Pros and cons

**Default + rest + destructured params**

- Pros: self-documenting signature, missing args safe, real array, arrow-compatible, call-site clarity.
- Cons: `fn.length` badal jaata hai (arity-based libs affected), default expression har call chalta hai, destructuring nesting deep ho to padhna mushkil.

**`arguments` object**

- Pros: legacy code mein har arg mil jaata hai bina signature badle.
- Cons: array nahi, arrow mein nahi, signature se intent chhupta hai, strict mode mein params se de-linked.

### Alternatives

- **`Array.from(arguments)` / `[...arguments]`** — legacy `arguments` ko array banane ke liye (better: `...rest`).
- **Options object without destructuring** — `function f(opts) { opts = opts || {}; }` — purana pattern; destructured default cleaner.
- **`arguments.length` check** — "argument pass hua tha ya nahi" exactly janne ke liye (default `undefined` ko distinguish nahi kar paata).

### Interview mein "default kab trigger hota hai?"

> "Default parameter sirf tab apply hota hai jab us position ki value `undefined` ho — yaani argument missing ho ya explicitly `undefined` pass ho. `null`, `0`, `""`, `false` real values hain, unpe default nahi chalta. Default expression har call pe left-to-right evaluate hota hai aur pehle ke params ko refer kar sakta hai. Aur main `arguments` object avoid karta hoon — rest parameter `...args` real array deta hai aur arrow functions mein bhi kaam karta hai."

</Hinglish>

<Callout type="tip">

`function f(x, y = 2, z) {}` legal hai, par `f(1, undefined, 3)` likhna padega `z` ko `3` dene ke liye. Isiliye default params ko signature ke end mein rakho.

</Callout>

## Real World Example

<RealWorld company="Express / Node libraries">

Express jaisi libraries `fn.length` (arity) se decide karti hain ki middleware "normal" hai (`(req, res, next)` — 3 params) ya "error handler" (`(err, req, res, next)` — 4 params). Isiliye agar tum error middleware ko `(err, req, res, next)` likhte ho par galti se ek param ka default de dete ho, `fn.length` badal jaata hai aur Express use error handler nahi maanta — ek silent routing bug.

</RealWorld>

<RealWorld company="React component props">

React function components destructured params + defaults ka textbook example hain: `function Button({ variant = "primary", size = "md", disabled = false, onClick }) {}`. Call-site (`<Button size="lg" />`) pe naam se pass hota hai, order matter nahi karta, aur missing props apne defaults le lete hain. `= {}` fallback yahaan React khud handle kar deta hai (props hamesha object hota hai).

</RealWorld>

## Numbers That Matter

<Numbers>

- Default parameters aur rest parameters dono **ES2015 (ES6)** mein aaye.
- Default trigger karne wali **ek hi** value: `undefined` (missing ya explicit).
- Rest parameter hamesha function signature ka **last** aur **sirf ek** ho sakta hai.
- `fn.length` **pehle default parameter se pehle** wale params count karta hai — defaults aur rest exclude.
- `arguments` array-like hai: `length` aur index milte hain, par `Array.prototype` methods **nahi**.

</Numbers>

## Interview Angle

<InterviewAngle>

Do sawaal common hain: "parameter aur argument mein farak?" (warm-up) aur "default kab lagta hai / `arguments` vs rest?" (asli test).

Achhe jawaab ka shape:

1. **Definition farak** — parameter definition ka, argument call ka.
2. **Missing/extra** — kam args -> `undefined`; zyada args -> ignore (par `arguments`/`...rest` mein).
3. **Default rule** — sirf `undefined` pe; `null`/`0`/`""`/`false` pe nahi; per-call evaluate.
4. **arguments vs rest** — `arguments` array-like, no arrow, legacy; `...rest` real array, arrow-ok, modern.
5. **`fn.length`** — defaults/rest count nahi hote.

Red flag: "default `null` ya `0` pe bhi lag jaata hai" — galat.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Ye sochna ki default `null` ya falsy pe bhi chalta hai.** `function f(x = 5) {}` — `f(null)` ka `x` `null` hi rahega, `5` nahi. Sirf `undefined` (ya missing) default trigger karta hai. Falsy fallback chahiye to body mein `x = x ?? 5`.

</Mistake>

<Mistake>

**Arrow function ke andar `arguments` use karna.** Arrow mein `arguments` hota hi nahi — ya to enclosing function ka uthega ya `ReferenceError`. Rest `(...args)` use karo.

</Mistake>

<Mistake>

**`arguments` ko array samajh kar `.map`/`.filter` call karna.** `arguments.map(...)` `TypeError: arguments.map is not a function`. Pehle `[...arguments]` ya `Array.from(arguments)`, ya better — `...rest` parameter.

</Mistake>

<Mistake>

**Default expression mein expensive kaam.** `function load(cache = buildExpensiveCache()) {}` — `buildExpensiveCache()` har call pe chalega jahan `cache` pass nahi hua. Module-level constant banao aur usko default do.

</Mistake>

<Mistake>

**Bahut saare positional parameters + defaults beech mein.** `f(a, b = 1, c, d = 2, e)` — `c` ya `e` dene ke liye `undefined` placeholders pass karne padte hain. 3+ optional inputs ho to destructured options object `({ ... } = {})` use karo.

</Mistake>

## Quick Revision

<QuickRevision>

- **Parameter** = definition ka naam; **argument** = call ki value.
- Kam args -> `undefined`; zyada args -> ignore (par `arguments` / `...rest` pakad lete hain).
- Default sirf `undefined` (missing ya explicit) pe; `null` / `0` / `""` / `false` pe **nahi**.
- Default expression **per call** evaluate; left params ko refer kar sakta hai.
- `arguments` = array-LIKE, non-arrow only, legacy — avoid.
- `...rest` = real Array, arrow-ok, sirf last param — `arguments` ka modern replacement.
- `fn.length` defaults + rest ko count **nahi** karta.
- 3+ optional inputs -> destructured options object `({ a = 1, b = 2 } = {})`.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Predict karo: `function f(x = 1) { return x; } console.log(f(undefined), f(null), f(0));` — teen values kya, aur `null`/`0` pe default kyun nahi laga?

**Medium:** Ek `logger` function likho `function logger(prefix = "LOG", ...messages)` jo `[PREFIX] msg1 msg2` print kare. Phir isse arrow function se dobara likho aur explain karo ki `...messages` ne yahan `arguments` object ki jagah kya solve kiya.

**Bada:** Ek `createClient(options)` function likho destructured params + defaults ke saath: `{ baseUrl = "/api", timeout = 5000, retries = 3, headers = {} } = {}`. `createClient()` aur `createClient({ timeout: 1000 })` dono ke liye output dikhao. Phir batao `= {}` outer default hataane par `createClient()` kyun crash karega.

</Callout>
