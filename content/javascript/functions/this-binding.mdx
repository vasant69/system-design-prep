<SimpleDefinition>

In JavaScript, `this` is a reference decided by **how a function is called**, not where it is defined. Four rules apply in precedence order: with `new`, `this` is the newly created object; with `call`, `apply`, or `bind`, `this` is the explicitly given object; when called as `obj.method()`, `this` is `obj`; and for a plain standalone call `this` is `undefined` in strict mode (the global object otherwise). **Arrow functions** ignore all four rules and take `this` **lexically** from their enclosing scope.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

`this` JavaScript ka sabse confusing keyword hai kyunki wo **call ke time** decide hota hai, define ke time nahi. Ek hi function alag-alag tareeke se call karo to `this` alag hoga. Interview mein ye guarantee question hai.

### Ye kya hai — call-site ka rule

`this` = "is call mein function ko kis object ke context mein chalaya gaya". Function likhte waqt `this` fix nahi hota — jab call hota hai tab bhara jaata hai. isiliye ek reference ko variable mein rakh ke call karo to `this` badal jaata hai.

### 4 rules — precedence order (upar wala jeetta hai)

**1. `new` binding**

```javascript
function Person(name) {
  this.name = name; // this = naya khaali object
}
const p = new Person("Vasant"); // p.name === "Vasant"
```

`new` ek fresh object banata hai, use `this` set karta hai, aur (agar function object return na kare) use return karta hai.

**2. Explicit binding — `call` / `apply` / `bind`**

```javascript
function greet() { return `Hi ${this.name}`; }
const user = { name: "Raj" };
greet.call(user);  // "Hi Raj" -- this = user
greet.apply(user); // "Hi Raj"
const bound = greet.bind(user);
bound();           // "Hi Raj" -- permanently bound
```

**3. Implicit binding — `obj.method()`**

```javascript
const counter = {
  count: 0,
  inc() { this.count++; }, // this = counter (jo dot ke left mein hai)
};
counter.inc(); // this = counter
```

Rule: call ke waqt **dot ke left** jo object hai, wahi `this`. Sirf **last** dot matter karta hai — `a.b.c.method()` mein `this` `a.b.c`.

**4. Default binding — standalone call**

```javascript
"use strict";
function show() { console.log(this); }
show(); // undefined (strict mode)
        // globalThis / window (sloppy mode)
```

Koi dot nahi, koi `new` nahi, koi `call` nahi — `this` default pe jaata hai: strict mode mein `undefined`, warna global object.

### Arrow functions — 4 rules ignore

Arrow ka apna `this` nahi hota. Wo lexically enclosing scope ka `this` use karta hai — call kaise bhi ho, farak nahi padta.

```javascript
const obj = {
  name: "A",
  regular() { return (() => this.name)(); }, // arrow -> this = obj (regular ka this)
};
obj.regular(); // "A"
```

### Ye kyun exist karta hai

`this` isiliye hai taaki ek function multiple objects pe reuse ho sake — `Array.prototype.push` har array pe chalta hai, `this` batata hai kaunsa array. Problem tab aati hai jab function apne object se "alag" ho jaata hai (callback ban ke) — tab `this` ka connection toot jaata hai.

### Internally kaise kaam karta hai

Jab engine `foo.bar()` dekhta hai, wo do cheezein karta hai: `foo.bar` function reference nikaalta hai, aur `foo` ko us call ka `this` bana deta hai (Reference Record). Jab tumne `const fn = foo.bar; fn()` likha, to `fn()` ke waqt koi "base object" nahi hai — Reference Record khatm — isiliye `this` default pe chala jaata hai.

### Simple real-life analogy

`this` = "abhi bol kaun raha hai". Ek microphone (function) alag-alag log (objects) use karte hain — jab tum bolo to "main" = tum, jab main bolun to "main" = main. Microphone khud "main" fix nahi karta. Arrow function ek recording hai — usme "main" hamesha wahi jisne record kiya.

### Code — line by line

```javascript
class Timer {
  constructor() {
    this.n = 0;
    setInterval(function () {
      this.n++;              // BUG: this yahan Timer nahi
      console.log(this.n);   // NaN, NaN, ...
    }, 1000);
  }
}
new Timer();
```

- `new Timer()` — constructor ke andar `this` = naya instance.
- `setInterval(function () { ... })` — ye regular function `setInterval` ke through **standalone** call hoti hai; `this` `undefined`/global, instance nahi.
- `this.n++` — `undefined.n` -> `NaN` (ya crash strict mein).

**Fix — arrow:**

```javascript
setInterval(() => {
  this.n++;            // arrow -> this = constructor ka this = instance
  console.log(this.n); // 1, 2, 3
}, 1000);
```

### Classic bugs

1. **`obj.method` ko callback ki tarah pass karna** — `btn.addEventListener("click", obj.handle)` — call ke waqt dot nahi, `this` khota hai.
2. **`setTimeout(this.tick, 1000)`** — `this.tick` ek naked function reference; `setTimeout` use standalone call karta hai.
3. **Method ke andar nested regular `function`** — `arr.forEach(function () { this... })` — callback standalone.

### Fixes — teen tareeke

```javascript
// 1. Arrow (best jab lexical this chahiye)
btn.addEventListener("click", () => obj.handle());

// 2. .bind(this)
btn.addEventListener("click", obj.handle.bind(obj));

// 3. const self = this (purana, still works)
const self = this;
arr.forEach(function () { self.push(1); });
```

### Day-to-day use

- Class/prototype methods jinhe instance data chahiye.
- Object literal methods.
- Constructor functions.
- Method borrowing (`Array.prototype.slice.call(arguments)`).
- React class components (`this.props`, `this.setState`) — isiliye handlers bind karne padte the.

### Kab `this` pe dhyan dena chahiye

- Jab method ko pass kar rahe ho as callback — bind ya arrow-wrap karo.
- `setTimeout`/`setInterval`/event listener ke andar.
- Nested function inside a method.

### Kab `this` avoid karna chahiye

- Simple utility functions — `this` ki zarurat hi nahi, pure params use karo.
- Functional style code — `this`-free functions test aur compose karna aasan.
- Jab confusion ka risk zyada ho — closure over ek explicit variable clearer ho sakta hai.

### Pros and cons

**`this`-based code**

- Pros: ek method multiple instances pe reuse; OO patterns natural; method borrowing possible.
- Cons: call-site pe depend karta hai — refactor/pass karne pe silently toot ta hai; arrow vs regular ka mental overhead; beginners ke liye #1 confusion.

### Alternatives

- **Arrow function** — lexical `this`, callback bug khatam.
- **`.bind()`** — `this` permanently fix; ek naya function object.
- **Closure over explicit variable** — `const self = this` ya seedha koi variable capture — `this` se bacho hi.
- **Functional composition** — `this`-free functions jo sab kuch parameters se lete hain.

### Interview mein "`this` kaise decide hota hai?"

> "`this` call-site pe decide hota hai, definition pe nahi. Precedence: `new` sabse pehle — naya object; phir explicit `call`/`apply`/`bind` — diya gaya object; phir implicit `obj.method()` — dot ke left ka object; phir default — strict mode mein `undefined`, warna global. Arrow functions in rules ko ignore karte hain aur `this` lexically enclosing scope se lete hain. Classic bug: `obj.method` ko callback ki tarah pass karo to dot chhoot jaata hai aur `this` default pe chala jaata hai — fix arrow-wrap ya `.bind`."

</Hinglish>

<Callout type="tip">

Jaldi test: call mein `.` (dot) dhoondo. `foo.bar()` -> `this` = `foo`. `bar()` (dot nahi) -> default `this`. `new bar()` -> naya object. `bar.call(x)` -> `x`. Arrow -> signature dekho hi mat, enclosing scope dekho.

</Callout>

## Real World Example

<RealWorld company="React (class components)">

React class components mein `this.setState`, `this.props` har jagah the — aur `<button onClick={this.handleClick}>` likhne pe `handleClick` ke andar `this` `undefined` ho jaata tha, kyunki JSX sirf function reference pass karta hai (dot chhoot gaya). isiliye har class mein constructor mein `this.handleClick = this.handleClick.bind(this)` likhna padta tha, ya class field arrow `handleClick = () => {}` use karna padta tha. Hooks ne `this` ko poori tarah picture se hata diya — isi confusion se bachne ke liye.

</RealWorld>

<RealWorld company="Array method borrowing (older code)">

Rest parameters se pehle, `arguments` (array-like) pe array methods chalane ke liye log `Array.prototype.slice.call(arguments)` likhte the — `slice` ko borrow karke `this` `arguments` set kar dete the. Isi tarah `[].forEach.call(document.querySelectorAll('div'), fn)` NodeList pe `forEach` borrow karta tha. `call` yahaan `this` ko wo collection bana deta hai jispe method chalana hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- `this` ke **4** binding rules: `new` > explicit (`call`/`apply`/`bind`) > implicit (`obj.method()`) > default.
- Strict mode mein default `this` = `undefined`; sloppy mode mein = global object (`window`/`globalThis`).
- Arrow functions: `this` binding rules **0** — poori tarah lexical.
- `obj.a.b.method()` mein `this` = `obj.a.b` — sirf **aakhri** dot count hota hai.
- `bind` ek baar hone ke baad **re-bind nahi** hota — doosra `.bind` ignore, `new` uske through kaam karta hai.

</Numbers>

## Interview Angle

<InterviewAngle>

Format: ek object/class snippet jismein method ko variable mein rakha ya callback banaya gaya hai, aur output/`this` poocha jaata hai.

Achhe jawaab ka shape:

1. **Core** — "`this` call-site pe decide hota hai, define pe nahi."
2. **4 rules precedence order mein** — `new` / explicit / implicit / default.
3. **Is snippet pe apply** — dot hai? `new`? `call`? koi nahi -> default (`undefined` strict).
4. **Arrow** — rules ignore, lexical `this`.
5. **Fix** — callback bug ke liye arrow-wrap ya `.bind`.

Red flag: "`this` us object ko refer karta hai jismein function define hua hai" — define nahi, call.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`this` ko definition se jodna.** `this` jahan function likha hai us object ko refer nahi karta — call kaise hua us pe depend karta hai. Ek hi method ko `obj.m()` aur `const f = obj.m; f()` se call karo to `this` alag hoga.

</Mistake>

<Mistake>

**`obj.method` ko callback ki tarah pass karna.** `setTimeout(obj.tick, 1000)` ya `arr.map(obj.format)` — call ke waqt dot nahi, `this` default (`undefined`) pe chala jaata hai. `() => obj.tick()` ya `obj.tick.bind(obj)` use karo.

</Mistake>

<Mistake>

**Method ke andar nested regular `function` mein `this` expect karna.** `outer() { arr.forEach(function () { this.x }); }` — callback standalone call hoti hai, `this` `undefined`. Arrow callback use karo ya `forEach` ka thisArg / `const self = this`.

</Mistake>

<Mistake>

**Object method ko arrow banana `this` "fix" karne ke liye.** `const o = { v: 1, get: () => this.v }` — arrow ka `this` `o` nahi, enclosing (module) scope hai. Object methods regular function / shorthand hone chahiye.

</Mistake>

<Mistake>

**Sloppy mode maankar `this === window` pe bharosa.** Modules aur `"use strict"` mein standalone `this` `undefined` hai — `this.something` `TypeError` dega. Modern code strict hai by default (ES modules).

</Mistake>

## Quick Revision

<QuickRevision>

- `this` = **kaise call hua**, not kahan define hua.
- Precedence: `new` > `call`/`apply`/`bind` > `obj.method()` > default.
- `new` -> naya object; explicit -> diya object; implicit -> dot ke **left** ka object; default -> `undefined` (strict) / global (sloppy).
- `a.b.c.m()` -> `this` = `a.b.c` (sirf last dot).
- **Arrow** -> 4 rules ignore, `this` lexical (enclosing scope).
- Classic bug: `obj.m` as callback -> dot chhoot gaya -> default `this`.
- Fixes: arrow-wrap `() => obj.m()`, `.bind(obj)`, `const self = this`.
- Object/prototype methods: regular function; callbacks jinhe outer `this` chahiye: arrow.

</QuickRevision>
