<SimpleDefinition>

A **higher-order function** is a function that takes another function as an argument, returns a function, or both. A **callback** is a function passed to another function to be called later — **synchronously** (as in `map`, `filter`, `sort`) or **asynchronously** (as in `setTimeout`, event listeners, older Node APIs). Returning functions enables function factories, decorators like `once` and `debounce`, middleware, composition (`compose`/`pipe`), and currying. Higher-order functions make code declarative when the operation is the point, but can obscure control flow when overused.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

"Functions are values" ka practical natija ye topic hai. Higher-order functions (HOFs) roz use hote hain — `map`, `filter`, `reduce`, event listeners, `setTimeout`, promises. Interview mein "HOF kya hai", "callback kya hai", aur "ek `once`/`debounce` likho" common hain.

### Ye kya hai — higher-order function

Ek function jo in dono mein se kam se kam ek karta hai:

1. Ek ya zyada functions ko **argument** ki tarah leta hai.
2. Ek function **return** karta hai.

```javascript
// 1. function ko argument leta hai
[1, 2, 3].map(x => x * 2);           // map ek HOF hai
arr.filter(isEven);
setTimeout(() => console.log("hi"), 100);

// 2. function return karta hai
function multiplier(factor) {
  return n => n * factor;            // multiplier ek HOF hai
}
const double = multiplier(2);
```

Jo function na argument leta hai na return karta hai (`function add(a, b) { return a + b; }`) — wo **first-order** hai.

### Ye kya hai — callback

Callback = wo function jo tum kisi aur function ko dete ho taaki wo use **baad mein** call kare. Do tarah:

- **Synchronous callback** — turant, isi call stack mein chalta hai. `arr.map(fn)`, `arr.sort(compareFn)`, `arr.forEach(fn)`. `map` return hone se pehle `fn` sab elements pe chal chuka hota hai.
- **Asynchronous callback** — baad mein, event loop ke kisi future tick pe. `setTimeout(fn)`, `el.addEventListener("click", fn)`, `fs.readFile(path, cb)`.

```javascript
// sync
[3, 1, 2].sort((a, b) => a - b); // compareFn abhi chalta hai -> [1, 2, 3]

// async
button.addEventListener("click", () => console.log("clicked")); // kabhi bhi, baad mein
```

### Ye kyun exist karta hai

- **Behaviour ko parameterize karna** — `sort` ko nahi pata tum kaise compare karna chahte ho; tum `compareFn` do. Ek generic function, infinite behaviours.
- **Async ka result handle karna** — data baad mein aayega; callback batata hai "aane pe ye karna". (Aage promises/async-await isko replace karte hain.)
- **Reusable wrappers** — ek function ko le kar uska "enhanced" version return karna (`once`, `debounce`, `withLogging`).

### Internally kaise kaam karta hai

Function ek value hai, isliye use argument slot mein rakhna normal hai — engine bas us reference ko parameter se bind karta hai aur andar `fn()` call karta hai. Jo function return hota hai wo aksar ek **closure** hota hai (outer params/vars capture karta hai) — isiliye `multiplier(2)` ka lauta function `factor` yaad rakhta hai.

### Simple real-life analogy

HOF = ek manager. Tum use kaam (callback) dete ho: "ye list lo aur har item pe ye karo" (`map`), ya "jab customer aaye tab ye karna" (event listener). Manager kab aur kaise call karega wo uska kaam; tum sirf "kya karna hai" batate ho.

### Code — line by line: `once`

```javascript
function once(fn) {
  let done = false;
  let result;
  return function (...args) {
    if (!done) {
      done = true;
      result = fn.apply(this, args);
    }
    return result;
  };
}
const init = once(() => console.log("setup"));
init(); // "setup"
init(); // (kuch nahi)
```

- `once(fn)` — HOF: function leta hai, function return karta hai.
- `let done`, `let result` — closure mein private state.
- `return function (...args)` — enhanced version.
- `if (!done)` — pehli baar hi asli `fn` chalta hai.
- `fn.apply(this, args)` — original `this` aur args forward.
- Aage har call cached `result`.

### `debounce` / `throttle` ka shape

```javascript
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
```

- Har call pichla pending timer cancel karta hai.
- `fn` sirf tab chalta hai jab `delay` ms tak koi nayi call na aaye.
- Use: search input, resize/scroll handlers. `throttle` alag — fixed rate pe chalne deta hai.

### Composition — `compose` / `pipe`

```javascript
const pipe = (...fns) => x => fns.reduce((acc, fn) => fn(acc), x);

const clean = pipe(
  s => s.trim(),
  s => s.toLowerCase(),
  s => s.replace(/\s+/g, "-")
);
clean("  Hello World  "); // "hello-world"
```

- `pipe` left-to-right chalata hai; `compose` right-to-left (`compose(f, g)(x) === f(g(x))`).
- Chhoti single-purpose functions ko ek data pipeline mein jodta hai.

### Currying basics

```javascript
const add = a => b => c => a + b + c;
add(1)(2)(3); // 6

const add1 = add(1);
add1(2)(3);   // 6
```

Har call ek arg leta hai aur agla function return karta hai jab tak sab args na mil jaayein. Fayda: partial application natural — `add(1)` ek reusable "1 add karne wala" deta hai.

### Middleware pattern

```javascript
const requireRole = role => (req, res, next) => {
  if (req.user?.role !== role) return res.status(403).end();
  next();
};
app.get("/admin", requireRole("admin"), handler);
```

`requireRole` ek HOF hai jo config (`role`) le kar ek middleware function deta hai. `next` bhi ek callback hai — "mera kaam ho gaya, aage badho".

### Day-to-day use

- Array transforms: `map`/`filter`/`reduce`/`some`/`every`/`find`/`sort`.
- Async: `setTimeout`, `addEventListener`, `.then`/`.catch`, `fetch`.
- Wrappers: `once`, `debounce`, `throttle`, `memoize`, `withRetry`, `withLogging`.
- Framework: React `useEffect(fn)`, `useMemo(fn)`, custom hooks; Express middleware; Array of validators.

### Kab HOF use karna chahiye

- Jab "operation" hi point ho — "har item transform karo", "filter karo", "reduce karo" — loop se zyada declarative.
- Jab tumhe ek function ka enhanced version chahiye (retry/cache/debounce) bina original ko chhue.
- Config-driven behaviour — factory jo ek customized function de.

### Kab HOF use nahi karna chahiye

- Deeply nested callbacks (callback hell) — waha promises / `async-await` use karo.
- Jab ek simple `for`/`for...of` zyada readable ho — 3 chained `.map().filter().reduce()` jo har baar naya array banaye, hot path mein slow + kam saaf.
- Over-abstraction — `pipe(pipe(pipe(...)))` jise team padh na paaye.
- Jab early `break`/`return` chahiye — `forEach` se nahi ho sakta; `for...of` better.

### Pros and cons

**HOFs / callbacks**

- Pros: declarative, reusable, DRY, behaviour parameterize hota hai, functional patterns (compose/curry/memoize) enable.
- Cons: nested async callbacks = callback hell; har `.map/.filter` naya array (memory); stack traces gehri ho jaati hain; over-abstraction se control flow chhupta hai; `break`/`continue` nahi.

### Alternatives

- **Promises / async-await** — async callbacks ki jagah; flat, try/catch-able.
- **`for...of` loop** — jab `break`/index/performance chahiye, ya side-effect-heavy iteration ho.
- **Generators** — lazy sequences ke liye callback-based iteration ki jagah.
- **Classes / plain objects** — jab HOF factory sirf state hold kar raha ho, ek object clearer ho sakta hai.

### Interview mein "HOF kya hai / kahan use kiya?"

> "Higher-order function wo hai jo ek function ko argument leta hai, ya ek function return karta hai — `map`, `filter`, `setTimeout` sab HOFs hain. Maine `debounce` aur `once` jaise wrappers likhne mein use kiya: ye ek function le kar uska controlled version return karte hain, aur private state closure mein rakhte hain. Ek generic function ko callback se parameterize karne se ek hi implementation infinite behaviours support karta hai. Dhyan rakhta hoon ki nested async callbacks na banein — waha promises/async-await, aur jab `break` chahiye to plain loop."

</Hinglish>

<Callout type="tip">

`arr.forEach` se tum loop `break` nahi kar sakte, aur `return` sirf current callback se nikalta hai — poore iteration se nahi. Jaldi bahar nikalna ho to `for...of` + `break`, ya `some()`/`every()` (jo `true`/`false` return pe ruk jaate hain).

</Callout>

## Real World Example

<RealWorld company="React hooks">

React ke saare hooks HOF-style hain: `useEffect(() => { ... }, deps)` ek callback leta hai jise React sahi time pe chalata hai; `useMemo(() => expensiveCalc(), deps)` ek factory callback leta hai. Custom hooks bhi HOF pattern follow karte hain — `useDebouncedValue(value, 300)` internally ek `debounce`-jaisa closure banata hai. Event handlers `onChange={e => setName(e.target.value)}` — callback passed to the framework.

</RealWorld>

<RealWorld company="Express / server middleware">

Express ki poori design HOF-based hai. `app.use((req, res, next) => { ... })` — har middleware ek callback. Auth, logging, rate-limiting sab factories hain: `rateLimit({ max: 100 })` ek middleware function return karta hai jo config ko closure mein rakhta hai. `next()` khud ek callback hai jo control agle middleware ko pass karta hai — is chain se request-handling composable ban jaati hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- `map`, `filter`, `reduce`, `forEach`, `some`, `every`, `find`, `findIndex`, `sort`, `flatMap` — sab HOFs jo callback lete hain.
- Sync callback: caller ke return hone se **pehle** poora chal jaata hai. Async callback: event loop ke **future tick** pe.
- Har `.map()` / `.filter()` ek **naya array** allocate karta hai — chained calls = multiple intermediate arrays.
- `compose(f, g)(x)` === `f(g(x))` — right-to-left; `pipe` left-to-right.
- Currying: N-arg function ko N chained 1-arg calls mein todna.

</Numbers>

<InterviewAngle>

3. **Sync vs async** — "`map` ka callback turant sab pe chalta hai; `setTimeout` ka future tick pe."
4. **Return-a-function** — closure se private state (`once`, `debounce`, middleware factory).

## Common Mistakes

<Mistake>

**Ye maanna ki har callback asynchronous hai.** `arr.map`, `arr.filter`, `arr.sort`, `arr.forEach` ke callbacks **synchronous** hain — function return hone se pehle chal chuke hote hain. Sirf `setTimeout`, event listeners, I/O, promises ke callbacks async hain.

</Mistake>

<Mistake>

**`forEach` se loop `break` karne ki koshish.** `arr.forEach(x => { if (x === target) break; })` — `SyntaxError`. `return` bhi sirf current callback se nikalta hai. Jaldi rukna ho to `for...of` + `break`, ya `some()`.

</Mistake>

<Mistake>

**Nested async callbacks (callback hell).** `getUser(id, u => getPosts(u, p => getComments(p, c => {...})))` — deep nesting, error handling har level pe. Promises ya `async-await` se flatten karo.

</Mistake>

<Mistake>

**Chained `.map().filter().map()` hot path mein bina soche.** Har call ek naya array banata hai; bade data ya tight loop mein ye teen passes + teen allocations. Ek `reduce` ya `for...of` mein combine karo jab performance matter kare.

</Mistake>

<Mistake>

**Returned function mein `this`/args forward na karna.** `once`/`debounce` likhte waqt `return () => fn()` — original `this` aur arguments kho jaate hain. `return function (...args) { fn.apply(this, args); }` likho.

</Mistake>

## Quick Revision

<QuickRevision>

- **HOF** = function ko argument leta hai, ya function return karta hai (ya dono).
- **Callback** = baad mein call hone ke liye pass kiya function.
- **Sync callback** (`map`/`filter`/`sort`/`forEach`) — caller ke return se pehle chal jaata hai.
- **Async callback** (`setTimeout`/events/IO/promises) — event loop ke future tick pe.
- **Return-a-function** = factory/decorator; private state closure mein (`once`, `debounce`, `memoize`, middleware).
- **compose** right-to-left, **pipe** left-to-right; chhote functions ko pipeline mein jodo.
- **Currying** = N-arg ko chained 1-arg calls mein; partial application free.
- Returned wrapper mein `fn.apply(this, args)` se `this` + args forward karo.
- Nested async callbacks -> promises/async-await; `break` chahiye -> `for...of`.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Bina chalaye batao kaunse callbacks sync hain kaunse async: `[1,2].map(f)`, `setTimeout(f)`, `[1,2].forEach(f)`, `el.addEventListener("click", f)`, `[3,1].sort(f)`. Ek line mein rule.

**Medium:** Ek `debounce(fn, delay)` likho jo `this` aur args sahi forward kare. Ek `console.log` wale function pe wrap karke 300ms delay set karo, aur 5 tez calls ke baad kitni baar log hua — batao aur kyun.

**Bada:** Ek `pipe(...fns)` likho. Phir ek text-processing pipeline banao: `trim -> lowercase -> remove punctuation -> split on spaces -> filter stop-words -> join with "-"` (slug banane ke liye). `compose` se dobara likho aur explain karo argument order kyun ulta ho gaya.

</Callout>
