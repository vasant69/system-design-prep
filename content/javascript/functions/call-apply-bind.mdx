<SimpleDefinition>

`call`, `apply`, and `bind` are methods on every function that let you set `this` **explicitly**. `call(thisArg, a, b)` invokes the function **immediately** with arguments listed individually. `apply(thisArg, [a, b])` invokes it **immediately** with arguments passed as an **array**. `bind(thisArg, ...partialArgs)` does **not** invoke — it returns a **new function** permanently bound to `thisArg`, optionally with some arguments pre-filled (partial application). A bound function cannot be re-bound.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Ye teen methods "explicit binding" hain — `this` ka rule #2. Inhe samajhna isliye zaroori hai kyunki callback `this`-bugs ka fix, method borrowing, aur partial application sab inhi pe khade hain.

### Ye kya hai — teeno ek line mein

| Method | Kab chalta hai | Arguments kaise |
|---|---|---|
| `fn.call(thisArg, a, b, c)` | **abhi** | individually listed |
| `fn.apply(thisArg, [a, b, c])` | **abhi** | ek array mein |
| `fn.bind(thisArg, a, b)` | **kabhi nahi** (naya function return) | pre-fill (partial) |

Yaad rakhne ka trick: **A**pply = **A**rray. **C**all = **C**omma-separated. **B**ind = **B**aad mein (later).

### Ye kyun exist karta hai

`this` call-site pe decide hota hai, isliye jab function apne object se detach ho jaata hai (callback), `this` toot jaata hai. `call`/`apply`/`bind` tumhe `this` ko **force** karne dete hain. `apply` ka historic use: array ko "spread" karke variadic function ko dena (`Math.max.apply(null, nums)`) — spread operator se pehle yahi tarika tha. `bind` ka use: callback ka `this` permanently fix karna, aur partial application.

### Internally kaise kaam karta hai

- `call`/`apply` — function ko turant invoke karte hain aur us ek call ke liye `this` ko diya gaya `thisArg` bana dete hain. Farak sirf argument passing ka hai.
- `bind` — ek **naya exotic function object** banata hai jiske andar target function, fixed `thisArg`, aur pre-filled args store hote hain. Jab bound function call hota hai, wo internally target ko us fixed `this` + (pre-filled + new) args ke saath chalata hai. Bound function ka `this` badla nahi ja sakta — doosra `.bind` ya `.call` uspe bekaar hai.

```javascript
function greet(greeting, punct) {
  return `${greeting}, ${this.name}${punct}`;
}
const user = { name: "Vasant" };

greet.call(user, "Hi", "!");        // "Hi, Vasant!"
greet.apply(user, ["Hi", "!"]);     // "Hi, Vasant!"
const sayHi = greet.bind(user, "Hi");
sayHi("!");                          // "Hi, Vasant!"  -- "Hi" pre-filled
sayHi("?");                          // "Hi, Vasant?"
```

### Simple real-life analogy

Ek chef (function) recipe jaanta hai par ingredients (`this`) kisi aur ke laane par depend karta hai. `call`/`apply` = "ye ingredients lo aur abhi pakao" (call haath se ek-ek deta hai, apply ek thaili mein). `bind` = "ye permanent kitchen tumhara, jab bhi bulaya jaaye isi kitchen mein pakana" — ek naya, pre-configured chef milta hai.

### Code — line by line (method borrowing)

```javascript
function toArray() {
  return Array.prototype.slice.call(arguments);
}
toArray(1, 2, 3); // [1, 2, 3]
```

- `arguments` array-like hai — uspe `.slice` nahi hota.
- `Array.prototype.slice` — asli array ka `slice` method.
- `.call(arguments)` — `slice` ko chalao par uska `this` `arguments` bana do. `slice` bina args ke poori copy banata hai — ab ek real array.
- Modern equivalent: `Array.from(arguments)` ya `[...arguments]` ya rest param.

### `apply` aur variadic functions (pre-spread)

```javascript
const nums = [5, 1, 9, 3];
Math.max(nums);              // NaN  -- ek array pass hua
Math.max.apply(null, nums);  // 9    -- array "spread" ho gaya
Math.max(...nums);           // 9    -- modern: spread operator
```

`Math.max` alag-alag numbers leta hai, array nahi. `apply` ne array ko individual args mein khol diya. Aaj `...nums` yahi kaam karta hai, cleaner.

### Real uses

1. **Method borrowing** — `Array.prototype.slice.call(arguments)`, `[].forEach.call(nodeList, fn)`.
2. **Callback `this` fix** — `this.handler = this.handler.bind(this)` (React class components).
3. **Partial application** — `const add5 = add.bind(null, 5); add5(10) // 15`.
4. **Function borrowing across objects** — `getFullName.call(otherUser)`.

### Day-to-day use

- `bind` — event handlers, `setTimeout` callbacks jinhe fixed `this` chahiye.
- `apply` — legacy code; naye code mein spread se replace.
- `call` — method borrowing, ya ek function ko dusre object ke context mein chalana.

### Kab use karna chahiye

- `bind` — jab tumhe ek reusable function chahiye jiska `this` (ya kuch leading args) fix ho, aur wo baad mein call hoga.
- `call` — one-off: abhi is function ko is `this` ke saath chalao (borrowing).
- `apply` — jab args already ek array mein hain aur tum legacy env mein ho jahan spread nahi (warna spread).

### Kab use nahi karna chahiye

- `apply` sirf array-spread ke liye — modern code mein `fn(...args)` use karo.
- `bind` sirf lexical `this` ke liye callback mein — arrow function zyada readable.
- Har render pe `.bind` call karna (React) — naya function object har baar, `PureComponent`/`memo` ki equality tod deta hai. Constructor mein ek baar bind karo ya class field arrow.
- `bind` ko re-bind karne ki koshish — chalega nahi, silently ignore.

### Pros and cons

**`call` / `apply`**

- Pros: turant, `this` explicit, method borrowing possible, `apply` array-args handle karta hai.
- Cons: `apply` ka array-spread ab spread operator se better; readability average; har call pe likhna padta.

**`bind`**

- Pros: `this` permanently fix, partial application free, ek reusable function.
- Cons: naya function object (memory + identity change — React equality); re-bind nahi hota; overuse se code me `.bind(this)` shor.

### Alternatives

- **Arrow function** — `this` lexically fix karne ka readable tarika; `bind`-for-this ki jagah.
- **Spread operator `fn(...arr)`** — `apply`-for-array ki jagah.
- **Closure / partial helper** — `const add5 = x => add(5, x)` — `bind` partial ki jagah, zyada explicit.
- **`Function.prototype.bind` polyfill patterns** — sirf bahut purane environments mein relevant.

### Interview mein "call vs apply vs bind?"

> "Teeno `this` explicitly set karte hain. `call` aur `apply` function ko turant chalate hain — `call` args comma-separated leta hai, `apply` ek array. `bind` chalata nahi, ek naya function return karta hai jiska `this` permanently fixed hai, aur optionally kuch leading args pre-filled (partial application). Main `bind` tab use karta hoon jab callback ka `this` fix karna ho aur wo reusable ho; `call` method borrowing ke liye; `apply` ki jagah ab spread operator. Ek gotcha: bound function `new` ke saath call karo to bound `this` ignore hota hai."

</Hinglish>

<Callout type="tip">

`fn.bind(obj)` har baar ek **naya** function object deta hai. `el.addEventListener("click", fn.bind(this))` ke baad usi listener ko `removeEventListener` se hataana impossible hai — reference match nahi karega. Bound function ko ek variable mein rakho.

</Callout>

## Real World Example

<RealWorld company="React (class components)">

React class components mein `this.handleClick = this.handleClick.bind(this)` constructor mein likhna standard tha. Wajah: JSX `onClick={this.handleClick}` sirf reference pass karta hai, aur click ke waqt `this` `undefined` hota. Constructor mein ek baar bind karne se ek stable bound reference milta tha — agar har render pe `onClick={this.handleClick.bind(this)}` likhte to har render naya function, child components bewajah re-render.

</RealWorld>

<RealWorld company="Lodash / Ramda partial application">

Functional libraries `_.partial(fn, arg1)` aur currying provide karte hain jo internally `bind`-jaise partial application pe based hai. `const greetHi = _.partial(greet, "Hi")` — pehla arg lock, baaki baad mein. Native `greet.bind(null, "Hi")` bhi wahi deta hai, bas `this` ko `null` set karna padta hai jab sirf args pre-fill karne hain.

</RealWorld>

## Numbers That Matter

<Numbers>

- Teeno methods `Function.prototype` pe hain — har function inhe inherit karta hai.
- `call` vs `apply`: sirf **argument passing** ka farak — `call` list, `apply` array.
- `bind` **ES5 (2009)** mein aaya; `call`/`apply` shuru se hain.
- Bound function `new` ke saath: bound `this` **ignore**, par bound leading args **rehte hain**.
- `bind` ek baar — dobara `.bind` ya `.call`/`.apply` bound `this` ko **badal nahi sakte**.

</Numbers>

## Common Mistakes

<Mistake>

**`bind` ke return ko ignore karna.** `fn.bind(obj)` original `fn` ko modify nahi karta — wo ek **naya** function return karta hai. `const bound = fn.bind(obj); bound()` — return ko capture karo, warna bind bekaar gaya.

</Mistake>

<Mistake>

**`call` aur `apply` ka argument format ulta karna.** `fn.call(obj, [1, 2])` — ye ek single argument (array) pass karta hai, do nahi. Array chahiye to `apply`. `fn.apply(obj, 1, 2)` — `apply` doosra arg array chahta hai, ye `TypeError`.

</Mistake>

<Mistake>

**Har render pe `.bind(this)` karna (React).** `onClick={this.save.bind(this)}` har render naya function object banata hai, jisse `React.memo`/`PureComponent` child bewajah re-render karte hain. Constructor mein ek baar bind, ya class field arrow.

</Mistake>

<Mistake>

**Bound function ko `removeEventListener` se hataane ki koshish.** `el.addEventListener("click", this.h.bind(this))` ke baad `el.removeEventListener("click", this.h.bind(this))` — dono `bind` alag objects, match nahi hota, listener bana rehta hai. Bound reference ek variable/field mein store karo.

</Mistake>

<Mistake>

**`apply` ko array-spread ke liye use karna jab spread available hai.** `Math.max.apply(null, nums)` legacy hai. Modern: `Math.max(...nums)` — clearer, aur `null` thisArg ka jugaad nahi chahiye.

</Mistake>

## Quick Revision

<QuickRevision>

- Teeno `Function.prototype` pe — `this` explicitly set karte hain.
- `call(thisArg, a, b)` — **abhi** chalao, args listed.
- `apply(thisArg, [a, b])` — **abhi** chalao, args **array** (A = Array).
- `bind(thisArg, ...pre)` — **naya function** return, permanently bound + partial application.
- Method borrowing: `Array.prototype.slice.call(arguments)`.
- `apply` array-spread ki jagah ab `fn(...arr)`.
- `bind` re-bind nahi hota; `new` bound `this` ignore karta hai (bound args rehte hain).
- Har `.bind()` naya function object — React equality / `removeEventListener` ka dhyan.
- `bind`-for-this ki jagah arrow function zyada readable.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `const nums = [4, 2, 8]; console.log(Math.max.apply(null, nums), Math.max(...nums));` — dono kya dete hain, aur `apply` ne array ke saath kya kiya?

**Medium:** Ek `greet(greeting, name)` function likho jo `` `${greeting}, ${name}` `` return kare. `call`, `apply`, aur `bind` teeno se ise chalao (jahan `this` use nahi ho raha, sirf args). `bind` se ek `sayHello` banao jismein `greeting` "Hello" pe locked ho. Har form ka ek line farak likho.

**Bada:** `Function.prototype.myBind` naam se apna `bind` polyfill likho jo `this` fix kare, leading args support kare, aur bound function ko `new` ke saath call karne par target ke prototype ko respect kare. Native `bind` se compare karke 2 edge cases test karo.

</Callout>
