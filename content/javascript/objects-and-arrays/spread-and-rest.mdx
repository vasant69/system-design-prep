<SimpleDefinition>

**Spread** and **rest** use the same `...` token for opposite jobs. **Spread** *expands* an iterable or an object into individual pieces — array copy/merge (`[...a, ...b]`), object copy/merge (`{ ...a, ...b }`), and passing an array as separate function arguments (`Math.max(...nums)`). **Rest** *collects* leftovers into a single real array — rest parameters (`function f(...args)`) and the trailing binding in destructuring (`const [first, ...others] = arr`). Spread copies are **shallow** — nested objects/arrays stay shared.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

`...` do bilkul opposite kaam karta hai, aur log confuse hote hain kaunsa kab. Simple rule: agar `...` **right side / call arguments / literal ke andar** hai to **spread** (kholna); agar `...` **left side / parameter list mein** hai to **rest** (samet-na).

### Spread — ek cheez ko tod ke bikhraana

```javascript
const a = [1, 2];
const b = [3, 4];

const copy = [...a];              // [1, 2]  -- shallow copy
const merged = [...a, ...b];      // [1, 2, 3, 4]
const withExtra = [0, ...a, 99];  // [0, 1, 2, 99]

Math.max(...[5, 1, 8]);           // Math.max(5, 1, 8) -> 8
const chars = [..."abc"];         // ["a", "b", "c"]
const nodes = [...document.querySelectorAll("li")]; // NodeList -> real Array
```

Object spread:

```javascript
const base = { role: "user", active: true };
const patched = { ...base, role: "admin" };  // { role: "admin", active: true }
```

- Object spread mein **baad wali key jeet-ti hai** — `{ ...base, role: "admin" }` mein `role` overwrite ho gaya.
- Array spread kisi bhi **iterable** pe chalta hai (array, string, Set, Map, NodeList, arguments).
- Object spread sirf **own enumerable** properties copy karta hai — prototype se aaye keys nahi.

### Rest — bahut cheezein ek array mein samet-na

```javascript
function sum(...nums) {          // nums ek REAL array hai
  return nums.reduce((a, n) => a + n, 0);
}
sum(1, 2, 3);                    // 6

const [head, ...tail] = [10, 20, 30];  // head = 10, tail = [20, 30]
const { id, ...rest } = { id: 1, x: 2, y: 3 }; // rest = { x: 2, y: 3 }
```

- Rest parameter ek **sacha array** deta hai — `arguments` object ki tarah "array-jaisa" nahi. `nums.map(...)` seedha chalega.
- Rest hamesha **last** position pe — `function f(a, ...b, c)` `SyntaxError`.
- Ek signature/pattern mein sirf **ek** rest.

### `arguments` vs rest parameters

`arguments` har (non-arrow) function mein ek implicit array-jaisa object hai. Problems: array methods nahi (`arguments.map` fail), arrow functions mein hai hi nahi, aur named params ke saath sync hota hai (confusing). Rest params inme se koi problem nahi rakhte — modern code mein hamesha `...args` use karo.

### Internally kaise kaam karta hai

- **Array spread** — engine source ka `Symbol.iterator` chalata hai aur ek-ek karke values naye array/call mein daalta hai. Isi liye sirf iterables pe chalta hai; plain object `{}` array spread mein `TypeError` (`{}` iterable nahi).
- **Object spread** — `{ ...src }` roughly `Object.assign({}, src)` jaisa: `src` ki own enumerable string+symbol keys naye object mein copy. Getters yaha **call** hote hain (value copy hoti hai, getter nahi).
- **Rest** — baaki elements/properties ko ek fresh array/object mein pack.

### Key caveat — spread copy SHALLOW hai

```javascript
const original = { name: "V", address: { city: "Pune" } };
const clone = { ...original };

clone.name = "Raj";          // original.name still "V"  -- top-level OK
clone.address.city = "Mumbai";
console.log(original.address.city); // "Mumbai"  -- BUG! nested object shared
```

`{ ...original }` sirf **ek level** copy karta hai. `clone.address` aur `original.address` **wahi** object point karte hain. Yahi bug arrays mein bhi: `[...rows]` ke elements agar objects hain to woh shared hain.

Deep copy chahiye to: `structuredClone(original)` (modern, built-in), ya `JSON.parse(JSON.stringify(original))` (functions/Date/undefined kho deta hai), ya per-field manual spread.

### Simple real-life analogy

- **Spread** = ek bag ka saara saaman table pe nikaal dena — ab har cheez alag.
- **Rest** = bikhri hui cheezein utha ke ek naye bag mein daal dena.
- **Shallow copy** = tumne bag copy kiya par andar rakha dabba wahi purana hai — dabbe mein kuchh badla to dono "copies" mein dikhega.

### `...` in calls vs `.apply`

Pehle array ko separate args banane ke liye `fn.apply(null, arr)` likhna padta tha. Ab `fn(...arr)`. Spread cleaner hai, `this` ke saath khilwaad nahi, aur `new Thing(...args)` bhi kaam karta hai (jo `.apply` se possible nahi tha).

### Day-to-day use

- **Immutable updates** — React/Redux: `setUser({ ...user, name: newName })`, `setList([...list, item])`.
- **Function ko variable args** — `function log(level, ...messages)`.
- **Merge defaults** — `const config = { ...DEFAULTS, ...userConfig }`.
- **Array-jaise ko array banana** — `[...nodeList]`, `[...new Set(arr)]` (dedupe).
- **Clone before mutate** — `const sorted = [...arr].sort()` (kyunki `sort` in-place hai).

### Kab spread use karna chahiye

- Naya array/object chahiye purane ko **badle bina** (immutability).
- Do+ arrays/objects **merge** karne ho.
- Array ke elements ko function ko **separate args** dene ho.
- Iterable ya array-jaisa ko **real array** banana ho.

### Kab spread use nahi karna chahiye

- **Bahut bada array** function call mein spread karna — `fn(...hugeArray)` engine ke argument limit (~65k–500k, engine-dependent) se `RangeError` de sakta hai. Loop ya `reduce` use karo.
- **Deep clone** samajh ke spread use karna — woh sirf shallow hai; `structuredClone` use karo.
- **Performance-critical hot loop** mein har iteration `[...acc, x]` — yeh O(n^2) ho jaata hai (har baar poora copy). `acc.push(x)` ya ek mutable local use karo.
- Plain object ko **array** spread karna — `[...{}]` `TypeError`.

### Pros and cons

**Pros**

- Immutable update pattern short aur readable.
- `.apply` se cleaner, `this` issues nahi, `new` ke saath bhi.
- Ek token, do jagah (spread + rest) — seekhna aasan.
- Rest param se sacha array (`arguments` ke gotchas nahi).

**Cons**

- Shallow copy — sabse aam bug source.
- Bade data pe spread copy costly; hot loop mein O(n^2) trap.
- Call mein bahut bade array ka spread `RangeError`.
- Object spread getters ko call kar deta hai (side effects).

### Alternatives

- **`structuredClone(x)`** — deep copy ke liye (built-in, handles Date/Map/Set/nested).
- **`Array.from(iterable)`** — array-jaise ko array banana; `Array.from({length: 5}, (_, i) => i)` jaisa bhi.
- **`Object.assign(target, ...sources)`** — merge; spread se difference: `assign` target ko mutate karta hai (agar target `{}` na ho).
- **`arr.concat(other)`** — do arrays jodna; spread se thoda tez bade arrays pe.
- **`.push(...)` / mutable accumulator** — hot loop mein spread-in-loop ki jagah.

### Interview mein "spread se clone kiya — koi risk?"

> "Maine `{ ...state }` se clone banaya taaki original state mutate na ho aur React ko naya reference mile. Risk yeh hai ki spread **shallow** hai — agar state ke andar nested objects/arrays hain to woh clone aur original ke beech shared rehte hain, aur nested ko mutate karne pe dono jagah dikhega. Isliye main sirf woh nested level bhi spread karta hoon jise change kar raha hoon (`{ ...state, user: { ...state.user, name } }`), ya poore deep copy ke liye `structuredClone` use karta hoon. Aur bade arrays ke liye main loop mein `[...acc, x]` avoid karta hoon kyunki woh har iteration full copy karke O(n^2) ban jaata hai."

</Hinglish>

`...` right side / call args / literal ke andar = **spread** (kholna). `...` left side / parameter list mein = **rest** (samet-na). `[...a]` spread; `const [...a] = x` rest.

</Callout>

## Real World Example

<RealWorld company="React / Redux">

Immutable state updates ka poora idiom spread pe khada hai: `setTodos([...todos, newTodo])`, `setUser({ ...user, verified: true })`. React reference equality se re-render decide karta hai, isliye naya array/object reference chahiye — mutate karke same reference dena silent "UI update nahi hua" bug deta hai. Redux reducers mein bhi `return { ...state, loading: false }` standard hai. Yahi jagah shallow-copy bug bhi sabse zyada aata hai jab state nested ho.

</RealWorld>

<RealWorld company="Node.js / utility functions">

Config merging mein `const options = { ...DEFAULT_OPTIONS, ...userOptions }` har library mein milta hai — user ne jo diya woh defaults ko override karta hai kyunki baad wali key jeet-ti hai. Logger/wrapper functions `function wrap(fn) { return (...args) => fn(...args); }` pattern use karte hain — rest se saare arguments capture, spread se aage pass. Yeh `arguments` object se cleaner hai aur arrow function mein bhi chalta hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- Array/rest spread **ES6 (2015)**; **object spread ES2018** mein aaya (teen saal baad).
- Spread copy **1 level** deep — nested references shared rehte hain.
- `fn(...arr)` mein `arr` bahut bada ho to **`RangeError`** — limit engine-dependent (V8 pe roughly 65k–500k args).
- Loop ke andar `acc = [...acc, x]` = **O(n^2)** total kaam; `acc.push(x)` = O(n).
- Object spread mein **baad wali** duplicate key jeet-ti hai — left-to-right last wins.
- Rest parameter sirf **last** position; ek function mein sirf **ek**.

</Numbers>

## Interview Angle

<InterviewAngle>

Poocha jaata hai: (1) "spread aur rest mein farak" — same token, opposite job. (2) "spread se clone kiya, kya problem ho sakti hai" — shallow copy. (3) "`arguments` vs rest params". (4) code output: object spread mein key precedence, ya nested mutation dikhne wala trap.

Achhe jawaab ka shape:

1. **Spread** — expand: array/object copy/merge, call args.
2. **Rest** — collect: rest params (real array), destructuring tail.
3. **Position se pehchaan** — `...` kahan hai (value side vs binding side).
4. **Shallow** — nested shared; `structuredClone` for deep.
5. **Perf** — bade array call spread `RangeError`; loop mein spread O(n^2).

Red flag: `{ ...obj }` ko "deep clone" batana.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Spread ko deep copy samajhna.** `const clone = { ...state }; clone.user.name = "X"` bhi `state.user.name` ko badal deta hai — `user` object dono mein shared hai. Deep copy ke liye `structuredClone(state)` ya har nested level ka spread.

</Mistake>

<Mistake>

**Loop ke andar `acc = [...acc, item]`.** Har iteration poora `acc` copy hota hai — 10k items pe ~50M operations, O(n^2). `acc.push(item)` use karo, ya `reduce` mein mutable accumulator.

</Mistake>

<Mistake>

**Bahut bade array ko function call mein spread karna.** `Math.max(...millionElementArray)` `RangeError: Maximum call stack` ya argument-limit error de sakta hai. Bade data pe `arr.reduce((m, n) => n > m ? n : m, -Infinity)` use karo.

</Mistake>

<Mistake>

**Object spread mein key order galat.** `{ role: "admin", ...userInput }` mein agar `userInput` mein `role` hai to woh tumhare `"admin"` ko override kar dega — override chahiye to spread **pehle**, fixed value **baad mein**: `{ ...userInput, role: "admin" }`.

</Mistake>

<Mistake>

**Plain object ko array-spread karna.** `[...{ a: 1 }]` `TypeError: object is not iterable`. Object ki values chahiye to `Object.values(obj)`, entries chahiye to `Object.entries(obj)`, phir spread.

</Mistake>

## Quick Revision

<QuickRevision>

- Same `...` token: **spread** = expand (value side), **rest** = collect (binding side).
- Array copy `[...a]`, merge `[...a, ...b]`, call args `fn(...a)`, string→chars `[..."ab"]`.
- Object copy/merge `{ ...a, ...b }` — **baad wali key jeet-ti hai**.
- Rest param `function f(...args)` — sacha array, `arguments` ke gotchas nahi.
- Rest **last position only**, ek hi allowed.
- Spread copy **shallow** — nested objects/arrays shared → `structuredClone` for deep.
- Loop mein `[...acc, x]` = **O(n^2)** → `acc.push(x)`.
- `fn(...hugeArray)` → possible `RangeError`.
- `[...plainObject]` → `TypeError` (object iterable nahi).
- `fn(...arr)` ne `fn.apply(null, arr)` ko replace kiya — `new T(...args)` bhi chalta hai.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `const a = { x: 1, nested: { y: 2 } }; const b = { ...a }; b.nested.y = 99;` — `a.nested.y` ab kya hai aur kyun?

**Medium:** Ek function `mergeConfig(userConfig)` likho jo `DEFAULTS` object ke saath user config merge kare taaki user ki values jeeten, lekin `version` field hamesha `DEFAULTS` se aaye (user override na kar sake). Spread order dikhao.

**Bada:** Ek `pushAll(target, ...arrays)` likho jo har diye gaye array ke saare elements `target` mein push kare aur `target` return kare. Phir 100000-element array ke saath dikhaao ki `result = [...result, x]` loop vs `result.push(x)` loop mein timing ka farak kyun aata hai (O(n^2) vs O(n) samjhao).

</Callout>
