<SimpleDefinition>

`Array.prototype.reduce` walks an array left to right, carrying an **accumulator** value from one step to the next, and returns that final accumulator. The callback gets `(accumulator, currentItem, index, array)`. An optional **initial value** (second argument) sets the starting accumulator; without it, `array[0]` becomes the initial accumulator and iteration starts at index `1`. `reduce` can express sum, max, counting, grouping, flattening, and object building — but a plain loop is often clearer when the per-step logic is large.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

`reduce` woh array method hai jo log sabse zyada dar ke chhodte hain, aur interview mein sabse zyada poocha jaata hai. Idea simple hai: ek array ko **ek single value** mein "fold" karna — woh value number ho sakti hai, string, object, Map, ya doosra array.

### Ye kya hai — accumulator ko aage carry karna

`reduce` har element pe tumhara callback chalata hai aur ek "running value" (accumulator) maintain karta hai. Har call ka **return** hi agli call ka accumulator ban jaata hai. Loop khatam, jo aakhri accumulator bacha wahi `reduce` ka result.

```javascript
const sum = [1, 2, 3, 4].reduce((acc, n) => acc + n, 0);
// acc: 0 -> 1 -> 3 -> 6 -> 10 ; result 10
```

Callback ke 4 arguments: `(acc, item, index, array)`. Zyada tar sirf pehle do chahiye.

### Ye kyun exist karta hai

`map`/`filter` har element ko independently transform ya select karte hain — output length input jaisa (ya chhota). Par jab tumhe **saare elements ko mila ke ek cheez** banani ho — total, ginti, grouped object — tab har step ko pichhle step ka result chahiye. `reduce` isi "carry state across iterations" pattern ko ek standard shape deta hai, taaki tum apna `let total = 0` loop baar-baar na likho.

### Internally kaise kaam karta hai — initial value ka role

Do case hain:

**Initial value diya (`reduce(fn, init)`):**
- `acc` = `init`, iteration `index 0` se shuru.
- Empty array pe: callback kabhi nahi chalta, `reduce` seedha `init` return karta hai. Safe.

**Initial value nahi diya (`reduce(fn)`):**
- `acc` = `array[0]`, iteration `index 1` se shuru (pehla element consume ho gaya).
- **Empty array pe: `TypeError: Reduce of empty array with no initial value`.** Ye crash production mein aata hai jab list unexpectedly khaali ho.
- Single-element array pe: callback chalta hi nahi, woh ek element return ho jaata hai.

```javascript
[].reduce((a, b) => a + b);        // TypeError
[].reduce((a, b) => a + b, 0);     // 0  -- safe
[42].reduce((a, b) => a + b);      // 42 -- callback never ran
```

**Wrong-type init = silent bug.** Sum karna hai par `init` `""` de diya to `"" + 1 + 2` = `"12"` string milega, `3` nahi. Init ka type wahi rakho jo final result ka type hai — object banao to `{}`, Map banao to `new Map()`, array banao to `[]`.

### Simple real-life analogy

Ek almari mein kapde tah kar ke rakhna. Haath mein jo dher (accumulator) hai usme har naya kapda (element) add karte ho, tah karte ho, aur dher wapas haath mein. Aakhir mein poora tah kiya hua dher = result. Tumhara "starting dher" (init) khaali ho sakta hai (`[]`/`{}`), ya pehla kapda hi starting dher ban jaaye (no init).

### Code — line by line (worked examples)

```javascript
// 1. Sum
const total = nums.reduce((acc, n) => acc + n, 0);

// 2. Max (init -Infinity, ya no-init agar array kabhi khaali nahi)
const max = nums.reduce((m, n) => (n > m ? n : m), -Infinity);

// 3. Count occurrences / groupBy into an object
const counts = words.reduce((acc, w) => {
  acc[w] = (acc[w] ?? 0) + 1;
  return acc;
}, {});

// 4. Flatten one level
const flat = rows.reduce((acc, row) => acc.concat(row), []);

// 5. Build a Map (id -> record) from an array
const byId = records.reduce((map, r) => map.set(r.id, r), new Map());

// 6. "Pipe" — ek value ko functions ki chain se guzaarna
const result = [trim, toLower, slugify].reduce((val, fn) => fn(val), rawInput);
```

- Example 3 ka `return acc` **zaroori** hai — bhoole to agli iteration `acc` `undefined` ban jaata hai aur `undefined[w]` crash karta hai. Yeh reduce ka sabse common bug hai.
- Example 5 kaam karta hai kyunki `Map.set` khud Map return karta hai — accumulator naturally aage chala jaata hai.
- Example 6: `reduce` sirf numbers ke liye nahi — accumulator kuchh bhi ho sakta hai, yaha woh "abhi tak transform hui value" hai.

### Day-to-day use

- API response ke line-items ka **grand total** nikalna.
- List ko **lookup object/Map** mein badalna taaki baad mein O(1) `byId[x]` ho.
- Tags/categories ki **frequency** count karna (word cloud, analytics).
- Nested arrays ko **ek level flatten** karna.
- Redux-style reducer — woh literally yahi pattern hai: `(state, action) => newState`.

### Kab `reduce` use karna chahiye

- Aggregation: sum, product, min/max, average ka numerator.
- Array se object/Map banana jab logic **chhota** ho (ek-do line per step).
- Functional "pipe/compose" chain.
- Jab tum ek hi expression mein "fold" express kar sakte ho.

### Kab `reduce` use nahi karna chahiye

- Per-step logic **bada** hai (kai `if`, nested loops, multiple accumulators) — `for...of` padhne mein saaf rehta hai, `acc` ko har branch mein return karne ki ceremony nahi.
- Beech mein **break/early exit** chahiye — `reduce` ruk nahi sakta; `for...of` + `break` use karo (ya `some`/`find`).
- Sirf **side effects** chahiye (console, API call) — woh `for...of` ya `forEach` ka kaam hai, `reduce` ka nahi.
- Grouping ke liye ab **`Object.groupBy` / `Map.groupBy`** built-in hain (ES2024) — clearer intent.

```javascript
// reduce jo bada object banata hai -- loop zyada readable
const summary = for_of_version(orders); // 15 lines, 3 accumulators -> loop
```

### Pros and cons

**Pros**

- Ek standard shape har "carry state across iterations" problem ke liye.
- Expression hai — seedha `const x = arr.reduce(...)` mein assign, koi mutable `let` bahar nahi.
- Chainable — `arr.filter(...).map(...).reduce(...)` ek flow mein.

**Cons**

- Argument order (`acc` pehle, `item` doosra) log ulta yaad karte hain.
- `return acc` bhoolna = silent `undefined` accumulator.
- No-init + empty array = runtime `TypeError`.
- Bade callbacks mein loop se kam readable — "clever" dikhta hai, maintainable nahi.

### Alternatives

- **`for...of` loop** — jab step logic bada ho ya early exit chahiye.
- **`Object.groupBy(items, fn)` / `Map.groupBy(items, fn)`** — grouping ke liye purpose-built (ES2024 / modern runtimes).
- **`Math.max(...arr)`** — max ke liye reduce se simple, par bahut bade arrays pe stack limit.
- **`arr.flat()`** — one-level flatten ke liye reduce+concat se saaf.
- **`array.reduceRight`** — same cheez, right se left. `compose` (last function pehle chale) aur right-associative folds ke liye.

### Interview mein "Why did you use reduce here?"

> "Mujhe list se ek `id -> record` Map banana tha. `reduce` isliye kyunki mujhe ek accumulator chahiye tha jo har element pe grow kare aur end mein ek single value bane — `map`/`filter` yeh nahi karte, woh element-wise hain. Callback chhota tha (ek `set` call), isliye `reduce` readable raha. Agar per-step logic bada hota — kai conditions, multiple accumulators — to main `for...of` loop use karta, kyunki tab reduce ka `return acc` har branch mein likhna aur nesting padhna mushkil ho jaata hai. Aur pure grouping ke liye aajkal `Object.groupBy` seedha available hai."

</Hinglish>

<Callout type="tip">

`reduce` mein `return acc` bhoolna sabse aam bug hai. Agar accumulator object/array hai to har code path pe use return karo. Ek-line arrow (`(acc, x) => (acc[x] = 1, acc)`) chalega par team ke liye `{ ... return acc; }` clearer hai.

</Callout>

## Real World Example

<RealWorld company="Redux / React state">

Redux ka core `reducer` function `(state, action) => newState` bilkul `Array.prototype.reduce` ke callback jaisa hai — naam bhi wahi. Redux internally actions ke stream ko in reducers se "fold" karta hai. Isi wajah se React devs ke liye `reduce` ka mental model already familiar hota hai: accumulator = state, item = action.

</RealWorld>

<RealWorld company="Node.js API layer">

Backend mein invoice endpoints aksar line-items array ka `subtotal`, `taxTotal`, aur `grandTotal` ek hi pass mein nikaalte hain. Yaha teams often `reduce` se hat ke ek `for...of` loop rakhti hain kyunki teen alag accumulators aur rounding rules ke saath ek object-accumulator wali `reduce` "read once, understand" nahi rehti. Yeh "reduce ke bajaye loop" decision ka classic real case hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- `reduce` **ES5 (2009)** mein aaya, `reduceRight` ke saath.
- No-init `reduce` empty array pe **`TypeError`** deta hai — ES spec mein explicitly defined message.
- Callback ke **4** parameters: `accumulator`, `currentValue`, `currentIndex`, `array`.
- No init: iteration `index 1` se; init ke saath: `index 0` se.
- `Object.groupBy` / `Map.groupBy` **ES2024** — grouping ke liye reduce ka modern replacement.
- `reduce` **short-circuit nahi** karta — poora array hamesha traverse hota hai (koi `break` nahi).

</Numbers>

## Interview Angle

<InterviewAngle>

Poocha jaata hai do tarah se: (1) "Yeh code kya print karega?" — aksar no-init + empty array, ya `return acc` missing wala trap. (2) "`reduce` se X implement karo" — groupBy, flatten, ya `map`/`filter` ko `reduce` se dobara likhna.

Achhe jawaab ka shape:

1. **Definition** — "accumulator carry karta hai, har callback ka return agla accumulator, final accumulator = result."
2. **Init value** — "diya to index 0 se aur empty-safe; nahi diya to `array[0]` accumulator aur empty array pe `TypeError`."
3. **Ek worked example** — groupBy ya sum bol ke likh do.
4. **Kab nahi** — "bada step logic ya early exit chahiye to `for...of`."
5. **Modern note** — "grouping ke liye ab `Object.groupBy`."

Red flag: `reduce` ko sirf "sum nikalne wali cheez" batana, ya `return acc` ke bina groupBy likhna.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Object/array accumulator se `return acc` bhoolna.** `words.reduce((acc, w) => { acc[w] = 1; }, {})` — callback `undefined` return karta hai, agli iteration `acc` `undefined`, phir `undefined[w] = 1` `TypeError`. Har path pe accumulator return karo.

</Mistake>

<Mistake>

**No-init `reduce` aisi list pe jo khaali ho sakti hai.** `cart.reduce((a, b) => a + b.price)` tab crash karta hai jab `cart` `[]` ho. Hamesha init do (`, 0`) jab tak tum 100% sure na ho array non-empty hai.

</Mistake>

<Mistake>

**Galat type ka init.** Sum ke liye `""` de diya to result string concatenation ban jaata hai (`"012..."`). Count ke liye `[]` de diya to `acc.foo` `undefined`. Init ka type = final result ka type.

</Mistake>

<Mistake>

**Bade, branch-bhare callback ko `reduce` mein thoosna.** Teen `if`, do accumulators, nested loop — yeh `for...of` loop mein saaf padha jaata hai. `reduce` ko "smart" dikhne ke liye use mat karo; readability jeetti hai.

</Mistake>

<Mistake>

**`reduce` se early exit ki koshish.** `reduce` beech mein ruk nahi sakta — `return` sirf callback se return karta hai, loop se nahi. "Pehla matching element" chahiye to `find`; "koi match hai kya" chahiye to `some`.

</Mistake>

## Quick Revision

<QuickRevision>

- `arr.reduce((acc, item, i, arr) => next, init)` — har return agla `acc`, final `acc` = result.
- **Init do** — empty array + no init = `TypeError`; init ka type = result ka type.
- No init: `acc = arr[0]`, iteration index `1` se.
- Object/array accumulator ke saath **har path pe `return acc`**.
- Patterns: sum, max, count/groupBy, flatten-one-level, array-to-Map, pipe.
- `reduce` **ruk nahi sakta** — early exit ke liye `for...of` + `break`, ya `find`/`some`.
- Bada/branchy step logic ya multiple accumulators → `for...of` zyada readable.
- Grouping ke liye modern: `Object.groupBy` (plain object), `Map.groupBy` (Map).
- `reduceRight` = same, right se left (compose, right-associative folds).

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `[].reduce((a, b) => a + b)` aur `[].reduce((a, b) => a + b, 0)` — dono ka result batao aur kyun.

**Medium:** `reduce` se `groupBy(people, p => p.city)` likho jo `{ city: [person, ...] }` return kare. Phir usi ko `Object.groupBy` se ek line mein likho aur farak batao.

**Bada:** Ek `pipe(...fns)` helper likho jo `reduce` use kare aur ek function return kare jo input ko saari `fns` se left-to-right guzaare. Phir `pipe` ke basis pe `compose` `reduceRight` se likho. Test: `pipe(x => x + 1, x => x * 2)(3)` === `8`.

</Callout>
