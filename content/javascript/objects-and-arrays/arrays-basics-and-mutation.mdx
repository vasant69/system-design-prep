<SimpleDefinition>

A JavaScript **array** is a special object with integer-like keys (`"0"`, `"1"`, ...) and a `length` property that auto-updates. Array methods split into two groups: **mutating** methods (`push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`) change the array **in place** and often return something other than the array, while **non-mutating** methods (`slice`, `concat`, `map`, `filter`, spread) leave the original untouched and return a **new** array. The default `sort` is **lexicographic** on stringified elements, so numbers need an explicit compare function.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Array daily code ka sabse zyada use hone wala structure hai — lists, results, rows, sab. Sabse zyada bugs yahan se aate hain: ek method original ko chupke se badal deta hai jab tumne socha tha wo naya array de raha hai. Isliye "mutating vs non-mutating" is topic ka dil hai.

### Ye kya hai — integer keys wala object

Array ek object hi hai. `["a", "b", "c"]` andar se `{ "0": "a", "1": "b", "2": "c", length: 3 }` jaisa hai — plus `Array.prototype` se saare methods.

```javascript
const arr = ["a", "b", "c"];
arr[0];        // "a"
arr.length;    // 3
typeof arr;    // "object"
Array.isArray(arr); // true  -- sahi check
```

`typeof arr` `"object"` deta hai (helpful nahi), isliye array check ke liye `Array.isArray(arr)`.

### Ye kyun exist karta hai

Ordered data ke liye — jahan **position matter karti hai** aur tum index se access karna chahte ho. Object unordered string-keyed hai; array ordered integer-indexed hai, `length` free milta hai, aur `map`/`filter`/`reduce` jaisa rich toolkit milta hai.

### Internally kaise kaam karta hai — length ka jaadu

`length` hamesha "sabse bade integer index + 1" hota hai, aur wo **writable** hai:

```javascript
const a = [1, 2, 3, 4, 5];
a.length = 3;      // a ab [1, 2, 3]  -- truncation trick
a.length = 5;      // a ab [1, 2, 3, empty, empty]  -- holes
a[10] = "x";       // a.length ab 11, beech mein 6 holes
```

- `a.length = 3` — end se elements kaat deta hai. Ye array khali karne ka fast tareeka hai (`a.length = 0`).
- Index pe jump karke assign karne se beech mein **holes** (empty slots) ban jate hain — ye `undefined` nahi hote, "kuch bhi nahi" hote, aur kuch methods inhe skip karte hain.

### Simple real-life analogy

Array ek **train** hai jiske dabbe number 0, 1, 2... se labelled hain. `push`/`pop` = peeche wala dabba jodna/hatana. `shift`/`unshift` = aage wala dabba hatana/jodna (poori train ko renumber karna padta hai — isliye slow). `slice` = train ki photo ka ek hissa crop karna (asli train waise ki waise). `splice` = beech se dabbe nikalna/ghusana (asli train badal jati hai).

### Code — line by line

```javascript
const nums = [3, 1, 2];

const doubled = nums.map((n) => n * 2);
const copy = nums.slice();
const withFour = [...nums, 4];

nums.push(4);
const last = nums.pop();
nums.sort((a, b) => a - b);
```

- `nums.map(...)` — **non-mutating**: `[6, 2, 4]` naya array, `nums` abhi bhi `[3, 1, 2]`.
- `nums.slice()` — **non-mutating**: `nums` ki shallow copy.
- `[...nums, 4]` — **non-mutating**: spread se naya array `[3, 1, 2, 4]`.
- `nums.push(4)` — **mutating**: `nums` khud ab `[3, 1, 2, 4]`; return value nayi `length` (`4`), array nahi.
- `nums.pop()` — **mutating**: aakhri element hata ke wahi return karta hai (`4`).
- `nums.sort((a, b) => a - b)` — **mutating**: `nums` ko jagah pe sort karta hai aur wahi array return karta hai.

### Mutating vs non-mutating — poori table

| Method | Mutates? | Return karta hai |
|---|---|---|
| `push(x)` | haan | nayi `length` |
| `pop()` | haan | hataya gaya element |
| `shift()` | haan | hataya gaya pehla element |
| `unshift(x)` | haan | nayi `length` |
| `splice(i, n, ...items)` | haan | hataye gaye elements ka array |
| `sort(cmp)` | haan | wahi (mutated) array |
| `reverse()` | haan | wahi (mutated) array |
| `fill(v, s, e)` | haan | wahi (mutated) array |
| `slice(s, e)` | **nahi** | naya sub-array |
| `concat(...)` | **nahi** | naya joined array |
| `map(fn)` | **nahi** | naya transformed array |
| `filter(fn)` | **nahi** | naya filtered array |
| `[...arr]` spread | **nahi** | naya array |
| `flat()` / `flatMap()` | **nahi** | naya array |

Yaad rakhne ka trick: agar naam se lagta hai "list badal do" (`push`, `pop`, `sort`, `reverse`, `splice`) → mutating. Agar lagta hai "naya nikalo" (`map`, `filter`, `slice`, `concat`) → non-mutating.

### The `.sort()` gotcha

```javascript
[1, 2, 10].sort();              // [1, 10, 2]  -- WRONG for numbers!
[1, 2, 10].sort((a, b) => a - b); // [1, 2, 10]  -- correct
```

Default `sort` har element ko **string** mein badal ke **lexicographic** (dictionary) order mein compare karta hai. String world mein `"10"` `"2"` se pehle aata hai (`"1"` < `"2"`). Numbers sort karne ke liye hamesha compare function do: `(a, b) => a - b` ascending, `(a, b) => b - a` descending. Aur yaad rakho `sort` **mutating** hai — original array reorder ho jata hai.

### Emptiness aur holes — `Array(3)` vs `Array.of(3)`

```javascript
Array(3);            // [empty x 3]  -- length 3, koi actual element nahi
Array.of(3);         // [3]          -- ek element: number 3
Array(3).fill(0);    // [0, 0, 0]    -- holes ko 0 se bhara
[...Array(3)];       // [undefined, undefined, undefined]  -- spread holes ko undefined banata

const holey = [1, , 3];       // index 1 ek hole hai
holey.map((x) => x * 2);      // [2, empty, 6]  -- map hole SKIP karta hai
holey.forEach((x) => console.log(x)); // sirf 1 aur 3 print, hole skip
```

`Array(n)` sirf `length` set karta hai — beech sab holes. `Array.of(n)` `n` ko literal element banata hai. `map`/`forEach`/`filter` holes ko skip karte hain (jo confusing hai), lekin `[...arr]` aur `Array.from` unhe `undefined` mein convert kar dete hain. `Array.from({ length: 3 }, (_, i) => i)` → `[0, 1, 2]` — holes-free array banane ka reliable tareeka.

### Day-to-day use

- List of anything — API rows, todo items, search results.
- `map` se render (React `items.map(item => <Row .../>)`), `filter` se subset, `reduce` se aggregate.
- Stack (`push`/`pop`) ya queue (`push`/`shift`) banana.

### Kab mutate karna theek hai

- Local array jo tumne abhi is function ke andar banaya — koi aur usko nahi dekh raha.
- Performance-critical hot loop jahan har iteration pe naya array banana costly ho.
- `array.length = 0` se ek array ko in-place khali karna jab wahi reference kai jagah cache ho.

### Kab mutate NAHI karna chahiye

- Function ka **parameter** (caller ka array) — usse mutate karna surprise side effect hai.
- React/Redux state — mutate karne pe reference wahi rehti hai, re-render nahi hota. `setItems([...items, newItem])`.
- Shared/module-level data jise kai jagah se padha ja raha ho.
- Jab tumhe **dono** chahiye — original aur naya version.

### Pros and cons

**Non-mutating (`map`/`filter`/`slice`/spread)**

- Original safe — koi hidden side effect nahi, debugging aasaan.
- React/Redux mein reference change → re-render trigger.
- Chain karna aasaan.
- Cons: har call naya array (memory + GC); bade arrays ke hot loops mein cost.

**Mutating (`push`/`splice`/`sort`)**

- Zero extra allocation — in-place, fast.
- Kabhi-kabhi zyada readable (`arr.push(x)` vs `arr = [...arr, x]`).
- Cons: shared array pe side effect; React state todта hai; `sort`/`reverse` original order kho dete hain.

### Alternatives

- **`toSorted` / `toReversed` / `toSpliced` / `with`** (ES2023) — `sort`/`reverse`/`splice`/index-set ke **non-mutating** versions. `arr.toSorted((a,b)=>a-b)` original ko chhodta hai. Modern environments mein prefer karo.
- **Immer** — mutable-looking code likho, andar se immutable update milta hai (Redux Toolkit).
- **Readonly arrays (TypeScript `readonly T[]`)** — compile-time pe mutation rok deta hai.

### Interview mein "sort ka output galat kyun aaya?"

> "`Array.prototype.sort` bina compare function ke har element ko string mein convert karke lexicographically compare karta hai — isliye `[1, 2, 10].sort()` `[1, 10, 2]` deta hai, kyunki string `'10'` `'2'` se pehle aata hai. Numbers ke liye `(a, b) => a - b` dena zaroori hai. Aur `sort` in-place mutating hai — agar original order chahiye to pehle `slice()` se copy lo, ya ES2023 ka `toSorted` use karo."

</Hinglish>

<Callout type="tip">

`const arr = [1, 2, 3]` ke saath `arr.push(4)` bilkul valid hai — `const` binding lock karta hai, array content nahi. Jise tum "immutable" chahte ho wo `Object.freeze(arr)` hai (aur wo bhi shallow).

</Callout>

## Real World Example

<RealWorld company="React">

React mein list state update karte waqt `items.push(newItem); setItems(items)` **kuch nahi karta** — `items` ki reference wahi hai, React ko lagta hai kuch badla nahi, component re-render nahi hota. Sahi tareeka `setItems([...items, newItem])` ya `setItems(items.concat(newItem))` — nayi array reference. Isi wajah se React docs explicitly `push`/`splice`/`sort` ko state pe ban karte hain aur `map`/`filter`/spread recommend karte hain (ya `toSorted`/`with`).

</RealWorld>

<RealWorld company="Node.js / data pipelines">

Backend mein DB se aaye `rows` ko process karte waqt `rows.sort(...)` seedha chala dena tab bugs deta hai jab wahi `rows` array kisi cache ya doosre function ke paas bhi hai — order globally badal jata hai. Teams `const sorted = [...rows].sort(cmp)` ya `rows.toSorted(cmp)` likhti hain. Aur `array.length = 0` ek common trick hai jab ek buffer array ko har batch ke baad reuse karna ho bina nayi allocation ke.

</RealWorld>

## Numbers That Matter

<Numbers>

- **8 core mutating** methods: `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`.
- `sort` bina compare fn ke: elements ko **UTF-16 string** mein convert karke compare — numbers ke liye galat.
- `sort` **ES2019 se guaranteed stable** hai (equal elements ka relative order preserve).
- `shift`/`unshift` **O(n)** — saare elements re-index hote hain; `push`/`pop` **O(1)** amortized.
- `Array(3)` → `length` 3, **0** actual elements (3 holes). `Array.of(3)` → **1** element.
- Non-mutating copy methods (`toSorted`, `toReversed`, `toSpliced`, `with`) **ES2023** mein aaye.
- `map`/`filter`/`forEach` array **holes ko skip** karte hain; spread aur `Array.from` unhe `undefined` banate hain.

</Numbers>

## Interview Angle

<InterviewAngle>

Interviewer do cheezein pakadta hai: (1) kya tum jante ho kaunsa method mutate karta hai, (2) `sort` ka lexicographic default.

Model answer shape:

1. **Array = object** — "Integer keys + auto `length`; `Array.isArray` se check."
2. **Do groups** — "`push`/`pop`/`shift`/`unshift`/`splice`/`sort`/`reverse`/`fill` mutate karte hain; `map`/`filter`/`slice`/`concat`/spread naya array dete hain."
3. **Return values** — "`push` `length` deta hai, `pop`/`shift` hataya element, `sort`/`reverse` wahi array."
4. **sort gotcha** — "Default lexicographic; `[1,2,10].sort()` → `[1,10,2]`; numbers ke liye `(a,b)=>a-b`; aur `sort` mutating."
5. **Immutable update** — "State ke liye `[...arr]`, `map`, `filter`, ya `toSorted`."

Red flag: "`sort` naya array return karta hai" — nahi, wahi mutated array.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`[1, 2, 10].sort()` se numeric sort expect karna.** Default `sort` stringify karke lexicographic compare karta hai — result `[1, 10, 2]`. Numbers ke liye hamesha `(a, b) => a - b` (ascending) ya `(a, b) => b - a` (descending) compare function do.

</Mistake>

<Mistake>

**`sort` / `reverse` / `splice` ko non-mutating samajhna.** Ye original array ko jagah pe badal dete hain. Agar original chahiye to `[...arr].sort(...)`, ya ES2023 ka `arr.toSorted(...)` / `arr.toReversed()`.

</Mistake>

<Mistake>

**React state pe `push` / `splice` karke `setState` call karna.** Array reference wahi rehti hai, React ko change nahi dikhta, re-render nahi hota. `setItems([...items, x])`, `setItems(items.filter(...))` — nayi reference banao.

</Mistake>

<Mistake>

**`const x = arr.push(item)` likhna copy paane ke liye.** `push` **nayi length** return karta hai, array nahi. `x` ek number ban jata hai. Naya array chahiye to `const x = [...arr, item]`.

</Mistake>

<Mistake>

**`Array(3)` ko `[undefined, undefined, undefined]` samajhna aur `.map` chalana.** `Array(3)` mein 3 **holes** hain, actual elements nahi — `Array(3).map((_, i) => i)` `[empty, empty, empty]` deta hai, `[0,1,2]` nahi. `Array.from({ length: 3 }, (_, i) => i)` ya `[...Array(3)].map(...)` use karo.

</Mistake>

## Quick Revision

<QuickRevision>

- Array = object with integer keys + auto-updating `length`; check with `Array.isArray(x)`.
- `length` writable: `arr.length = 0` array khali karta hai; index-jump se holes bante hain.
- **Mutating**: `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`.
- **Non-mutating**: `slice`, `concat`, `map`, `filter`, `flat`, `flatMap`, spread.
- `push` → nayi length; `pop`/`shift` → hataya element; `sort`/`reverse` → wahi array.
- `sort()` default = lexicographic on strings → `[1,2,10].sort()` is `[1,10,2]`; numbers: `(a,b)=>a-b`.
- `sort` mutating + (ES2019 se) stable.
- `shift`/`unshift` O(n); `push`/`pop` O(1).
- `Array(3)` = 3 holes; `Array.of(3)` = `[3]`; holes-free: `Array.from({length:3}, (_, i) => i)`.
- ES2023 non-mutating: `toSorted`, `toReversed`, `toSpliced`, `with`.

</QuickRevision>
