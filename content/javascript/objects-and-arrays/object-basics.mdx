<SimpleDefinition>

A JavaScript **object** is an unordered collection of **key-value pairs**, where every key is a string (or symbol) and the value can be anything — a number, a string, an array, a function, another object. You create objects with **literal syntax** (`{ }`), read and write properties with **dot** or **bracket** notation, add **computed keys** at creation time, remove keys with `delete`, and check for a key with the `in` operator or `Object.hasOwn`. Objects also serve as JavaScript's built-in string-keyed map, with a few pitfalls that later motivate the real `Map` type.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Object JavaScript ka sabse core data structure hai. Array, function, `Date`, even `class` instances — sab andar se object hi hain. Agar object ka mental model saaf hai, to baaki bahut kuch apne aap samajh aata hai.

### Ye kya hai — key-value pairs ka bag

Ek object = ek dabba jisme **naam wali cheezein** rakhi hain. Har entry ke do hisse: ek **key** (hamesha string ya symbol) aur ek **value** (kuch bhi).

```javascript
const user = {
  name: "Vasant",
  age: 30,
  isAdmin: false,
  address: { city: "Pune", pin: "411001" },
  greet: function () {
    return "Hi " + this.name;
  },
};
```

- Keys: `name`, `age`, `isAdmin`, `address`, `greet`.
- `address` ki value khud ek object hai — **nested object**.
- `greet` ki value ek function hai — ise **method** kehte hain.

### Ye kyun exist karta hai

Related data ko ek naam ke neeche group karne ke liye. `name`, `age`, `city` ko teen alag variables mein rakhne ke bajaye ek `user` object mein rakho — pass karna, return karna, aur "ye sab ek cheez ke baare mein hai" express karna aasaan ho jata hai. Real APIs, config, DOM nodes, React props — sab objects hi hain.

### Internally kaise kaam karta hai

Object ke andar ek **property table** hoti hai jo key ko value se map karti hai. Jab tum `user.name` likhte ho, engine us table mein `"name"` key dhoondta hai; na mile to **prototype chain** upar chadhta hai (`Object.prototype` tak), phir `undefined` deta hai — error nahi. Isi liye kisi bhi missing property ko padhna safe hai, wo bas `undefined` return karta hai.

Dot notation `user.name` compile time pe fixed key `"name"` maanta hai. Bracket notation `user["name"]` ek **expression** leta hai aur usko string mein convert karke key banata hai — isi liye dynamic keys sirf bracket se possible hain.

### Simple real-life analogy

Object ek **locker room** hai. Har locker pe ek **naam ka sticker** (key) hai, andar kuch bhi rakha ho sakta hai (value). Dot notation = tum seedha locker ka naam bolte ho ("locker `name` kholo"). Bracket notation = tumhare haath mein ek parchi hai jispe naam likha hai, tum parchi dekh ke locker kholte ho — parchi runtime pe badal sakti hai.

### Code — line by line

```javascript
const key = "user-role";
const obj = {
  name: "Vasant",
  [key]: "admin",
  ["is" + "Active"]: true,
};

obj.age = 30;
obj["salary band"] = "L3";

console.log(obj.name);
console.log(obj["user-role"]);
delete obj.age;
console.log("age" in obj);
console.log(Object.hasOwn(obj, "name"));
```

- `const key = "user-role"` — ek variable jisme key ka naam string form mein hai.
- `[key]: "admin"` — **computed key**: `key` variable ko evaluate karke uski value (`"user-role"`) ko property naam banaya.
- `["is" + "Active"]: true` — computed key koi bhi expression ho sakta hai; yahan concatenation se `"isActive"` bana.
- `obj.age = 30` — nayi property dot se add ki (key ek valid identifier hai).
- `obj["salary band"] = "L3"` — key mein space hai, isliye dot kaam nahi karega — **bracket zaroori**.
- `obj.name` — dot access, fixed key.
- `obj["user-role"]` — key mein dash hai (`obj.user-role` ko JS `obj.user minus role` samajh leta), isliye bracket zaroori.
- `delete obj.age` — property poori tarah hata di (key + value dono).
- `"age" in obj` — ab `false`, kyunki delete ho gaya.
- `Object.hasOwn(obj, "name")` — `true`; sirf object ki apni property check karta hai, prototype ki nahi.

### Kab dot, kab bracket

| Situation | Notation | Kyun |
|---|---|---|
| Key fixed hai, valid identifier (`name`, `age1`, `_id`) | dot (`obj.name`) | Chhota, readable |
| Key ek variable mein hai (runtime pe decide) | bracket (`obj[k]`) | Dot literal key maanta hai |
| Key mein space / dash / dot / digit-start | bracket (`obj["a-b"]`) | Dot syntax-error ya galat parse |
| Key aik loop se aa rahi | bracket (`obj[k]`) | Same — dynamic |

### Existence check — teen tarike, teen matlab

```javascript
const obj = { a: undefined, b: 2 };

console.log(obj.a !== undefined); // false  -- key hai par value undefined
console.log("a" in obj);          // true   -- key mojood hai (value chahe kuch bhi)
console.log(Object.hasOwn(obj, "a")); // true -- key obj ki apni hai
console.log("toString" in obj);   // true   -- prototype se aaya!
console.log(Object.hasOwn(obj, "toString")); // false
```

- `obj.k !== undefined` — sabse common, par **jhoothi negative** deta hai jab value genuinely `undefined` set ki gayi ho.
- `"k" in obj` — key hai ya nahi, sahi jawab; lekin prototype chain bhi check karta hai (`"toString" in obj` `true`).
- `Object.hasOwn(obj, "k")` — sabse precise: sirf **own** property, prototype ignore. ES2022 mein aaya; isse pehle `obj.hasOwnProperty("k")` (par wo tab tootта hai jab object ne khud `hasOwnProperty` naam ki property overwrite kar di ho).

### Object as string-keyed map — aur uske pitfalls

Log aksar object ko "dictionary" ki tarah use karte hain: `const counts = {}; counts[word] = (counts[word] || 0) + 1`. Chhote cases mein theek, par:

- Keys **hamesha string** ban jati hain — `obj[1]` aur `obj["1"]` same slot.
- Prototype keys ghus jati hain — `counts["toString"]` shuru se hi `"function..."` jaisa kuch deta hai (own nahi, par `in` aur access pe dikhta hai). Isi liye plain map ke liye `Object.create(null)` ya seedha `Map` behtar hai.
- Insertion order mostly preserve hota hai, lekin integer-jaisi keys pehle numeric order mein aati hain — surprising.
- Size janne ke liye `Object.keys(obj).length` — O(n).

Ye sab `Map` ko motivate karta hai (alag topic).

### Object.freeze — shallow immutability

```javascript
const config = Object.freeze({ retries: 3, db: { host: "localhost" } });
config.retries = 5;      // silently ignore (strict mode mein TypeError)
config.db.host = "prod"; // ye CHAL jata hai -- freeze shallow hai
```

`Object.freeze` sirf **top level** properties ko lock karta hai. Nested object abhi bhi mutable. Deep freeze chahiye to recursive helper likhna padta hai.

### Kab plain object use karna chahiye

- Fixed, known shape wala structured data — ek `user`, ek `config`, ek API response.
- JSON ke saath kaam — `JSON.parse` object hi deta hai.
- Function ko "named arguments" pass karne ke liye — `createUser({ name, age, role })`.

### Kab plain object use nahi karna chahiye

- Keys **dynamic aur user-controlled** hain (word counts, cache, id-to-object lookup) → `Map` (ya `Object.create(null)`).
- Non-string keys chahiye (object ko key banana) → `Map`.
- Frequent add/delete + size tracking → `Map` (`.size` O(1)).
- Ordered collection jaha index matter kare → array.

### Pros and cons

**Plain object**

- Literal syntax sabse concise; JSON ke saath native.
- Dot access fast aur readable.
- Har jagah supported, koi import nahi.

**Cons**

- Prototype keys leak (`toString`, `constructor`).
- Keys sirf string/symbol; integer keys reorder ho jati hain.
- Koi `.size`, `.has`, iteration protocol nahi (helpers chahiye).
- `Object.freeze` shallow.

### Alternatives

- **`Map`** — dynamic keys, kisi bhi type ki key, `.size`, clean iteration. Jab object "lookup table" ban raha ho.
- **`Object.create(null)`** — prototype-less object; safe dictionary jab `Map` overkill lage par prototype pollution se bachna ho.
- **`class`** — jab same shape ke bahut instances chahiye with shared methods.
- **`Set`** — jab sirf "ye value mojood hai ya nahi" chahiye, key-value nahi.

### Interview mein "Dot ya bracket kyun?"

> "Dot notation tab jab key ek fixed, valid identifier ho — chhota aur readable. Bracket tab **zaroori** jab key runtime pe decide hoti hai (variable ya loop se aati hai), ya key mein space/dash/dot ho ya wo digit se shuru ho, kyunki `obj.user-role` ko engine subtraction samajh leta hai. Computed key `{ [expr]: value }` bhi isi wajah se exist karta hai — creation ke waqt dynamic key set karne ke liye."

</Hinglish>

<Callout type="tip">

`obj.someKey` missing hone pe `undefined` deta hai, error nahi — isi liye typos silent bugs ban jate hain. `obj.usr.name` jab `usr` `undefined` ho tab crash hota hai (`Cannot read properties of undefined`). Optional chaining `obj.usr?.name` isse `undefined` mein badal deta hai.

</Callout>

## Real World Example

<RealWorld company="React">

React component props ek plain object hote hain. `function Card(props)` mein `props.title`, `props.onClick` sab dot access hai. Jab prop ka naam dynamic ho — jaise ek generic `<Field name={fieldName} value={values[fieldName]} />` — to `values[fieldName]` bracket notation hai, kyunki `fieldName` ek variable hai. Form libraries (Formik, React Hook Form) andar se yehi karte hain: ek `values` object jisme field names dynamic keys hain.

</RealWorld>

<RealWorld company="Node.js / Express">

Express mein `req.headers`, `req.params`, `req.query` sab plain objects hain. `req.params.id` dot se milta hai. `req.headers["content-type"]` bracket se — kyunki HTTP header names mein dash hota hai aur `req.headers.content-type` valid JS nahi. Config loading bhi yehi pattern: `process.env` ek object hai, `process.env.NODE_ENV` dot, par `process.env[dynamicVarName]` bracket jab env var ka naam code mein compute hota hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- Object literal `{ }` shuruat se (1995) JavaScript mein hai; **computed keys** aur **shorthand** ES6 (2015) mein aaye.
- `Object.hasOwn` **ES2022** mein aaya — `hasOwnProperty` ka safe replacement.
- Object key sirf **2 types**: string aur symbol. Number key do — `obj[1]` chupke se `obj["1"]` ban jata hai.
- `Object.keys(obj).length` = size nikalne ka O(n) tarika; `Map.size` O(1).
- `Object.freeze` **1 level** deep — nested objects untouched.
- `delete obj.k` property poori hata deta hai; `obj.k = undefined` key rakhta hai bas value badalta hai — `"k" in obj` inhe alag batata hai.

</Numbers>

## Interview Angle

<InterviewAngle>

Ye foundational question hai; interviewer dekhta hai ki tum "object kya hai" se aage bracket/dot ke **kab-kyun**, computed keys, aur existence-check ke nuances jante ho.

Model answer ka shape:

1. **Definition** — "Object string/symbol keys se values ka mapping hai; values kuch bhi."
2. **Access** — "Dot jab key fixed identifier; bracket jab key dynamic ya invalid-identifier."
3. **Creation-time dynamic key** — "`{ [k]: v }` computed key; `{ name }` shorthand for `{ name: name }`."
4. **Existence** — "`in` prototype bhi dekhta hai; `Object.hasOwn` sirf own; `obj.k !== undefined` fails jab value hi `undefined` ho."
5. **Delete** — "`delete obj.k` key hatata hai; `obj.k = undefined` nahi."
6. **Freeze** — "`Object.freeze` shallow."

Red flag: "bracket aur dot bilkul same hain, style choice hai" — nahi, dynamic keys sirf bracket se possible hain.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Dynamic key ke liye dot notation likhna.** `obj.key` jab `key` ek variable ho, `obj["key"]` (literal string `"key"`) ko access karta hai, `key` ki value ko nahi. Dynamic key hamesha `obj[key]` — bracket ke andar bina quotes ke variable.

</Mistake>

<Mistake>

**Existence check ke liye `obj.k !== undefined` par bharosa karna.** Agar property genuinely `undefined` set ki gayi hai (`{ a: undefined }`), ye check `false` deta hai jabki key mojood hai. Key ki presence chahiye to `"k" in obj` ya `Object.hasOwn(obj, "k")`.

</Mistake>

<Mistake>

**`in` operator se own-property check karna.** `"toString" in obj` har object pe `true` — wo `Object.prototype` se aata hai. Sirf apni property chahiye to `Object.hasOwn(obj, key)`.

</Mistake>

<Mistake>

**`Object.freeze` ko deep samajhna.** `Object.freeze(config)` ke baad `config.db.host = "x"` bina rok-tok chalta hai, kyunki freeze sirf top-level keys ko lock karta hai. Nested immutability chahiye to har nested object ko recursively freeze karo.

</Mistake>

<Mistake>

**Plain object ko general-purpose map ki tarah use karna with user-controlled keys.** `cache[userInput]` mein agar `userInput` `"__proto__"` ya `"constructor"` ho to ajeeb behaviour milta hai. Dynamic, untrusted keys ke liye `Map` ya `Object.create(null)`.

</Mistake>

## Quick Revision

<QuickRevision>

- Object = string/symbol key → koi bhi value ka mapping; nested objects allowed.
- Dot access = fixed identifier key; bracket access = dynamic key ya invalid-identifier key (space, dash, digit-start).
- Computed key `{ [expr]: v }` — creation ke waqt dynamic key set karo.
- Shorthand `{ name }` == `{ name: name }`.
- `delete obj.k` key + value dono hatata hai; `obj.k = undefined` sirf value.
- `"k" in obj` — prototype bhi dekhta hai; `Object.hasOwn(obj, k)` — sirf own; `obj.k !== undefined` — value `undefined` ho to jhoota `false`.
- `Object.freeze` **shallow** — nested object still mutable.
- Missing property padhna = `undefined` (error nahi); missing object pe `.x` padhna = crash.
- Dynamic / untrusted keys → `Map` ya `Object.create(null)`, plain object nahi.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `const k = "full name"; const o = {}; o[k] = "Vasant Vyas"; console.log(o.k, o[k]);` — dono kya print honge aur `o.k` `undefined` kyun hai?

**Medium:** Ek function `pick(obj, keys)` likho jo `keys` array mein diye gaye keys ki nayi copy return kare (sirf woh keys jo `Object.hasOwn` se own hain). `pick({a:1,b:2,c:3}, ["a","c","z"])` → `{ a: 1, c: 3 }`.

**Bada:** Ek `wordCount(text)` likho jo plain object se counts banaye. Phir `text` mein `"constructor"` aur `"toString"` words daal ke dekho kya galat hota hai. Ise `Object.create(null)` ya `Map` se fix karo aur do line mein likho ki kya badla.

</Callout>
