<SimpleDefinition>

**Destructuring** is syntax for pulling values out of arrays (by **position**) or properties out of objects (by **name**) into distinct variables in one statement. Both forms support **default values** for missing entries and a **rest pattern** (`...`) to collect whatever is left. It is used constantly in function parameters (the "options object" pattern), in `import` statements, and when reading API responses.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Destructuring woh syntax hai jo tum har React/Node file mein dekhte ho — `const { name, age } = user` ya `const [first, ...rest] = list`. Isse "ek object/array se cheezein nikaal ke alag variables banana" ek line mein ho jaata hai, `const name = user.name; const age = user.age;` ki repetition ke bina.

### Ye kya hai — pattern ko value ke saamne rakhna

Normally left side ek variable naam hota hai. Destructuring mein left side ek **pattern** hota hai jo right side ke structure jaisa dikhta hai, aur JS us shape ko match karke values assign kar deta hai.

```javascript
const [a, b] = [10, 20];        // a = 10, b = 20  (position se)
const { x, y } = { x: 1, y: 2 };// x = 1, y = 2    (naam se)
```

### Ye kyun exist karta hai

Do reasons. (1) **Boilerplate kam** — ek object ki 5 properties nikaalne ke liye 5 lines ki jagah 1. (2) **Function signatures readable** — jab function ek "options object" leta hai, destructuring se caller ko dikhta hai andar kaunse fields use hote hain, aur defaults ek hi jagah declare ho jaate hain.

### Array destructuring — position matters

```javascript
const arr = ["Vasant", "Vyas", "Pune"];

const [first, last] = arr;          // first = "Vasant", last = "Vyas"
const [, , city] = arr;             // skip 2, city = "Pune"
const [x = 1, z = 2] = [10];        // x = 10, z = 2  (z missing -> default)
let a = 1, b = 2;
[a, b] = [b, a];                    // swap without a temp var
const [head, ...tail] = [1, 2, 3, 4]; // head = 1, tail = [2, 3, 4]
```

- `[, , city]` — comma se position skip karte ho. Har comma ek slot.
- `x = 1` default **sirf tab lagta hai jab value `undefined` ho** (missing slot ya literal `undefined`). `null` pe default nahi lagta.
- Swap: right side pehle ek array `[b, a]` banta hai, phir destructure hota hai — isliye temp variable ki zaroorat nahi.
- `...tail` **sirf last** position pe aa sakta hai.

### Object destructuring — name matters

```javascript
const user = { name: "Vasant", age: 30, role: "dev" };

const { name, age } = user;                  // name, age
const { name: userName } = user;             // rename -> userName = "Vasant"
const { country = "IN" } = user;             // default (missing)
const { name: n = "Anon" } = user;           // rename + default
const { role, ...others } = user;            // others = { name, age }
```

- **Rename**: `{ apiKey: key }` ka matlab "property `apiKey` nikaalo, use `key` naam do". Colon ke baaye purana naam, daaye naya.
- Rename + default: `{ x: y = 5 }` — property `x` nikaalo `y` mein, na mile to `y = 5`.
- Rest `...others` ek **naya object** banata hai baaki properties ke saath (shallow copy of the rest).

### Nested destructuring

```javascript
const user = { name: "V", address: { city: "Pune", pin: "411001" } };
const { address: { city } } = user;   // city = "Pune"
```

Yaha `address` **variable nahi banta** — woh sirf "raste" ke liye hai. Sirf `city` variable banta hai. Agar `address` bhi chahiye to alag se likho: `const { address, address: { city } } = user`.

### Function parameters — the "options object" pattern

```javascript
function createUser({ name, role = "member", active = true } = {}) {
  // ...
}

createUser({ name: "Vasant", role: "admin" });
createUser();  // {} default se destructure -> name undefined, role/active defaults
```

- Parameter position pe hi destructure — caller named arguments jaisa feel deta hai, order yaad nahi rakhna.
- Defaults yaha declare — function body clean.
- `= {}` **zaroori** hai: `createUser()` bina iske `undefined` ko destructure karega → **`TypeError`**.

### Internally — right side pehle evaluate, phir shape match

Engine right side ki value leta hai. Array pattern ke liye woh value **iterable** honi chahiye (uske `Symbol.iterator` se elements khiche jaate hain). Object pattern ke liye bas property access hota hai. Missing → `undefined` → default (agar diya) → warna variable `undefined`.

### Simple real-life analogy

Ek parcel aaya jisme cheezein fixed slots mein hain. Array destructuring = "pehla dabba, doosra dabba, teesra chhod do". Object destructuring = "jisme `charger` likha hai woh nikaal do, jisme `manual` likha na ho to yeh default manual rakh lo".

### Day-to-day use

- `const { data, error } = await supabase.from(...)` — API responses.
- `const [state, setState] = useState(0)` — React hooks (array destructuring by design).
- `import { useEffect, useMemo } from "react"` — named imports bhi destructuring-jaisi shape.
- Function ke options object.
- `for (const [key, value] of Object.entries(obj))` — loop ke andar.

### Kab use karna chahiye

- Ek value se 2+ cheezein nikaalni hon.
- Function ko 3+ config-jaise arguments dene ho (options object + destructure).
- Nested response se sirf 1-2 deep fields chahiye.
- Swap, ya ek function se multiple values return (array/object return + destructure).

### Kab use nahi karna chahiye

- Sirf **ek** property chahiye jo aage kai baar use nahi hoti — `user.id` seedha likhna clearer.
- **Bahut deep nesting** (`{ a: { b: { c: { d } } } }`) — ek missing intermediate pe `TypeError`, aur padhna mushkil. Optional chaining (`a?.b?.c?.d`) safer.
- Jab source `null`/`undefined` ho sakta hai aur tumne default guard nahi lagaya — crash.
- Rename ki chain itni lambi ho jaaye ki reader ko original naam hi na pata chale.

### Pros and cons

**Pros**

- Kam boilerplate, ek line mein multiple bindings.
- Defaults ek hi jagah, readable.
- Options-object pattern se caller ko order yaad nahi rakhna.
- Rest se "baaki sab" ek object/array mein.

**Cons**

- `undefined`/`null` destructure karna `TypeError` deta hai.
- Nested pattern ek missing intermediate pe crash.
- Statement-position object destructuring ko `( )` chahiye (neeche).
- Over-renaming se code ka original naam se rishta toot jaata hai.

### Alternatives

- **Seedha property access** (`obj.prop`) — jab sirf ek cheez ek hi baar chahiye.
- **Optional chaining `?.`** — jab path missing ho sakta hai; destructuring se safe.
- **`Object.assign` / spread** — merge ke liye (destructuring extract ke liye hai).
- **Named parameters via ek `options` var** — bina destructure kiye `options.name` — kam idiomatic, par jab bahut fields hon aur sab optional hon to theek.

### Interview mein "Why destructure the params?"

> "Function ek options object leta hai jisme 4-5 optional fields the. Destructuring params position pe isliye kiya taaki caller ko argument order yaad na rakhna pade — woh sirf `{ role: 'admin' }` bhej de. Defaults maine wahin parameter mein declare kiye, isliye body clean rahi. `= {}` fallback isliye lagaya taaki bina argument call karne pe `undefined` destructure na ho aur `TypeError` na aaye. Agar mujhe sirf ek field chahiye hota to main seedha `options.name` likhta — destructuring tabhi jab 2+ cheezein ya defaults involved hon."

</Hinglish>

<Callout type="tip">

Statement ki shuruaat mein object destructuring ko parentheses chahiye: `({ a, b } = obj);`. Bina `( )` ke JS `{` ko block samajh leta hai aur `SyntaxError` deta hai. `const { a, b } = obj` mein yeh problem nahi kyunki `const` aage hai.

</Callout>

## Real World Example

<RealWorld company="React">

React hooks ka API destructuring maan ke design hua hai. `useState` ek 2-element array `[value, setter]` return karta hai — tuple — taaki tum `const [count, setCount]` naam khud choose kar sako (do `useState` calls naming clash na karein). Agar object return hota `{ value, setValue }` to har call pe rename karna padta. Yeh array-destructuring ka jaan-boojh kar kiya gaya use hai.

</RealWorld>

<RealWorld company="Express / Node handlers">

Express route handlers mein `const { id } = req.params;` aur `const { page = 1, limit = 20 } = req.query;` bahut common hai — query params ke defaults ek hi line mein, aur `req.query` ka baaki noise handler mein nahi aata. Yaha `req.query` hamesha ek object hota hai (kabhi `undefined` nahi), isliye `= {}` guard ki zaroorat nahi — par nested config objects ke saath woh guard zaroori ho jaata hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- Destructuring **ES6 (ES2015)** mein aaya — spread/rest ke saath usi release mein.
- Array default value **sirf `undefined`** pe lagti hai — `null`, `0`, `""`, `false` pe nahi.
- Rest element (`...x`) sirf **last** position pe legal hai — beech mein `SyntaxError`.
- `const {} = null` aur `const {} = undefined` → **`TypeError`**; `const {} = 0` ya `"str"` chalta hai (primitives box ho jaate hain).
- Nested pattern ka intermediate key missing → **`TypeError`** us line pe.
- Statement-start object destructuring ko `( ... )` wrap chahiye — spec requirement.

</Numbers>

## Interview Angle

<InterviewAngle>

Poocha jaata hai: (1) "Yeh code kya print karega" — aksar default-value edge case (`null` vs `undefined`) ya nested-missing `TypeError`. (2) "Swap without temp variable" — array destructuring. (3) "Options object pattern likho with defaults."

Achhe jawaab ka shape:

1. **Do forms** — array position se, object naam se; dono mein defaults aur rest.
2. **Default ka rule** — sirf `undefined` pe lagti hai.
3. **Rename syntax** — `{ old: newName }`.
4. **Param pattern** — `function f({ a, b = 1 } = {})` aur `= {}` kyun chahiye.
5. **Kab nahi** — single-use single property, ya deep nesting (optional chaining better).

Red flag: yeh sochna ki `const { a } = null` bas `a = undefined` de dega — woh `TypeError` deta hai.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`undefined`/`null` ko destructure karna.** `const { name } = users.find(u => u.id === 99)` — agar koi user na mile to `find` `undefined` deta hai, aur `undefined` ko destructure karna `TypeError` phenkta hai. Guard lagao: `const { name } = users.find(...) ?? {}`.

</Mistake>

<Mistake>

**`= {}` param default bhoolna.** `function opts({ timeout = 5000 } = {})` mein `= {}` na ho to `opts()` (bina argument) `undefined` destructure karke crash karta hai. Options-object pattern mein `= {}` hamesha lagao.

</Mistake>

<Mistake>

**`null` pe default value expect karna.** `const { retries = 3 } = { retries: null }` mein `retries` `null` rehta hai, `3` nahi — default sirf `undefined` pe lagti hai. Agar `null` ko bhi handle karna hai: `const retries = config.retries ?? 3`.

</Mistake>

<Mistake>

**Nested destructuring jab intermediate optional ho.** `const { address: { city } } = user` — agar `user.address` `undefined` hai to `undefined.city` `TypeError`. Deep aur uncertain paths ke liye optional chaining (`user.address?.city`) use karo.

</Mistake>

<Mistake>

**Statement-position object destructuring bina `( )`.** `{ a, b } = obj;` (already-declared vars pe) `SyntaxError` deta hai kyunki `{` block samjha jaata hai. `({ a, b } = obj);` likho.

</Mistake>

## Quick Revision

<QuickRevision>

- Array: `const [a, b] = arr` — position se; `[, , third]` — skip; `[a, b] = [b, a]` — swap.
- Object: `const { a } = obj` — naam se; `{ a: b }` — rename; `{ a = 1 }` — default.
- Default **sirf `undefined`** pe lagti hai — `null`/`0`/`""` pe nahi.
- Rest `...x` sirf **last** position pe; naya array/object banata hai.
- Nested: `const { a: { b } } = obj` — `a` variable nahi banta, sirf `b`.
- Param pattern: `function f({ x, y = 1 } = {})` — `= {}` bina call-without-args crash karta hai.
- `const {} = null | undefined` → **`TypeError`**.
- Statement-start object destructure ko `({ ... } = obj)` parentheses chahiye.
- Deep/uncertain paths → optional chaining (`a?.b?.c`), destructuring nahi.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `const { a = 1, b = 2 } = { a: undefined, b: null };` — `a` aur `b` ki final values kya hain aur kyun?

**Medium:** Ek function `formatName({ first, last, title = "" } = {})` likho jo `"Dr. Vasant Vyas"` jaisa string return kare. Test karo: full object ke saath, bina `title` ke, aur bina kisi argument ke — teeno crash na karein.

**Bada:** Ek API response `{ user: { name, roles }, meta: { page, total } }` shape maano. Ek line mein `name`, `roles` (default `[]`), aur `page` (default `1`) destructure karo — lekin aise ki agar poora `response` `undefined` ho to bhi crash na ho. Batao tumne kaunse guards lagaye.

</Callout>
