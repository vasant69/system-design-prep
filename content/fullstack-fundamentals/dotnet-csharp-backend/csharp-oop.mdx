## 1. Concept Overview

- **Encapsulation** — fields private rakho, behaviour ko methods aur properties ke through expose karo, invariants ek jagah enforce karo. Caller object ko invalid state me nahi daal sakta.
- **Inheritance** — `class Dog : Animal` `Animal` ke members reuse karta hai aur add ya specialise kar sakta hai. Ek genuine "is-a" model karo; jab sach me "has-a" ho to composition prefer karo.
- **Polymorphism** — `Animal` type ka variable ek `Dog` ya `Cat` rakh sakta hai; `animal.Speak()` call karne par derived override chalta hai. Ek call site, kai behaviours. `virtual`/`override` ya interfaces se hota hai.
- **Abstraction** — contract (`abstract class` ya `interface`) par depend karo, concrete implementation par nahi, taaki callers ye na jaanein ki wo kaise kaam karta hai aur implementations swap ho sakein.

Interview me definitions mat ratao — dikhao ki har ek *kyun* matter karta hai: encapsulation invariants ke liye, polymorphism `switch`-on-type khatam karne ke liye, abstraction testability aur swap-ability ke liye.

## 2. Core Syntax

```csharp
// Encapsulation: private state, controlled surface
public class BankAccount
{
    private decimal _balance;                       // hidden
    public decimal Balance => _balance;             // read-only property

    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        _balance += amount;
    }
}

// Abstraction + inheritance + polymorphism
public abstract class PaymentMethod
{
    public abstract void Pay(decimal amount);       // no body -> subclass must implement
    public void Validate()                          // shared, non-virtual
    {
        if (!IsConfigured()) throw new InvalidOperationException("not configured");
    }
    protected abstract bool IsConfigured();
}

public class UpiPayment : PaymentMethod
{
    private readonly string _vpa;
    public UpiPayment(string vpa) => _vpa = vpa;
    public override void Pay(decimal amount) => Console.WriteLine($"UPI {amount} from {_vpa}");
    protected override bool IsConfigured() => !string.IsNullOrWhiteSpace(_vpa);
}

// Interface: capability contract, multiple inheritance of type
public interface IRefundable { void Refund(decimal amount); }

// virtual/override vs new (method hiding)
public class Base { public virtual string Name() => "base"; }
public class Derived : Base { public override string Name() => "derived"; }
```

## 3. Working Example

Ek payment processor jo type checks ke bajaye polymorphism use karta hai.

```csharp
public abstract class PaymentMethod
{
    public abstract string Kind { get; }
    public abstract PaymentResult Pay(decimal amount);
}

public sealed class CreditCard : PaymentMethod, IRefundable
{
    private readonly string _number;                 // encapsulated
    public CreditCard(string number) => _number = number;
    public string Last4 => _number[^4..];            // expose only last 4
    public override string Kind => "card";
    public override PaymentResult Pay(decimal amount) => PaymentResult.Ok($"card ****{Last4}");
    public void Refund(decimal amount) => Console.WriteLine($"refund {amount} to ****{Last4}");
}

public sealed class Wallet : PaymentMethod, IRefundable
{
    public override string Kind => "wallet";
    public override PaymentResult Pay(decimal amount) => PaymentResult.Ok("wallet");
    public void Refund(decimal amount) => Console.WriteLine($"refund {amount} to wallet");
}

public sealed class UpiPayment : PaymentMethod
{
    public override string Kind => "upi";
    public override PaymentResult Pay(decimal amount) => PaymentResult.Ok("upi");
}

public class PaymentProcessor
{
    public PaymentResult Process(PaymentMethod method, decimal amount)
    {
        // no `if (method is CreditCard) ...` — polymorphism handles it
        var result = method.Pay(amount);
        if (method is IRefundable r && amount > 100_000m) r.Refund(0m); // capability check, not type check
        return result;
    }
}
```

`NetBankingPayment` add karne ke liye ek nayi class chahiye aur `PaymentProcessor` me zero changes — yahi polymorphism plus optional "refundable" capability ke interface ka payoff hai.

## 4. Common Mistakes / Interview Traps

- **Definitions bina "kyun" ke ratana.** Interviewers ye chahte hain: encapsulation invariants protect karta hai; polymorphism `switch` on type hata deta hai; abstraction mocking enable karta hai.
- **`virtual`/`override` vs `new`.** `override` true polymorphism deta hai; `new` base member ko *hide* karta hai, isliye call compile-time type se resolve hoti hai — ek subtle bug.
- **"Convenience ke liye" public fields.** Encapsulation todta hai; baad me validation add ya representation change nahi kar sakte bina breaking change ke. Properties use karo.
- **Deep inheritance chains.** Teen-se-zyada levels fragile ho jaate hain (fragile base class problem). Composition aur interfaces prefer karo.
- **Constructor se `virtual` methods call karna.** Derived override derived constructor body se pehle chalta hai — fields uninitialised ho sakte hain.
- **`abstract` class vs `interface` confusion.** Abstract class = shared implementation + state + single base. Interface = pure contract, per class kai. C# 8 se interfaces me default methods ho sakte hain, par state abhi bhi classes me.
- **Kuch bhi seal na karna.** Leaf classes par `sealed` intent document karta hai aur devirtualisation enable karta hai.

## 5. Practice Task

Ek chhota payments domain model karo:

- `abstract class PaymentMethod` ek abstract `Pay(decimal amount)` aur ek **non-virtual** `Validate()` ke saath jo ek `protected abstract bool IsConfigured()` call kare.
- Concrete `CreditCard`, `UpiPayment`, `Wallet`. `CreditCard` me card number encapsulate karo — sirf `Last4` expose karo.
- `interface IRefundable { void Refund(decimal amount); }` sirf `CreditCard` aur `Wallet` implement karein.
- `class PaymentProcessor` with `Process(PaymentMethod method, decimal amount)` jo kaise pay karna hai ye decide karne ke liye concrete types par `switch`/`is`-check **na** kare — polymorphism use kare. Ek optional auto-refund path ke liye `is IRefundable` capability check use kar sakta hai.
- Dikhao ki chautha method (`NetBanking`) add karne se `PaymentProcessor` me koi change nahi chahiye.
