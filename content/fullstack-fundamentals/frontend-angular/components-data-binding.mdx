## 1. Concept Overview

Angular app ek **component tree** hai. Har component ek class hai jise `@Component` se decorate karte hain — usme `selector` (jo tag tum HTML me likhte ho), `template` (markup) aur optional `styles` hote hain. Class state aur methods rakhti hai; template us state ko render karta hai aur user interaction wire karta hai.

Class aur template ke beech ka glue hai **data binding**, aur iske exactly 4 types hain:

- **Interpolation** — `{{ expr }}` class ki value ko text me daalta hai.
- **Property binding** — `[prop]="expr"` DOM property ya component input set karta hai.
- **Event binding** — `(event)="handler()"` DOM ya component event par method chalata hai.
- **Two-way binding** — `[(ngModel)]="field"` ek hi jagah property + event binding hai, form field aur class field ko mirror rakhta hai.

Har binding me data ka **direction** samajhna hi asli baat hai: interpolation aur property binding class se view; event binding view se class; two-way dono taraf.

## 2. Core Syntax

```ts
import { Component } from '@angular/core';

@Component({
  selector: 'app-greeting',
  standalone: true,
  template: `
    <!-- interpolation: value into text -->
    <h2>Hello, {{ name }}</h2>

    <!-- property binding: bind to the DOM 'disabled' property -->
    <button [disabled]="isBusy">Save</button>

    <!-- class + style binding are property binding variants -->
    <p [class.error]="hasError" [style.color]="hasError ? 'red' : 'green'">Status</p>

    <!-- event binding: method runs on click, $event is the DOM event -->
    <button (click)="onSave($event)">Save now</button>

    <!-- attribute binding for real HTML attributes (no matching DOM property) -->
    <td [attr.colspan]="span">cell</td>
  `,
})
export class GreetingComponent {
  name = 'Asha';
  isBusy = false;
  hasError = false;
  span = 2;

  onSave(e: Event) {
    this.isBusy = true;
  }
}
```

Interview me ye distinctions bol dena:

- `[prop]="x"` **property** se bind hota hai; `attr.x` **attribute** se. `colspan`, `aria-*`, SVG jaise cases me farak padta hai.
- `{{ x }}` basically text node par `[textContent]` ka shorthand hai — direction property binding jaisa.
- Template expressions **side-effect free aur fast** hone chahiye — har change detection pass par chalte hain.

## 3. Working Example

Ek counter jo chaaro binding types use karta hai.

```ts
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';

@Component({
  selector: 'app-counter',
  standalone: true,
  imports: [FormsModule], // needed for [(ngModel)]
  template: `
    <label>Step: <input type="number" [(ngModel)]="step" /></label>

    <p [class.negative]="count < 0">Count: {{ count }}</p>

    <button (click)="change(-step)" [disabled]="count - step < min">-</button>
    <button (click)="change(step)">+</button>

    <p>{{ count === 0 ? 'at zero' : (count > 0 ? 'positive' : 'negative') }}</p>
  `,
  styles: [`.negative { color: crimson; }`],
})
export class CounterComponent {
  count = 0;
  step = 1;
  min = -10;

  change(delta: number) {
    this.count += delta;
  }
}
```

- `[(ngModel)]="step"` input aur `this.step` ko dono taraf sync rakhta hai.
- `(click)="change(step)"` user action ko class tak wapas bhejta hai.
- `{{ count }}` aur `[class.negative]` class state ko view me push karte hain.
- `[disabled]` ek computed boolean bind karta hai — koi method call nahi chahiye.

## 4. Common Mistakes / Interview Traps

- **`[]`, `()` aur `[()]` me confuse hona.** `[]` = input/one-way to view, `()` = output/event to class, `[()]` = dono. `[(x)]` tabhi chalega jab matching `x` input aur `xChange` output ho (yahi "banana in a box" contract hai).
- **Template me derived value ke liye function call karna.** `{{ getTotal() }}` har change detection tick par re-run hota hai. Field, sasta getter, pipe, ya signal/`computed` use karo.
- **`FormsModule` (ya `ReactiveFormsModule`) import bhoolna** — phir `[(ngModel)]` chupchaap kuch nahi karta ya template error deta hai.
- **Non-string property ke liye interpolation.** `{{ }}` stringify karta hai. Boolean, real number DOM property, ya object ke liye `[prop]` use karo.
- **Template expression me state mutate karna** (`{{ items.push(x) }}`). Expressions me side effect nahi hone chahiye; dev mode me Angular `ExpressionChangedAfterItHasBeenCheckedError` throw kar sakta hai.
- **`[attr.disabled]` vs `[disabled]`.** `[disabled]="false"` attribute sahi se hata deta hai; `[attr.disabled]="false"` kabhi `disabled=""` chhod sakta hai.

## 5. Practice Task

Ek `TemperatureCardComponent` banao (standalone):

- Ek class field `celsius: number` (abhi ke liye parent me class edit karke set kar do — agle topic me isse `@Input` banaoge).
- Celsius value interpolation se dikhao, aur ek **computed Fahrenheit** getter se.
- **Class binding** use karke `celsius <= 0` par `is-freezing` class lagao aur `celsius >= 35` par `is-hot` class.
- Ek button jiska **click** `unit` field ko `'C'` aur `'F'` ke beech toggle kare; interpolation me ternary se current unit ka temperature dikhao.
- Ek number `<input>` **two-way binding** ke saath `celsius` se joda hua, taaki card live drive ho.

Koi `@Output` nahi, koi service nahi, signals bhi zaroori nahi. Har template expression side-effect free rakhna.

3. `[something]` ke bajaye `[attr.something]` kab use karoge?
