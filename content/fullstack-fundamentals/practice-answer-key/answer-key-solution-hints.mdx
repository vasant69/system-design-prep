## Module 1 — Angular / Frontend

### 1. Components, Templates & Data Binding — TemperatureCardComponent

- `celsius` ek plain field; `get fahrenheit() { return this.celsius * 9 / 5 + 32; }`.
- Template: `{{ celsius }}` aur `{{ fahrenheit }}` interpolation se; `[class.is-freezing]="celsius <= 0"` aur `[class.is-hot]="celsius >= 35"`.
- Unit toggle: `unit: 'C' | 'F' = 'C'`; button `(click)="unit = unit === 'C' ? 'F' : 'C'"`.
- Displayed value: `{{ unit === 'C' ? celsius : fahrenheit }} °{{ unit }}`.
- Two-way: `<input type="number" [(ngModel)]="celsius" />` — `FormsModule` import karna mat bhoolna.
- Trap: `fahrenheit` ko getter rakho, method `{{ toF() }}` mat banao (har CD tick par chalega).

### 2. Component Communication — ProductCardComponent + CatalogComponent

- Child: `@Input({ required: true }) product`, `@Input() disabled = false`, `@Output() addToCart = new EventEmitter<string>()`.
- Button: `<button *ngIf="!disabled" (click)="addToCart.emit(product.id)">Add</button>`.
- Parent: `*ngFor="let p of products"` par `[product]="p"` aur `(addToCart)="cart.push($event)"`; count `{{ cart.length }}`.
- Trap: child me `product.xxx = ...` mat karo — sirf emit. State ka owner parent hai.

### 3. Services & Dependency Injection — LoggerService + CartService

- `LoggerService`: `log(msg) { console.log(new Date().toISOString() + ' ' + msg); }`, `@Injectable({ providedIn: 'root' })`.
- `CartService`: `constructor(private logger: LoggerService) {}`; `add/remove/total` har mutation par `this.logger.log(...)`.
- Do siblings dono `inject(CartService)` — same singleton, same data.
- Doosra part: `CartService` ko ek component ke `providers: [CartService]` me daalte hi wo component (aur uske children) ko apna alag instance milta hai — ab dusra sibling use nahi dekhta. Reason: injector hierarchy — component provider root wale ko shadow karta hai.

### 4. RxJS & Observables — search pipeline

- `fromEvent(input, 'keyup').pipe(map(e => (e.target as HTMLInputElement).value), map(v => v.trim()), debounceTime(300), distinctUntilChanged(), switchMap(term => searchApi(term)))`.
- `searchApi = (t: string) => of(['result for ' + t]).pipe(delay(200))`.
- Teardown: `private destroy$ = new Subject<void>()`; pipeline me `takeUntil(this.destroy$)`; `ngOnDestroy() { this.destroy$.next(); this.destroy$.complete(); }`. Ya `takeUntilDestroyed()`.
- `switchMap` vs `mergeMap`: tez type karne par `switchMap` har naye term par pichhli in-flight `searchApi` call cancel kar deta hai, isliye sirf aakhri term ka result aata hai — order guaranteed. `mergeMap` sab chalne deta, slow purani response nayi ko overwrite kar sakti.

### 5. Routing & Navigation

- Routes: `{ path: 'users', component: UserListComponent }`, `{ path: 'users/:id', component: UserDetailComponent }`, `{ path: 'admin', canActivate: [authGuard], loadChildren: () => import('./admin/routes').then(m => m.ADMIN) }`, `{ path: '**', component: NotFoundComponent }` (last).
- `authGuard: CanActivateFn = (r, state) => { const router = inject(Router); return localStorage.getItem('token') ? true : router.createUrlTree(['/login'], { queryParams: { redirect: state.url } }); }`.
- Detail component: `route.paramMap.pipe(map(p => p.get('id')), tap(id => console.log('id', id)), switchMap(id => api.get(id)))` + `route.queryParamMap` for `tab`.
- Trap: `snapshot.paramMap` mat use karo yahan — `/users/1` -> `/users/2` par component reuse hota hai, snapshot stale rahega.

### 6. Forms — template-driven vs reactive

- Reactive: `fb.group({ name: ['', [Validators.required, Validators.minLength(3)]], email: ['', [Validators.required, Validators.email]], age: [null, [Validators.required, Validators.min(18)]] })`.
- Template-driven: `<input name="name" [(ngModel)]="m.name" required minlength="3" #name="ngModel">` + `*ngIf="name.touched && name.errors"`.
- Error visibility: `control.touched && control.invalid` — fresh form laal na ho.
- Submit disabled: `[disabled]="form.invalid"` / `[disabled]="f.invalid"`.
- Do reasons reactive easier: (a) validation pure functions + synchronous state -> `TestBed` ke bina `form.setValue(...)` karke `form.valid` assert; (b) dynamic fields / cross-field validators (`FormArray`, group validator) class me clean hote hain.

### 7. Change Detection & Lifecycle Hooks — ClockComponent (OnPush)

- Time source: `time = signal(new Date()); setInterval(() => this.time.set(new Date()), 1000)` — signal read template me OnPush ko auto-update karta hai. Ya `interval(1000).pipe(map(() => new Date()))` + `async` pipe.
- Log hooks: `ngOnChanges`, `ngOnInit`, `ngDoCheck`, `ngAfterViewInit`, `ngOnDestroy` — `console.log` each.
- Parent 3s baad `label` badle -> `ngOnChanges` (label) + `ngDoCheck` + `ngAfterViewChecked` fire; `ngOnInit`/`ngAfterViewInit` dubara nahi.
- Answer: plain `setInterval` jo `this.now = new Date()` kare, **OnPush ke under UI update nahi karega** — Angular us mutation ko watch nahi kar raha; `markForCheck()`, signal, ya `async` pipe chahiye.
- Trap: `ngOnDestroy` me `clearInterval` — warna leak.

### 8. State Management — TodoStore (no NgRx)

- `private _todos = signal<Todo[]>([])`; `todos = this._todos.asReadonly()`; `remaining = computed(() => this._todos().filter(t => !t.done).length)`.
- `addTodo`: `this._todos.update(list => [...list, newTodo])`; `toggleTodo`: `.update(list => list.map(t => t.id === id ? { ...t, done: !t.done } : t))`; `removeTodo`: `.update(list => list.filter(t => t.id !== id))` — sab immutable.
- Migration paragraph: NgRx tab jab (a) team badi ho aur ek enforced pattern chahiye, (b) kai features same state share karein, (c) "kisne kab badla" debug karna recurring ho. NgRx adds: devtools time-travel/replay, ek strict action log, memoized selectors, aur side-effects ka ek consistent ghar (effects). Cost: boilerplate + indirection.

## Module 2 — JavaScript / TypeScript Core

### 1. Closures & Scope — createRateLimiter(maxCalls, windowMs)

- `function createRateLimiter(maxCalls, windowMs) { const hits = []; return function attempt() { const now = Date.now(); while (hits.length && now - hits[0] >= windowMs) hits.shift(); if (hits.length < maxCalls) { hits.push(now); return true; } return false; }; }`.
- `hits` sirf closure me — koi property, koi global nahi.
- Prune: har call par window ke bahar wali purani timestamps `shift()` se hatao (unbounded growth rokna).
- Check: `const rl = createRateLimiter(3, 1000)` -> `rl(), rl(), rl()` = `true`, chautha `false`; ~1s baad phir `true`.

### 2. "this" Keyword & Binding — greet call sites

- `'A'`: `obj.greet()` — implicit binding (dot ke left `obj`).
- `undefined`: `const g = obj.greet; g();` — default binding (strict mode `this` = undefined).
- `'B'`: `obj.greet.call({ name: 'B' })` (ya `.apply`).
- `'C'` permanent: `const c = obj.greet.bind({ name: 'C' }); c(); c.call({ name: 'Z' });` -> dono `'hi C'` (bind override nahi hota).
- `setTimeout(obj.greet, 0)` fix: (a) `setTimeout(obj.greet.bind(obj), 0)`; (b) `setTimeout(() => obj.greet(), 0)` — arrow wrapper implicit call rakhta hai.

### 3. Hoisting — predict + rewrite

- Output: line 1 `undefined` (`var p` hoisted, assign baad me). Line 2 `"function"` (`function q` fully hoisted). Line 3 `ReferenceError: Cannot access 'r' before initialization` (`let r` TDZ) — script yahin ruk jaata hai.
- Rules: `var` = hoisted as `undefined`; function declaration = name + body hoisted; `let` = hoisted but uninitialised (TDZ).
- Rewrite: sab `const`/`let`, use se pehle declare: `const q = () => {}; const p = 'P'; const r = 'R'; console.log(p, typeof q, r);` — koi hoisting surprise nahi.

### 4. Prototypes & Inheritance — Queue + PriorityQueue

- Class version: `class Queue { #items = []; enqueue(x){...} dequeue(){...} get size(){...} }`; `class PriorityQueue extends Queue` — `enqueue(x, p)` sorted insert; `super`/`extends` chain.
- Constructor-fn version: `function Queue(){ this.items = []; }` + methods on `Queue.prototype`; `function PriorityQueue(){ Queue.call(this); }`; `PriorityQueue.prototype = Object.create(Queue.prototype)`; `PriorityQueue.prototype.constructor = PriorityQueue;`.
- Verify: `pq instanceof Queue === true`, `pq.constructor === PriorityQueue` (isiliye `constructor` wapas set karna zaroori tha), aur `items`/`#items` per-instance banti hai (constructor me) — do instances share nahi karte.
- Trap: array ko `Queue.prototype.items` par mat rakho — shared ho jaayega.

### 5. Event Loop — predict + move a line

- Output: `start`, `end`, `promise1`, `microtask1`, `async1`, `promise2`, `timeout1`.
- Key: sync pehle (`start`, `end`). Phir microtasks FIFO: `promise1` callback. Uska `return Promise.resolve()` ek thenable return karta hai -> `.then(promise2)` ko **extra microtask ticks** wait karna padta hai, isliye `promise2` apni "jagah" `microtask1` aur `async1` ko de deta hai. Phir macrotask `timeout1`.
- Extra `setTimeout(() => console.log('X'), 0)` ko snippet me pehle wale `setTimeout` ke baad rakho -> `X` `timeout1` ke turant baad. `Promise.then` ko `timeout1` ke baad nahi la sakte kyunki saari microtasks kisi bhi macrotask (timer) se pehle drain hoti hain.

### 6. Promises & Async/Await — fetchWithRetry

- `async function fetchWithRetry(fn, retries, delayMs) { let lastErr; for (let i = 1; i <= retries; i++) { try { return await Promise.race([fn(), timeout(perTryMs)]); } catch (e) { lastErr = e; if (i < retries) await delay(delayMs * 2 ** (i - 1)); } } throw lastErr; }`.
- `timeout = ms => new Promise((_, rej) => setTimeout(() => rej(new Error('timeout')), ms))`.
- `delay = ms => new Promise(r => setTimeout(r, ms))`.
- Demo `fn`: closure counter, pehli 2 calls `Promise.reject`, teesri `Promise.resolve('ok')` -> wrapper `'ok'` deta hai.
- Trap: last error rethrow karo, retries loop ke andar swallow mat karo.

### 7. TypeScript Essentials — `Result<T>`, unwrap, `Repository<T>`

- `type Result<T> = { ok: true; value: T } | { ok: false; error: string };`.
- `function unwrap<T>(r: Result<T>): T { if (r.ok) return r.value; throw new Error(r.error); }` — `if (r.ok)` discriminant narrow karta hai, koi `as`/`!` nahi.
- `interface Repository<T> { getById(id: string): Promise<T | null>; getAll(): Promise<T[]>; save(entity: T): Promise<void>; }`; in-memory impl: ek `Map<string, User>` par.
- `mapResult<T, U>(r, fn): Result<U>` -> `r.ok ? { ok: true, value: fn(r.value) } : r`.
- `type` vs `interface`: `Result` ek union hai -> `type` (interface union nahi kar sakta). `Repository` ek object contract hai jise classes `implements` karengi -> `interface` (aur declaration merging possible).

## Module 3 — .NET Core / C# Backend

### 1. OOP in C# — payments domain

- `abstract class PaymentMethod { public abstract void Pay(decimal amount); public void Validate() { if (!IsConfigured()) throw new InvalidOperationException(); } protected abstract bool IsConfigured(); }`.
- `CreditCard`: `private readonly string _number;` + `public string Last4 => _number[^4..];` — number bahar expose nahi.
- `interface IRefundable { void Refund(decimal amount); }` -> `CreditCard`, `Wallet` implement; `UpiPayment` nahi.
- `PaymentProcessor.Process(PaymentMethod m, decimal amt)`: `m.Validate(); m.Pay(amt);` + optional `if (m is IRefundable r && condition) r.Refund(...)`. Koi `if (m is CreditCard)` branch nahi.
- `NetBanking : PaymentMethod` add karo -> `PaymentProcessor` unchanged (yahi open/closed ka proof).

### 2. DI & Service Lifetimes

- `AddSingleton<IClock, SystemClock>()`, `AddScoped<IRequestContext, RequestContext>()` (`RequestId = Guid.NewGuid()` in ctor), `AddTransient<IEmailSender, ...>()`.
- Controller + ek doosri service dono me teeno inject; `GetHashCode()` / `RequestId` log.
- Do requests: `IClock` hash dono requests me same; `IRequestContext.RequestId` per request alag par ek request ke andar (controller + service) same; `IEmailSender` har injection point par naya.
- Captive dependency: Scoped `IRequestContext` ko Singleton `IClock` me inject karo -> `IClock` use hamesha ke liye hold kar leta hai, ek hi `RequestId` sab requests ke liye. ASP.NET Core Development me `ValidateScopes` startup par ise exception deta hai.

### 3. Web API Design — ProductsController

- Endpoints: `GET` (list, by id), `POST` (201 + `CreatedAtAction`), `PUT` (204/404), `DELETE` (204/404).
- `record ProductDto(...)` read; `record CreateProductRequest(...)` write with `[Required]`/`[Range]`. Entity kabhi return/accept mat karo.
- AutoMapper `Profile`: `CreateMap<Product, ProductDto>()`, `CreateMap<CreateProductRequest, Product>()`; `AddAutoMapper(...)` in `Program.cs`.
- Middleware: `Stopwatch` around `await next(ctx)`, phir `logger.LogInformation("{Method} {Path} {Status} {Ms}", ...)`.
- `[ApiController]` invalid model par automatic `400` — manual `ModelState` check ki zaroorat nahi.
- `Program.cs` order: `UseExceptionHandler` -> `UseHttpsRedirection` -> custom middleware -> `UseAuthentication` -> `UseAuthorization` -> `MapControllers`. `UseAuthentication` pehle kyunki `UseAuthorization` ko populated `HttpContext.User` chahiye.

### 4. EF Core Basics — Author / Book

- `class LibraryContext : DbContext { DbSet<Author> Authors; DbSet<Book> Books; }`; `OnModelCreating` me `HasOne(b => b.Author).WithMany(a => a.Books).HasForeignKey(b => b.AuthorId)`.
- `dotnet ef migrations add InitialCreate` -> `dotnet ef database update`.
- Queries:
  - `db.Books.Where(b => b.AuthorId == id).OrderByDescending(b => b.Year).ToListAsync()`.
  - `db.Authors.Where(a => a.Books.Count > 3).Select(a => a.Name).ToListAsync()`.
  - `db.Books.Select(b => new BookListItemDto(b.Title, b.Author.Name)).ToListAsync()` — projection, no full entity.
- N+1: `db.Authors.ToListAsync()` phir loop me `a.Books` access = 1 + N. Fix: `.Include(a => a.Books)` ya projection.
- `AsNoTracking()` teeno read-only queries par — snapshot overhead bachao.

### 5. Async Programming — ReportService + fix 3 pitfalls

- `GenerateAsync`: `using var gate = new SemaphoreSlim(4);` -> `var tasks = ids.Select(async id => { await gate.WaitAsync(ct); try { return await FetchAsync(id, ct); } finally { gate.Release(); } });` -> `return await Task.WhenAll(tasks);`.
- Pitfall 1: `async void Handle` -> `async Task Handle` (caller await/observe kar sake, exceptions capture hon).
- Pitfall 2: `GetReport(id).Result` -> `await GetReport(id)` inside a proper async loop / `Task.WhenAll` (sync-over-async = thread-pool starvation / deadlock).
- Pitfall 3: `GetReport` ko `CancellationToken` accept karke `GetFromJsonAsync<Report>(url, ct)` me pass karo; library-style code me `ConfigureAwait(false)` bhi.

### 6. JWT Authentication — /auth/login + protected route

- `POST /auth/login` (`[AllowAnonymous]`): user dhundo, `PasswordHasher.Verify(plain, storedHash)` (PBKDF2/bcrypt, constant-time); fail -> `Unauthorized` with generic message.
- Token: claims `sub` (user id), `name`, `ClaimTypes.Role`, `exp = UtcNow.AddMinutes(15)`; `SigningCredentials(new SymmetricSecurityKey(keyBytes), HmacSha256)`.
- `AddAuthentication(JwtBearerDefaults...).AddJwtBearer(o => o.TokenValidationParameters = new { ValidateIssuer/Audience/Lifetime/IssuerSigningKey = true, ... })`. Pipeline: `UseAuthentication()` phir `UseAuthorization()`.
- `[Authorize(Roles = "admin")]` on `GET /admin/stats`.
- Payload me kabhi nahi: password/hash, full PAN/card number, internal flags/secrets — kyunki payload sirf base64url hai, koi bhi decode kar sakta hai. Logout: stateless JWT server-side invalidate nahi hota; client token discard kare, aur instant revoke chahiye to short expiry + DB-backed refresh token (revoke/rotate) ya jti deny-list.
