## 1. Concept Overview

**Scope** ye batata hai ki "ye line kaunse variables dekh sakti hai?". JavaScript **lexical scope** use karta hai: jawab is baat se tay hota hai ki *code kahan likha hai*, kahan call hua isse nahi. Ek inner function apne khud ke variables dekhta hai, phir parent ke, phir parent ke parent ke, upar global scope tak — yahi **scope chain** hai. `let` aur `const` block-scoped hain (`{ }`); `var` function-scoped hai.

**Closure** tab banta hai jab koi function apne outer scope ke variable ko reference karta hai. Function us variable ko "close over" karta hai, ek live reference rakhta hai (copy nahi). Toh agar tum ek function ke andar function bana kar return karo, wo returned function ab bhi outer function ke locals dekhta hai — aur unhe badal bhi sakta hai — chahe wo outer call khatam ho chuka ho aur uska stack frame ja chuka ho.

Closures se JavaScript private state, function factories, memoization, once-only functions, aur module pattern banata hai.

## 2. Core Syntax

```js
// lexical scope: `secret` is visible to inner because inner is written inside outer
function outer() {
  const secret = 42;
  function inner() { return secret; }   // closes over `secret`
  return inner;
}
const f = outer();   // outer() has returned...
f();                  // ...but f still returns 42

// closure captures a REFERENCE, not a snapshot
function makeCounter() {
  let count = 0;
  return {
    inc() { return ++count; },   // shared `count`
    get() { return count; },
  };
}
const c = makeCounter();
c.inc();      // 1
c.inc();      // 2  -> same captured variable

// each call to the factory gets a fresh scope
const c2 = makeCounter();
c2.inc();     // 1  -> independent of c
```

```js
// the classic loop trap
const fns = [];
for (var i = 0; i < 3; i++) fns.push(() => i);
fns.map(fn => fn());        // [3, 3, 3] — one shared `i`, ended at 3

for (let j = 0; j < 3; j++) fns.push(() => j);
// with `let`, each iteration has its own binding -> 0, 1, 2
```

## 3. Working Example

Ek rate limiter jiska state closure se poora private hai.

```js
function createOncePerInterval(fn, intervalMs) {
  let lastRun = 0;                       // private — no way to reach it from outside

  return function (...args) {
    const now = Date.now();
    if (now - lastRun < intervalMs) {
      return { skipped: true };
    }
    lastRun = now;
    return { skipped: false, value: fn(...args) };
  };
}

const save = createOncePerInterval((doc) => `saved ${doc}`, 1000);

save('a');   // { skipped: false, value: 'saved a' }
save('b');   // { skipped: true }        -> within 1s
// ...1s later...
save('c');   // { skipped: false, value: 'saved c' }
```

`lastRun` sirf closure me rehta hai. Koi property nahi, koi global nahi, chhedne ke liye kuch nahi — use affect karne ka ek hi tareeka hai: returned function ko call karo. `createOncePerInterval` ka har call ek independent limiter banata hai.

## 4. Common Mistakes / Interview Traps

- **"Closures value copy karti hain."** Wo variable ka **reference** capture karti hain. Agar variable baad me badle, closure nayi value dekhta hai (yahi `var` wala loop bug hai).
- **`var` loops me async callbacks ke saath.** Sab callbacks ek `i` share karte hain. `let` se fix, ya per iteration ek IIFE.
- **Sochna ki outer function ke variables return hote hi garbage-collect ho jaate hain.** Wo tab tak zinda rehte hain jab tak koi closure unhe reference karta hai — isi se closures memory leak bhi kar sakti hain (ek long-lived listener jo bade object ko close over kare).
- **Scope ko `this` se confuse karna.** Scope variable lookup ke baare me hai aur lexical hai; `this` call site ke baare me hai aur dynamic hai. Arrow functions `this` lexically inherit karte hain par `arguments` ke liye naya variable scope nahi banate.
- **`var` ke liye block scope maan lena.** `if` ya `for` ke andar ka `var` poore function me leak hota hai.
- **Same block me `let` se re-declare karna** -> `SyntaxError`; inner block me shadowing theek hai.

## 5. Practice Task

`createRateLimiter(maxCalls, windowMs)` likho jo ek function `attempt()` return kare:

- `attempt()` `true` return kare agar call allowed hai — matlab last `windowMs` milliseconds me `maxCalls` se kam calls hui hain — warna `false`.
- Call timestamps closure me **private** state me track karo: returned function par koi property nahi, koi module-level ya global variable nahi.
- Window ke bahar wali purani timestamps prune ho jayein taaki memory unbounded na badhe.
- `maxCalls = 3`, `windowMs = 1000` ke saath demonstrate karo: teen quick calls `true` return karein, chauthi `false`, aur window ke baad ek call phir `true`.
