## 1. Concept Overview

Scope run karne se pehle engine use scan karta hai aur har declaration register kar leta hai. Yahi **hoisting** hai — par "hoisted" ka matlab kind ke hisaab se alag hai:

- **Function declarations** (`function foo() {}`) — naam *aur body* scope ke top se available. `foo()` ko uski line se pehle call kar sakte ho.
- **`var`** — naam register hota hai aur top se `undefined` set. Assignment line se pehle read karne par `undefined` milta hai, error nahi.
- **`let` / `const` / `class`** — naam register hota hai par **uninitialised** rehta hai. Declaration line se pehle koi bhi access `ReferenceError` throw karta hai. Ye gap **temporal dead zone (TDZ)** hai.
- **Function expressions / arrow functions** — sirf variable hoist hota hai (`var`/`let` rules ke hisaab se); function value runtime par assign hoti hai, isliye jaldi call karna fail karta hai.

Mental model: declarations "upar move ho jaati hain", initialisations wahin rehti hain. `let`/`const` bhi hoisted hain — TDZ iska proof hai, kyunki ek sach me absent naam to outer scopes me dekhta, throw nahi karta.

## 2. Core Syntax

```js
// function declaration: callable before definition
sayHi();                    // "hi"  -> body is hoisted
function sayHi() { console.log('hi'); }

// var: hoisted as undefined
console.log(x);             // undefined  (NOT ReferenceError)
var x = 10;
console.log(x);             // 10

// let / const: TDZ
console.log(y);             // ReferenceError: Cannot access 'y' before initialization
let y = 5;

// typeof does not save you inside the TDZ
console.log(typeof z);      // ReferenceError
let z = 1;
console.log(typeof undeclared);  // "undefined"  -> truly undeclared name is fine

// function expression: only the variable is hoisted
greet();                    // TypeError: greet is not a function
var greet = function () { console.log('hey'); };
```

```js
// declaration order: function declarations win over var of the same name
console.log(typeof thing);  // "function"
var thing = 1;
function thing() {}
```

## 3. Working Example

Output predict karna — bilkul wahi cheez jo interviewer whiteboard par likhta hai.

```js
function demo() {
  console.log(a);          // undefined      -> var a hoisted, not yet assigned
  console.log(typeof b);   // "function"     -> function declaration fully hoisted
  // console.log(c);       // would throw    -> c is in the TDZ

  var a = 1;
  function b() {}
  let c = 3;

  console.log(a, typeof b, c);   // 1 "function" 3
}
demo();
```

Aise rewrite kiya ki intent obvious ho (hoisting par bharosa nahi):

```js
function demo() {
  let a = 1;
  const b = () => {};
  let c = 3;
  console.log(a, typeof b, c);   // 1 "function" 3
}
```

`let`/`const` use karke aur use se pehle declare karke har surprise hat jaata hai: pehla version teen alag hoisting rules jaanne par depend karta hai, doosra top se bottom padha jaata hai.

## 4. Common Mistakes / Interview Traps

- **"`let` aur `const` hoisted nahi hain."** Hain — TDZ sirf isliye exist karta hai kyunki binding jaldi ban jaati hai par uninitialised chhod di jaati hai. Agar hoist na hoti to lookup outer scope me fall through kar jaata.
- **TDZ me `typeof` ko safe maan lena.** `typeof x` throw karta hai agar `x` ek `let`/`const` hai apni line se pehle. Ye sirf genuinely undeclared identifiers ke liye safe hai.
- **Function expression ko declaration ki tarah jaldi callable maan lena.** Sirf `var greet`/`let greet` hoist hota hai; function runtime par assign hota hai.
- **Block me `var`** poore function me leak karta hai, isliye loop ka `var i` loop ke baad bhi visible (aur shared) hai.
- **Blocks ke aar-paar function-declaration hoisting par bharosa.** `if` block ke andar declare `function` strict mode / modules me reliably function top tak hoist nahi hota.
- **Same scope me `let` re-declare karna** -> parse time par `SyntaxError`, kuch chalne se pehle.
