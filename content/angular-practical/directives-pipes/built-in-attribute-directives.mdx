<SimpleDefinition>

An attribute directive changes an existing element's look or behaviour without adding or removing it from the DOM (that is a structural directive's job). Angular ships `ngClass` and `ngStyle` for applying several classes or inline styles from an object or expression, alongside the plain `[class.name]` and `[style.prop]` bindings that handle most simple cases.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Angular me 3 tarah ki directives hoti hain:

1. **Components** — directive with a template (jo humne ab tak dekha).
2. **Attribute directives** — existing element ka look/behaviour badalti hain (`ngClass`, `ngStyle`, custom `appHighlight`).
3. **Structural directives** — DOM add/remove karti hain (`*ngIf`, `*ngFor` — ab `@if`/`@for` blocks ne inhe replace kiya).

Is topic me attribute directives — khaaskar classes aur styles conditionally lagana.

### The simple way — `[class.x]` and `[style.prop]`

```html
<span [class.active]="employee.isActive">{{ status }}</span>
<span [class.text-danger]="employee.leaveBalance < 0">{{ employee.leaveBalance }}</span>
<div [style.width.px]="progress">...</div>
<div [style.color]="employee.isActive ? 'green' : 'grey'">...</div>
```

- `[class.active]="expr"` — `active` class tab lagti hai jab `expr` truthy.
- `[style.width.px]="progress"` — `width: <progress>px`. Unit template me hi (`.px`, `.%`, `.em`).
- Ye Angular ke core bindings hain, **koi import nahi** chahiye.

### `ngClass` — kai classes ek saath (object/array)

```html
<span [ngClass]="{
  'badge': true,
  'badge-green': employee.status === 'active',
  'badge-amber': employee.status === 'on-leave',
  'badge-grey': employee.status === 'inactive'
}">{{ employee.status }}</span>
```

Ya array / string:

```html
<div [ngClass]="['card', isSelected ? 'card-selected' : '']">...</div>
```

`ngClass` `CommonModule` (ya `NgClass`) se aata hai — component ke `imports` me chahiye.

### `ngStyle` — kai inline styles ek object se

```html
<div [ngStyle]="{
  'background-color': employee.isActive ? '#e6ffed' : '#f0f0f0',
  'opacity': employee.isActive ? 1 : 0.6
}">...</div>
```

### Why do we need it — kyun

Conditional styling har UI me hai — active/inactive rows, valid/invalid fields, selected items, progress bars. Bina directive ke aap `element.classList.add/remove` khud karte, jo imperative aur bug-prone. Ye bindings declarative hain — condition template me dikhti hai.

### `[class.x]` vs `ngClass` — kaunsa kab

- 1–3 conditional classes -> `[class.x]` (no import, simple, fast).
- Bahut si classes ek object/map se, ya class list dynamic -> `ngClass`.
- **Dono ek element pe** mix kar sakte ho, par avoid — confusing.

### Show it in our project

`EmployeeRow`:

```html
<tr [class.row-inactive]="!employee().isActive"
    [class.row-selected]="selected()">
  <td>{{ employee().firstName }}</td>
  <td>
    <span class="badge" [ngClass]="statusClass()">{{ employee().status }}</span>
  </td>
</tr>
```

```ts
statusClass = computed(() => ({
  "badge-green": this.employee().status === "active",
  "badge-amber": this.employee().status === "on-leave",
  "badge-grey": this.employee().status === "inactive",
}));
```

`computed()` se object sirf tab banta hai jab `employee` badle — OnPush friendly.

### Where is it used in day-to-day development

Table rows, form field error states, selected cards, nav active links, progress/meter bars, disabled-look elements. Practically har list aur form me kahin na kahin conditional class hai.

### Pros and cons

**Pros**

- Declarative — style condition template me visible.
- `[class.x]` zero-import, minimal.
- `ngClass`/`ngStyle` ek object se bahut si classes/styles ek jagah.

**Cons**

- `ngStyle` inline styles ko encourage karta hai — aksar CSS class behtar (maintainability, theming).
- `[ngClass]="{...}"` template me har CD cycle me naya object -> ideally `computed()`/getter me nikaalo.
- `ngClass` needs `CommonModule` import — bhool jao to silent no-op / error.

</Hinglish>

<Callout type="tip">

Preference order: (1) static `class="..."` jo hamesha lagti hai, (2) `[class.x]="cond"` 1–3 conditionals ke liye, (3) `[ngClass]="obj"` jab genuinely kai classes map karni ho — aur us object ko `computed()` me banao, template me inline nahi.

</Callout>

## Numbers That Matter

<Numbers>

- `[class.x]` aur `[style.prop]` **core template syntax** hain — zero imports, fastest path.
- `ngClass` / `ngStyle` **`CommonModule`** (ya `NgClass`/`NgStyle`) par depend karte hain.
- `[style.width.px]` me unit suffixes supported: `px`, `%`, `em`, `rem`, `pt`, `vh`, etc.
- `ngStyle` object ko har change-detection cycle me diff kiya jaata hai — bade objects sasti nahi, `computed()` me rakho.

</Numbers>

## Interview Angle

<InterviewAngle>

Common: "directive types kitne?", "attribute vs structural directive?", "`ngClass` aur `[class.x]` me farak?", "`ngStyle` vs CSS class?".

Strong answer:

1. Teen types: component (with template), attribute (look/behaviour), structural (DOM add/remove).
2. `[class.x]`/`[style.p]` core bindings, no import; `ngClass`/`ngStyle` `CommonModule` se, object/array/string map.
3. `[class.x]` few conditionals; `ngClass` bahut si classes ek map se.
4. `ngStyle` inline styles — prefer CSS classes for theming/maintainability.

Red flag: "`*ngIf` ek attribute directive hai" — nahi, wo structural (DOM add/remove); ab `@if` block.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`[ngClass]="{...}"` object template me inline banana.** Har CD cycle me naya object — OnPush aur perf ke liye bura. `computed()` ya getter me banao.

</Mistake>

<Mistake>

**`ngClass` use karna bina `CommonModule` / `NgClass` import kiye.** Standalone component me silently kaam nahi karega (ya error). `imports` me add karo.

</Mistake>

<Mistake>

**`ngStyle` se poora styling karna.** Inline styles CSS specificity wars, no media queries, no `:hover`, theming hard. Sirf genuinely dynamic values (`width.px` from data) ke liye; baaki classes me.

</Mistake>

<Mistake>

**`[style.width]="progress + 'px'"` vs `[style.width.px]="progress"`.** Dono kaam karte hain par `.px` suffix cleaner — string concat template me avoid.

</Mistake>

<Mistake>

**`class="foo"` aur `[class.foo]="cond"` ek saath same class pe.** Confusing — `[class.foo]` jeetega. Static class chahiye to `class`, conditional chahiye to `[class.foo]`, dono nahi.

</Mistake>

## Quick Revision

<QuickRevision>

- Three directive types: component (has a template), attribute (changes an existing element), structural (adds/removes DOM).
- `[class.name]="cond"` and `[style.prop]="expr"` (with unit suffix like `.px`) — core syntax, no import.
- `[ngClass]="obj|array|string"` and `[ngStyle]="obj"` — from `CommonModule`/`NgClass`/`NgStyle`.
- Prefer static `class`, then `[class.x]` for a few conditionals, then `ngClass` for many.
- Build the `ngClass`/`ngStyle` object in a `computed()` / getter, not inline in the template.
- Prefer CSS classes over `ngStyle`; use inline style only for genuinely dynamic values.
- `*ngIf`/`*ngFor` were structural, now replaced by `@if`/`@for` blocks.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `EmployeeRow` ke `<tr>` par `[class.row-inactive]="!employee.isActive"` lagao aur CSS me `.row-inactive { opacity: 0.5; }`. Ek employee ko inactive karke dekho row dim ho jaati hai.

**Medium:** Status badge banao `[ngClass]` se: `active` -> green, `on-leave` -> amber, `inactive` -> grey. `ngClass` object ko pehle template me inline likho, phir ek `computed()` `statusClass` me move karo. Behaviour same, par socho kyun `computed()` behtar (OnPush + naya object har cycle).

**Bada:** Ek progress bar banao `[style.width.%]="percent()"` se jahan `percent` ek signal hai. Ek button se `percent` 0 se 100 tak animate karo (`setInterval`). Phir wahi bar `ngStyle` se banao (`{ width: percent() + '%' }`) aur teesra `[style.width.px]` fixed container me. Teenon approaches ke pros/cons 4 line me likho (units, readability, CD cost).

</Callout>
