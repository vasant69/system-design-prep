<SimpleDefinition>

An Angular component is a plain TypeScript class (holding state and methods) plus an `@Component` decorator that carries metadata about how Angular should use it: the `selector`, the `template`/`templateUrl`, the `styles`/`styleUrl`, the `imports` it needs, and options like `changeDetection`, `encapsulation`, and `host`. Learning the metadata fields is learning most of what a component "is".

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Pichhle topic me humne pehla component banaya. Ab uski **anatomy** — har field jo `@Component({...})` me aa sakti hai, aur wo control kya karti hai.

### What is it — component ki poori shape

```ts
import { Component, ChangeDetectionStrategy, ViewEncapsulation } from "@angular/core";
import { DatePipe } from "@angular/common";
import { EmployeeBadge } from "./employee-badge/employee-badge";

@Component({
  selector: "app-employee-card",
  imports: [DatePipe, EmployeeBadge],
  templateUrl: "./employee-card.html",
  styleUrl: "./employee-card.scss",
  changeDetection: ChangeDetectionStrategy.OnPush,
  encapsulation: ViewEncapsulation.Emulated,
  host: { class: "employee-card", "[class.inactive]": "!employee.isActive" },
})
export class EmployeeCard {
  // ---- state ----
  employee = { id: 1, firstName: "Aarav", lastName: "Sharma", isActive: true, joinDate: "2023-04-01" };

  // ---- methods ----
  get fullName(): string {
    return `${this.employee.firstName} ${this.employee.lastName}`;
  }
}
```

### Why do we need to know each field — kyun

Har field ek real decision hai jo aap projects me lete ho:

- `selector` galat prefix -> naming clash / lint error.
- `imports` incomplete -> "not a known element".
- `changeDetection` default (`Default`) vs `OnPush` -> performance ka sabse bada lever.
- `encapsulation` -> aapki CSS leak karegi ya nahi.
- `host` -> component ke apne root element pe class/attribute/listener lagana bina wrapper `<div>` ke.

### How does it work — field by field

**`selector`** — component ka HTML tag. Kebab-case, `app-` prefix. Attribute selector (`selector: "[appHighlight]"`) directives ke liye zyada common.

**`template` / `templateUrl`** — rendered HTML. Ek hi component me dono nahi. Inline chhote ke liye, external bade ke liye.

**`styles` / `styleUrl` / `styleUrls`** — component ke scoped CSS. Array of strings ya file path(s).

**`imports`** — standalone component ki template dependencies: dusre components, directives, pipes, ya NgModules.

**`changeDetection`** — `ChangeDetectionStrategy.Default` (har event pe check) ya `OnPush` (sirf jab `@Input` reference badle, event component se aaye, ya signal badle). Production apps me OnPush recommended — detail change-detection topic me.

**`encapsulation`** —
- `Emulated` (default): Angular CSS selectors me ek unique attribute add karta hai, isliye component ke styles bahar leak nahi karte.
- `None`: styles global ban jaate hain (kabhi-kabhi theme components me).
- `ShadowDom`: real browser Shadow DOM use karta hai (strong isolation, par kuch trade-offs).

**`host`** — component ke root element pe bindings. `host: { class: "employee-card" }` root element pe class add karta hai; `"[class.inactive]": "expr"` conditional class; `"(click)": "onClick()"` listener. Isse aapko extra wrapper `<div>` nahi chahiye.

**`providers`** — component-level DI (naya instance is component + children ke liye). App-wide singleton ke liye use mat karo.

### Show it in our project

EMS me hamare zyadatar components:

```ts
@Component({
  selector: "app-employee-table",
  imports: [EmployeeRow, Paginator],
  templateUrl: "./employee-table.html",
  styleUrl: "./employee-table.scss",
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class EmployeeTable { /* @Input rows, @Output events */ }
```

Default hum OnPush rakhenge (signals + inputs ke saath ye natural fit hai). `host` hum layout components me use karenge (`host: { class: "page" }`).

### Where is it used in day-to-day development

Har naya component: selector auto (CLI), `imports` aap bharte ho jaise template grow karta hai, `changeDetection: OnPush` aap add karte ho (ya CLI schematic se default), `host` aap tab use karte ho jab wrapper div se bachna ho. `encapsulation` aap 95% time chhedte nahi — default theek hai.

### Pros and cons

**Pros (is model ke)**

- Ek consistent shape — har component same jagah dekhna: decorator upar, class neeche.
- Metadata declarative — Angular ko "kaise use karoon" saaf pata.
- `host` se clean DOM (extra wrappers nahi).

**Cons**

- Decorator me bahut options — beginners ko pata nahi kya zaroori kya optional (zyadatar optional).
- `encapsulation` aur `changeDetection` ke effects invisible hote hain jab tak bug na aaye.
- Inline vs external template/style ka choice har baar.

</Hinglish>

Beginner ke liye minimum viable metadata: `selector`, `templateUrl`, `styleUrl`, `imports`. Baaki (`changeDetection`, `host`, `encapsulation`, `providers`) tab add karo jab specific zaroorat ho — aur OnPush jaldi apna lo, wo aadat achhi hai.

</Callout>

## Real World Example

<RealWorld company="Design-system component libraries">

Angular Material jaise libraries har component me `changeDetection: OnPush`, `encapsulation` carefully chosen, aur `host` bindings heavily use karti hain (`mat-button` apne root `<button>` pe classes/ARIA attributes `host` se lagata hai). Wo ek wrapper `<div>` add nahi karte — isse markup clean rehta hai aur CSS predictable. Aapki EMS ki `shared/ui` components isi style ko follow kar sakti hain.

</RealWorld>

## Numbers That Matter

<Numbers>

- `@Component` me roughly **12+ possible metadata fields**, par ek typical component **4–6** use karta hai.
- `OnPush` bade lists me change-detection work ko **10x ya zyada** kam kar sakta hai (kai components skip ho jaate hain).
- Default `encapsulation` (`Emulated`): Angular har component ke elements pe **ek `_ngcontent` attribute** add karta hai — yahi CSS scoping ka mechanism hai.
- `host` binding se saved wrapper elements: ek deeply nested tree me **dozens of `<div>`s** kam ho sakte hain.

</Numbers>

## Interview Angle

<InterviewAngle>

Poochha jaata hai: "`@Component` decorator me kya-kya hota hai?", "`encapsulation` kya karti hai?", "`host` property kis liye?", "`changeDetection: OnPush` ka matlab?".

Strong answer ka shape:

1. Component = class + `@Component` metadata.
2. Core fields: `selector`, `template(Url)`, `style(Url)`, `imports`.
3. `changeDetection` — `Default` vs `OnPush`; OnPush = kam checks, better perf, signals/immutable inputs ke saath.
4. `encapsulation` — `Emulated` (default, scoped via attributes), `None` (global), `ShadowDom` (real shadow DOM).
5. `host` — component ke root element pe class/attr/listener bina wrapper.

Red flag: "encapsulation ka matlab component ko dusre components se hide karna" — nahi, ye sirf CSS scoping hai.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`template` aur `templateUrl` dono dena.** Angular error deta hai — ek hi allowed. Similarly `styles` aur `styleUrl` ek saath sochke rakho.

</Mistake>

<Mistake>

**`encapsulation: ViewEncapsulation.None` casually use karna taaki "CSS kaam kare".** Isse us component ka saara CSS global ban jaata hai aur dusre components ko silently todta hai. Root cause (galat selector, missing import) fix karo, encapsulation mat todo.

</Mistake>

<Mistake>

**Har component ke `providers` me shared service daal dena.** Ye component-scoped instance banata hai — app-wide singleton toot jaata hai. Singleton ke liye `providedIn: "root"`.

</Mistake>

<Mistake>

**`host` binding ki jagah template me wrapper `<div [class]>` add karna sirf ek class ke liye.** Component ke apne root element pe class chahiye to `host: { class: "..." }` cleaner hai — DOM me ek extra div nahi.

</Mistake>

<Mistake>

**OnPush lagana par mutation karte rehna.** OnPush component ka `@Input` object aap mutate karte ho (`this.employee.name = "x"`) to view update nahi hoga — reference badalna padega (`this.employee = { ...this.employee, name: "x" }`) ya signal use karo.

</Mistake>

## Quick Revision

<QuickRevision>

- Component = plain class + `@Component` decorator (metadata).
- Core metadata: `selector`, `template`/`templateUrl`, `styles`/`styleUrl`, `imports`.
- `changeDetection`: `Default` (check every event) vs `OnPush` (check on input ref change / component event / signal change). Prefer OnPush.
- `encapsulation`: `Emulated` (default, CSS scoped via attributes), `None` (global CSS), `ShadowDom` (native isolation).
- `host`: put `class` / `[class.x]` / `(event)` on the component's own root element — no wrapper div.
- `providers` in a component = scoped instance for it + children; not for app-wide singletons.
- Can't set both `template` and `templateUrl`.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Apne `EmployeeCard` component me `host: { class: "employee-card" }` add karo. Browser DevTools me component ka root element inspect karke confirm karo `class="employee-card"` wahan hai — bina koi wrapper div add kiye.

**Medium:** `EmployeeCard` me `changeDetection: ChangeDetectionStrategy.OnPush` set karo. Ek button add karo jo `this.employee.firstName = "Changed"` karta hai (mutation). Click karo — naam update nahi hoga. Ab code badlo `this.employee = { ...this.employee, firstName: "Changed" }` (new reference) — ab update hoga. Dono behaviours note karo.

**Bada:** Ek chhota table banao 3 `encapsulation` modes ke liye — `Emulated`, `None`, `ShadowDom` — columns: *CSS kahan apply hoti hai*, *ek risk*, *kab use karein*. Phir ek throwaway component me `ViewEncapsulation.None` set karke ek generic selector (`.title`) style karo, aur dekho wo dusre component ke `.title` ko bhi affect karta hai. 3-line conclusion.

</Callout>
