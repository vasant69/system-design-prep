<SimpleDefinition>

Interpolation (`{{ expr }}`) inserts a component value into the template as text. Property binding (`[prop]="expr"`) sets a DOM property or a child component's input from a class expression. Both flow one way — from the component class to the view — and re-render automatically when the value changes.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Data binding ka matlab: component ki class aur uske template ko ek dusre se "jodna", taaki data ya events flow karein. Angular me 4 tarah ki binding hoti hai — is topic me pehli do (dono **one-way, class se view**).

### What is it

**Interpolation** — `{{ }}` ke andar ek expression, jiska result **text** banke DOM me aata hai:

```html
<h2>{{ employee.firstName }} {{ employee.lastName }}</h2>
<p>Employee ID: {{ employee.id }}</p>
<p>Status: {{ employee.isActive ? "Active" : "Inactive" }}</p>
<p>Total employees: {{ employees.length }}</p>
```

**Property binding** — `[ ]` ke andar element ki **property** set karna class expression se:

```html
<img [src]="employee.avatarUrl" [alt]="employee.firstName" />
<button [disabled]="isSaving">Save</button>
<app-employee-badge [status]="employee.isActive" />
<input [value]="employee.email" />
```

### Why do we need it — kyun

Bina binding ke aapko DOM manually update karna padta (`element.textContent = ...`, `element.disabled = ...`). Binding se aap sirf class me value badalte ho, Angular DOM sync kar deta hai. Aur ye **declarative** hai — template padhke turant pata chalta hai kaunsa DOM part kis class value se aata hai.

### How does it work

- Angular expression ko evaluate karta hai component instance ke context me (`employee` matlab `this.employee`).
- Change detection ke har cycle me Angular value dobara evaluate karta hai; badli to DOM update.
- **Interpolation** hamesha string me convert karta hai aur HTML ko escape karta hai (XSS safety) — `{{ }}` me daala gaya `<script>` text banke dikhega, execute nahi hoga.
- **Property binding** actual JS property set karti hai — `[disabled]="false"` element ki `disabled` property ko boolean `false` deta hai (attribute `disabled="false"` se alag, jo browser me truthy hota).

### Interpolation vs property binding — kab kya

- Text content chahiye -> interpolation: `<span>{{ name }}</span>`.
- Element/component ki property set karni -> property binding: `[disabled]`, `[src]`, `[value]`, `[status]`.
- `{{ }}` internally `[textContent]` binding jaisa hi hai — `<span [textContent]="name">` aur `<span>{{ name }}</span>` practically same.
- Non-string property (boolean, number, object) -> property binding zaroori: `[disabled]="isSaving"` sahi; `disabled="{{ isSaving }}"` string `"true"`/`"false"` bhejega (dono truthy!).

### Attribute vs property (ek common confusion)

HTML **attributes** initial values hote hain; DOM **properties** live state. `[value]` property hai (live), `value=""` attribute hai (initial). Jab koi cheez DOM property nahi hoti (jaise `colspan`, `aria-label`), tab `[attr.]` use karo:

```html
<td [attr.colspan]="span">...</td>
<button [attr.aria-label]="label">X</button>
```

### Show it in our project

`EmployeeCard` template:

```html
<article>
  <h3>{{ fullName }}</h3>
  <p>{{ employee.email }}</p>
  <span [class.active]="employee.isActive">
    {{ employee.isActive ? "Active" : "Inactive" }}
  </span>
  <img [src]="employee.avatarUrl || 'assets/avatar-placeholder.png'"
       [alt]="fullName" />
  <button [disabled]="!canEdit" (click)="edit()">Edit</button>
</article>
```

`fullName` ek getter hai class me. `[disabled]="!canEdit"` — button tabhi enabled jab `canEdit` true.

### Where is it used in day-to-day development

Practically har template line me. Labels, counts, statuses -> interpolation. Disabled buttons, image sources, input values, child component inputs -> property binding. Ye Angular templates ki roti-paani hai.

### Pros and cons

**Pros**

- Declarative, readable — data flow template me dikhta hai.
- Auto re-render on change.
- Interpolation HTML escape karke XSS se bachata hai.

**Cons**

- Template me heavy logic (`{{ a ? b.map(x => ...) : c }}`) unreadable aur har CD cycle me chalta hai — getters/signals/pipes me nikaalo.
- Attribute vs property confusion beginners ko bahut pareshan karti hai.
- `{{ }}` sirf strings — objects `[object Object]` dikhaata hai (use `json` pipe for debugging).

</Hinglish>

<Callout type="trap">

`disabled="{{ isSaving }}"` mat likho. Ye hamesha string deta hai — `"false"` bhi truthy hai, to button hamesha disabled. Sahi: `[disabled]="isSaving"`.

</Callout>

## Real World Example

<RealWorld company="Every Angular form and list UI">

Ek EMS employee table me har row me: `{{ emp.firstName }}` (interpolation), `[routerLink]="['/employees', emp.id]"` (property binding to a directive input), `[class.text-muted]="!emp.isActive"` (class binding), `[attr.data-id]="emp.id"` (attribute binding for test hooks). Ye chaar patterns milke ek row banate hain — aur poori app inhi ke combinations se bani hoti hai.

## Numbers That Matter

<Numbers>

- Angular template expressions har change-detection cycle me re-evaluate hote hain — ek busy screen par **kai baar per second**. Isliye expression sasta hona chahiye.
- Interpolation `{{ }}` browser me `textContent` set karta hai, `innerHTML` nahi — isliye **zero** HTML injection risk.
- Property binding `[x]` aur interpolation `{{ }}` dono **one-way** hain (class -> view); do-tarfa binding alag syntax (`[( )]`) hai.
- `[attr.]` tab chahiye jab element ki koi matching DOM property nahi — SVG attributes, `colspan`, `aria-*`, `data-*` common cases.

</Numbers>

## Interview Angle

<InterviewAngle>

Common: "Angular me kitni tarah ki data binding hai?", "interpolation aur property binding me farak?", "attribute binding kab?", "`[disabled]="x"` vs `disabled="{{x}}"`?".

Strong answer:

1. Chaar types: interpolation `{{ }}`, property `[ ]`, event `( )`, two-way `[( )]`.
2. Interpolation -> text content, hamesha string, HTML-escaped.
3. Property binding -> real DOM/component property, koi bhi type.
4. `[attr.x]` -> jab DOM property nahi hoti (aria, colspan, data).
5. `disabled="{{x}}"` bug: string `"false"` truthy — hamesha `[disabled]="x"`.

Red flag: "interpolation aur property binding same hain" — result type aur use-case alag.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`disabled="{{ isSaving }}"` ya `[src]="{{ url }}"`.** `[ ]` ke andar `{{ }}` mat mixao. `[ ]` already expression leta hai: `[src]="url"`. Aur plain attribute + interpolation boolean properties par bug deta hai.

</Mistake>

<Mistake>

**Template me bhaari logic.** `{{ employees.filter(e => e.isActive).length }}` har CD cycle me chalega. Ek getter `activeCount` banao ya `computed()` signal use karo.

</Mistake>

<Mistake>

**Object ko `{{ }}` me daalna aur `[object Object]` dekhna.** Debug ke liye `{{ employee | json }}` use karo; production me specific fields interpolate karo.

</Mistake>

<Mistake>

**`[attr.]` aur `[ ]` ko confuse karna.** `[value]`, `[disabled]`, `[hidden]` DOM properties hain -> `[ ]`. `[attr.colspan]`, `[attr.aria-label]` -> `[attr.]` kyunki inka DOM property nahi hota.

</Mistake>

<Mistake>

**Null/undefined pe crash.** `{{ employee.address.city }}` jab `address` undefined -> error. Optional chaining use karo: `{{ employee.address?.city }}`.

</Mistake>

## Quick Revision

<QuickRevision>

- Four bindings: interpolation `{{ }}`, property `[ ]`, event `( )`, two-way `[( )]`.
- Interpolation -> text, always string, HTML-escaped (XSS-safe).
- Property binding `[prop]="expr"` -> real DOM / component property, any type.
- Use property binding for booleans/numbers/objects: `[disabled]="isSaving"`, never `disabled="{{isSaving}}"`.
- `[attr.x]="expr"` when there's no matching DOM property (`aria-*`, `colspan`, `data-*`, SVG).
- All of these are one-way: class -> view.
- Keep expressions cheap (they run every change-detection cycle); move logic to getters / `computed()`.
- Use optional chaining `?.` to avoid null errors in templates.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `EmployeeCard` template me interpolation se `firstName`, `lastName`, `email` dikhao. Ek `<button [disabled]="!employee.isActive">` add karo aur toggle karke dekho button enable/disable hota hai.

**Medium:** Ek `activeCount` getter banao jo `this.employees.filter(e => e.isActive).length` return karta hai, aur template me `{{ activeCount }}` dikhao. Phir wahi logic seedha interpolation me `{{ employees.filter(...).length }}` likho — dono kaam karenge, par socho kaunsa behtar aur kyun (hint: change detection).

**Bada:** Ek chhoti table banao 3 rows ki — *scenario* (`disabled` a button, set an `<img src>`, set `colspan` on a `<td>`), *sahi syntax*, *galat syntax jo bug dega*. Phir `disabled="{{ isSaving }}"` wala bug apne code me reproduce karo (button hamesha disabled), phir `[disabled]="isSaving"` se theek karo. 3-line note.

</Callout>
