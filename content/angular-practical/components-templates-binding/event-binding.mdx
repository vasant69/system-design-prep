<SimpleDefinition>

Event binding is `(eventName)="statement()"` — parentheses around a DOM event (`click`, `input`, `submit`) or a component's `@Output`, running a template statement in the component class when it fires. It flows one way, from the view to the class, and exposes the event payload as `$event`.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Interpolation aur property binding data ko class se view me le jaate the. Event binding **ulta** — user ne kuch kiya (click, type, submit), wo class ke method ko batao.

### What is it

```html
<button (click)="save()">Save</button>
<input (input)="onSearch($event)" />
<form (submit)="onSubmit()">...</form>
<app-employee-row (delete)="removeEmployee($event)" />
```

- `(click)`, `(input)`, `(submit)` — DOM events.
- `(delete)` — child component ka `@Output` (custom event).
- `$event` — event ka data: DOM events me `Event` object, `@Output` me jo child ne emit kiya.
- `"save()"` — **template statement**: expression se thoda alag, ismein assignment aur method calls allowed hain.

### Why do we need it — kyun

Bina iske aapko `addEventListener` manually lagana padta, aur `removeEventListener` cleanup bhi. Angular ye handle karta hai — listener component ke saath bind hota hai aur component destroy pe hat jaata hai. Aur template me `(click)="save()"` padhke turant pata chalta hai is button ka kaam kya hai.

### How does it work

- Angular ek native listener attach karta hai element par.
- Event fire hone par template statement chalti hai component ke context me.
- Uske baad Angular change detection chalata hai (state badla ho to view update).
- Component destroy hone par listener automatically remove.

### `$event` kya hota hai

- DOM events: `(input)="onSearch($event)"` -> `$event` ek `Event` hai; value chahiye to `($event.target as HTMLInputElement).value`.
- Key events: `(keyup.enter)="add()"` — Angular ka "key modifier" — sirf Enter par chalega.
- Component `@Output`: `(delete)="removeEmployee($event)"` -> `$event` wahi jo child ne `this.delete.emit(emp.id)` me bheja (yaani `emp.id`).

### Template statements — kya allowed hai

- Method calls: `save()`, `removeEmployee(emp.id)`
- Assignment: `showMenu = !showMenu`
- Chaining with `;`: `(click)="open(); track('open')"`
- **Not allowed**: `new`, `++`/`--`, bitwise, complex logic — wo class me nikaalo.

### Show it in our project

`EmployeeToolbar`:

```html
<input [value]="search()" (input)="onSearch($event)" placeholder="Search..." />
<button (click)="addClicked.emit()">+ Add Employee</button>
```

```ts
export class EmployeeToolbar {
  search = signal("");
  addClicked = output<void>();

  onSearch(e: Event) {
    this.search.set((e.target as HTMLInputElement).value);
  }
}
```

`EmployeeRow`:

```html
<button (click)="edit.emit(employee.id)">Edit</button>
<button (click)="delete.emit(employee.id)">Delete</button>
```

### Where is it used in day-to-day development

Har button, form, input, checkbox, dropdown. Custom component events (`@Output`). Keyboard shortcuts (`keydown.escape`). Practically har interactive element ke saath ek `( )` binding hoti hai.

### Pros and cons

**Pros**

- Declarative — element ke saath hi uska handler dikhta hai.
- Automatic listener cleanup on destroy.
- Key modifiers (`keyup.enter`, `click.stop`) boilerplate bachate hain.

**Cons**

- `$event.target.value` ko TypeScript me cast karna padta hai — thoda boilerplate.
- Template me inline statement bada ho jaaye to unreadable — method me le jao.
- `(click)` har render me function reference — OnPush aur perf me dhyaan (usually fine).

</Hinglish>

<Callout type="tip">

`$event.target.value` ka clean alternative: `(input)="onSearch($event)"` ki jagah newer template `(input)="search.set($any($event.target).value)"` — par sabse saaf ye hai ki chhota `onSearch(e: Event)` method banao aur casting wahan karo.

</Callout>

## Numbers That Matter

<Numbers>

- Angular event binding ke baad **hamesha ek change-detection pass** chalta hai (jab tak `NgZone` se opt-out na kiya ho).
- Key modifiers supported: `enter`, `escape`, `space`, `tab`, `arrowup`/`down`, plus combos like `control.shift.z`.
- Event modifiers: `.stop` (stopPropagation), `.prevent` (preventDefault), `.self`, `.once`, `.passive` — inline, no boilerplate in the method.
- A component `@Output` fires **synchronously** — parent handler runs before the child's emitting line returns.

</Numbers>

## Interview Angle

<InterviewAngle>

Common: "event binding syntax?", "`$event` kya hai?", "template statement aur template expression me farak?", "keyboard event kaise handle karte ho?".

Strong answer:

1. `(event)="statement()"` — view se class, one-way.
2. `$event` — DOM `Event`, ya `@Output` ka emitted payload.
3. Statement: method calls + assignment + `;` chaining allowed; complex logic nahi.
4. Angular listener attach + cleanup handle karta hai; har event ke baad CD.
5. Key/event modifiers: `(keyup.enter)`, `(click.stop)`.

Red flag: "event ke baad manually `detectChanges()` call karna padta hai" — nahi, Angular zone ke through auto karta hai.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`$event.target.value` ko bina cast kiye use karna (strict TS).** `$event.target` type `EventTarget | null` hai. Method me `(e: Event)` lo aur `(e.target as HTMLInputElement).value` karo.

</Mistake>

<Mistake>

**`(click)="count++"` jaisa increment.** Template statements me `++`/`--` allowed nahi. `(click)="count = count + 1"` ya method use karo.

</Mistake>

<Mistake>

**`(submit)` ke saath `preventDefault` bhoolna.** Native form submit page reload karega. `(submit)="onSubmit()"` ke saath ya to `type="button"` use karo ya `(submit)="$event.preventDefault(); onSubmit()"` / reactive forms handle it.

</Mistake>

<Mistake>

**Parent me `@Output` ka naam `on...` rakhna aur phir `(onDelete)` bind karna.** Convention: output ka naam action ka noun/verb (`delete`, `save`), aur bind `(delete)`. `on` prefix redundant.

</Mistake>

<Mistake>

**Manually `addEventListener` lagana component me.** Bina cleanup wo leak karega. Template `( )` binding ya `@HostListener` use karo — dono auto-cleanup karte hain.

</Mistake>

## Quick Revision

<QuickRevision>

- Syntax: `(event)="statement()"` — one-way, view -> class.
- Works for DOM events (`click`, `input`, `submit`) and component `@Output`s.
- `$event` = DOM `Event` for native events, emitted payload for `@Output`s.
- For inputs: take `(e: Event)` and cast `(e.target as HTMLInputElement).value`.
- Template statements allow method calls, assignment, `;` chaining — no `++`, `new`, heavy logic.
- Key/event modifiers: `(keyup.enter)`, `(click.stop)`, `(submit)` + `.prevent`.
- Angular attaches and cleans up listeners; a change-detection pass runs after each event.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** Ek button par `(click)="toggle()"` lagao jahan `toggle()` ek boolean `showDetails` flip karta hai. Template me `@if (showDetails) { ... }` se ek panel dikhao/chhupao.

**Medium:** `EmployeeToolbar` me ek search `<input>` add karo `(input)="onSearch($event)"` ke saath. `onSearch(e: Event)` me value ko ek `search` signal me set karo aur `{{ search() }}` template me dikhao. Confirm karo type karte hi text update hota hai.

**Bada:** Ek `EmployeeRow` component banao jo `edit` aur `delete` `output()` emit karta hai (`edit.emit(employee.id)`). Parent `EmployeeList` me `(edit)` aur `(delete)` bind karke console.log karo received id. Phir delete button par `.stop` modifier lagao (`(click.stop)="delete.emit(...)"`) taaki row-level click na fire ho — pehle bina `.stop` dekho dono fire hote hain, phir `.stop` se sirf delete.

</Callout>
