<SimpleDefinition>

**Angular Material** is Google's component library implementing Material Design (buttons, form fields, dialogs, tables, date pickers, menus). The **CDK** (Component Dev Kit) is the unstyled behaviour layer beneath it: overlays/positioning, accessibility (focus trap, live announcer, key managers), drag-and-drop, virtual scrolling, a headless table, portals, and layout/breakpoint observers. Use Material when Material Design is acceptable; use the CDK to build a custom design system with correct behaviour and a11y.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Har button, modal, dropdown, table khud banana — mehnat aur bugs (khaas kar accessibility). Ek UI library ye deta hai. Angular ki official do layers hain.

### Angular Material — styled components

```bash
ng add @angular/material
```

```ts
import { MatButtonModule } from "@angular/material/button";
import { MatDialog } from "@angular/material/dialog";

@Component({ imports: [MatButtonModule], template: `<button mat-raised-button>Save</button>` })
```

- Implements **Material Design** (Google's design language) — a specific look.
- Components: `mat-button`, `mat-form-field` + `matInput`, `mat-table`, `mat-dialog`, `mat-datepicker`, `mat-menu`, `mat-snack-bar`, `mat-paginator`, `mat-sort`, etc.
- Theming via SCSS + CSS custom properties (M3 tokens).
- Accessible by default — ARIA, focus management, keyboard support are done for you.

### The CDK — behaviour without style

The CDK is what Material is built on, exposed for your own use:

| CDK piece | What it gives you |
|---|---|
| `Overlay` | Positioned floating panels (the basis of dialogs, tooltips, menus, autocompletes) |
| `a11y` | `FocusTrap`, `LiveAnnouncer`, `FocusMonitor`, `ListKeyManager` (arrow-key nav) |
| `DragDrop` | `cdkDrag` / `cdkDropList` — reorderable lists, kanban |
| `ScrollingModule` | `cdk-virtual-scroll-viewport` — render only visible rows of a 100k list |
| `Table` (`cdk-table`) | A headless table: you bring the markup and CSS |
| `Portal` | Render a component/template somewhere else in the DOM |
| `Layout` | `BreakpointObserver` — responsive logic in TS |
| `Clipboard`, `TextField` (autosize), `Stepper`, `Tree` | misc behaviours |

```ts
// Example: a dialog with your own styles, using the CDK Overlay
const ref = this.overlay.create({ hasBackdrop: true, positionStrategy: this.overlay.position().global().centerHorizontally().centerVertically() });
ref.attach(new ComponentPortal(MyDialogComponent));
```

### When to use what

- **Material fits your product** (internal tools, admin apps often accept Material Design) -> use Material. Fast, accessible, themeable.
- **You have a custom design system** (brand components, a specific look) -> build your own components **on the CDK** so you don't re-implement overlay positioning, focus traps, and key managers (which are genuinely hard to get right).
- **Neither** — a small app, a few plain components -> hand-roll with care for a11y.

Mixing Material and a custom design system in one app usually looks inconsistent — pick a direction.

### Show it in our project

The EMS `shared/ui` components (`DataTable`, `ConfirmModal`, `Paginator`, `SearchBox`) are hand-rolled to a simple custom style — but a production version would likely build `ConfirmModal` on `@angular/cdk/overlay` + `@angular/cdk/a11y` (`FocusTrap`, backdrop, Escape-to-close), and use `@angular/cdk/scrolling` if a list can exceed a few thousand visible rows. `BreakpointObserver` drives the sidebar collapse on mobile.

### Where is it used in day-to-day development

Choosing (or being handed) a UI library on day one shapes the whole app. After that: importing components, theming, and reaching for a CDK primitive when a custom component needs real behaviour (a positioned popover, keyboard nav in a listbox, a virtualised list).

### Pros and cons

**Material — Pros:** complete, accessible, themeable, maintained by the Angular team, huge time save. **Cons:** it *is* Material Design — hard to make it not look like Material; theming M3 has a learning curve; bundle size for many components.

**CDK — Pros:** the hard behaviour (overlay, a11y, virtual scroll, drag-drop) done right, unstyled so it fits any design. **Cons:** you write the markup/CSS/ARIA wiring; more work than dropping in Material.

</Hinglish>

<Callout type="tip">

Custom design system bana rahe ho to bhi **CDK use karo** — overlay positioning, focus trap, aur keyboard navigation ko scratch se sahi banana bahut mushkil hai aur usually buggy/inaccessible nikalta hai. CDK unstyled behaviour deta hai; style aap dete ho.

</Callout>

## Real World Example

<RealWorld company="Design-system decision">

A team with a strict brand can't use Material's look, so they build their own `Button`, `Dialog`, `Menu`, `Select`, `Tooltip` — but each is built on a CDK primitive: `Dialog` on `Overlay` + `FocusTrap` + `LiveAnnouncer`; `Menu`/`Select` on `Overlay` + `ListKeyManager` (arrow keys, type-ahead); `Tooltip` on `Overlay` + `FocusMonitor`. They get correct positioning, focus management, and keyboard behaviour for free, and only own the CSS. Another team building an internal admin tool just runs `ng add @angular/material` and ships — Material Design is fine for that audience.

</RealWorld>

## Numbers That Matter

<Numbers>

- Angular Material and the CDK ship together, versioned with Angular (`@angular/material`, `@angular/cdk`).
- `ng add @angular/material` sets up theming, typography, and animations in one step.
- CDK `Virtual Scroll` renders only the visible rows — a 100,000-row list stays smooth.
- CDK `a11y` covers `FocusTrap`, `LiveAnnouncer` (screen-reader announcements), `FocusMonitor`, and `ListKeyManager` (roving tabindex / arrow keys).
- Material components are tree-shakeable — import only the modules you use.

</Numbers>

## Interview Angle

<InterviewAngle>

Common: "Angular Material aur CDK me farak?", "custom design system kaise banaoge?", "virtual scroll kab?", "Material use karein ya nahi?".

Strong answer:

1. Material = styled Material Design components; CDK = the unstyled behaviour layer beneath (overlay, a11y, drag-drop, virtual scroll, table, portal).
2. Material when Material Design is acceptable; the CDK to build custom-styled components with correct behaviour.
3. Virtual scroll (`cdk-virtual-scroll-viewport`) when a list can have thousands of rows in the DOM.
4. CDK `a11y` (`FocusTrap`, `LiveAnnouncer`, `ListKeyManager`) is why you don't hand-roll overlays/menus.

Red flag: "custom dropdown/dialog ko scratch se banata hoon" — positioning + focus + keyboard is hard; use the CDK.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Hand-rolling overlays/menus/dialogs from scratch.** Positioning at viewport edges, focus trapping, Escape/backdrop, and arrow-key navigation are hard and usually shipped broken/inaccessible. Use `@angular/cdk/overlay` + `@angular/cdk/a11y`.

</Mistake>

<Mistake>

**Mixing Material components with a custom design system.** They clash visually. Commit to one.

</Mistake>

<Mistake>

**Rendering a 10k-row list in the DOM.** The browser chokes. `cdk-virtual-scroll-viewport` renders only what's visible.

</Mistake>

<Mistake>

**Importing all of `MatXModule` when you use one component.** Import per-component modules (or standalone imports) so tree-shaking works.

</Mistake>

<Mistake>

**Skipping a11y in custom components.** No focus trap in a modal, no `aria-live` for async results, no keyboard nav in a listbox. The CDK gives you these.

</Mistake>

## Quick Revision

<QuickRevision>

- **Angular Material** = Google's Material Design component library (styled, accessible, themeable). `ng add @angular/material`.
- **CDK** = the unstyled behaviour layer beneath it: `Overlay` (positioned panels), `a11y` (`FocusTrap`, `LiveAnnouncer`, `ListKeyManager`), `DragDrop`, `ScrollingModule` (virtual scroll), `cdk-table` (headless), `Portal`, `BreakpointObserver`.
- Use Material when Material Design fits; use the CDK to build custom-styled components with correct behaviour/a11y.
- Virtual scroll for lists that can hold thousands of DOM rows.
- Never hand-roll overlay positioning, focus traps, or key managers — the CDK exists for that.
- Don't mix Material and a custom design system in one app.
- Import components per-module / standalone so tree-shaking works.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `ng add @angular/material` on a scratch app. Use `mat-form-field` + `matInput`, `mat-raised-button`, and `MatDialog` for a confirm dialog. Note the built-in focus management and keyboard support.

**Medium:** Rebuild your `ConfirmModal` on `@angular/cdk/overlay` + `@angular/cdk/a11y`: `Overlay.create({ hasBackdrop: true, positionStrategy: global centre })`, attach a `ComponentPortal`, add a `cdkTrapFocus`, close on backdrop click and Escape. Your CSS, CDK's behaviour.

**Bada:** Put a 50,000-item array behind `cdk-virtual-scroll-viewport` and confirm scrolling stays smooth (compare with a plain `@for` — the browser struggles). Then use `BreakpointObserver` to collapse the sidebar below `768px`. 6-line note on Material vs CDK vs hand-rolled.

</Callout>
