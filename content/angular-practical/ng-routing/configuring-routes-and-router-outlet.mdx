<SimpleDefinition>

The Angular Router maps URL paths to components. You declare a `Routes` array (each entry: a `path` plus a `component` or `loadComponent`), register it with `provideRouter(routes)` in `app.config.ts`, and put a `<router-outlet />` in a template where the matched component should render. Routes are matched top-to-bottom, `''` is the empty path, and `'**'` is a wildcard for unknown URLs.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Ab tak humne ek hi component screen pe rakha. Real app me kai screens — Login, Dashboard, Employees, Departments. URL badle to screen badle, bina page reload. Ye **Router** karta hai.

### What is it

```ts
// app.routes.ts
import { Routes } from "@angular/router";
import { LoginPage } from "./features/auth/login-page";
import { DashboardPage } from "./features/dashboard/dashboard-page";
import { EmployeeListPage } from "./features/employees/employee-list-page";

export const routes: Routes = [
  { path: "", redirectTo: "dashboard", pathMatch: "full" },
  { path: "login", component: LoginPage, title: "Login | EMS" },
  { path: "dashboard", component: DashboardPage, title: "Dashboard | EMS" },
  { path: "employees", component: EmployeeListPage, title: "Employees | EMS" },
  { path: "**", component: NotFoundPage },
];
```

```ts
// app.config.ts
import { provideRouter, withComponentInputBinding } from "@angular/router";

export const appConfig: ApplicationConfig = {
  providers: [provideRouter(routes, withComponentInputBinding())],
};
```

```html
<!-- app.html -->
<app-site-header />
<main>
  <router-outlet />
</main>
```

Line by line:

- `Routes` — ek array of route objects.
- `{ path: "employees", component: EmployeeListPage }` — URL `/employees` -> render `EmployeeListPage`.
- `{ path: "", redirectTo: "dashboard", pathMatch: "full" }` — `/` ko `/dashboard` pe bhejo. `pathMatch: "full"` zaroori hai empty-path redirects me.
- `{ path: "**", component: NotFoundPage }` — jo kisi route se match nahi, wildcard. **Hamesha last**.
- `provideRouter(routes)` — router ko config deta hai (purana `RouterModule.forRoot`).
- `withComponentInputBinding()` — route params ko `@Input`/`input()` ke roop me deta hai (aage ke topics).
- `<router-outlet />` — matched component yahan render hota hai.
- `title` — browser tab ka title, route change par auto-set.

### Why do we need it — kyun

- **Deep linking** — `/employees/42` share karo, wahi screen khulే.
- **Back/forward** — browser history kaam karein.
- **Code organisation** — har screen ek route, lazy load ho sake.
- **No reload** — SPA navigation, fast.

### How does it work

1. URL badalta hai (link click, `router.navigate`, browser back).
2. Router `routes` array ko top-se-bottom match karta hai.
3. Pehla match jeetta hai — uska component `<router-outlet>` me render.
4. History update, `title` set, guards/resolvers (aage) chalte hain.

### Route matching — order matters

```ts
{ path: "employees/new", component: AddEmployeePage },
{ path: "employees/:id", component: EmployeeDetailsPage },
```

`employees/new` ko `employees/:id` **se pehle** rakho — warna `new` ko `:id = "new"` samajh liya jaayega. Router first-match-wins hai, most-specific-first likho.

### Show it in our project

Top-level routes: `login`, `dashboard`, `employees` (with children — next topics), `departments`, `roles`, `leave`, `documents`, `notifications`, `''` redirect, `**` not-found. `app.html` me ek `<router-outlet />` shell ke andar.

### Where is it used in day-to-day development

Har naya screen = ek route entry. `app.routes.ts` (ya feature `*.routes.ts`) edit karna routine hai. `<router-outlet>` shell/layout components me. `title` har route pe.

### Pros and cons

**Pros**

- Declarative URL-to-component map.
- Deep linking, history, code-splitting all built-in.
- `provideRouter` features (`withComponentInputBinding`, `withViewTransitions`, `withInMemoryScrolling`) opt-in.

**Cons**

- Route order bugs (`:id` before `new`) — silent wrong match.
- `pathMatch: "full"` bhoolna empty-redirect me -> infinite redirect / wrong match.
- Wildcard `**` galat jagah -> sab kuch not-found.
- Big flat route arrays -> split into feature route files.

</Hinglish>

<Callout type="trap">

`{ path: "", redirectTo: "dashboard" }` bina `pathMatch: "full"` ke likhna — prefix match hone se **har** URL `dashboard` pe redirect ho jaata hai. Empty-path redirect me hamesha `pathMatch: "full"`.

</Callout>

## Real World Example

<RealWorld company="Any multi-screen SPA">

EMS ka `app.routes.ts`: `''` -> `dashboard` redirect, `login`, `dashboard`, `employees` (lazy, with children), `departments` (lazy), ... `**` -> `NotFoundPage`. Har feature ka apna `employees.routes.ts` jo `app.routes.ts` me `loadChildren` se attach hota hai — top-level file chhoti rehti hai aur har feature apna routing khud own karta hai. Ye structure 30-route app me bhi navigable rehta hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- Route matching is **first-match-wins**, top to bottom — order is significant.
- `path: ""` = the empty path; `path: "**"` = wildcard, must be **last**.
- Empty-path `redirectTo` needs `pathMatch: "full"` (default is `"prefix"`).
- `provideRouter` replaces the legacy `RouterModule.forRoot`; feature routes use `loadChildren` / `RouterModule.forChild` (legacy) or a plain `Routes` array (standalone).
- `title` on a route sets `document.title` automatically on navigation (via the built-in `TitleStrategy`).

</Numbers>

## Interview Angle

<InterviewAngle>

Very common: "routing kaise setup karte ho?", "`router-outlet` kya hai?", "route order kyun matter karta hai?", "wildcard route?", "`pathMatch: 'full'` kyun?".

Strong answer:

1. `Routes` array (`path` + `component`/`loadComponent`), `provideRouter(routes)` in config, `<router-outlet />` in a layout template.
2. First-match-wins top-to-bottom — specific before generic (`employees/new` before `employees/:id`).
3. `''` empty path + `redirectTo` needs `pathMatch: "full"`.
4. `'**'` wildcard last for 404.
5. Modern standalone: `provideRouter` + `loadComponent`/`loadChildren`; no `RouterModule`.

Red flag: "`**` ko upar rakhta hoon" — sab kuch not-found ho jaata hai.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`:id` route ko `new`/static route se pehle rakhna.** `employees/:id` pehle -> `/employees/new` me `id = "new"`. Static/specific routes upar.

</Mistake>

<Mistake>

**Empty-path redirect me `pathMatch: "full"` bhoolna.** Default `"prefix"` -> har URL match -> sab redirect. `{ path: "", redirectTo: "x", pathMatch: "full" }`.

</Mistake>

<Mistake>

**Wildcard `**` ko last nahi rakhna.** Uske baad ki routes kabhi match nahi hongi.

</Mistake>

<Mistake>

**`<router-outlet>` bhoolna.** Routes configured hain par kuch render nahi hota — layout template me outlet chahiye.

</Mistake>

<Mistake>

**Sab routes ek hi giant `app.routes.ts` me.** 30 routes flat -> unmanageable. Feature `*.routes.ts` files + `loadChildren`.

</Mistake>

## Quick Revision

<QuickRevision>

- `Routes` array: `{ path, component | loadComponent, title, children, canActivate, ... }`.
- Register with `provideRouter(routes, ...features)` in `app.config.ts`; place `<router-outlet />` in a layout template.
- Matching is first-match-wins, top-to-bottom — put specific routes before parameterised/generic ones.
- `path: ""` empty path; empty-path `redirectTo` needs `pathMatch: "full"`.
- `path: "**"` wildcard for 404 — must be last.
- `title` on a route auto-sets the browser tab title.
- Split large route sets into feature `*.routes.ts` files loaded via `loadChildren`.
- `withComponentInputBinding()` lets route params arrive as component inputs.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `app.routes.ts` me `login`, `dashboard`, `employees` routes banao + `{ path: "", redirectTo: "dashboard", pathMatch: "full" }` + `{ path: "**", component: NotFoundPage }`. `app.html` me `<router-outlet />` rakho. URLs type karke screens switch hote dekho.

**Medium:** `employees/new` aur `employees/:id` dono add karo. Pehle `:id` ko upar rakho aur `/employees/new` kholkar dekho `EmployeeDetailsPage` khulta hai `id="new"` ke saath (bug). Order swap karke fix karo.

**Bada:** `pathMatch: "full"` hata do empty-redirect se aur observe har URL dashboard pe chala jaata hai. Wapas laga do. Phir `**` route ko array me 2nd position pe move karke dekho baaki routes 404 ho jaati hain. Sab findings 4 line me.

</Callout>
