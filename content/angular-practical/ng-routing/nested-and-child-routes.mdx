<SimpleDefinition>

Child routes let a parent route render a layout component that contains its own `<router-outlet />`, into which child routes render. This models master-detail screens, tabbed detail pages, and shared section layouts. A pathless route (`path: ""` with `children`) is the common way to wrap a group of routes in a layout or apply one guard to all of them.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Ab tak har route ek top-level screen tha. Real apps me screens **nest** hote hain — ek "Employees" section jiske andar list, add, details, edit — sab ek shared layout ke andar.

### Child routes — structure

```ts
export const routes: Routes = [
  {
    path: "employees",
    component: EmployeesLayout,        // has its own <router-outlet />
    children: [
      { path: "", component: EmployeeListPage },
      { path: "new", component: AddEmployeePage },
      { path: ":id", component: EmployeeDetailsPage },
      { path: ":id/edit", component: EditEmployeePage },
    ],
  },
];
```

```ts
// EmployeesLayout template
@Component({
  template: `
    <h1>Employees</h1>
    <nav>
      <a routerLink="" routerLinkActive="active" [routerLinkActiveOptions]="{ exact: true }">List</a>
      <a routerLink="new" routerLinkActive="active">Add</a>
    </nav>
    <router-outlet />   <!-- children render here -->
  `,
})
export class EmployeesLayout {}
```

- URL `/employees` -> `EmployeesLayout` + child `''` (`EmployeeListPage`) in its outlet.
- URL `/employees/42` -> `EmployeesLayout` + `EmployeeDetailsPage`.
- The layout (heading, section nav) stays; only the inner outlet swaps.

### Pathless (layout / grouping) routes

```ts
{
  path: "",
  component: ShellLayout,             // header + sidebar + <router-outlet />
  canActivate: [authGuard],           // applies to ALL children
  children: [
    { path: "dashboard", component: DashboardPage },
    { path: "employees", loadChildren: () => import("./features/employees/employees.routes") },
    { path: "departments", loadChildren: () => import("./features/departments/departments.routes") },
  ],
},
{ path: "login", component: LoginPage },   // outside the shell / guard
```

- `path: ""` with no `component` and just `children` = a **grouping** route (guard/data for many).
- `path: ""` with a `component` and `children` = a **layout** route (shared chrome).
- `login` is a sibling — no shell, no auth guard.

### Nested outlets — how they stack

```text
app.html                -> <router-outlet />   (level 1)
  ShellLayout           -> <router-outlet />   (level 2)
    EmployeesLayout     -> <router-outlet />   (level 3)
      EmployeeListPage
```

Har layout ka apna outlet; matched child usme aata hai.

### Relative navigation inside children

```html
<a routerLink="../">Back to list</a>          <!-- one level up -->
<a [routerLink]="['..', otherId]">Sibling</a>
<a routerLink="edit">Edit</a>                 <!-- relative to current -->
```

Ya code me: `this.router.navigate(['../'], { relativeTo: this.route })`.

### Tabs via child routes

```ts
{
  path: ":id",
  component: EmployeeDetailsPage,     // has tabs + <router-outlet />
  children: [
    { path: "", redirectTo: "profile", pathMatch: "full" },
    { path: "profile", component: ProfileTab },
    { path: "documents", component: DocumentsTab },
    { path: "leave", component: LeaveTab },
  ],
}
```

`/employees/42/documents` — details page (with the employee loaded once) + the Documents tab. Tabs are `routerLink`s; deep-linkable and back-button friendly.

### Show it in our project

- `ShellLayout` (pathless `''` + `authGuard`): header, sidebar, main outlet — wraps every authenticated area.
- `login` sibling outside the shell.
- `EmployeesLayout` (child under `employees`): section heading + list/add nav + outlet.
- `EmployeeDetailsPage` with child tab routes: `profile`, `documents`, `leave`.

### Where is it used in day-to-day development

Any app with a persistent shell (header/sidebar). Any section with its own sub-navigation. Any detail page with tabs. Applying one guard/resolver/layout to a group of routes.

### Pros and cons

**Pros**

- Shared layout renders once; only the inner part changes on navigation.
- One guard/resolver on a parent covers all children.
- Tabs and master-detail become deep-linkable for free.
- Feature routes compose cleanly (`loadChildren`).

**Cons**

- Multiple `<router-outlet>`s to keep track of — "why isn't my component showing" often = wrong outlet level.
- Relative vs absolute `routerLink` confusion inside children.
- Empty-child `redirectTo` needs `pathMatch: "full"`.
- Deep nesting (4+ levels) gets hard to reason about.

</Hinglish>

<Callout type="tip">

Ek `path: ""` route with only `canActivate` + `children` (no `component`) is the cleanest way to guard a whole area — you write the guard once, and every child route under it is protected.

</Callout>

## Real World Example

<RealWorld company="Authenticated shell + tabbed details">

EMS structure: a pathless `''` route with `canActivate: [authGuard]` and `component: ShellLayout` (header + sidebar + outlet) wraps `dashboard`, `employees`, `departments`, etc. `login` sits outside it — no shell, no guard. Under `employees/:id`, `EmployeeDetailsPage` loads the employee once and renders a tab bar plus a nested outlet for `profile` / `documents` / `leave` tabs. Navigating between tabs changes only the inner outlet — the employee header and the sidebar never re-render. `/employees/42/documents` is a shareable link straight to that tab.

</RealWorld>

## Numbers That Matter

<Numbers>

- Each layout/parent component needs its **own** `<router-outlet />` for children to render.
- A `canActivate` / `resolve` on a parent route applies to **all** its children.
- Empty-string child route with `redirectTo` needs `pathMatch: "full"`.
- Relative `routerLink` (`"../"`, `"edit"`) resolves against the current route; leading `/` makes it absolute.
- `path: ""` + `children` + no `component` = a pure grouping route (guards/data, no UI).

</Numbers>

## Interview Angle

<InterviewAngle>

Common: "child routes kaise banate ho?", "pathless route kya hai?", "ek shared layout kaise?", "detail page pe tabs?".

Strong answer:

1. Parent route with `children`; parent component has its own `<router-outlet />`.
2. `path: ""` + `component` + `children` = layout route (shared chrome); `path: ""` + `children` only = grouping route (one guard/resolver for many).
3. Nested outlets stack; the matched child renders in its parent's outlet.
4. Tabs = child routes under the detail route -> deep-linkable.
5. Relative navigation: `routerLink="../"`, `relativeTo: this.route`.

Red flag: "layout component me `<router-outlet>` add karna bhool gaya" — children never render.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Layout/parent component me `<router-outlet />` na daalna.** Children configured hain par kuch render nahi hota.

</Mistake>

<Mistake>

**Child ke andar absolute `routerLink="/employees"` jab relative chahiye tha.** `routerLink="../"` / `routerLink="edit"` use karo, ya `relativeTo: this.route`.

</Mistake>

<Mistake>

**Empty child redirect bina `pathMatch: "full"`.** `{ path: "", redirectTo: "profile" }` -> prefix match chaos. `pathMatch: "full"`.

</Mistake>

<Mistake>

**Guard ko har child route pe alag-alag lagana.** Ek pathless parent route pe `canActivate` -> sab children covered, DRY.

</Mistake>

<Mistake>

**Details page ke tabs ko `@if`/signal se toggle karna instead of child routes.** Tabs ko routes banao -> deep-linkable, back button, refresh-safe.

</Mistake>

## Quick Revision

<QuickRevision>

- Child routes: `{ path, component, children: [...] }`; the parent component must contain its own `<router-outlet />`.
- Layout route: `path: ""` + `component` (shared chrome) + `children`. Grouping route: `path: ""` + `children` only + a `canActivate`/`resolve` (one guard for many).
- Nested outlets stack; the matched child renders in its parent's outlet.
- Empty-child `redirectTo` needs `pathMatch: "full"`.
- Relative navigation inside children: `routerLink="../"`, `routerLink="edit"`, or `navigate([...], { relativeTo: this.route })`.
- Model tabs as child routes -> deep-linkable, back-button-safe.
- Put `login` outside the guarded shell as a sibling route.

</QuickRevision>

**Medium:** Ek pathless `{ path: "", component: ShellLayout, canActivate: [authGuard], children: [...] }` banao jisme `dashboard` aur `employees` hain, aur `login` ko iske bahar sibling rakho. Confirm `login` par shell/guard nahi lagta, baaki sab par lagta hai.

**Bada:** `EmployeeDetailsPage` (loads employee via `:id`) ke neeche child routes `profile`/`documents`/`leave` + `{ path: "", redirectTo: "profile", pathMatch: "full" }`.
