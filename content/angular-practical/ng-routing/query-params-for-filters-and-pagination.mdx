<SimpleDefinition>

Query parameters are the `?key=value&...` part of a URL. Unlike route params, they are optional and order-independent, so they are the right place for list-view state: `search`, filters, `page`, `sort`. Read them via `ActivatedRoute.queryParamMap`; write them with `router.navigate([], { queryParams, queryParamsHandling: 'merge' })` so the list URL stays shareable and the back button works.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Route params (`:id`) resource identity ke liye. Filters, page number, sort — ye **optional view state** hai. Iske liye query params (`?search=aar&page=2&sort=name`).

### Reading query params

```ts
export class EmployeeListPage {
  private route = inject(ActivatedRoute);

  vm$ = this.route.queryParamMap.pipe(
    map(qp => ({
      search: qp.get("search") ?? "",
      page: +(qp.get("page") ?? "1"),
      sort: qp.get("sort") ?? "name",
    })),
    switchMap(params => this.service.getEmployees(params)),
  );
}
```

Ya `withComponentInputBinding()` ke saath: `search = input("")`, `page = input(1)` — query params matching inputs me aate hain.

### Writing query params

```ts
updateSearch(search: string) {
  this.router.navigate([], {
    relativeTo: this.route,
    queryParams: { search: search || null, page: 1 },   // reset page on new search
    queryParamsHandling: "merge",                        // keep other params
    replaceUrl: true,                                    // don't spam history per keystroke
  });
}
```

- `navigate([])` — same route, sirf query params badlo.
- `queryParams: { search }` — set/update.
- `search || null` — `null` value se param **remove** ho jaata hai (empty search -> clean URL).
- `queryParamsHandling: "merge"` — baaki params (`sort`, etc.) preserve. Bina iske wo wipe ho jaate.
- `replaceUrl: true` — har keystroke ek history entry na banaye.

### `queryParamsHandling` options

- `"merge"` — new params ko existing ke saath merge. (Filters me usually ye.)
- `"preserve"` — current params rakho, naye ignore. (Navigating to a related route jahan same filters chahiye.)
- default (omit) — replace all query params.

### Route params vs query params — decision

| | Route param `:id` | Query param `?page=2` |
|---|---|---|
| Required? | Yes (part of the path) | Optional |
| Order matters? | Yes | No |
| Use for | Resource identity | Filters, page, sort, tabs |
| Missing = | 404 / no match | Just a default |

### Why put list state in the URL — kyun

- **Shareable** — "yeh filtered view dekho" link bhejo.
- **Back/forward** — filter change -> back -> previous filter.
- **Refresh-safe** — F5 par filters gaye nahi.
- **Bookmarkable**.

Trade-off: rapid changes (typing) history spam kar sakti hain -> `replaceUrl: true` + debounce.

### Show it in our project

`EmployeeListPage`: `search`, `departmentId`, `page`, `sort` sab query params. Toolbar inputs `router.navigate([], { queryParams: {...}, queryParamsHandling: 'merge', replaceUrl: true })` se update. Ek pipeline `queryParamMap` -> `debounceTime` -> `switchMap(api.getEmployees)` list ko drive karta hai. Refresh/share -> exact same view.

### Where is it used in day-to-day development

Every list/search/table screen. Tab selection (`?tab=details`). Wizard step. Report parameters. Any "the URL should capture what I'm looking at" case.

### Pros and cons

**Pros**

- Shareable, bookmarkable, refresh-safe, back-button-correct list views.
- One source of truth for view state (the URL).
- Decouples toolbar components (they just navigate) from the list (it reads the URL).

**Cons**

- Verbose `router.navigate([], { queryParams, queryParamsHandling, replaceUrl })` boilerplate.
- Forgetting `queryParamsHandling: 'merge'` wipes other params.
- History spam without `replaceUrl` + debounce.
- Everything is a string — coerce numbers/booleans.

</Hinglish>

`router.navigate([], { queryParams: { page: 2 } })` bina `queryParamsHandling: 'merge'` — ye baaki saare query params (`search`, `sort`, `filter`) **hata deta hai**. Filters update karte waqt hamesha `queryParamsHandling: 'merge'`.

</Callout>

## Real World Example

<RealWorld company="Employee list with shareable filtered views">

An HR manager filters EMS employees to "Engineering, active, page 3, sorted by join date" — the URL becomes `/employees?departmentId=4&active=true&page=3&sort=joinDate`. They paste that link in Slack; a teammate opens it and sees the exact same filtered, paginated, sorted view. Pressing back returns to page 2. Refreshing keeps the filters. None of this needs extra code beyond reading `queryParamMap` and navigating with `queryParamsHandling: 'merge'` — the URL is the state.

</RealWorld>

## Numbers That Matter

<Numbers>

- Query params are optional and order-independent; a missing one just falls back to a default.
- `queryParams: { key: null }` **removes** that param from the URL.
- `queryParamsHandling`: `"merge"` (combine), `"preserve"` (keep current, ignore new), omitted (replace all).
- `{ replaceUrl: true }` + debounce keeps a search box from creating one history entry per keystroke.
- Query param values are **strings** — `+page`, `value === "true"` to coerce.

</Numbers>

## Interview Angle

<InterviewAngle>

Common: "route params vs query params?", "list filters kahan store karoge?", "`queryParamsHandling` kya karta hai?", "shareable filtered URL kaise?".

Strong answer:

1. Route param = required identity in the path; query param = optional, order-independent view state (filters/page/sort/tab).
2. Read `queryParamMap`; write `router.navigate([], { queryParams, queryParamsHandling: 'merge', replaceUrl: true })`.
3. `null` value removes a param; `'merge'` preserves the others.
4. URL-as-state = shareable, refresh-safe, back-button correct.
5. Debounce + `replaceUrl` for search to avoid history spam.

Red flag: "filters ko sirf component state me rakhta hoon" — no sharing, no back button, lost on refresh.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`queryParamsHandling: 'merge'` bhoolna.** Ek filter update karo aur baaki saare query params wipe. Almost always want `'merge'`.

</Mistake>

<Mistake>

**Empty filter ke liye `queryParams: { search: '' }`.** URL me `?search=` ganda dikhta hai. `search || null` se param hi remove ho jaata hai.

</Mistake>

<Mistake>

**Har keystroke pe `navigate` bina `replaceUrl`.** Back button 30 baar dabana padta hai ek search se bahar aane ke liye. `replaceUrl: true` + `debounceTime`.

</Mistake>

<Mistake>

**Query param ko typed maan lena.** `qp.get('page')` -> `"2"` string; `qp.get('active') === true` -> false. Coerce.

</Mistake>

<Mistake>

**New search par `page` reset na karna.** User page 5 par hai, naya search karta hai, page 5 rehta hai -> "no results". `queryParams: { search, page: 1 }`.

</Mistake>

## Quick Revision

<QuickRevision>

- Query params (`?k=v`) = optional, order-independent — use for `search`, filters, `page`, `sort`, `tab`.
- Read: `ActivatedRoute.queryParamMap` (Observable) or `withComponentInputBinding()` -> inputs.
- Write: `router.navigate([], { relativeTo: route, queryParams, queryParamsHandling: 'merge', replaceUrl: true })`.
- `queryParams: { key: null }` removes the param; `'merge'` preserves the rest; omitting `queryParamsHandling` replaces all.
- Reset `page: 1` whenever a filter/search changes.
- `replaceUrl: true` + debounce for search — avoid history spam.
- Values are strings — coerce numbers/booleans.
- URL-as-state = shareable, refresh-safe, back/forward correct.

</QuickRevision>

**Chhota:** `EmployeeListPage` me `queryParamMap` se `page` padho (default 1) aur `{{ page }}` dikhao. `/employees?page=3` kholkar verify.

**Medium:** Search box `(input)` -> `router.navigate([], { relativeTo: route, queryParams: { search: value || null, page: 1 }, queryParamsHandling: 'merge', replaceUrl: true })`. `queryParamMap` -> `debounceTime(300)` -> `switchMap(api.getEmployees)`. Confirm URL updates, refresh keeps the filter, back button returns to previous search.

**Bada:** `search`, `departmentId`, `sort`, `page` — chaaron query params. Toolbar sabko `merge` se update kare. Ek filter update karke dekho baaki preserve hote hain. Phir jaan-boojhke `queryParamsHandling` hata do — dekho ek filter set karne par baaki wipe. `search: ''` vs `search: null` compare karo URL me. 5-line note.

</Callout>
