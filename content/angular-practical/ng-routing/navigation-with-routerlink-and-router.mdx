<SimpleDefinition>

`routerLink` is a directive for declarative navigation in templates (`<a routerLink="/employees">`); `routerLinkActive` adds a CSS class while its link matches the current URL. The `Router` service navigates imperatively from code — `router.navigate(['/employees', id])` or `router.navigateByUrl('/login')` — which you use after actions like a successful save or logout.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Routes define ho gaye. Ab un routes pe **jaana** kaise — do tareeke: template me links (`routerLink`), aur code se (`Router` service).

### `routerLink` — declarative, template me

```html
<a routerLink="/dashboard">Dashboard</a>
<a routerLink="/employees">Employees</a>

<!-- array form — segments + params -->
<a [routerLink]="['/employees', emp.id]">{{ emp.firstName }}</a>
<a [routerLink]="['/employees', emp.id, 'edit']">Edit</a>

<!-- with query params + fragment -->
<a [routerLink]="['/employees']"
   [queryParams]="{ page: 2, search: 'aar' }"
   fragment="list">Page 2</a>

<!-- relative navigation -->
<a routerLink="../">Back</a>
<a routerLink="edit" relativeTo="...">Edit</a>
```

- String form: `routerLink="/employees"` — fixed path.
- Array form: `[routerLink]="['/employees', id]"` — dynamic segments; each item a path segment.
- `[queryParams]` — `?key=value`.
- `fragment` — `#anchor`.
- `<a href>` mat use karo internal navigation ke liye — wo full page reload karega. `routerLink` = SPA navigation.

### `routerLinkActive` — active link styling

```html
<a routerLink="/employees"
   routerLinkActive="active"
   [routerLinkActiveOptions]="{ exact: true }">Employees</a>
```

- `routerLinkActive="active"` — `active` class tab lagti hai jab URL is link se match kare.
- `{ exact: true }` — sirf exact match (warna `/employees/42` bhi `/employees` link ko active kar deta hai).
- Nav menus me har item pe.

### `Router` service — imperative, code se

```ts
import { Router } from "@angular/router";

export class AddEmployeePage {
  private router = inject(Router);

  async save(form: EmployeeForm) {
    const created = await firstValueFrom(this.service.create(form));
    this.router.navigate(["/employees", created.id]);   // go to details
  }

  cancel() {
    this.router.navigate(["/employees"]);
  }
}
```

- `router.navigate(commands, extras?)` — array of segments (like `routerLink`).
- `router.navigateByUrl("/employees?page=2")` — full URL string.
- Extras: `{ queryParams, fragment, relativeTo, replaceUrl, state, queryParamsHandling }`.
- Returns a `Promise<boolean>` — `true` if navigation succeeded (guards can cancel it).

### `routerLink` vs `router.navigate` — kab kya

- User ke click karne ke liye ek link/button jo hamesha same jagah jaaye -> `routerLink` (accessible `<a>`, right-click "open in new tab" kaam karta hai).
- Kisi **action ke baad** navigate (form save, login success, logout, guard redirect) -> `Router` service.

### `replaceUrl` and history

`router.navigate([...], { replaceUrl: true })` — current history entry ko replace karta hai (back button us page pe wapas nahi jaata). Login page ke baad dashboard pe jaate waqt useful — user back kare to login pe wapas na aaye.

### Show it in our project

- Sidebar nav: `routerLink` + `routerLinkActive` for each area.
- Employee row: `[routerLink]="['/employees', emp.id]"` for details.
- After "Add Employee" save: `router.navigate(['/employees', newId])`.
- Auth guard redirect: `router.navigate(['/login'], { queryParams: { returnUrl } })`.
- Logout: `router.navigateByUrl('/login', { replaceUrl: true })`.

### Where is it used in day-to-day development

Every nav menu, every list-to-details link, every "after save go to X", every guard redirect. `routerLink` in templates and `router.navigate` in components are among the most-used APIs.

### Pros and cons

**Pros**

- `routerLink` = accessible `<a>`, SPA navigation, new-tab support, prefetch-friendly.
- `routerLinkActive` = zero-code active styling.
- `Router` service = programmatic flows (post-action redirects, guards).

**Cons**

- `href` instead of `routerLink` -> full reload (common beginner bug).
- `routerLinkActive` without `{ exact: true }` -> parent link stays active on child routes (sometimes wanted, sometimes not).
- `router.navigate` array vs string form confusion (query params go in `extras`, not the array).
- Forgetting `await`/`.then` on `navigate` when you need to know it succeeded.

</Hinglish>

<Callout type="trap">

Internal navigation ke liye `<a href="/employees">` mat likho — wo browser ko full page reload karwata hai, poori Angular app dobdara load. `<a routerLink="/employees">` use karo.

</Callout>

## Numbers That Matter

<Numbers>

- `routerLink` renders a real `<a href>` — middle-click / Ctrl+click / "open in new tab" all work; `<button (click)="router.navigate(...)">` does not.
- `router.navigate(...)` returns `Promise<boolean>` — `false` when a guard cancels.
- `routerLinkActive` matches by URL prefix unless `[routerLinkActiveOptions]="{ exact: true }"`.
- `{ replaceUrl: true }` swaps the current history entry instead of pushing a new one.

</Numbers>

## Interview Angle

<InterviewAngle>

Common: "`routerLink` vs `href`?", "`routerLink` vs `router.navigate`?", "active link styling?", "`replaceUrl` kab?".

Strong answer:

1. `routerLink` = declarative SPA navigation in templates (real `<a>`, no reload); `href` = full reload.
2. `router.navigate(commands, extras)` = imperative, for post-action redirects and guards.
3. `routerLinkActive="cls"` (+ `{ exact: true }`) for active styling without code.
4. Array form for dynamic segments; query params/fragment go in `[queryParams]`/`fragment` (or `extras`).
5. `{ replaceUrl: true }` after login/logout so back doesn't return to that page.

Red flag: nav menu me `<button (click)="go()">` with `router.navigate` — loses `<a>` semantics and new-tab support.

</InterviewAngle>

## Common Mistakes

<Mistake>

**`<a href="/route">` for internal links.** Full page reload, Angular re-bootstraps. Use `routerLink`.

</Mistake>

<Mistake>

**Query params array me daalna: `[routerLink]="['/employees', { page: 2 }]"`.** Ye matrix params banata hai (`;page=2`), query params nahi. Use `[queryParams]="{ page: 2 }"`.

</Mistake>

<Mistake>

**`routerLinkActive` bina `{ exact: true }` jab exact chahiye.** `/` (home) link har route par active dikhega (prefix match).

</Mistake>

<Mistake>

**`router.navigate` ka result ignore karna jab wo matter karta hai.** Guard cancel kar sakta hai (`false`). `if (await this.router.navigate(...)) { ... }`.

</Mistake>

<Mistake>

**Nav items ko `<button>` + `router.navigate` se banana.** No `<a>` semantics, no keyboard/new-tab behaviour. Links = `<a routerLink>`.

</Mistake>

## Quick Revision

<QuickRevision>

- `routerLink="/path"` or `[routerLink]="['/employees', id]"` — declarative SPA navigation (renders a real `<a>`); never use `href` for internal links.
- Query params: `[queryParams]="{ page: 2 }"`; fragment: `fragment="section"` — not inside the `routerLink` array.
- `routerLinkActive="cls"` + `[routerLinkActiveOptions]="{ exact: true }"` for active styling.
- `Router.navigate(commands, extras)` / `navigateByUrl(url)` — imperative, for post-action redirects and guard flows; returns `Promise<boolean>`.
- `extras`: `queryParams`, `fragment`, `relativeTo`, `replaceUrl`, `state`, `queryParamsHandling`.
- `{ replaceUrl: true }` after login/logout so the back button skips that page.

</QuickRevision>
