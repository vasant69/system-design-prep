<SimpleDefinition>

Content projection lets a component render markup that its parent supplies between the component's opening and closing tags. `<ng-content />` is a single default slot; several `<ng-content select="...">` tags make named slots that route different pieces of projected content to different places. It is the standard way to build flexible wrapper components — cards, panels, dialogs, toolbars.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

`@Input` se aap **data** pass karte ho. Content projection se aap **markup** pass karte ho — ready-made HTML/components jo wrapper component apne layout me kahin render karta hai.

### What is it — single slot

```ts
@Component({
  selector: "app-card",
  template: `
    <div class="card">
      <ng-content />
    </div>
  `,
})
export class Card {}
```

Use:

```html
<app-card>
  <h3>Aarav Sharma</h3>
  <p>Senior Engineer</p>
</app-card>
```

`<app-card>` ke tags ke beech ka sab kuch `<ng-content />` ki jagah render hota hai, `.card` div ke andar. Card component ne styling/structure diya, content parent ne.

### Named slots — `<ng-content select>`

```ts
@Component({
  selector: "app-panel",
  template: `
    <header><ng-content select="[panelTitle]" /></header>
    <div class="body"><ng-content /></div>
    <footer><ng-content select="[panelActions]" /></footer>
  `,
})
export class Panel {}
```

Use:

```html
<app-panel>
  <h2 panelTitle>Employee Details</h2>
  <p>Main body content goes to the default slot.</p>
  <div panelActions>
    <button>Save</button>
    <button>Cancel</button>
  </div>
</app-panel>
```

- `select="[panelTitle]"` — attribute selector; `<h2 panelTitle>` us slot me.
- `select=".foo"`, `select="app-x"` bhi possible (class / element selectors).
- Jo kisi named slot se match nahi karta, wo default (bina `select`) `<ng-content>` me jaata hai.

### Why do we need it — kyun

`@Input` se aap markup pass nahi kar sakte cleanly. Ek `Card` jo `[title]` aur `[body]` string inputs le — us body me aap button, link, formatted text nahi daal sakte. Content projection se `Card` ek pure **layout/style shell** ban jata hai aur consumer kuch bhi bhar sakta hai. Ye "composition over configuration" hai.

### Projected content ka context — important

Projected content parent ke context me evaluate hota hai, wrapper ke nahi:

```html
<app-card>
  <p>{{ employee.name }}</p>   <!-- employee = PARENT ka property -->
</app-card>
```

`employee` yahan **parent** component ka hai, `Card` ka nahi. Card sirf position deta hai.

### Conditionally rendering a slot

```ts
@Component({
  selector: "app-panel",
  template: `
    <div class="body"><ng-content /></div>
    @if (hasFooter()) {
      <footer><ng-content select="[panelActions]" /></footer>
    }
  `,
})
export class Panel {
  private actions = contentChildren(PanelActionsDirective);
  hasFooter = computed(() => this.actions().length > 0);
}
```

### `ng-content` vs `@if` — a gotcha

`<ng-content>` ko `@if` me daalne pe: agar `@if` false ho, to projected content **create hi nahi hota** (achha for expensive content). Par `<ng-content>` ko multiple jagah nahi daal sakte "select same content twice" ke liye — har projected node ek hi slot me jaata hai.

### Show it in our project

- `Card` — dashboard stat cards, employee list cards.
- `Panel` — Details page sections (title / body / actions slots).
- `Modal` — `<ng-content select="[modalTitle]">`, default body, `<ng-content select="[modalFooter]">`.
- `EmptyState` — `<ng-content>` for a custom CTA button.

### Where is it used in day-to-day development

Har reusable "container" component: cards, panels, dialogs, accordions, tabs, list-items with custom templates, form-field wrappers (label + control + error slot). Design systems content projection par bahut depend karte hain.

### Pros and cons

**Pros**

- Wrapper component pure layout/style — consumer markup control me.
- Composition — ek `Card` infinite content shapes.
- Named slots -> structured flexibility (header/body/footer).

**Cons**

- Projected content ka context parent ka hai — beginners confuse hote hain.
- `select` selectors typo -> content silently default slot me ya gayab.
- Styling projected content wrapper se tricky (`::ng-deep` deprecated; `::slotted` sirf ShadowDom).
- Zyada slots = complex API; kabhi ek "render prop" style (`<ng-template>` + `ngTemplateOutlet`) better.

</Hinglish>

<Callout type="tip">

Rule: **data** parent -> child = `@Input`. **Markup/UI** parent -> child slot = `<ng-content>`. Dono milke flexible aur DRY components banate hain.

</Callout>

<RealWorld company="Design-system wrappers">

EMS ka `<app-modal>` ek single component hai jo backdrop, centering, focus-trap, escape-to-close, aur animations handle karta hai — aur teen slots deta hai: `[modalTitle]`, default body, `[modalFooter]`. Delete-confirm, Add-employee, Assign-role, Upload-document — sab isi modal ko use karte hain, alag content ke saath. Modal ko kabhi nahi pata usme kya hai; wo sirf ek accessible shell hai. ## Numbers That Matter

<Numbers>

- A single `<ng-content>` = one default slot; each `<ng-content select="...">` = one named slot.
- Content not matching any `select` falls into the default (unselected) `<ng-content>`; if there is none, it is dropped.
- Projected content is created in and bound to the **parent's** context, not the wrapper's.
- `select` accepts CSS selectors: `[attr]`, `.class`, `element`, or combinations.

</Numbers>

## Interview Angle

<InterviewAngle>

Common: "content projection kya hai?", "`ng-content` vs `@Input`?", "multi-slot projection?", "projected content kis context me bind hota hai?".

Strong answer:

1. `<ng-content>` renders markup the parent puts between the component's tags.
2. `@Input` = data; `<ng-content>` = markup/UI.
3. `<ng-content select="[x]">` = named slots; unmatched -> default slot.
4. Projected content binds in the **parent's** scope, not the wrapper's.
5. Use for wrappers: card, panel, modal, form-field.

Red flag: "projected content ke expressions wrapper component ki properties dekhte hain" — nahi, parent ki.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Yeh sochna ki `{{ x }}` in projected content wrapper ki property hai.** Wo **parent** ki hai — projected content parent ke context me bind hota hai.

</Mistake>

<Mistake>

**`select` selector typo / mismatch.** `<ng-content select="[panelTitle]">` par consumer `<h2 panel-title>` likhe — match fail, content default slot me chala jaata hai (ya drop). Selector exact.

</Mistake>

<Mistake>

**Same content ko do slots me dikhane ki koshish.** Har projected node exactly ek slot me jaata hai. Duplicate chahiye to `<ng-template>` + `ngTemplateOutlet` use karo.

</Mistake>

<Mistake>

**Projected content ko wrapper ke CSS se style karne ki koshish `::ng-deep` se.** Deprecated aur brittle. Consumer apni classes laaye, ya wrapper CSS custom properties expose kare.

</Mistake>

<Mistake>

**Bahut saare named slots (6+) banana.** API complex. Ek `<ng-template>`-based (`ngTemplateOutlet` with context) approach ya fewer, well-chosen slots.

</Mistake>

## Quick Revision

<QuickRevision>

- `<ng-content />` renders markup the parent passes between the component's tags.
- `@Input` = data down; `<ng-content>` = markup/UI down.
- `<ng-content select="[attr] | .class | element">` = named slots; unmatched content -> default `<ng-content>` (or dropped if none).
- Projected content is bound in the **parent's** context, not the wrapper's.
- Detect projected content with `contentChild`/`contentChildren` (ready in `ngAfterContentInit`).
- Use for wrappers: card, panel, modal, form-field, empty-state.
- Too many slots -> consider `<ng-template>` + `ngTemplateOutlet` instead.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `Card` component banao jiske template me sirf `<div class="card"><ng-content /></div>` ho. `<app-card><h3>Name</h3><p>Role</p></app-card>` se use karo aur confirm content `.card` ke andar render hota hai styled.

**Medium:** `Panel` banao 3 slots ke saath: `[panelTitle]`, default body, `[panelActions]`. Employee Details page ke ek section ko is Panel me wrap karo. `<h2 panelTitle>` me `{{ employee().firstName }}` use karo — confirm wo parent ke `employee` signal se aata hai (wrapper ke paas wo signal nahi).

**Bada:** `Panel` me footer slot ko `@if (hasFooter())` ke andar rakho jahan `hasFooter = computed(() => contentChildren(...).length > 0)`. Ek jagah Panel actions ke saath, ek jagah bina — confirm footer container sirf actions hone par render hota hai. Phir `::ng-deep` se projected `<button>` style karne ki koshish karo, dekho warning/deprecation, aur likho behtar tareeka kya hai (2-3 line).

</Callout>
