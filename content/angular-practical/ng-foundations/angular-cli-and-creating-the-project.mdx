<SimpleDefinition>

The Angular CLI (`ng`) is the official command-line tool for Angular. It scaffolds a new project, runs a live-reload development server, builds the app for production, runs unit tests, and generates components/services/guards on demand. In this course every project task starts with an `ng` command so nothing is hand-typed boilerplate.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Pichhle topic me humne decide kiya "Angular kyun". Ab hum EMS project **banayenge** — aur wo kaam Angular CLI karta hai.

### What is it — Angular CLI hai kya

CLI = Command Line Interface. Angular team ek npm package deti hai `@angular/cli` jiska command hota hai `ng`. Ye ek hi tool se:

- naya project banata hai (`ng new`)
- dev server chalata hai live-reload ke saath (`ng serve`)
- naye components/services/etc. generate karta hai (`ng generate` ya short `ng g`)
- production build banata hai (`ng build`)
- unit tests chalata hai (`ng test`)
- Angular version upgrade karta hai (`ng update`)

Andar ye Vite/esbuild (naye Angular me) ya webpack use karta hai, TypeScript compile karta hai, aur ek dev server deta hai. Aapko ye sab khud configure nahi karna padta — yahi CLI ka faayda.

### Why do we need it — haath se kyun nahi

Bina CLI ke ek Angular app chalane ke liye aapko chahiye: TypeScript config, bundler config, dev server, test runner config, production optimization (minify, tree-shake, hashing), aur ek folder structure jo Angular expect karta hai. Ye sab manually set karna ghante lega aur har project me thoda alag ho jaayega. CLI ye ek command me, **standard** tareeke se karta hai — isliye koi bhi Angular dev aapke project me aakar turant samajh jaata hai.

Doosra bada faayda: **generators**. `ng g c employee-list` ek command me component ki 2 files (TS + HTML), uska test file, aur sahi naming/structure de deta hai. Aap galat naam ya galchi jagah pe file nahi banate.

### How does it work — step by step

**Step 1 — Node aur npm check.** Angular ko ek recent Node LTS chahiye:

```bash
node --version
npm --version
```

Node 18.19+ ya 20+ hona chahiye modern Angular ke liye.

**Step 2 — CLI install karo (globally).**

```bash
npm install -g @angular/cli
ng version
```

`ng version` Angular CLI ka version aur aapke system ka setup dikha deta hai.

**Step 3 — project banao.**

```bash
ng new ems-frontend --routing --style=scss --ssr=false
```

Line by line:

- `ng new ems-frontend` — `ems-frontend` naam ka folder + project banata hai.
- `--routing` — ek routing setup ready deta hai (`app.routes.ts` file), taaki baad me pages add karna aasan ho.
- `--style=scss` — component styles SCSS me (plain CSS se thoda zyada powerful — variables, nesting).
- `--ssr=false` — abhi ke liye sirf client-side app. Server-side rendering baad ka topic hai; isko off rakhne se setup simple rehta hai.

Modern Angular me `ng new` **by default standalone** project deta hai — koi `app.module.ts` nahi.

**Step 4 — chalao.**

```bash
cd ems-frontend
ng serve --open
```

`ng serve` app ko compile karke `http://localhost:4200` pe serve karta hai. `--open` browser khud khol deta hai. Ab aap koi bhi file save karo — browser **automatically reload** ho jaata hai (live reload / HMR).

**Step 5 — pehla generate.**

```bash
ng generate component features/employees/employee-list
```

Ye banata hai `src/app/features/employees/employee-list/` folder me component files. `ng g c` short form hai.

### Show it in our project — humari commands

EMS ke liye hum ye base commands use karenge:

```bash
ng new ems-frontend --routing --style=scss --ssr=false
cd ems-frontend
ng g c features/auth/login
ng g c features/dashboard
ng g c features/employees/employee-list
ng g s core/services/employee        # service
ng g guard core/guards/auth --functional
ng g interceptor core/interceptors/auth
```

- `ng g s` = generate service, `ng g guard` = generate route guard, `ng g interceptor` = generate HTTP interceptor.
- `--functional` guard modern functional style (`CanActivateFn`) deta hai — is course me hum wahi use karenge.

### Where is it used in day-to-day development

Har din: `ng serve` background me chalta rehta hai jab aap kaam kar rahe ho. Naya screen chahiye — `ng g c ...`. Naya shared logic — `ng g s ...`. Release ke waqt — `ng build`. Angular ka naya version aaya — `ng update @angular/core @angular/cli`. CI pipeline me — `ng build` aur `ng test`. Practically har Angular task ka entry point `ng` hi hai.

### Pros and cons

**Pros**

- Ek command me consistent, production-ready setup — koi manual bundler config nahi.
- Generators naming aur structure standard rakhte hain, boilerplate khatam.
- `ng update` framework upgrades ko automated migrations ke saath aasan banata hai.
- CI-friendly — `ng build` / `ng test` seedhe pipeline me.

**Cons**

- Config abstracted hai — jab aap kuch non-standard chahte ho (custom webpack plugin), to thoda fight karna padta hai (`@angular-builders/custom-webpack` jaise).
- Global CLI version aur project ka CLI version mismatch ho jaaye to confusing errors — `npx ng` ya project-local CLI safe rehta hai.
- Initial `ng new` npm install slow ho sakta hai (bahut dependencies).

</Hinglish>

<Callout type="tip">

Global CLI aur project CLI mismatch se bachne ke liye project ke andar `npx ng serve` use karo — ye project ke `node_modules` wala CLI chalata hai, wahi version jo `package.json` me pinned hai.

</Callout>

## Numbers That Matter

<Numbers>

- `ng new` ek fresh app me roughly **900+ npm packages** install karta hai (framework + build toolchain + test runner) — pehli baar 1–3 minute lag sakte hain.
- `ng serve` ka incremental rebuild modern Angular (esbuild-based) me aksar **under 1 second** hota hai ek chhoti file change pe.
- Default dev server port: **4200**. Production `ng build` ka output `dist/<project>/browser/` me jaata hai.
- `ng update` Angular ke har major version ke saath **automated code migrations** chalata hai — manual find-replace ki zaroorat kaafi kam.

</Numbers>

## Interview Angle

<InterviewAngle>

Ye topic aksar practical/screening round me aata hai: "Naya Angular project kaise start karoge?", "`ng serve` aur `ng build` me farak?", "`ng generate` kya deta hai?".

Strong answer ka shape:

1. `ng new <name>` se scaffold, common flags: `--routing`, `--style=scss`, `--ssr`.
2. `ng serve` = dev server, in-memory build, live reload, optimize NAHI karta — sirf local development.
3. `ng build` = disk pe production bundle, minify + tree-shake + hashing, `dist/` me — yahi deploy hota hai.
4. `ng g c/s/guard/...` = boilerplate + test file + correct structure, naming conventions enforce.

Red flag: "main files khud copy-paste karke banata hoon" — CLI generators use na karna beginner signal hai.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Global CLI aur project CLI version mismatch.** Aapne 2 saal pehle `npm i -g @angular/cli` kiya tha, ab naya project v18 ka hai. `ng serve` ajeeb errors deta hai. Fix: project ke andar `npx ng ...` chalao, ya global CLI ko `npm i -g @angular/cli@latest` se update karo.

</Mistake>

<Mistake>

**`ng serve` ke output ko deploy karne ki koshish.** `ng serve` disk pe kuch likhta hi nahi — wo in-memory serve karta hai aur optimize nahi karta. Deploy ke liye hamesha `ng build`, phir `dist/.../browser/` folder host karo.

</Mistake>

<Mistake>

**`node_modules` git me commit karna.** `ng new` ek `.gitignore` deta hai jisme `node_modules` already hota hai. Use hataana mat — repo ka size 100x badh jaayega. `npm install` har machine pe `package-lock.json` se wahi versions la aata hai.

</Mistake>

<Mistake>

**Files haath se banana galat folder me.** `ng g c employee-list` (bina path) `src/app/` me banata hai. Structure chahiye to path do: `ng g c features/employees/employee-list`. Baad me file move karna imports tod deta hai.

</Mistake>

<Mistake>

**`ng new` ke saare prompts bina padhe Enter dabana.** SSR, SSG, style format — ye choices project ka setup badalte hain. Flags explicitly do (`--ssr=false --style=scss`) taaki har baar predictable rahe, khaas kar scripts me.

</Mistake>

## Quick Revision

<QuickRevision>

- Angular CLI = `ng` command from `@angular/cli`; official tool for scaffold / serve / generate / build / test / update.
- `ng new <name> --routing --style=scss --ssr=false` — creates the project; modern default is **standalone** (no `app.module.ts`).
- `ng serve` = dev server on **4200**, in-memory, live reload, NOT optimized — local only.
- `ng build` = production bundle to `dist/<project>/browser/` — minified, tree-shaken, hashed — this is what deploys.
- `ng g c|s|guard|interceptor <path/name>` = generate with correct structure + test file; use `--functional` for guards/interceptors.
- Use `npx ng` inside a project to dodge global-vs-project CLI version mismatch.
- Never commit `node_modules`; `package-lock.json` reproduces exact versions.

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `ng new ems-frontend --routing --style=scss --ssr=false` chalao, phir `cd ems-frontend && ng serve --open`. Browser me `localhost:4200` khulna chahiye. `src/app/app.html` me kuch text badlo aur save karo — dekho browser bina refresh ke update hota hai.

**Medium:** In dono ko generate karo: `ng g c features/dashboard` aur `ng g s core/services/employee`. Naye folders aur files list karo. Har generated file ka ek line me purpose likho (component TS, component HTML, spec file, service TS).

**Bada:** Ek chhoti table banao 4 commands ke liye — `ng serve`, `ng build`, `ng test`, `ng generate` — columns: *kya karta hai*, *output kahan jaata hai (disk/memory/browser)*, *kab chalaoge (dev/CI/deploy)*. Phir `ng build` chalao aur `dist/` ke andar dekho kaunsi files bani — `.js` file names me hash kyun hai, socho.

</Callout>
