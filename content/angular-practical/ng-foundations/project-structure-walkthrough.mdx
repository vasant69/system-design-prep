<SimpleDefinition>

A tour of every important file and folder the Angular CLI creates: `package.json` (dependencies + scripts), `angular.json` (build/serve config), the `tsconfig` files (TypeScript settings), `src/index.html` (the shell), `src/main.ts` (the bootstrap), `src/styles.scss` (global styles), and `src/app/` (your code). The goal is that nothing in the project is a black box before we start editing it.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

`ng new` ke baad folder me kaafi files dikhti hain. Beginners aksar in sabko "config, chhedo mat" maan lete hain — aur phir jab port badalna ho, ya ek global CSS file add karni ho, ya build ka output path badalna ho, to pata nahi chalta kaunsi file kholein. Chaliye har file ka kaam dekhte hain.

### What is it — kya dekh rahe hain

Ye ek fresh standalone Angular project ka layout hai:

```text
ems-frontend/
├── node_modules/            # installed dependencies (git-ignored)
├── src/
│   ├── app/
│   │   ├── app.ts           # root component class
│   │   ├── app.html         # root component template
│   │   ├── app.scss         # root component styles
│   │   ├── app.spec.ts      # root component test
│   │   ├── app.config.ts    # ApplicationConfig (providers)
│   │   └── app.routes.ts    # route definitions
│   ├── index.html           # the single HTML page
│   ├── main.ts              # entry point: bootstraps the app
│   └── styles.scss          # global styles
├── public/                  # static assets copied as-is
├── angular.json             # CLI build/serve/test configuration
├── package.json             # dependencies + npm scripts
├── package-lock.json        # exact dependency versions
├── tsconfig.json            # base TypeScript config
├── tsconfig.app.json        # TS config for the app build
├── tsconfig.spec.json       # TS config for tests
└── .gitignore
```

(File naam Angular version pe thoda vary karte hain — purane me `app.component.ts`, naye me `app.ts`. Concept same hai.)

### Why do we need to know this — kyun

Har real problem ka ek "kaunsi file" jawaab hota hai:

- Dev server ka port badalna? -> `angular.json` (ya `ng serve --port`).
- Ek npm library add ki, wo global CSS maangti hai? -> `angular.json` ke `styles` array me path daalo.
- App boot pe kaunse providers milte hain (HttpClient, Router)? -> `app.config.ts`.
- TypeScript strict mode on/off? -> `tsconfig.json`.
- `npm start` kya chalata hai? -> `package.json` ke `scripts`.

Ye map dimaag me ho to debugging guesswork nahi rehti.

### How does it work — file by file

**`package.json`** — project ka manifest. Do important hisse:

```json
{
  "scripts": {
    "start": "ng serve",
    "build": "ng build",
    "test": "ng test"
  },
  "dependencies": { "@angular/core": "^18.0.0", "rxjs": "~7.8.0" },
  "devDependencies": { "@angular/cli": "^18.0.0", "typescript": "~5.4.0" }
}
```

- `scripts` — `npm start`, `npm run build` in shortcuts ko define karte hain.
- `dependencies` — runtime pe chahiye (framework, rxjs).
- `devDependencies` — sirf development/build pe chahiye (CLI, TypeScript, test tools).
- `^` aur `~` version ranges hain; exact versions `package-lock.json` me lock hote hain.

**`angular.json`** — CLI ki config. Yahan define hota hai: source root, `index.html` ka path, `main.ts` ka path, `styles` aur `scripts` arrays (global CSS/JS), aur `configurations` (`production`, `development`) jo alag build settings dete hain (budgets, source maps, optimization).

**`tsconfig.json`** — base TypeScript settings. Modern Angular me `"strict": true` hota hai — matlab null-checks, no implicit `any`, etc. `tsconfig.app.json` aur `tsconfig.spec.json` isko extend karte hain, app build aur tests ke liye alag include/exclude ke saath.

**`src/index.html`** — poori app ka ek hi HTML page:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <title>EmsFrontend</title>
  <base href="/" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
</head>
<body>
  <app-root></app-root>
</body>
</html>
```

- `<base href="/" />` — router ko batata hai URLs ka base kya hai (deploy pe kabhi badalna padta hai).
- `<app-root></app-root>` — yahan Angular root component render karta hai. Baaki sab JS inject karta hai.

**`src/main.ts`** — entry point:

```ts
import { bootstrapApplication } from "@angular/platform-browser";
import { App } from "./app/app";
import { appConfig } from "./app/app.config";

bootstrapApplication(App, appConfig)
  .catch((err) => console.error(err));
```

- `bootstrapApplication(App, appConfig)` — Angular ko chalu karo, `App` component ko root banao, `appConfig` ke providers use karo.

**`src/app/app.config.ts`** — application-wide providers:

```ts
import { ApplicationConfig } from "@angular/core";
import { provideRouter } from "@angular/router";
import { routes } from "./app.routes";

export const appConfig: ApplicationConfig = {
  providers: [provideRouter(routes)],
};
```

- Yahan hum baad me `provideHttpClient()`, interceptors, etc. add karenge.

**`src/styles.scss`** — global styles (resets, font, theme variables). Component ke `.scss` sirf us component ke liye scoped hote hain; jo sabko chahiye wo yahan.

**`public/`** — jo bhi yahan hai wo build me as-is copy hota hai (favicon, images). Code isse `/logo.png` jaise path se access karta hai.

### Show it in our project — EMS structure

Hum `src/app/` ke andar ye convention use karenge:

```text
src/app/
├── core/            # singletons: services, guards, interceptors, models
│   ├── services/
│   ├── guards/
│   ├── interceptors/
│   └── models/
├── shared/          # reusable dumb UI: components, pipes, directives
├── features/        # one folder per feature area
│   ├── auth/
│   ├── dashboard/
│   ├── employees/
│   ├── departments/
│   └── ...
├── app.ts / app.html / app.config.ts / app.routes.ts
```

`core` = "ek hi baar banti hai" cheezein. `shared` = "kai jagah use hoti hai, apna state nahi" cheezein. `features` = actual screens.

### Where is it used in day-to-day development

Naya global style? `styles.scss`. Naya provider (analytics, HTTP)? `app.config.ts`. Naya route? `app.routes.ts`. npm script chahiye (lint, format)? `package.json` scripts. Build budget error aaya? `angular.json` `budgets`. Ye files aap roz nahi chhedte, lekin jab chhedte ho to exactly pata hona chahiye kaunsi.

### Pros and cons

**Pros**

- Standard layout — koi bhi Angular dev turant navigate kar leta hai.
- Config alag files me split — TS settings, build settings, dependencies clearly separated.
- `core` / `shared` / `features` convention scale karti hai.

**Cons**

- Pehli baar file count overwhelming lagta hai.
- `angular.json` verbose aur nested hai — chhoti galti (comma, path) build tod deti hai.
- Convention CLI enforce nahi karta — team ko discipline se `core`/`shared`/`features` follow karna padta hai.

</Hinglish>

## Real World Example

<RealWorld company="Large internal admin apps">

Ek typical enterprise EMS-style app me `features/` ke andar 15–30 folders ho sakte hain (employees, departments, payroll, attendance, recruitment...). `core/` me ~10 services aur 2–3 interceptors, `shared/` me ~20 reusable components (table, modal, date-picker wrapper, empty-state). Kyunki har team member same `core`/`shared`/`features` split follow karta hai, ek nayi feature folder purani feature folder ko dekh kar 30 minute me ban jaati hai — structure ka faayda yahi hai.

</RealWorld>

## Numbers That Matter

<Numbers>

- Fresh `ng new` app: roughly **15–20 source/config files** outside `node_modules`.
- `angular.json` me typically **2 build configurations** out of the box: `production` aur `development`.
- Default production budgets: initial bundle warning around **500 KB**, error around **1 MB** (tunable in `angular.json`).
- `tsconfig.json` me modern Angular ke ~**8 strict-family flags** on hote hain (`strict`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, etc.).

</Numbers>

## Interview Angle

<InterviewAngle>

Poochha jaata hai: "Angular project ka structure walk-through karo", "`main.ts` kya karta hai?", "`angular.json` kis liye hai?", "global style kahan add karoge vs component style?".

Strong answer: har file ka ek-line role — `package.json` deps+scripts, `angular.json` CLI build/serve config, `tsconfig` TS settings, `index.html` single page with `app-root`, `main.ts` bootstrap, `app.config.ts` app-wide providers, `styles.scss` global CSS, `src/app` your code. Bonus: `core`/`shared`/`features` folder convention aur uska rationale.

Red flag: "sab config auto-generated hai, main dekhta nahi" — seniors se expected hai ki wo `angular.json` aur `tsconfig` comfortably edit kar sakein.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Component style aur global style ko confuse karna.** Component ke `.scss` me likha CSS default me sirf usi component ke elements pe lagta hai (view encapsulation). Agar aapko `body` font ya ek utility class sab jagah chahiye, wo `src/styles.scss` me jaani chahiye, component file me nahi.

</Mistake>

<Mistake>

**`angular.json` ko haath se edit karte waqt syntax todna.** Ye strict JSON hai — trailing comma, missing quote, galat path — build turant fail. Change chhota rakho, ek baar me ek, aur `ng build` se verify karo.

</Mistake>

<Mistake>

**npm library add karne ke baad uski CSS import bhoolna.** Bahut si UI libraries ek CSS file ship karti hain jise `angular.json` ke `styles` array me path add karke ya `styles.scss` me `@import` karke load karna padta hai — warna component to aata hai par bina styling ke dikhta hai.

</Mistake>

<Mistake>

**`src/assets` vs `public` galat samajhna.** Naye Angular me static files `public/` me jaati hain aur root path se serve hoti hain (`/logo.png`). Purane projects me `src/assets/` hota tha (`/assets/logo.png`). Version ke hisaab se sahi folder use karo.

</Mistake>

## Quick Revision

<QuickRevision>

- `package.json` — dependencies (runtime) vs devDependencies (build) + npm `scripts`.
- `angular.json` — CLI config: paths, `styles`/`scripts` arrays, `production`/`development` configurations, budgets.
- `tsconfig.json` (+ `.app` + `.spec`) — TypeScript settings; modern Angular is `strict`.
- `src/index.html` — the one page; `<base href>` + `<app-root>`.
- `src/main.ts` — `bootstrapApplication(App, appConfig)` — the entry point.
- `src/app/app.config.ts` — app-wide providers (`provideRouter`, later `provideHttpClient`).
- `src/styles.scss` — global styles; component `.scss` is scoped to that component.
- `public/` — static assets copied as-is (newer Angular); older projects use `src/assets/`.
- EMS convention: `core/` (singletons), `shared/` (dumb reusable UI), `features/` (screens).

</QuickRevision>

## Practice

<Callout type="tip">

**Chhota:** `angular.json` kholo. Dhoondho: `index` ka path, `main` ka path, aur `styles` array. Phir `package.json` ke `scripts` padho aur likho `npm start`, `npm run build`, `npm test` asal me kya chalate hain.

**Medium:** `src/app/` ke andar `core/`, `shared/`, `features/` folders banao. `features/dashboard` me `ng g c` se ek component generate karo aur confirm karo wo sahi folder me aaya. `core/models/employee.ts` naam ki ek file banao aur usme `Employee` interface likho (id, firstName, lastName, email, departmentId).

**Bada:** `src/styles.scss` me ek global CSS variable aur ek utility class (`.text-muted`) add karo. Phir `App` ke `app.scss` (component style) me ek rule likho jo sirf `app-root` ke andar apply ho. Dono ko template me use karke confirm karo: global class kahin bhi kaam karti hai, component rule sirf us component ke andar. Findings 3 line me likho.

</Callout>
