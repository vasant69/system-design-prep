<SimpleDefinition>

A component is a TypeScript class decorated with `@Component`, which links three things: a `selector` (the custom HTML tag), a `template` (the HTML it renders), and optional `styles`. You place a component on screen by putting its selector tag inside another component's template, or by routing to it. This lesson builds the EMS shell plus a first `EmployeeList` component.

</SimpleDefinition>

## Hinglish Deep Explanation

<Hinglish>

Ab tak humne project banaya aur samjha wo boot kaise hota hai. Is topic me pehla apna component screen pe laayenge — EMS ka layout shell aur ek `EmployeeList`.

### What is it — component hai kya

Component = **class + decorator**. Class me data aur methods (component ki "logic"). Decorator `@Component({...})` Angular ko metadata deta hai:

```ts
import { Component } from "@angular/core";

@Component({
  selector: "app-employee-list",
  template: `
    <h2>Employees</h2>
    <p>Total: {{ employees.length }}</p>
    <ul>
      @for (emp of employees; track emp.id) {
        <li>{{ emp.firstName }} {{ emp.lastName }} — {{ emp.email }}</li>
      }
    </ul>
  `,
  styles: [`
    h2 { margin-bottom: 0.5rem; }
  `],
})
export class EmployeeList {
  employees = [
    { id: 1, firstName: "Aarav", lastName: "Sharma", email: "aarav@ems.local" },
    { id: 2, firstName: "Diya", lastName: "Patel", email: "diya@ems.local" },
    { id: 3, firstName: "Kabir", lastName: "Rao", email: "kabir@ems.local" },
  ];
}
```

Line by line:

- `@Component({...})` — is class ko Angular component banata hai.
- `selector: "app-employee-list"` — is component ka HTML tag. Kahin `<app-employee-list></app-employee-list>` likho to yahi render hoga.
- `template` — inline HTML (backticks se multi-line). `templateUrl: "./employee-list.html"` se alag file bhi ho sakti hai.
- `{{ employees.length }}` — **interpolation**: class ki property ko HTML me daalna.
- `@for (emp of employees; track emp.id) { ... }` — naya control flow: list pe loop, `track` se Angular DOM efficiently update karta hai.
- `styles` — is component ke scoped CSS.
- `export class EmployeeList { employees = [...] }` — component ki state; template isko dekhta hai.

### Why do we need components — kyun

UI ko chhote, named, reusable tukdon me todna. Har tukda apni HTML + apni logic + apni CSS ek jagah rakhta hai. Faayde:

- **Reuse** — `EmployeeCard` ek baar banao, list me 100 baar use karo.
- **Isolation** — ek component ka CSS doosre ko nahi todta (encapsulation).
- **Testability** — chhota component alag se test karna aasan.
- **Team** — alag log alag components pe kaam kar sakte hain.

### How does it work — render kaise hota hai

```text
App component template me  <app-employee-list />
        |
Angular selector match karta hai -> EmployeeList class instantiate
        |
EmployeeList ka template compile hota hai, {{ }} aur @for evaluate
        |
Result DOM me inject hota hai jahan tag tha
        |
State badalne pe Angular sirf badla hua DOM node update karta hai
```

### Show it in our project — shell + list

**Step 1 — shell components generate karo:**

```bash
ng g c shared/ui/site-header
ng g c shared/ui/site-sidebar
ng g c features/employees/employee-list
```

**Step 2 — `App` ko layout shell banao** (`app.ts`):

```ts
import { Component } from "@angular/core";
import { RouterOutlet } from "@angular/router";
import { SiteHeader } from "./shared/ui/site-header/site-header";
import { SiteSidebar } from "./shared/ui/site-sidebar/site-sidebar";

@Component({
  selector: "app-root",
  imports: [RouterOutlet, SiteHeader, SiteSidebar],
  template: `
    <app-site-header />
    <div class="layout">
      <app-site-sidebar />
      <main class="content">
        <router-outlet />
      </main>
    </div>
  `,
  styleUrl: "./app.scss",
})
export class App {}
```

**Step 3 — `EmployeeList` ko ek route pe daalo** (`app.routes.ts`):

```ts
import { Routes } from "@angular/router";
import { EmployeeList } from "./features/employees/employee-list/employee-list";

export const routes: Routes = [
  { path: "", redirectTo: "employees", pathMatch: "full" },
  { path: "employees", component: EmployeeList },
];
```

Ab `localhost:4200` kholne pe: header + sidebar + `<router-outlet>` me `EmployeeList` (kyunki URL `/` `employees` pe redirect hota hai). Teen dummy employees dikhne chahiye.

### Where is it used in day-to-day development

Har naya screen = ek component. Har reusable UI piece = ek component. Din bhar aap `ng g c ...` chalate ho, template likhte ho, class me state/methods add karte ho, aur parent ke template me ya route me use place karte ho. Component Angular ki sabse basic building block hai — baaki sab (binding, inputs, lifecycle) isi ke around hai.

### Pros and cons

**Pros**

- Clear boundaries — har feature ka code ek folder me.
- Reuse aur isolation built-in.
- CLI generator naming/structure/test file handle karta hai.

**Cons**

- Chhoti UI ke liye bhi ek component + folder — kabhi over-structuring lagta hai.
- Inline vs external template/styles ka decision har baar lena padta hai (chhota inline theek, bada external).
- Naye devs selector naming (`app-` prefix) aur class naming conventions bhoolte hain.

</Hinglish>

<Callout type="tip">

Rule of thumb: template 5–10 line se chhota hai to `template:` inline rakho; usse bada to `templateUrl` alag file me — editor tooling (HTML highlighting, formatting) tab behtar kaam karta hai.

</Callout>

## Numbers That Matter

<Numbers>

- `ng g c <name>` typically **4 files** banata hai: `.ts`, `.html`, `.scss`, `.spec.ts` (flags se kam kiya ja sakta hai).
- Component selector convention: `app-` prefix (configurable in `angular.json` `prefix`), kebab-case.
- Ek healthy component: roughly **under 200 lines** of TS logic; usse zyada = todne ka time.
- `@for` me `track` dena list re-render pe DOM node reuse enable karta hai — bina `track` bade lists slow aur buggy ho sakti hain.

</Numbers>

## Interview Angle

<InterviewAngle>

Aksar: "Component kya hai?", "`selector`, `template`, `styles` ka role?", "component ko screen pe kaise laate ho?", "inline vs external template kab?".

Strong answer:

1. Component = class + `@Component` decorator jodta hai selector + template + styles.
2. Screen pe aata hai: parent template me selector tag se, ya router se (route ka `component`).
3. `{{ }}` interpolation se class property template me.
4. Angular selector match karke class instantiate karta hai, template render karta hai, state change pe minimal DOM update.

Red flag: "component ek HTML file hai" — component ek class hai; HTML uska ek hissa hai.

</InterviewAngle>

## Common Mistakes

<Mistake>

**Selector aur class naam ko galat convention me likhna.** Selector kebab-case with prefix (`app-employee-list`), class PascalCase (`EmployeeList`). CLI ye theek karta hai; haath se banaoge to aksar mismatch ho jaata hai aur "not a known element" milta hai.

</Mistake>

<Mistake>

**Parent ke `imports` me child component add karna bhoolna.** Standalone me `<app-employee-list />` tabhi render hoga jab parent component ke `imports` me `EmployeeList` ho. Bina uske Angular tag ko plain unknown HTML samajh kar chup rehta hai (ya error deta hai).

</Mistake>

<Mistake>

**`@for` me `track` na dena.** Bina `track`, list update pe Angular saare DOM nodes dob/ara banata hai — slow, aur input focus/scroll position kho jaata hai. Hamesha `track` do — usually unique `id`.

</Mistake>

<Mistake>

**Bahut bada inline template.** 100-line HTML string `template:` me daalna — koi syntax highlighting nahi, merge conflicts painful. Bada template `templateUrl` me le jao.

</Mistake>

<Mistake>

**Component ki state ko constructor me hi API se bharne ki koshish.** Abhi dummy array theek hai; real data fetch `ngOnInit` / service me hota hai (aage ke topics). Constructor sirf DI ke liye rakho.

</Mistake>

## Quick Revision

<QuickRevision>

- Component = class + `@Component` decorator linking `selector` + `template`/`templateUrl` + `styles`/`styleUrl`.
- Put it on screen: selector tag in a parent template, OR a route's `component`.
- `{{ expr }}` = interpolation (class property into template).
- `@for (x of list; track x.id) { ... }` = new control-flow loop; always give `track`.
- Standalone: parent must have the child in its `imports` to use its selector.
- Selector = kebab-case with `app-` prefix; class = PascalCase.
- Inline `template` for small; `templateUrl` for large.
- Keep components small (roughly under 200 lines of logic).

</QuickRevision>

**Medium:** `App` component ko layout shell banao: `ng g c shared/ui/site-header` aur `site-sidebar`, dono ko `App` ke `imports` aur template me daalo, `<router-outlet />` beech me rakho. Header me app ka naam, sidebar me 3 dummy links. Confirm karo har route change pe header/sidebar rehte hain, sirf outlet ka content badalta hai.

**Bada:** `EmployeeList` ke template me `@for` ke saath `track emp.id` do. Phir jaan-boojh ke `track` hata do aur ek button add karo jo `this.employees = [...this.employees].reverse()` karta hai. Dono versions (with/without track) me list reverse karke browser DevTools me dekho DOM nodes reuse hote hain ya dobara bante hain. 3-line observation likho.

</Callout>
